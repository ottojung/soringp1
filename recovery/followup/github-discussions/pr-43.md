# Pull request #43: Fix research keeper unable to replenish failed but front-owned agents

Upstream: https://github.com/ottojung/soringp1/pull/43

Production bug found live at 2026-10-22 17:51 UTC: Luna hit usage limits, all free model fallbacks failed, the running SoringP1 pool dropped from 8 to 1, and the keeper could not replenish it. Antonina correctly rejects `agent run --cwd ...` when an existing agent still owns its front—even when metadata says `failed`. The keeper always passed --cwd; thus it repeatedly failed. Independently verified that `antonina agent run --id <same> --prompt ... --detach` (without --cwd) relaunches the very same agent ID successfully. Fix: validate each managed agent's durable id+declared cwd against its assigned existing worktree, then issue the relaunch without --cwd. Preserve no upper cap, 5-agent hard minimum, per-track fresh prompts and provider failover. Replenished seven actual researchers manually during the incident; eight isolated keeper tests pass. No Lean. Signed commit c3bf1df.
