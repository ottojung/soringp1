# Pull request #39: Recover stalled SoringP1 agents while preserving minimum research capacity

Upstream: https://github.com/ottojung/soringp1/pull/39

On billy-dev all 8 SoringP1 agents remained `running` for ~7h without any new output because OpenCode's Beam Free backend was rate-limited/hung. The keeper counted those as capacity, so quota replenishment never triggered. This patch makes the keeper check each agent's declared worktree, invocation start and **actual output.log mtime**, then steer at most one 30-minute-silent agent per tick onto the next independent research packet. It uses a tested `antonina agent run --steer` path without `--cwd` (Antonina rejects `--cwd` while the front is owned), maintaining the agent's running slot throughout; successful steering updates persistent cursors/history to prevent rapid repeats. Recent output protects legitimate long sessions. Live `--once` on Billy successfully steered a stuck track and replenished the research pool to eight. Five focused Python unit tests pass. No Lean changes, model discovery, or resource limits.
