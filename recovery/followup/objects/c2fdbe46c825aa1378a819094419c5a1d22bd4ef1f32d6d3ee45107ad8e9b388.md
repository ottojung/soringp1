# FO(TC)-style strategy programs: uniform interpreter boundary

**Status:** model definition and complexity deduction; exact-completeness
conjecture remains open. This note coordinates with Antonina fervor and
SoringP1 issue #47 without asserting that the whole sorting-number function
has an NP or Sigma-2 upper bound.

## A concrete program model

For input size `n`, a program is a finite directed control graph with labels
from `0..m-1`. More formally, an instruction table is an encoding of a finite
map from labels to the forms below; each transition target is a valid label.
A label contains exactly one instruction:

* `Ask(i,j,yes,no)`, with `i,j` in `0..n-1` and `i != j`;
* `Emit(i,next)`; or
* `Halt`.

The configuration is `(label, H, out, q)`. `H` is a partial strict order
recording comparisons already answered, `out` is a sequence of emitted key
labels, and `q` counts oracle calls. `Ask` issues one charged query to the
hidden strict total order `X`; it branches according to `X(i)<X(j)` and adds
that answer to `H`. The program has no other access to `X`: in particular,
its control flow cannot test the input order or inspect an unqueried pair.
`Emit` appends the named key; it conveys no information about `X`. `Halt`
terminates. A run is correct when its output is exactly the keys in increasing
`X` order, and its comparison cost is the maximum `q` over all `n!` orders.
Programs that fail to halt or output incorrectly on any order are rejected.

This finite-control language deliberately allows arbitrary sharing of
continuations; its conventional table encoding has size `|p|` polynomial in
the number of labels and binary operand widths. It contains no source-level
FO(TC) quantifier evaluation. It is a uniform executable semantics against
which a proposed logical syntax may be compiled. To call it an FO(TC)
fragment, a syntax must supply a compiler into these instructions with a
proved size and time bound; the name of a logical formalism is not itself a
uniform interpreter bound.

## Sound quantified upper bound (conditional on a clock)

Let `N=n+k+1`, the length of `1^n#1^k`. Fix a polynomial `P` and a
deterministic interpreter `U(p,n,X)` which runs in at most
`P(N+|p|)` steps, including decoding, maintaining `H`, and producing output.
Define the syntactic verifier to simulate `U` on a proposed permutation `X`,
reject if any step exceeds the clock, reject if more than `k` `Ask`s occur,
and accept that trial precisely when the run halts with a permutation sorted
by `X`. Then

    exists p, |p| <= P(N)  forall total orders X: V(p,1^n#1^k,X).

is a `Sigma_2^P` predicate: guess `p`, universally quantify a polynomial-size
encoding of `X`, and run the fixed polynomial-time verifier. Invalid encodings
of total orders can be handled by making the verifier accept them. The
verifier requires that the query counter never exceed `k`; a larger count
cannot be clipped after the run.

For any `p` accepted by the verifier, its actual execution on every order is
correct and uses at most `k` comparisons. Therefore the quantified statement
implies `S(n) <= k`. The converse follows only from a **completeness premise**:
whenever `S(n) <= k`, there exists a program of size at most `P(N)` whose
uniformly clocked execution realizes a correct strategy with budget `k`.
Under that premise, `SORT-BOUND-U` is in `Sigma_2^P`. The universal simulation
alone does not give NP: correctness is universally checked over all orders.

Neither conclusion holds for the unrestricted problem just because some
mathematical strategy is a finite control graph: a depth-`k` comparison tree
can have `2^k` nodes, and is therefore exponentially long when `k` is unary.
Likewise FO(TC)=NL in data complexity for a **fixed** formula does not bound
combined evaluation of a growing guessed source text. The fixed `U` and its
uniform clock are explicit hypotheses, not consequences of fixed-formula
data complexity.

## Small program examples and the all-n gap

Insertion sort, merge sort, and the Ford--Johnson witnesses in
`docs/research-fo-tc-twophase.md` have ordinary uniform adaptive
implementations in this model: `Ask` is the sole observation of the unknown
order and each call costs one. Their known comparison bounds do not provide
optimality for every `n`. An implementation that first searches all strategy
trees for an optimum may have a short source description, but its execution
time is not polynomial; it does not satisfy the clock premise.

**Falsifiable conjecture.** There is a single polynomial `P` such that for
every `n>=1`, the exact optimum `S(n)` is attained by a correct program in a
fixed, effectively encoded extension of the above language, of description
length and per-order interpreter runtime at most `P(n+S(n))`, with comparison
budget exactly `S(n)`. A proof would make the program predicate complete and
give `SORT-BOUND-U` in `Sigma_2^P` (not NP from this argument). A refutation
must exhibit a lower bound against **every** such program family or a
complexity barrier for this specific uniform interpreter model; finite
misses of one compiler template do not refute it.

## Status and next discriminating experiment

* **PROVED:** the quantified program verifier is sound, and is in
  `Sigma_2^P` under the stated fixed-polynomial interpreter and size clock.
* **CONDITIONAL:** `SORT-BOUND-U` is in `Sigma_2^P` if the all-`n`
  polynomial-program completeness conjecture holds.
* **OPEN:** an FO(TC) source fragment with both polynomial combined
  evaluation and the required exact-sorting expressive power; the conjectured
  completeness itself.
* **NOT CLAIMED:** NP / `Sigma_2^P` membership for unrestricted
  `SORT-BOUND-U`, or that data-complexity FO(TC)=NL implies the needed clock.

The next experiment should compile insertion sort and merge sort into one
explicit syntax-to-`U` compiler, account separately for program bits,
interpreter steps, and `Ask`s as functions of `n`, then test whether bounding
the TC arity/variable inventory still permits those strategies. This checks
the model/compiler boundary; it cannot establish exact-optimum completeness.
Issue #47's framed-DAG certificates address the separate succinct
representation question: an efficiently checked DAG is one candidate program
encoding, but converting its certificate verifier to an executable strategy
must preserve every query branch and cannot be inferred from certificate
soundness alone.
