# FO(TC)-style strategy programs for exact sorting

**Status:** conditional model analysis plus a verifier regression; no all-n
optimal-program completeness theorem. The target remains unary
`SORT-BOUND-U = {1^n#1^k : S(n) <= k}`.

## 1. Query-program model and cost

Fix one deterministic universal machine `U`. A program is a finite byte string
`p`; its registers, instruction pointer, explicit working memory, and output
are mutable state. The only operation that observes the hidden total order on
the labels `[n]` is `QUERY(i,j)`, for distinct valid labels. It returns which
label is smaller and increments the comparison counter by one. All control,
arithmetic, memory, and output operations are ordinary machine steps and are
charged to runtime. In particular, a program cannot read the order, embed
oracle answers/advice, or use a primitive that executes an uncharged
transitive-closure search.

For a fixed constant `c`, reject malformed programs and clock every run at
`T=(n+k+|p|+2)^c` deterministic steps. A run accepts exactly when it halts
within `T`, emits a permutation of `[n]` consistent with every query answer
(equivalently, sorts the queried keys; universal verification over all total
orders then implies the required order), and has made at most `k` queries.
This is an explicit operational strategy syntax: query selection, answer
branching, state update, output, termination, query cost, and total runtime
are all defined by the fixed machine rather than by variable FO(TC) formulas.

Define `QWIN_c` to contain unary triples `1^n#1^k#1^b` for which some `p` of
length at most `b` passes the test for every permutation `pi` of `[n]`.
Then `QWIN_c` is in `Sigma_2^P`: guess `p`, universally quantify an
`O(n log(n+1))`-bit permutation, and run the fixed polynomial clocked verifier.
The verifier's polynomial bound is uniform in the text `p`, not a fixed-formula
FO(TC) data-complexity claim. The quantifiers are explicitly
`exists p forall pi`; outcomes are adversarial, not chosen existentially.

**Soundness.** If `p` passes for every `pi`, each execution is a legal adaptive
comparison strategy using at most `k` comparisons and producing the correct
increasing label order. Therefore `S(n)<=k`. Conversely, if `S(n)<=k` and an
eligible `p` implements a height-at-most-`k` tree, it passes. This converse is
only for strategies expressible and executable in the chosen fixed program
model.

## 2. Relation to FO(TC) and framed DAGs

An FO(TC) source language could encode the control/state rules, but it does not
inherit a polynomial combined-time evaluator merely because each fixed formula
has a data-complexity capture theorem. If formula text, tuple arity, or TC
nesting grows with the guessed program, a varying closure-state space must be
accounted for. A defensible route is to compile a restricted FO(TC) syntax to
the fixed clocked `U`, charging every evaluation step; the claim then belongs
to that compiled fragment, not unrestricted FO(TC).

Every explicit framed-DAG certificate with `m` nodes and polynomial-bit labels
can be compiled into a query program: store the node table, current node and
slot permutation; issue the node's comparison; follow the corresponding edge
and compose its explicit frame. A certificate of height at most `k` gives at
most `k` queries on every order. The table and per-transition frame work have
polynomial total code/runtime in the explicit certificate length and `n`.
This gives a cost-preserving embedding of the *explicit* DAG proof system into
query programs. It does not turn an exponentially large decision tree or
unknown-size DAG into a polynomial-size program.

## 3. Exact-completeness question

The sharp conjecture is: there are fixed constants `a,c` such that for every
`n,k`, if `S(n)<=k`, some program `p` of size at most `(n+k+2)^a` sorts every
permutation with at most `k` comparisons and runs within
`(n+k+|p|+2)^c` steps. This is falsifiable by a proved family of optimal-root
strategies requiring superpolynomial code/runtime in this specific model, or
provable by a uniform compiler preserving exact worst-case depth.

- **PROVED (conditional-class soundness):** `QWIN_c` is in `Sigma_2^P`; every
  accepted program witnesses `S(n)<=k`.
- **PROVED (embedding):** explicit framed DAGs compile to query programs with
  polynomial overhead in explicit certificate size and `n`.
- **CONDITIONAL (transfer):** the all-`n` polynomial-program conjecture would
  place `SORT-BOUND-U` in `Sigma_2^P`; the needed length bound is polynomial
  in `n+k`, the unary input parameters.
- **OPEN:** no proof/counterexample of that exact-depth all-`n` completeness is
  established. In particular, a polynomial interpreter alone does not imply
  it. Existing merge-sort witnesses are polynomial programs but use
  `O(n log n)` comparisons, not necessarily `S(n)`.
- **NOT CLAIMED:** unrestricted FO(TC) combined evaluation in polynomial time,
  or `SORT-BOUND-U` membership in `NP`/`Sigma_2^P`.

## 4. Scoped verifier finding and next experiment

The framed-DAG checker previously accepted unreachable nodes without
propagating any state through them. This contradicted the advertised syntax of
a single finite root-reachable strategy DAG and could hide malformed or
cyclic disconnected components. The checker now rejects any node not reached
from the root; its forward-edge rule already ensures acyclicity. A regression
test covers an unreachable leaf while preserving the reachable valid sorter.

Next experiment: construct one query-program interpreter for the existing
framed certificate JSON, independently execute it over all `n!` orders for
small `n`, and compare its query maxima/output with the existing abstract
checker. Then test size/runtime scaling on bubble, merge-sort, and available
optimal small witnesses. This checks the stated embedding and cost accounting;
it cannot settle the all-`n` completeness conjecture.
