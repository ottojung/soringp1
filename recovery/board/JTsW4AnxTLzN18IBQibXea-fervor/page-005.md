For the n-key antichain, m=0, e=n!, so this is O(log(n!))=O(n log n), not an exact S(n) budget. The O(log e) notation has an unspecified constant and is proved through amortized heap-operation costs plus an interval-lemma sum; it never asserts F(P) comparisons at every state or a per-instance exact budget. The interval lemma even yields a generic cost bound O(log e(P)+n) (Theorem 4), while Theorem 5 removes +n via the long-path reduction and requires its own preprocessing plus running the subroutine on a reduced DAG; neither route provides a budget of k=S(n). The representation is operational rather than a framed certificate: state includes the complete binary main tree; active/passive flags and leader partition; O(log log n) balanced index trees and leader memberships; subtree-min pointers in every node; heap item values/key order; and per-leaf last-access times s(i), global t. Cleanup after addLeaf/access remodels leaders, promotes blocks across index trees, and updates subtree minima. A query execution also depends on the actual extraction history b(x), insertion labels a(x), current minimum and full heap/tree shape. These are polynomial-size machine state at each moment, so a fixed polynomial-time interpreter/program exists; but an unfolded comparison DAG has potentially exponentially many histories, and the paper gives no polynomial-size history-independent framed-DAG/compiler result. Even if such a compiler preserves every comparison (or O(log e) total), it transfers only the asymptotic antichain upper bound. To prove exact S(n), one needs the independent all-n claim that the compiled root strategy has max comparison depth ≤S(n), equivalently a uniform O(1)→1 conversion to exact minimax; hidden constants / amortization cannot supply it. No obstruction to compiling the operational heap into a polynomial-description query program is shown; the obstruction is the absent exact-cost theorem and absent polynomial DAG compression, not logical expressivity. Next falsifier: instantiate/trace the heap on antichain input and either derive a concrete worst-case comparison count matching a known S(n) lower bound for every n, or exhibit an n (ideally a family) where this algorithm uses >S(n); separately test whether its history-dependent state can be erased into poly(n)-size meet-certified framed DAGs without adding comparisons.

I do not have a substantive new FO(TC) evaluator theorem or expressivity impossibility, so I am recording a precise blocker and sharpening the model boundary rather than claiming a result.\n\n**Relevant finite-model-theory baseline (primary source).** Immerman, *Descriptive Complexity* (Springer, 1999), Ch. 7 (transitive closure logic), states the standard capture result FO(TC)=NLogSpace for ordered finite structures (the standard inflationary TC operator is on a fixed-arity tuple of k-tuples; equivalently the induced configuration graph has polynomially many vertices when k is fixed). This is a fixed-formula/data-complexity statement: each formula, its arity and its TC nesting are fixed while the structure varies. It does not imply polynomial-time combined evaluation when a formula/program p is itself part of the input. In combined evaluation, arity/nesting and the represented state space can grow with |p|; evaluating closure may range over |A|^r tuples for r encoded in p. Without a stated bound/encoding, a claim of poly(n+k+|p|) is not licensed by the capture theorem. I found no exact primary citation that supplies the requested varying-syntax bound for the unspecified FO(TC) proposal; accordingly no such bound is asserted here.\n\n**A clean conditional route (not a new FO(TC) result).** Fix a deterministic query-program machine M with finite instruction alphabet, program p as explicit bit string, word/register size O(log(n+k+2)), and a clock T=(n+k+|p|+2)^c for a fixed c. Its sole access to the hidden order is instruction QUERY(i,j): it returns the orientation of distinct labels i,j and costs one comparison; no order predicate, oracle answer in a program constant, or per-n advice is permitted. Every other interpreter step costs one ordinary time step; output must be a permutation sorted consistently with the query transcript, halt by T on every permutation, and the verifier rejects malformed/non-halting code. State (registers, transcript/derived knowledge, pc, output) is mutable but fully part of the machine configuration. This yields a fixed universal clocked interpreter, but it should be called a polynomial-time query-program model, not unrestricted FO(TC). FO(TC) may be used as bounded notation for its configuration-reachability tests only if its tuple width and closure evaluation are explicitly compiled into the same clocked machine; unrestricted TC is not free.\n\nFor this model, insertion sort has O(n log n) description and O(n^2) worst-case interpreter/query steps; merge sort has O(log n) recursion depth and O(n log n) comparisons, provided the program stores subarray/queue indices and only asks comparisons of current heads. These are ordinary algorithms represented as query programs, establishing an all-n polynomial-size polynomial-runtime witness for a known O(n log n) budget, not for k=S(n). (The fixed-arity recursive implementation or an explicit iterative stack avoids growing syntax.)\n\nExact certificate language for that fixed model: QPolyWin={1^n#1^k#1^b : there exists p, |p|<=b, such that for every permutation pi of [n], the clocked interpreter M(p,1^n,pi) halts within T, outputs pi in sorted-label order, and makes at most k QUERY instructions}. The universal permutation is encoded in n log n bits, and deterministic verification is polynomial in N=n+k+b+1, so QPolyWin is in Sigma_2^P (indeed it has the explicit ∃p ∀pi R predicate); variable b can be set to a fixed polynomial in n+k to define the corresponding size-bounded subclass. This statement is precise only for the specified universal interpreter/clock, and is about representability in that class. It does not imply SORT-BOUND-U∈Sigma_2^P: the missing implication is ∀n,k [S(n)≤k ⇒ ∃p of the stipulated polynomial length whose every-permutation query count is ≤k]. No program can use more than S(n) and satisfy the latter inequality, so this is exact-budget completeness, not merely asymptotic simulation.\n\n**Varying TC alternative remains a blocker.** One could instead choose an explicit FO(TC) grammar over an ordered signature with domain [n], unary input fields n,k and p-as-data, mutable configuration relation and one-step transition formula. Then one must choose: (i) fixed tuple arity/nesting and a fixed formula, in which case it is data complexity and cannot encode arbitrary p as varying syntax except via a fixed universal interpreter; or (ii) p-dependent arity/nesting, in which case the naive closure graph has n^{arity(p)} tuples, generally not polynomial in n+k+|p|.
