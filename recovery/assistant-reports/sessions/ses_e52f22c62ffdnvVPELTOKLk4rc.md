### Checkpoint/recomputation scheme

Do not keep the path’s comparison transcript on the work tape. When processing a frame at depth `t`, reconstruct its path by replaying the deterministic DFS control computation from the root until that frame is reached. Store only the replay simulator’s configuration and the target depth `t`. At the target, execute the frame’s next step; when that step descends, repeat reconstruction for the child. A return is handled by reconstructing the parent and consuming the returned child Boolean.

A replay configuration consists of the current depth, one current pair and phase per active frame, and at most one saved first-child Boolean per frame. All counters and labels use `O(log(n+2))` bits, so the configuration uses `O((t+1)log(n+2))` bits. Reachability uses a single `O(n)`-bit visited vector and `O(n log(n+2))`-bit BFS queue; instead use Savitch-style directed reachability to use `O(log²(n+2))` bits, with polynomial-in-`n`-space-reduced recomputation time `n^{O(log n)}` per reachability query. The graph has at most `n` vertices and path-derived edges can be regenerated by replaying the relevant prefix. Thus peak space is `O((d+1)log(n+2))` unless we also remove the active-depth configurations.

To reach **O(n)** bits, checkpoint only at block boundaries of `b=⌈log(n+2)⌉` frames. Store the boundary configurations; reconstruct within one block by replay.
