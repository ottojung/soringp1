## Findings (paper argument; labels: definition/deduction/literature)

### 1. Single-input execution traces are insufficient (definition/deduction)
A single execution trace certifies only the comparison path taken on one input order (or one adversary branch). Worst-case depth `<= k` is a universal/adversarial property over all `n!` inputs (equivalently, over all adversary answers in the game `G(n,k)` of `docs/research-certificates-barriers.md` Claim A): every root-to-leaf path of the policy's induced comparison behavior must have length `<= k` and every reachable leaf must determine a total order. Therefore no family of per-input traces, taken individually, is a worst-case certificate except by exhaustive coverage of all branches — which is exactly the size issue below.

### 2. Falsification (a), for an explicit natural certificate format: reduced per-branch comparison-decision witnesses (deduction)
**Precise format.** A *reduced comparison-decision certificate for a fixed policy `π_n`* is a sound, explicit object whose accepted runs are in bijection with the feasible adversary/leaf outcomes of `π_n` on all `n`-key inputs, such that each internal certified step corresponds to one policy comparison and each terminal certified outcome corresponds to a uniquely determined sorted order (i.e. it explicitly witnesses global correctness and depth by covering every permutation-distinguishing outcome class). This includes: explicit reduced decision trees, and any uncompressed unfolding that keeps one certified node per reachable policy state/outcome class needed to separate all `n!` results (hash-consed state-DAGs help only when distinct paths reach the *same* certified state; see 3).

**Claim (deduction, all-n).** For **every** correct comparison-sorting policy `π_n` (hence for any FO(TC)-expressible correct policy family, if one fixes any standard uniform policy such as insertion-sort or merge-sort schedule as the FO(TC)-described object), every certificate of this format has `>= n!` terminal outcomes and `>= 2n! - 1` nodes, which is superpolynomial in the unary input length `N = n+k+1 = Θ(n log n)` for informative `k` (indeed `n! = 2^{Θ(N)}` in that regime). Moreover, it cannot be verified as a worst-case depth certificate in time polynomial in `n` (or in `N`) because reading it already requires superpolynomial time in `n`.

**Argument.** Correctness of a comparison sort means distinct permutations cannot yield the same certified terminal outcome (a single total-order output cannot be correct for two different input permutations). A deterministic policy maps each input permutation to exactly one feasible run/leaf, so at least `n!` distinct terminal outcomes are required. In a reduced binary comparison structure `nodes = 2*leaves - 1 >= 2n! - 1` (`docs/research-certificates-barriers.md` Claim C; `docs/research-strategy-certificates.md` Thm 2.1). This lower bound is independent of how succinctly the *policy* is described (FO(TC), RAM program, etc.): it is a property of certifying all permutation outcomes of that correct policy. Standard policies (insertion/merge/bubble schedules) are uniformly/simple-to-describe (descriptively low, hence compatible with an "FO(TC)-described policy" reading), so this gives an explicit family satisfying (a) **relative to this certificate format**: worst-case depth/correctness certification in this form provably requires superpolynomial witness size and superpolynomial checking in `n`.

**Caveat (important).** This falsifies the pairing for *explicit per-outcome/uncompressed* certificates, not for all conceivable certificate formats. It does not rule out compressed certificates whose verified nodes identify many outcomes via joins/quotients.

### 3. Compressed/framed/quotient certificates: sound+poly-checkable in size, completeness open (literature/deduction from repo)
- `scripts/check_framed_strategy.py` / `docs/research-framed-certificate-frontier.md`: framed permutation DAG certificates with meet/intersection are **sound** and checkable in time polynomial in the explicit graph size and `n` (local feasibility, closure/intersection, total-order leaves, DAG depth). They can be smaller by joining branches.
- Known/constructed polynomial-size framed witnesses exist for some non-optimal policies (all-n bubble-sort path-like witness; all-n adaptive merge-sort DAG, `O(n^2)` comparison nodes / `O(n log n)` path length, paper construction pending full audit; plausible rank-envelope/Ford–Johnson upper-bound construction pending frame/boundary audit). So for *some* simple/FO(TC)-describable policies, a poly-size worst-case certificate **can** exist in a compressed format — this limits how strong (a) can be made without fixing the format.
- A symmetry-quotient certificate with supplied relabelling maps is polynomial-time checkable in its own encoding (`docs/research-strategy-certificates.md` Thm 3.4/Rem 3.3), but the **number of quotient states/nodes** is unknown (all-n) and may be superpolynomial; experiments only cover tiny `n`.
- **Completeness gap (all-n).** No theorem is known that every true instance `1^n#1^k` (in particular at the exact optimum `k=S(n)`) has a polynomial-size sound certificate of any of these compressed forms, nor that every fixed FO(TC)-describable policy admits such a compressed worst-case certificate. Exact-optimal completeness would imply `SORT-BOUND-U ∈ NP` (frontier doc §5), which is open; the converse obstruction is also open. This is an **inconclusive/no-go-for-current-subclasses** situation rather than a proved all-n completeness failure for optimal strategies, except in the uncompressed sense of §2.

### 4. Status versus requested falsifiers (a)/(b)
- **(a)**: **Established conditionally on a precise natural format.** For the explicit reduced comparison-decision (per-permutation/uncompressed) certificate format, *every* correct policy — including explicit simple uniformly/FO(TC)-describable families — provably requires superpolynomial witness size/checking in `n` (>= `2n!-1` nodes). Not established for compressed framed/quotient DAG formats (some FO(TC)-simple policies have poly compressed certificates; general/optimal case open).
- **(b)**: **Not proved.** I did not find (and cannot here derive) an all-n completeness-failure theorem for a precisely specified `FO(TC)+compressed-certificate` subclass relative to *optimal* strategies. A precise subclass where completeness fails is the "FO(TC)-described policy + explicit reduced per-outcome certificate" class (fails completeness/compactness for all correct policies by §2, hence also cannot supply optimal-strategy certificates compactly), but that is essentially a restatement of the tree-size barrier rather than a new optimality-specific obstruction. For framed/quotient subclasses, completeness relative to optimal strategies remains open.

No claim is made that `SORT-BOUND-U ∉ NP`, `∉ P`, or any separation; the sparsity/Mahaney and model caveats of `docs/problem.md` apply.

## Clear next decisive obstacle

**Decisive obstacle (compressed completeness).** Either (i) construct, for all `n`, a polynomial-size sound framed/quotient (or other poly-checkable) worst-case depth certificate for *some* policy achieving depth `S(n)` (or prove a structural theorem forcing such a quotient, e.g. polynomially many root-reachable optimal equivalence classes with locally checkable congruence) — which would yield `SORT-BOUND-U ∈ NP`; or (ii) prove an all-n superpolynomial lower bound on the minimum size of any sound certificate in a precisely specified compressed class **even when restricted to optimal policies** (an optimality-relative analogue of the `2n!-1` per-outcome barrier), e.g. by exhibiting an infinite family forcing superpolynomially many pairwise-incompatible certified states/joins under that class. 

The gap between §2 (uncompressed: unconditional superpolynomial) and §3 (compressed: poly-checkable but completeness unknown) is exactly the live frontier (`fo-tc-policy-interpreter` / framed-certificate frontier).
