## 1. PGF annotation/perm definition

**Checker behavior (`scripts/check_framed_strategy.py`) `[definition]`.** For a feasible comparison outcome the checker: adds `smaller < larger` to the current bitmask relation, computes `_closure()` (Floyd–Warshall transitive closure on bitmasks; rejects cycles), applies `_rename(rows, perm, n)` where each old fact `i<j` becomes `perm[i] < perm[j]`, and joins at a node by bitwise intersection `R(child)=⋂ R_in` over feasible incoming renamed relations (lines 96–107). An edge `perm` must be a list of length `n` forming a permutation of `0..n-1` (lines 92–95). Leaves are accepted only when every pair is ordered in `R(leaf)` and reachable depth `<= budget` (lines 69–78, 109–111). Branches whose outcome contradicts current `R(v)` are skipped (99–100).

**Artifact alignment.** The artifact’s PGF description and its statement that the checker’s only per-edge annotation is `perm`, with no disjunctive/multi-state join field and single-poset meet only, matches the implementation `[deduction from code]`. Calling frame normalization (F-norm) “checker-acceptable” is correct when it uses only per-edge `perm` and the DAG format; calling stronger join annotations (disjunctions/poset sets/auxiliary metadata) “not checker-acceptable” without format/soundness extension is correct `[deduction]`.

**Minor precision note.** The artifact says “permutation maps old slot indices to new slot indices”; this matches `_rename` (`renamed[perm[i]] |= 1<<perm[j]`) and `triangular_bubble_certificate`’s compare-exchange frame. It is an implementation-level convention (a renaming of current slot contents/labels) — acceptable, but proofs should state the semantic invariant explicitly (what real orders the abstract state represents) rather than assuming an informal “physical slot” intuition.

**Finite constraint validity `[deduction]`.** For the stated fragment, `R1={0<1,0<5}`, `R2={1<0,0<5}` before join, identity on the `R1` edge, and a requirement that the join meet contain both `0<1` and `0<5`: preserving `0<1` from `1<0∈R2` forces `p2(1)=0,p2(0)=1`; preserving `0<5` from `0<5∈R2` forces `p2(0)=0,p2(5)=5`, contradiction. Symmetric over `(p1,p2)`. This is a correct finite permutation-constraint argument **conditional on those required meet facts**. The “required residual below the join demands both…” hypothesis is the load-bearing assumption; the artifact states it, which is appropriate. As a result, the conclusion should be read as: *no existing-checker-acceptable single-poset F-norm join can complete this specific bounded fragment if that fragment’s downstream total-order completion requires those two facts in the meet*.
