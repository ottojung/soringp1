# Framed DAG witness probe for `n=9` (front: `framed-dag-witness-n9-exact`)

## 1. Problem statement and baseline

**Task (falsifiable, independent):** Does there exist an explicit, checkable
permutation-framed strategy DAG certificate of exact height `S(9)=19` for
`n=9`, and what is its concrete size/depth/profile compared to polynomial
envelopes (e.g. `O(n^2)` nodes, `O(n log n)` path length as in merge-sort
constructions)?

**Model/certificate grammar (repo):** deterministic adaptive comparison sorting
of distinct labelled elements. A framed certificate is a topologically ordered
DAG (root 0) whose comparison nodes specify `(compare [a,b], lt {next,perm},
gt {next,perm})` with slot permutations; leaves must imply a total order.
Soundness is checked by propagating/intersecting guaranteed strict partial
orders along feasible branches and enforcing depth `<= budget`. Reference:
[`docs/research-framed-certificate-frontier.md`](docs/research-framed-certificate-frontier.md),
checker [`scripts/check_framed_strategy.py`](scripts/check_framed_strategy.py).

**`S(9)` baseline (literature/repo, not re-proved here):** the repository and
its research notes treat the standard exact values as known, including
`S(9)=19` (e.g. `tests/test_upper_witness.py` expects `9: 19`,
`docs/research-state-compression.md` states symmetry-quotient DP recomputes
`S(9)=19`, Ford–Johnson/MergeInsertion upper bound `M(9)=19` is exact for
`n<=11` per Knuth/Peczarski as cited in repo docs/scripts). This report does
**not** provide an independent proof of `S(9)=19`; it uses `19` as the target
exact budget for the framed-certificate question.

### 3.3 Relevant known constructions/envelopes (evidence, not newly certified here)

From `docs/research-framed-certificate-frontier.md` (paper constructions,
implementation/audit caveats noted there):
- **Adaptive merge-sort framed DAG (Sec. 2):** sequential composition of merge
  grids gives `O(n^2)` comparison nodes with balanced-merge **path length
  `O(n log n)`** (not `O(n^2)` path length). The note also states this
  architecture is not exact-optimal for large powers of two
  (`n log2 n - n + 1` vs `log2(n!) + o(n)`), so it cannot be assumed to reach
  `S(n)` in general.
- **Ford–Johnson rank-envelope framed certificate (Sec. 3):** plausible
  polynomial (`O(n^2)` query-node scale suggested) framed certificate for the
  *standard Ford–Johnson upper bound*
  `F_FJ(n)=sum_{j=1}^n ceil(log2(3j/4))`, **not** equal to `S(n)` for every
  `n`; for `n<=11` this bound matches known `S(n)` (including `M(9)=19` per
  repo sources), but an exact framed embedding requires independent
  frame/boundary/odd-case audit and was not implemented/checked here.

Concrete comparison-count evidence for `n=9` (standard algorithms, not framed
certificates verified here): balanced merge sort on split `4,5` uses
`S_merge(4)+S_merge(5)+8 = 5+7+8 = 20 > 19`; Ford–Johnson bound gives
`M(9)=19` (repo baseline). Thus a naive balanced merge-sort framed certificate
would be expected to miss exact height 19, while an FJ-framed certificate is a
candidate but un-audited/unconstructed.

## 4. Obstruction / evidence (why exact 19 not certified here)

- **Target gap:** smallest explicitly constructed and checker-verified framed DAG
  witness in this run has depth **36** (`n=9` bubble), versus target **19**.
- **Merge-sort route:** gives the desired polynomial envelope in principle
  (`O(n^2)` nodes, `O(n log n)` path length per Sec. 2) but standard balanced
  merge sort incurs ~20 comparisons for `n=9`, so it is not an exact-height
  witness; docs also warn it cannot be exact-optimal for all large powers of two.
- **Ford–Johnson route:** `M(9)=19` matches the target value, but the repo note
  explicitly marks the complete recursive framed permutation/boundary/odd-case
  embedding as needing independent audit; no generator or checked framed
  certificate for FJ at `n=9` exists in this worktree and one was not
  implemented here.
- **Optimal-strategy lifting:** known/claimed optimal strategies achieving
  `S(9)=19` are not present here as explicit framed certificates. Converting an
  optimal comparison decision policy into the checker’s permutation-framed DAG
  with sound join/intersection annotations is nontrivial (join soundness/feasible
  branches/permutation bookkeeping) and was not completed.
- **Search/resource limits:** no exhaustive framed-DAG search was attempted;
  pure-Python optimal tree/poset enumeration at `n=9` is impractical in this
  environment, and no existing `n=9` framed witness file was found.

**Conclusion (falsifiable status):** existence of an explicit, checkable
permutation-framed strategy DAG certificate of exact height `S(9)=19` remains
**open/unresolved by this run**. Verified lower-side evidence here is only the
explicit bubble framed witness at depth 36; upper/exact feasibility at 19 is not
refuted but not witnessed.
