# Sergeev TR20-096 group-insertion: effective finite-bound audit for unary `SORT-BOUND-U`

**Status:** research audit (paper analysis only). Not Lean-checked. No PR/main changes. No board post.

**Labels used:** `[literature]` (paper claims), `[deduction]` (logical consequence for this project), `[uncertain]` (text-extraction or reconstruction uncertainty), `[open]` (needed for effectivity).

**Task (SoringP1 #301, billy-dev).** Falsifiable question: can the Sergeev ECCC TR20-096 group-insertion proof be made **effective** for the unary `SORT-BOUND-U` threshold window?

**Decision (defensible).** **(B) Precise non-effectivity obstruction as stated.** TR20-096 gives a constructive group-insertion *sorting algorithm* and asymptotic comparison upper bounds (`S(n) = log2(n!) + O(n/(log n)^(1/5))`), but the proof as extracted does **not** supply an explicit all-`n` computable bound `S(n) <= log2(n!) + f(n)` with all constants, all parameter choices, and an explicit finite basis `n0` resolved. A finite effective bound *may* be extractable by a careful re-analysis of the proof, but that extraction is **not carried out here** and requires nontrivial bookkeeping listed below.

**Model consequence.** `[deduction]` If an explicit computable `f` and `n0` were produced with
`S(n) <= U_eff(n) := ceil(log2(n!)) + f(n)` for all `n >= n0`, then for unary inputs
`1^n # 1^k` (`N=n+k+1`) the threshold decision `S(n) <= k` would have the window narrowed to
`[ceil(log2(n!)), U_eff(n)]` for large `n`: answers outside this window would be immediate from
the information lower bound / effective upper bound. This would aid finite verification/search
but would **not** by itself place `SORT-BOUND-U` in P, NP, or change its known PSPACE/EXPTIME/DSPACE
upper bounds, and would not affect the out-of-scope separations noted in `docs/problem.md`.

## TR20-096 theorem/lemma statements (best-effort)

### Definitions
- `[literature]` `S(n)` = minimal worst-case number of pairwise comparisons to sort `n` elements (decision tree depth). Information lower bound `S(n) >= log2(n!)` (p.1, (1)).
- `[literature]` `Q(a)=2^{floor(log a)}` is the maximal interval length for inserting one element in complexity `<=a` (p.5, (4)).
- `[literature]` `P(a)` is the maximal interval length for inserting an ordered pair in complexity `<=2a`:
  `P(a) = ceil((17/14)*2^a)` for `a in N`, and `P(a)=ceil((12/7)*2^(a-1/2))` for `(a-1/2) in N` (p.5, (5), citing [6,7]). `[uncertain bracket rendering]`
- `[literature]` `Q_m(a)`, `P_m(a)` are the analogous maximal lengths for inserting `m` elements / `m` ordered pairs with total complexity `a*m` / `2a*m` (p.5). Trivial: `Q_m(a) >= Q(a)-(m-1)`, `P_m(a) >= P(a)-2(m-1)`. Also `Q_{2m}(a) >= P_m(a-1/2)` (6).
- `[literature]` Conditional complexity / containers: extra insertions from containers bounded roughly as `rho*m + C*log2(n+2m)` (p.7, (9)), with the paper noting a more accurate `O(1)` container effect is possible.

### Technical lemmas
- `[literature]` **Lemma 1 (p.9).** For `u in T^eps(sigma)`, `v in T(sigma)`, `0 < eps < ||v-u||`, there is a sequence `{x_i} subset [u,v]` satisfying system `sigma` of width `w`, starting at `u` and converging to `v` with rate
  `||v-x_i|| <= (1-eps*Delta)^(i/w - 1) * ||v-u||`, `Delta=||v-u||^{-1}` (13). Proof is constructive by interpolation (14),(15). `[uncertain symbol rendering]`
- `[literature]` **Lemma 2 (pp.9–13).** Converts a comparison strategy of depth `h`, width `w` and LP-feasible `v in T(sigma)`, `u in T^eps(sigma)` with `u_i <= pi(y_i)` into
  `P_m(r + y_i + (r+2)*phi*2^phi/m) >= v_i*2^r - (R/eps)*m*2^(phi+2) - R*2^r*exp(-eps/(2R)*(phi/(w(d+1)(h+1)) - 2))` (18),
  under `m <= min{u_min, eps/2}*2^(r-phi-1)` (17), `R=||v-u||`, for any `r,m in N`, `phi>0`. Proof is algorithmic by induction on the reduced strategy tree, with containers/rounding.
- `[literature]` **Lemma 3 (p.13).** Concrete 4-level example: for `m ≍ 2^(r/2)`, `v=(80/63,286/189,338/189,58/27)`, `gamma` small enough (say `1/100000`),
  `P_m(r + i/4 + 2^(-gamma*r)) >= v_i*2^r - O(2^((1-gamma)*r))`, `i=0..3` (22). Uses fixed strategy (`d=4,w=5,h=5`) and feasible `u=(1.02,17/14,1.47,12/7) in T^eps(sigma)`, `eps=1/350`.
- `[literature]` **Lemma 4 (p.27).** Universal strategy feasibility: for `s>=20`, `d=2s`, `mu=30*2^(-s)`, `lambda=20*2^(-s/2)+64*2^(-s)`, `eps=1/(25*2^s)`, `y_i=i/d`, `v_i=(1-lambda)*2^(y_i+1/2)`,
  (i) `v in T(sigma[s])`; (ii) `u=v/2 in T^eps(sigma[s])`.

### Main theorems / corollaries
- `[literature]` **Theorem 1 (pp.16–17).** `S(n) <= log(n!) + 0.09*n + o(n)`. (Intermediate constant improvement via modified Ford–Johnson final stage.)
- `[literature]` **Theorem 2 (p.28).** For any `a >= 2` and `2^(a/4) <= m <= 2^(a/2)`,
  `P_m(a) >= 2^(a+1/2) - O(a^(-gamma) * 2^a)`,
  where `gamma` is small enough, say `gamma = 1/5` (44). Proof applies Lemma 2 to Lemma 4 with `s=ceil(2*gamma*log a)`, `phi=log(m*eps/(4*a^2))`.
- `[literature]` **Corollary 2 (p.29).** For `a >= 2`, `2^(a/4) <= m <= 2^(a/2)`,
  `Q_{2m}(a) >= 2^a - O(a^(-1/5) * 2^a)`.
- `[literature]` **Theorem 3 (p.29).** For any `n`,
  `S(n) = log(n!) + O(n * log^(-1/5) n)`.
  Proof uses group insertion into a Ford–Johnson-like principal chain with `n0=n/log n`, `m ≈ sqrt(n)/log n`, group interval lengths `L_t`, and Corollary 2.

## (B) Precise non-effectivity obstruction

To obtain the requested **explicit computable bound**
`S(n) <= log2(n!) + f(n)` for all `n >= n0`, with `f,n0` and all group/balance/parameter choices resolved, the following steps of TR20-096 must be made effective. Each item states why extraction fails *from the theorem/proof as currently used here* and what would be needed.

1. **Theorem 2 hidden constant / small-`a` base.** `[literature]+[obstruction]`
   - *Non-effective step:* `a < 100` is handled by “sufficiently large values of the constant hidden behind the symbol `O`”; proof assumes `a >= 100` and ends with `O(a^(-gamma)*2^a)`, `gamma<=1/5`.
   - *Why extraction fails:* No explicit `a0` and no explicit `C2` with `P_m(a) >= 2^(a+1/2) - C2*a^(-1/5)*2^a` for all admissible `a>=a0,m`.
   - *Needed:* Track every inequality in Lemma 2(18) and the Theorem 2 simplification; fix `gamma` (e.g. `1/5`), fix all intermediate choices, compute an explicit `C2,a0`; separately verify all `a<a0` or absorb into a finite table/base bound.

2. **`a`-dependent strategy parameters.** `[literature]+[obstruction]`
   - *Non-effective step:* `s = ceil(2*gamma*log a)`, `phi = log(m*eps/(4*a^2))`, and Lemma 4 parameters `d=2s, eps=1/(25*2^s), lambda=20*2^(-s/2)+64*2^(-s), mu=30*2^(-s), h=2s+3, w<=s+4` depend on `a`/`m`.
   - *Why extraction fails:* The error term must be controlled uniformly after substituting these functions; the proof uses asymptotic `Θ`/`O` and approximates `a` by `r+y_i` within `1/d`.
   - *Needed:* A closed explicit inequality for (18) after substitution, including `exp(...)` and `1/d` slack, or a computable schedule giving `(a0,C2)`.

3. **Lemma 2 rounding and container overhead.** `[literature]+[obstruction]`
   - *Non-effective step:* real/non-integer lengths/ranks rounded “to the nearest integer in some direction”; containers `c_{dl+i} <= phi*2^phi` “very rough”; `rho*m + C*log2(n+2m)` / `O(1)` accounting; assumption `n+2m < 2^(r+2)`.
   - *Why extraction fails:* Finite-size losses are not given as explicit additive/multiplicative constants in the final `P_m/Q_m` inequalities.
   - *Needed:* Explicit integer-rounding lemma and explicit container bound in final form; remove or quantify every “some direction / rough / O(1)” step.

4. **Universal strategy feasibility/parameter balancing (§6, Lemma 4).** `[literature]+[obstruction]`
   - *Non-effective step:* §6 uses target `Y(a)=(1-lambda)2^(a+1/2)`, discretization, correction coefficients, and sufficient constraints (e.g. (38),(40)); Lemma 4(i) is justified by the strategy being built to satisfy it; numeric checks appear as sufficient conditions.
   - *Why extraction fails:* The feasible `(v,u,eps,R,lambda,mu,s,d,h,w)` data must be certified for every `s(a)` or for an explicit schedule; “sufficient for s>=...”/“direct numeric calculation” in the prose is not an explicit all-cases certificate here.
   - *Needed:* Either (i) a finite explicit lemma family with certified parameters for all needed `s>=s0`, or (ii) a machine-checkable/certified computation for all required finite cases plus an analytic tail.

5. **Corollary 2 / group insertion interface.** `[literature]+[obstruction]`
   - *Non-effective step:* Corollary 2 requires `2^(a/4) <= m <= 2^(a/2)` and gives `Q_{2m}(a) >= 2^a - O(a^(-1/5)*2^a)`.
   - *Why extraction fails:* No explicit `C_Q,a1` and no explicit finite-condition version.
   - *Needed:* Explicit `a1,C_Q` and an explicit hypothesis check for the chosen group sizes.

6. **Theorem 3 global schedule (`n0,m,L_t`) and threshold matching.** `[literature]+[obstruction]`
   - *Non-effective step:* `n0=n/log n`, `m≈sqrt(n)/log n`, groups inserted into intervals `L_t=2(n0+tm)-m`; uses `rho_t = log L_t + O(log^(-1/5)n)` from Corollary 2. Last group by binary method; first `n0` by Ford–Johnson.
   - *Why extraction fails:* The asymptotic choices must satisfy Corollary 2 for all relevant `t,n>=n0` with integer sizes and with the actual `log L_t` range. “`≈`” and `O(...)` hide finite alignment losses.
   - *Needed:* Explicit integer definitions, e.g. `n0(n)=floor(n/log2 n)` or another explicit rule, `m(n)=...`, group counts, and a proof/certificate that `2^(a_t/4)<=m_eff<=2^(a_t/2)` (or the actual Corollary-2 hypothesis form) holds whenever used, for all `n>=n0'`; else an adjusted effective schedule.

7. **Comparison-count accounting to an all-`n` function.** `[literature]+[obstruction]`
   - *Non-effective step:* Theorem 3 accumulates `S(n/2) + n/2 + n + O(n0) + sum (group insertion costs) + last-group cost + O(log n)` and solves recurrence `s(n)=S(n)-log(n!) <= s(n/2)+O(n*log^(-1/5)n)`.
   - *Why extraction fails:* Each `O` must become an explicit term; the recurrence needs an explicit closed `f(n)`.
   - *Needed:* A computable `f` such that every line is bounded by `log2(n!) + f(n)` (or a recurrence solved to such `f`), with finite-base handling.

8. **Finite basis and low-`n` regime.** `[obstruction]+[deduction]`
   - *Non-effective step:* No explicit `n0` is given by Theorem 3.
   - *Why extraction fails:* Even with an effective asymptotic tail, the claim “for all `n >= n0`” needs a concrete `n0`, and “for all `n`” would need either large `n0` plus finite computation/table, or a universal bound dominating known small-`n` exact values.
   - *Needed:* Explicit `n0`; computable check or table for `n < n0`; ensure `ceil(log2(n!))+f(n) >= S(n)` on that finite set (using known exact values/upper bounds where appropriate, with model fidelity).

## Partially explicit / constructive pieces (not sufficient for (A))

- `[literature]` The group-insertion algorithmic framework, comparison strategies, reduced LP constraints, containers, and Lemma 1 interpolation are constructive in form.
- `[literature]` Base pair-insertion `P(a)` is explicit (5). Lemma 4 gives explicit numeric parameter formulas in terms of `s`, and explicit slack estimates for (ii).
- `[literature]` Theorem 1 gives an explicit-looking leading constant `0.09*n` but still ends with `o(n)`/`O(n^(1-gamma))`; making it a finite all-`n` bound would require the same kind of constant/threshold extraction.
- `[deduction]` These pieces mean effectivity is *plausible in principle* but **not delivered** by the audit: an (A) claim would require a complete, checked finite inequality chain.

## Finite verification checklist for `n < n0` (if/when an effective tail is proposed)

Any future (A)-style claim `S(n) <= ceil(log2(n!)) + f(n)` for all `n >= n0` should include this checklist:

1. **Model fidelity.** Confirm `S(n)` means adaptive worst-case pairwise comparisons on `n` distinct labelled keys (decision-tree height), not sorting-network depth/size and not average case.
2. **State the bound precisely.** Give computable `f` (formula or algorithm), rounding convention for `log2(n!)`, and explicit integer `n0`.
3. **Cite/derive every constant.** For each TR20-096 step used (esp. Lemmas 2,4, Thm 2, Cor. 2, Thm 3), record either an explicit constant/slack derivation or a certified computation.
4. **Schedule validity.** Verify the integer `n0(n), m(n), L_t, a_t` satisfy the effective Corollary-2/Thm-2 hypotheses for all `n>=n0`.
5. **Finite base.** For every `n < n0`, check `U_eff(n) >= S(n)` using a sound source: exact literature values where known (`S(1..22)` per local `research-plan.md/literature.md`) and/or a verified constructive upper-bound algorithm; record the source for each value/bound.
6. **Sanity checks.** Ensure `U_eff(n) >= ceil(log2(n!))`; compare with known upper bounds (Ford–Johnson / merge sort / exact values) on representative `n`; flag any violation as refutation.
7. **Encoding note (unary).** `[deduction]` For `SORT-BOUND-U`, evaluating `ceil(log2(n!))` and `f(n)` on input `1^n` is polynomial in `n` for ordinary explicit `f`; the resulting threshold window affects search/verification, not the separation barriers in `problem.md`.
8. **Reproducibility.** If a script/computation is used for the finite base or parameter certificates, pin inputs/outputs and make the computation deterministic and auditable.

## What would be needed for a future (A) answer

A defensible (A) report would contain:
- an explicit theorem: `exists computable f, n0 . forall n>=n0, S(n) <= ceil(log2(n!)) + f(n)` (or equivalent exact/log form), with all constants numeric;
- an explicit integer schedule for all group/balance/basis choices (`n0(n), m(n), group partition, s(a), gamma, phi, ...`) or a proof that the chosen schedule is valid;
- a line-by-line effective reproof/certificate of TR20-096 Thm 2 -> Cor. 2 -> Thm 3 (or an independent effective proof inspired by them) with no hidden `O` in the final finite inequality;
- a finite verification artifact/checklist for `n<n0`; and
- primary-source citations checked against the PDF (not only text extraction), ideally with `pdftotext`/mutool corroboration.

## Bottom line

`[deduction]` **Current evidence supports (B): a precise non-effectivity obstruction, not an extracted finite bound.** Sergeev TR20-096 is constructive as an algorithmic framework and proves the asymptotic target, but the published asymptotic form leaves constants, thresholds, parameter schedules, rounding/container losses, and finite-base handling unresolved for the specific deliverable `S(n) <= log2(n!) + f(n)` with all choices explicit for the unary `SORT-BOUND-U` threshold window. Extracting such a bound remains open and should be treated as a separate finite-effectivization project, not assumed from Theorem 3.
