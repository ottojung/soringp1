## Question (all n)

For small disjoint chains and ordinal factors, find sound, compositional,
polynomially verifiable exact rules for `F(P)`; then test whether they can be
glued into an optimal `A_n` root tree without losing global branch optimality.
In particular: exact all-`n` identities for disjoint sums / ordinal sums of
chains (or small factors), and whether optimal gluing preserves both sibling
branches.

Definitions (from `docs/problem.md`, `docs/research-series-decomposition.md`,
`docs/research-structural-lower-bounds.md`):

- `F(P)=adv L(P)`; `S(n)=F(antichain_n)`.
- Ordinal sum `A⊕B`: all of `A` below all of `B`; `L(A⊕B)≅L(A)×L(B)`.
- Disjoint (parallel) sum of chains `Merge(a,b)`: two chains, no cross
  relations; `F=M(a,b)` is the exact two-list merge cost.
- A state is a transitively closed strict poset on labelled keys, represented by
  successor bitmasks. `e(P)` = #linear extensions; `info(P)=ceil(log2 e(P))`.

## Findings

### 1. Ordinal-sum rule: sound, exact, all `n`, polynomially verifiable

**[deduction + experiment]** For finite posets `A,B` on disjoint ground sets,

```
F(A ⊕ B) = F(A) + F(B).
```

Verification: all posets on `n≤5` (series-decomposition tests, 0 failures) and
targeted ordinal sums, e.g. `Merge(2,3) ⊕ singleton` has `F=4`,
`Merge(2,2) ⊕ singleton ⊕ singleton` has `F=3`, matching the rule.

Polynomial verification: compute incomparability-graph components, check that
they are totally ordered by the poset order (bottom-to-top), i.e. a genuine
ordinal sum; then return the sum of the component values. This is `O(n^2)` from
the transitive closure (`ordered_blocks`).

**Boundary.** The antichain root `A_n` is series-prime for `n≥2`, so this rule
never applies at the root. It is a rule for states, not a recurrence for
`S(n)`.

### 2. Disjoint-sum (merge) rules: exact only in certified ranges

For `Merge(a,b)` (disjoint union of an `a`-chain and a `b`-chain):

- **`a=1` (all `b`):** `[literature: Hwang–Lin 1972]`

  ```
  M(1,b) = ceil(log2(b+1)).
  ```

  Verified by memoized DP for `b≤10` (and `b≤15` in this run), 0 failures.

- **`a≥2`, tight range:** `[literature: Stockmeyer–Yao/Christen/Murphy–Paull]`

  ```
  M(a,b) = a + b - 1   if a ≤ b ≤ floor(3a/2)+1.
  ```

  Verified on `Merge(2,2)`, `Merge(2,3)`, `Merge(2,4)`, `Merge(3,3)`,
  `Merge(3,4)`, `Merge(3,5)`.

- **Falsifier of the universal formula.** Outside the certified range,
  `a+b-1` is unsound:

  ```
  M(2,5)=5  (not 6),   M(2,6)=6  (not 7),   M(2,9)=7  (not 10).
  ```

  These were computed by the memoized poset DP in this run. Thus any proposed
  compositional rule using `a+b-1` for all `b` is false; the rule must carry
  the certified-range precondition or an exact merge value.

- **`k≥3` chains / outside certified ranges.** No simple all-`n` closed form
  was established in this run. Exact values were computed by DP up to total size
  15 (e.g. `M(2,15)=8`), but these are data, not an identity. Treating them
  as exact requires either a certified merge algorithm or the DP.

### 3. Ordinal composition of certified factors

If `P = P_1 ⊕ ⋯ ⊕ P_k` and each `P_i` is a chain or a certified merge factor,
then

```
F(P) = Σ_i F(P_i),
```

with each summand given by the rules above. This combines the ordinal-sum
identity with the merge-factor identities. Verification: structural-bound
tests over all posets `n≤5` (0 failures) plus targeted `n=6` states.

Polynomial verification: series decomposition `O(n^2)`, then factor recognition
and certified-value lookup `O(1)` per factor.

### 4. Gluing into an optimal `A_n` root tree: sibling obstruction

Locally, `F(P)` is the minimum height of any completion from `P`, so an
optimal subtree for a factor can be attached at `P` without increasing height.
Global optimality is not automatic: a comparison is usable in a height-`k`
sorter only when **both** children fit the residual budget.

**Experiment (`n=6`, target `Merge(2,4)`).** `S(6)=10` and `F(Merge(2,4))=5`,
so a naive gluing would suggest depth `≤5` is enough. Enumerating all
topological orders of the four chain comparabilities in `Merge(2,4)` (with the
memoized DP as the feasibility oracle) found **no** order in which every
comparison keeps both siblings within budget:

- First failure occurs at a comparison such as `3<4` with residual budget `7`,
  where the reversed sibling has `F=8 > 7`.
- Hence the `Merge(2,4)` factor state is not reachable on any height-`10`
  optimal sorter from the 6-antichain.

This is the same mechanism as the prior root-prefix obstruction (e.g. `n=5`
`C2` ordinal `A3`: `d+F=S(5)` but `R_h=8>S(5)=7`): local factor optimality
ignores sibling obligations. Thus compositional exact rules give polynomial
certificates for `F(P)` of decomposable/reachable states, but do not by
themselves give polynomial-size certificates for `SORT-BOUND-U` at the
antichain root.

## Complexity implication

Sound compositional exact rules with polynomial verification would support
polynomial-size certificates for `F(P)` (and hence for `SORT-BOUND-U`) **only
for posets that decompose into certified factors and whose construction path
satisfies sibling viability**. The failure above identifies where global branch
optimality is lost: not in `F(P)` (which is exact and compositional), but in
the root-prefix viability condition `R_h(P)=max(d+F(P), max_i(i+F(Q_i)))`.
No claim about `SORT-BOUND-U ∈ NP/P` follows from these rules.

## Conclusion

- **New usable exact rules:** ordinal-sum additivity (all `n`) and `1×b`
  merge identity (all `b`), plus certified-range `a+b-1` for merge factors.
- **Falsification:** universal `a+b-1` for disjoint chain sums is false
  (`Merge(2,5)`, `Merge(2,6)`, ...).
- **Gluing test:** fails for `Merge(2,4)` on the 6-antichain root due to sibling
  branch infeasibility. Compositional rules do not transfer to the antichain
  root without an additional sibling-viability certificate.
