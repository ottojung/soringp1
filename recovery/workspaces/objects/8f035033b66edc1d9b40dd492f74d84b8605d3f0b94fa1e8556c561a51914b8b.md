# Is P/log advice tight for SORT-BOUND-U given S(n) constraints?

**Status:** research note (deduction + information-theoretic counting). Not Lean-checked.
**Scope:** unary encoding `SORT-BOUND-U = {1^n # 1^k : S(n) ≤ k}`, N = n+k+1.

## Known result (tight in general form)

For fixed total length L = n+k+1, define
`f(n)=n+S(n)`, strictly increasing in n (by `S_mono`). Let
`t_L = max{n ≤ L-1 : f(n) ≤ L-1}`. Then `SORT-BOUND-U ∈ P/O(log L)`
with advice `a_L = bin(t_L)` of length `Θ(log L)` (Theorem 3.7 of
`research-encoding-consequences.md`). This is optimal in the general sense that
there are L+1 possible cutoff positions and each requires specifying one of them.

## The question

Does the fact that `S(n)` is the exact sorting number (minimax comparison
complexity of the antichain) impose stronger constraints on the sequence
`(t_L)_{L≥1}` that would allow sub-logarithmic advice, or is P/log tight
even for this combinatorially constrained function?

## Constraints on S(n) (relevant)

- Monotonicity: `S(n) ≤ S(n+1)` (kernel-checked `S_mono`).
- Information bound: `⌈log₂ n!⌉ ≤ S(n)`.
- Upper bounds: `S(n) ≤ n⌈log₂ n⌉` (merge sort) and the tighter insertion bound
  `S(n) ≤ n(n-1)/2` (kernel-checked).
- Increment bounds: `1 ≤ S(n+1)-S(n) ≤ ⌈log₂(n+1)⌉`.
- Asymptotics: `S(n) = log₂(n!) + o(n)` (Sergeev).

These constrain `f(n)=n+S(n)` to be strictly increasing with
`f(n+1)-f(n) ∈ {2, ..., 1 + ⌈log₂(n+1)⌉}`, so steps grow slowly (logarithmically)
relative to n. Also `f` is completely determined by the sorting number.

## Information-theoretic analysis

Let `V_L = { t ∈ {0,...,L-1} : ∃ valid S with cutoff t_L = t }` be the set of
possible cutoff values at length L consistent with some realizable sorting
number function. The advice must distinguish among all possible `t_L` that
can actually arise. The length of advice is `Ω(log_2 |V_L'|)` in the worst case
over a family of possible `S` functions that produce different cutoffs and are
indistinguishable without advice, but more directly: if `|V_L| = Ω(L / g(L))`
then advice needs `Ω(log L - log g(L))` bits.

Constraints on `f` mean `f(n+1)-f(n) ≤ C log n`, so `f(n) ≤ O(n log n)`.
But `f` is strictly increasing sequence of integers with those step bounds.
The number of such sequences up to the point where they reach ~L is
large? Or is it constrained?

Alternatively, think of placing "jumps": to have cutoff at position n at
length L, we need `f(n) ≤ L-1 < f(n+1)`. Given step bounds `1 < d(n) ≤ D(n)=1+⌈log₂(n+1)⌉`,
the mapping from valid `S` to cutoffs is not obviously surjective onto all
{0,...,L-1}. For example, can we get any t_L regardless of step constraints?
To have a particular t, we need `f(t) ≤ L-1` and `f(t+1) ≥ L`. Since
`f(t+1) = f(t) + d(t+1) ≤ f(t) + D(t+1)`, the step constraint limits how
"late" the next jump can be. But combined with fixed L = n+k+1 and the
interval structure, it’s not obvious the step bounds create a large reduction
in the number of possible cutoffs.

More directly: for each possible choice of `S(0),...,S(L)` satisfying the
known constraints, we get some cutoff. The advice must encode which one it is.
Even with constraints, the state graph of possible `S` values grows quickly
(exponentially in n² in general by the poset count, though with constraints
much less; but the cutoff sequence is just the inverse). The information-theoretic
lower bound from the number of possible advice strings is `|advice| ≥ log2(M_L)`
where `M_L` is the number of possible cutoff patterns consistent with realizable
`S`. Without strong constraints forcing many cutoffs to coincide, this remains
`Ω(log L)`. The known constraints (monotonicity, polynomial upper bounds from
merge sort) are necessary but don't obviously collapse `M_L` below Ω(L^c)
for small c.

## Conclusion

**Deduction (information-theoretic):** The P/log bound is tight up to
constants unless the combinatorial constraints on the sorting number force
the cutoff function `t_L` to lie in a set of size `L^{o(1)}`. The known
constraints (step bounds `d(n) ≤ 1+⌈log₂(n+1)⌉`, monotonicity) do not obviously
imply such compression; they are consistent with Ω(L / log L) possible
cutoff values. Proving tightness would require showing that for every
admissible cutoff pattern there is some realizable `S(n)` producing it, or
finding a reduction - neither is obvious. Proving better-than-log advice
would require exploiting strong constraints on `S(n)` not yet established.

**Residual gaps:** (1) Characterize exactly which integer sequences `S(n)`
are realizable by some comparison tree (the "graphical" constraints of
minimax). (2) Determine the entropy of the cutoff sequence given those
constraints. (3) Distinguish advice-computability from advice-existence
(nonuniform vs uniform).

**Stop condition:** This is a structural question about advice complexity
given realizability constraints. It doesn't directly address uniform
complexity of computing `S(n)`, and tightness is plausible but not obviously
provable from known results. No new theorem is established here - just a
precise formulation of the question.
