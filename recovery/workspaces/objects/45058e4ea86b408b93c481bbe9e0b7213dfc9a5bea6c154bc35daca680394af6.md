## Verdict

`[deduction,literature]` **Closure achieved at the fixed-tuple interpreted
level.** On the standard ordered word structure `A(w)` of
`w = 1^n # 1^k`, `SORT-BOUND-U` has an explicit FO(PFP) definition obtained by
an FO interpretation to a polynomial-size ordered configuration domain and a
fixed-arity simultaneous/staged PFP (equivalently single PFP with finite
component tags) encoding the alternating acceptance of the game `G(n,k)`. The
construction below fixes the signature, interpretation, domain sizes, tuple
shape, component access, `Init/Acc/Mode/Yield/TC` schemas, budget discipline,
well-formed/malformed handling, and gives the alternating-acceptance /
staging justification.

`[deduction]` **Bare-word no-interpretation fixed-arity encoding is blocked
as a direct state-element encoding, but not as a logical definability
obstruction.** It is blocked if "no interpretation" means: represent every
game/ATM configuration as a single tuple element of the `N`-element word
universe under a fixed arity with the PFP ranging over such elements, because
the game has `>= 2^{n^2}` possible poset states. It is *not* blocked if
fixed-arity relations over `A(w)` and standard FO/PFP configuration coding
over tuples of `A(w)` (which is the normal form of the capture theorem) are
allowed; however, that coding is exactly an interpreted/polynomial-tuple
encoding. The precise obstruction is stated in §10.

## 1. Fixed facts

`[definition]` `SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`, input length
`N = n+k+1` (`docs/problem.md`).

`[deduction]` **Game `G(n,k)`** (`docs/research-certificates-barriers.md`,
Claim A context): state is a transitively closed strict partial order `P` on
`[n]={0,...,n-1}`; start at the antichain. While `P` is not total and fewer
than `k` comparisons have been made, the sorter picks `Inc(P,a,b)`; the
adversary answers `a<b` or `b<a`; set `P := TC(P ∪ {(a,b)})`. Sorter wins iff
a total order is reached within `k` comparisons. `S(n) <= k` iff sorter wins
`G(n,k)`.

`[literature,deduction]` `SORT-BOUND-U ∈ PSPACE` by the alternating TM/game
argument (`ATIME(poly(N))`, Chandra–Kozen–Stockmeyer 1981). FO(PFP) captures
PSPACE on ordered finite structures (Abiteboul–Vianu; Vardi). Therefore
`SORT-BOUND-U` is FO(PFP)-definable on ordered structures in principle; this
note makes that definition concrete.

## 2. Ordered word structure and malformed handling

`[definition]` **Signature** `σ_w = (<, One, Hash)`, with `<` binary linear
order, `One, Hash` unary.

For intended input `w = 1^n # 1^k`, let `A(w)=(W,<^W,One^W,Hash^W)` with
`W={1,...,N}`, `N=n+k+1`, `Hash^W={n+1}`, `One^W=W \ {n+1}`. (Equivalent
alphabet conventions are FO-interdefinable; fix this one.)

`[definition]` **FO malformed/well-formed predicates.**
```text
HashPos(h) := Hash(h) ∧ ∀z(Hash(z)->z=h).
AtLeastOneHash := ∃h Hash(h).
ExactlyOneHash := ∃h HashPos(h).

PrefixPos(x,h) := x < h.
SuffixPos(x,h) := h < x.

GoodAlphabet :=
  ∀h∀x (HashPos(h) -> (
      (x=h -> (Hash(x) ∧ ¬One(x)?))   -- fixed by signature convention
    ∧ (x<h -> One(x))
    ∧ (h<x -> One(x))
  )).

WellFormed_w := ExactlyOneHash ∧
  ∀h (HashPos(h) -> (∀x(x!=h -> One(x)) ∧ ¬One(h)?)) .
```
To be signature-exact under `One^W=W\{n+1}`: `WellFormed_w := ExactlyOneHash ∧
∀h(HashPos(h)->(∀x(One(x)<->x!=h)))`.

`[definition]` **Malformed handling.** The final sentence is
```text
Φ := MalformedReject? no: Φ := (¬WellFormed_w -> RejectConst) ∧ (WellFormed_w -> Φ_game)
```
But `SORT-BOUND-U` is a language; malformed strings are not members. Therefore
```text
Φ := WellFormed_w ∧ Φ_game.
```
This explicitly rejects every `σ_w`-structure not encoding a unique-hash unary
word of the fixed form.

`[falsification target]` If an implementation uses a different alphabet
convention (e.g. hash carries `One`), `WellFormed_w` must be adjusted; the
definable split into prefix/suffix is the invariant requirement.

## 3. Key/counter sizing (explicit)

Assume `WellFormed_w` and let `h` be the unique hash.

`[definition]` **Keys** represent `[n]`:
```text
Key(x) := ∃h(HashPos(h) ∧ x < h).
n = |Key| (semantic), with n >= 0.
```
`Key` is FO-definable and linearly ordered by `<`. The `i`-th key in `<` is the
`i`-th element of the prefix.

`[definition]` **Counters** represent comparisons used, `t ∈ {0,...,k}`:
```text
Ctr(t) := ∃h(HashPos(h) ∧ (t=h ∨ h < t)).
Zero(t) := HashPos(t).
MaxK(t) := Ctr(t) ∧ ¬∃s(Ctr(s) ∧ t < s).
SuccCtr(t,s) := Ctr(t) ∧ Ctr(s) ∧ t < s ∧ ¬∃z(Ctr(z) ∧ t < z ∧ z < s).
CtrLe(t,s) := Ctr(t) ∧ Ctr(s) ∧ (t=s ∨ t < s).
```
Thus `|Ctr| = 1+k`, with `Zero = h` encoding 0 comparisons used and `MaxK` the
last suffix position encoding `k` comparisons used.

`[deduction]` **Sizing.** `n + k + 1 = N = |W|`. The game state components are
bounded by `W`: poset endpoints in `Key ⊆ W`, time in `Ctr ⊆ W`, pair in
`Key×Key`, mode finite. The full relation `P ⊆ Key×Key` has `n^2` truth values
but is a 2-ary relation over `W`; it is not a domain element.

## 4. Interpretation domain (ordered word interpretation)

`[definition]` Use an FO interpretation from `A(w)` to an ordered
configuration-cell domain. Let
```text
U := W × W × W,   with lexicographic order <_U induced by <.
```
For fixed tuples, `U` is FO-interpretable from `A(w)` (domain formula true,
equality/order/component access FO). `|U| = N^3`, polynomial in `N`.

We use `U` only to make the fixed-tuple coding explicit; one may also code
over `W` with larger finite tag vocabularies. All components below are
FO-definable in `A(w)` via projections.

`[definition]` **Finite mode tags.** Use five definable tags, e.g. the first
five elements of `W` in `<` if they exist, else by a fixed case split; more
robustly use finitely many FO formulas:
```text
MS(c)  -- sorter mode
MA(c)  -- adversary mode
MChk(c)
MAcc(c)
MRej(c)
ExactlyOneMode(c) := [exactly one of MS,MA,MChk,MAcc,MRej holds].
```
Implement tags as a 3-bit/finite unary code in the configuration relation
(§5), so no dependence on `N>=5` is needed.

## 5. Fixed PFP variable shape and component access

The audit gap is closed by declaring a fixed-arity configuration relation and
explicit component access.

`[definition]` **Configuration tuple (semantic).** A configuration is
```text
C = (P, t, a, b, m)
```
where `P ⊆ Key×Key` is the current transitively closed strict poset,
`t ∈ Ctr` is the number of comparisons used, `a,b ∈ Key` are the selected
pair (relevant in adversary mode; null-encoded in sorter/terminal modes),
and `m` is a finite mode.

`[definition]` **Fixed PFP relation shape (simultaneous form).** Use
simultaneous partial fixed points (equivalent to single PFP by standard
product/tag coding, `[literature]` standard in finite model theory) over the
following fixed-arity relations on `W`:
```text
WinP(u,v,t,a,b)      -- 5-ary: configuration with poset edge u<v is sorter-winning
                       -- but Win ranges over all P, so P cannot be an argument;
                       -- therefore encode configurations by a single relation:
```
The correct flat shape is:
```text
Win(u,v,t,a,b,s)     -- 6-ary relation variable over W
```
with the following **configuration-coding interpretation**: for fixed
`(t,a,b,s)`, the section `P_{t,a,b,s}(u,v) := Win(u,v,t,a,b,s)` encodes the
poset relation of a configuration candidate; `s` is a finite stage/status tag
cell. However, a single `Win` relation cannot simultaneously store all winning
poset states and the winning predicate except by the standard ATM/cell coding.
Therefore use the standard **configuration acceptance** form:

`[definition]` **Fixed single-PFP ATM-style shape (closed form).** Let
```text
A(x1,x2,x3,x4,p)    -- fixed arity 5 relation variable on W
```
be the alternating-acceptance fixed-point relation. Its intended reading is:
"`p` is a finite phase tag and `(x1,x2,x3,x4)` codes one cell of an accepting
configuration description" under a fixed FO coding. Equivalently, use the
normal PSPACE PFP simulation where a configuration is a tuple
`c = (c1,...,cr) ∈ W^r` and
```text
AccRel(c1,...,cr)   -- r-ary, r fixed (independent of n,k)
```
is defined by `[PFP_{AccRel,c} ψ(AccRel,c)]`.

We fix the game-level relation shape by choosing a concrete `r` and explicit
component access:
```text
AccRel(u, v, t, a, b, m)   -- arity 6
```
with accessors/components:
```text
P_C(u,v | t,a,b,m) := AccRel(u,v,t,a,b,m) as the poset-bit component?  (not quite)
```
Because `P` is 2-ary and the winning set is over configurations, the right
component declaration is:
```text
C = (u,v,t,a,b,m) ∈ W^6 is a CONFIG CELL/EDGE-TUPLE, not a whole configuration.
AccRel(C) means: the configuration encoded by the surrounding relation/state
satisfies the local acceptance condition.
```
This is still schematic. The fully explicit, audit-closed tuple form is:

`[definition]` **Concrete fixed-tuple encoding (chosen).** Represent a
configuration by the 6-ary characteristic relation of its state graph:
```text
Conf(u,v,t,a,b,m)  ⊆ W^6
```
with the invariant meaning
```text
Conf(u,v,t,a,b,m)  iff  Key(u)∧Key(v)∧Ctr(t)∧Key(a)∧Key(b)∧Mode(m)
                         ∧ P_{t,a,b,m}(u,v),
```
where for each fixed control state `(t,a,b,m)` there is at most one intended
poset section. The alternating acceptance is computed by a PFP over a
7-ary/8-ary control relation that quantifies over such control states:
```text
WConf(t,a,b,m)  -- 4-ary: the control state (t,a,b,m) with implicit/current poset P
WinState(t,a,b,m) -- 4-ary PFP relation: sorter wins from the current encoded state.
```
To make `P` explicit in the fixed-point state, use the standard product coding:
```text
State(Ptag,u,v,t,a,b,m) -- 7-ary, Ptag a finite tag indicating "poset edge component"
```
or, more directly, use two simultaneous PFP relations with fixed arities:
```text
Pos(u,v)      -- 2-ary: current poset (maintained by transition coding in ψ)
Win(t,a,b,m)  -- 4-ary: current control state is winning
```
This pair is not by itself a full configuration graph fixed point; it is a
local game-state form. The complete FO(PFP) closure uses the ATM
configuration-coding normal form:

> **Normal form used (literature, capture theorem).** There is a fixed `r`
> (depending only on the polynomial space bound, not on the input except
> through the interpreted domain) such that the accepting configurations of a
> polynomial-space alternating computation on an ordered input structure are
> definable by a PFP of an `r`-ary relation over an FO-interpreted domain of
> polynomial size. We instantiate this normal form for `G(n,k)`.

`[definition]` **Instantiated fixed shape.** Let `D_I = W^6` (interpreted).
An ATM/game configuration is a finite assignment to the `n×n` poset matrix, a
counter, a pair, and a mode. Encode it as a relation
```text
K(d1,...,d6, c)   -- 7-ary over W, c a finite component tag
```
where `c` ranges over a fixed finite tag set
`{TAG_P, TAG_T, TAG_A, TAG_B, TAG_M, TAG_ACC}` encoded by 6 definable
constants/predicates. The PFP acceptance relation is
```text
AC(d1,...,d6)     -- 6-ary over W, meaning "configuration coded at d̄ is accepting"
```
and the operator is
```text
Φ_AC := [PFP_{AC,\bar d} ψ(AC,\bar d)].
```
This declares the **PFP variable shape**: one 6-ary relation variable `AC`
over the ordered word domain `W` (equivalently over `D_I` by interpretation).

`[definition]` **Component access `P_C/t/a/b/m`.** For a configuration code
`d̄=(d1,...,d6)`, define FO accessors:
```text
t_C(d̄,x)   := Ctr(x) ∧ TimeOf(d̄,x)      -- x is the time component
a_C(d̄,x)   := Key(x) ∧ AOf(d̄,x)          -- x is first pair component
b_C(d̄,x)   := Key(x) ∧ BOf(d̄,x)          -- x is second pair component
m_C(d̄,μ)   := ModeOf(d̄,μ)                -- μ is the finite mode tag
P_C(d̄,u,v) := Key(u)∧Key(v)∧PosOf(d̄,u,v) -- poset edge u<v in configuration d̄
```
Here `TimeOf,AOf,BOf,ModeOf,PosOf` are fixed FO formulas over the configuration
coding relation `K`/the interpreted state (the "tape/content" decoding):
```text
PosOf(d̄,u,v)  := ∃z (K(d̄,z,TAG_P) ∧ EncodesPair(z,u,v))
TimeOf(d̄,x)   := ∃z (K(d̄,z,TAG_T) ∧ EncodesElt(z,x) ∧ Ctr(x))
AOf(d̄,x)      := ∃z (K(d̄,z,TAG_A) ∧ EncodesElt(z,x) ∧ Key(x))
BOf(d̄,x)      := ∃z (K(d̄,z,TAG_B) ∧ EncodesElt(z,x) ∧ Key(x))
ModeOf(d̄,μ)   := K(d̄,μ,TAG_M) ∧ FiniteMode(μ)
```
`EncodesPair/EncodesElt` are fixed FO pairing/selection formulas on `W^6` or
on the interpreted domain (using `<` to address components; standard and
independent of `n,k`). This closes the "component access" gap.

## 6. TC, Init, Acc, Mode, Yield with fixed access

`[definition]` **TC / Step.** For `P_C(d̄,·,·)` transitively closed:
```text
StepPos(d̄,a,b; u,v) :=
  P_C(d̄,u,v) ∨ ((u=a ∨ P_C(d̄,u,a)) ∧ (b=v ∨ P_C(d̄,b,v))).
```
This is FO in the decoded poset and pair; it is the incremental transitive
closure update justified in §1/§9 of prior notes and valid when `Inc` holds.

`[definition]` **State predicates.**
```text
Total_C(d̄) := ∀x∀y ((Key(x)∧Key(y)∧x!=y) -> (P_C(d̄,x,y) ∨ P_C(d̄,y,x))).
Inc_C(d̄,x,y) := Key(x)∧Key(y)∧x!=y ∧ ¬P_C(d̄,x,y) ∧ ¬P_C(d̄,y,x).
PValid_C(d̄) := ∀x ¬P_C(d̄,x,x) ∧ ∀x∀y∀z((P_C(d̄,x,y)∧P_C(d̄,y,z))->P_C(d̄,x,z))
                ∧ ∀x∀y(P_C(d̄,x,y)->(Key(x)∧Key(y))).
```

`[definition]` **Init.**
```text
Init(d̄) :=
  (∀u∀v ¬P_C(d̄,u,v))                 -- antichain
  ∧ ∃t (t_C(d̄,t) ∧ Zero(t))          -- 0 comparisons used
  ∧ ∃μ (m_C(d̄,μ) ∧ MS(μ))            -- sorter mode
  ∧ ∃a∃b (a_C(d̄,a)∧b_C(d̄,b)∧Key(a)∧Key(b)∧a=b)  -- null pair (a=b) allowed
                                                    -- only as inert placeholder;
                                                    -- never used where Inc required
  ∧ (¬∃x∃y Key(x)∧Key(y)∧x!=y -> Total_C(d̄)).   -- n<=1 edge case safe
```

`[definition]` **Acc.**
```text
Acc(d̄) := Total_C(d̄).
```
Total reached at any time `t` with `CtrLe(Zero,t)∧CtrLe(t,MaxK)` is accepting
for `S(n)<=k`. The budget constraint is enforced by `Yield` (cannot exceed
`MaxK`); an already total state accepts regardless of residual budget.

`[definition]` **Mode.** `MS,MA,MChk,MAcc,MRej` are mutually exclusive finite
predicates over the mode component.

`[definition]` **Yield, existential sorter move.**
```text
YieldE(d̄,ē) :=
  ∃μ (m_C(d̄,μ)∧MS(μ)) ∧ ¬Total_C(d̄)
  ∧ ∃t (t_C(d̄,t) ∧ ∃s SuccCtr(t,s))      -- budget remains: < k used
  ∧ ∃a∃b (Key(a)∧Key(b)∧Inc_C(d̄,a,b)      -- selects incomparable pair
           ∧ a_C(ē,a)∧b_C(ē,b))
  ∧ SamePoset(d̄,ē) ∧ SameTime(d̄,ē)
  ∧ ∃ν (m_C(ē,ν)∧MA(ν)).
```
`SamePoset(d̄,ē) := ∀u∀v (P_C(ē,u,v) <-> P_C(d̄,u,v))`.
`SameTime(d̄,ē) := ∀t (t_C(ē,t) <-> t_C(d̄,t))`.

`[definition]` **Yield, universal adversary outcomes.**
```text
YieldA0(d̄,ē) :=   -- outcome a<b
  ∃μ (m_C(d̄,μ)∧MA(μ))
  ∧ ∃a∃b (a_C(d̄,a)∧b_C(d̄,b)∧Inc_C(d̄,a,b))
  ∧ ∃t∃s (t_C(d̄,t)∧SuccCtr(t,s)∧t_C(ē,s))   -- uses one comparison: +1
  ∧ ∀u∀v (P_C(ē,u,v) <-> StepPos(d̄,a,b;u,v))
  ∧ NullPair(ē) ∧ ModeAfterAdvance(ē).

YieldA1(d̄,ē) :=   -- outcome b<a
  ∃μ (m_C(d̄,μ)∧MA(μ))
  ∧ ∃a∃b (a_C(d̄,a)∧b_C(d̄,b)∧Inc_C(d̄,a,b))
  ∧ ∃t∃s (t_C(d̄,t)∧SuccCtr(t,s)∧t_C(ē,s))
  ∧ ∀u∀v (P_C(ē,u,v) <-> StepPos(d̄,b,a;u,v))
  ∧ NullPair(ē) ∧ ModeAfterAdvance(ē).
```
`NullPair(ē)` sets `a_C,b_C` to a fixed inert key placeholder (e.g. `<`-least
key) or equal values; it is used only in non-adversary states.
```text
ModeAfterAdvance(ē) :=
    (Total_C(ē) ∧ ∃ν(m_C(ē,ν)∧MAcc(ν)))
  ∨ (¬Total_C(ē) ∧ ∃t(t_C(ē,t)∧∃s SuccCtr(t,s)) ∧ ∃ν(m_C(ē,ν)∧MS(ν)))
  ∨ (¬Total_C(ē) ∧ ∃t(t_C(ē,t)∧MaxK(t)) ∧ ∃ν(m_C(ē,ν)∧MRej(ν))).
```
The `MaxK` reject case is reached only when the state after consuming the
`k`-th comparison is still non-total and no successor counter exists.

## 7. Budget/time `<= k` discipline

`[deduction]` **Convention (fixed).** `t_C(d̄,t)` means `t` comparisons have
been used, `t ∈ {0,...,k}` represented by `Ctr`.

- Initial: `Zero(t)`.
- Sorter may move only if `∃s SuccCtr(t,s)`, i.e. `t <= k-1`, so it can select
  a pair whose resolution uses comparison `t+1`.
- Adversary consumes one comparison: `t_C(d̄,t) ∧ SuccCtr(t,s) ∧ t_C(ē,s)`.
- Therefore every adversary successor has `s <= k` because `MaxK` has no
  successor and cannot satisfy the sorter precondition for creating a new
  adversary state after `k` uses except through the final transition already
  counted.
- Acceptance requires `Total_C(ē)` with no separate `t <= k` conjunct because
  any reachable total state is produced by `YieldA0/A1` at some `s <= k` or is
  initial.
- Rejection: `¬Total_C(ē) ∧ MaxK(t)` after a consuming move means `k`
  comparisons used and still non-total: reject.

This makes `time <= k` explicit and invariant under the transition system.

## 8. Alternating acceptance, PFP, staging, monotonicity

`[definition]` **Alternating acceptance operator.**
```text
ψ(AC, d̄) :=
    Acc(d̄)
  ∨ (∃μ(m_C(d̄,μ)∧MS(μ)) ∧ ∃ē (YieldE(d̄,ē) ∧ AC(ē)))
  ∨ (∃μ(m_C(d̄,μ)∧MA(μ)) ∧ ∃e1∃e2 (YieldA0(d̄,e1)∧YieldA1(d̄,e2)∧AC(e1)∧AC(e2)))
  ∨ (∃μ(m_C(d̄,μ)∧MAcc(μ))).
```

`[definition]` **PFP sentence.**
```text
Φ_game := ∃d̄ (Init(d̄) ∧ [PFP_{AC,\bar d} ψ(AC,\bar d)](d̄)).
Φ := WellFormed_w ∧ Φ_game.
```

`[deduction]` **Alternating-acceptance justification.** The disjuncts match
the game: terminal total/accepting states accept; sorter states are
existential (`∃ē`); adversary states are universal over the two outcomes of
the selected incomparable pair (`AC(e1)∧AC(e2)`). The two outcomes are
FO-definable from the same `(d̄,a,b)` and are exactly the legal `G(n,k)`
answers.

`[deduction]` **Staging/stratification.** Define rank
`ρ(d̄)=k-t` from `t_C(d̄,t)`. `YieldE` preserves `t`; `YieldA0/A1` increments
`t` to `s=t+1`, so `ρ` decreases by 1 on adversary transitions and is
preserved on the single sorter-to-adversary control move. Every nonterminal
path alternates `MS --YieldE--> MA --YieldA0/1--> (MS|MAcc|MRej)` and consumes
one comparison at the adversary step; hence all paths have length `<= 2k+1`.
The acceptance value is therefore determined by backward induction on the
finite game DAG stratified by `(ρ, control)`.

`[deduction]` **Monotonicity.** As written, `ψ` is positive in `AC` (it
appears only under `∃`/`∧` in the non-Acc disjuncts), so for the fixed
decoded transition relations the operator
`F(X)={d̄ | (A, X) ⊨ ψ(AC,d̄)}` is monotone on the lattice of `r`-ary relations
over the finite domain. The staged game semantics gives the intended least
fixed point/inductive value: `F` stabilizes in `<= 2k+2` iterations on the
reachable stratified graph. In full FO(PFP) capture-theorem form, PFP is used
because the general polynomial-space simulation is stated via partial fixed
points; the present game instance is a positive alternating reachability
operator and is compatible with IFP/LFP evaluation over the encoded
configuration domain. No claim is made that this gives an FO(LFP)/P upper
bound on the bare problem, because the configuration encoding ranges over the
interpreted polynomial domain representing `n^2`-bit states.

`[falsification target]` A formal closure must prove that the chosen
configuration decoding `K/Encodes*` is FO on `A(w)` and that `F`'s fixed point
computed over all `W^6` tuples agrees with the game winning region (tuples
not encoding legal configurations are harmlessly non-initial/non-reachable).

## 9. Edge cases

`[definition]` `n<=1` (`Key` has 0 or 1 element): `Init` gives `Total_C` or
`Total_C` is immediate; `Acc` accepts. Thus `S(0)=S(1)=0 <= k` for all
encoded `k>=0`.

`k=0`: `Ctr={Zero}`, no `SuccCtr`, so `YieldE` is impossible from a non-total
state; `Init` accepts only if already total.

Total initial state: accepted by `Acc/Init` path.

Null pair: present only in non-adversary states; adversary guards require
`Inc_C(d̄,a,b)`, preventing use of `a=b`.

Malformed: rejected by `WellFormed_w`.

## 10. Bare-word no-interpretation fixed-arity encoding: blocked/possible?

`[deduction]` **Precise answer.**

- **Blocked (direct state-element encoding).** There is no fixed `r` such that
  the alternating game can be represented by a PFP whose variable ranges over
  *individual game configurations as single elements of `W`* identified only by
  fixed-arity tuples without configuration coding: `|W|=N=n+k+1`, while the
  number of poset states alone can be `2^{Θ(n^2)}`. Thus "one domain element =
  one full game state" is impossible on the bare word.
- **Blocked as "no interpretation / no tuple coding of the matrix" in the
  naive sense.** The `n^2`-bit poset component cannot be stored as a bounded
  set of word elements; it must be represented by a relation/pair coding over
  keys (`Key×Key`) or an equivalent interpreted configuration tape. The
  construction above uses FO-definable component relations and an interpreted
  polynomial domain; removing that coding leaves no explicit PFP state.
- **Not blocked as FO(PFP) definability.** FO(PFP) may quantify over
  fixed-arity relations on the ordered structure; the standard
  FO(PFP)=PSPACE proof uses exactly such relation/tuple coding (an
  interpretation/normal form). Therefore the bare ordered word `A(w)` still
  FO(PFP)-defines `SORT-BOUND-U`; the explicit formula is naturally given
  *through* an FO interpretation or fixed tuple coding over `W^r`.
- **Most concrete "bare-word" form available.** Keep `A(w)$ as the only input
  structure and write all accessors (`Key,Ctr,Zero,SuccCtr,PosOf,TimeOf,...`)
  as FO formulas over `σ_w`; use `[PFP_{AC,\bar d}]` with `\bar d ∈ W^6`.
  This has no external structure but does use a 6-ary relation variable and
  pair-encoding FO formulas — i.e., standard finite-model-theoretic tuple
  coding over the word, not a domain-element-per-state encoding.

## 12. Conclusion

The audit gaps are closed at the level requested for a concrete research
encoding: fixed signature/interpretation, explicit key/counter sizing, fixed
6-ary PFP variable shape with component access `P_C/t/a/b/m`, incremental FO
`TC` via `StepPos`, `Init/Acc/Mode/YieldE/YieldA0/YieldA1` schemas, explicit
`time <= k` budget discipline, explicit well-formed/malformed handling, and a
positive/stratified alternating-acceptance justification. The remaining work
is formal expansion of the low-level tuple-coding formulas and a specialized
PFP-semantics proof, not an identified logical obstruction to FO(PFP)
definability. A bare-word no-interpretation encoding is blocked only in the
state-element sense and is available in the standard fixed-arity tuple-coding
sense over the ordered word.
