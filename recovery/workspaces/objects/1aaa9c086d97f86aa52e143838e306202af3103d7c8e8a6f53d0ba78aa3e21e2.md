# exec-report: explicit FO(PFP)/FO(IFP) witness for `SORT-BOUND-U` (derived from budgeted game)

**Task (falsifiable question).** Produce an explicit FO(PFP) (or FO(IFP)) formula/schema defining
`SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }` on an appropriate ordered structure encoding `1^n#1^k`
(`N = n+k+1`), derived from the known PSPACE/budgeted-game characterization, with a careful
correspondence argument; or identify a precise technical obstruction to making it explicit/auditable.
As stated in the request and in `docs/research-plan.md`, this would **not** be a new complexity-class
upper bound beyond PSPACE but a concrete descriptive-complexity witness.

**Labels used:** [definition], [literature], [deduction], [conjecture/open].

**Scope/limits:** Paper-level schema and correspondence only. No Lean, no repo-wide edits, no claim of
`P`, `NP`, `coNP`, hardness, or separation. No kernel-checked theorem is asserted.

## 1. Structure / encoding

[definition][deduction] Fix the unary decision input `w = 1^n # 1^k` of length `N = n+k+1`.
Work over the finite ordered structure
`A_w = (D, <, One, Hash, Min, Max)`
with
- `D = {1,...,N}` in the standard order `<` (successor, constants for endpoints definable in FO on
  ordered structures; we name `Min,Max` for readability),
- `One(i)` iff the `i`-th symbol of `w` is `1`,
- `Hash(i)` iff the `i`-th symbol is `#`.

Define FO-definable unary regions (by position relative to the unique `Hash` element `h`):
- `Elem(i) :≡ One(i) ∧ i < h` — the `n` "key/element" positions (a copy of `[n]` in input order),
- `Bud(j)  :≡ One(j) ∧ h < j` — the `k` "budget/step" positions (a copy of `[k]`).

Then `|Elem| = n`, `|Bud| = k`, and the induced order on each region is a linear order of that size.
This encoding is first-order interpretable from the word and has size `N`; all resource bounds below
are measured in `N`.

**Model correspondence anchors** (from `docs/problem.md`, `docs/research-certificates-barriers.md`).
`S(n)` is the minimax height of the adaptive comparison game `G(n,k)`:
state = transitively closed strict partial order `P` on `n` labelled elements, start empty; while
`P` not total and budget remains, sorter picks an incomparable pair, adversary answers with one of the
two orientations, state becomes its transitive closure; sorter wins iff a total order is reached within
`k` comparisons. `S(n) <= k` iff sorter wins `G(n,k)` [deduction]. Claim A gives an alternating TM
deciding `G(n,k)` in time `O(k n^2) = O(N^3)` and space `O(n^2)` by keeping the current `n x n` poset
matrix and a step counter, hence `SORT-BOUND-U ∈ ATIME(poly(N)) = PSPACE` [literature: CK$81,
APTIME=PSPACE]+[deduction].

## 2. Formula sketch or obstruction

### 2.1 Descriptive-complexity baseline [literature]

On ordered finite structures, `FO(PFP) = PSPACE` and `FO(IFP) = FO(LFP) = P` (Immerman–Vardi capture
for P; Abiteboul–Vianu/Vardi characterization for PSPACE). Since Claim A places `SORT-BOUND-U` in
PSPACE, a defining FO(PFP) sentence exists in principle. The task is an *explicit/auditable* schema
derived from the game/ATM characterization, not merely existence.

### 2.2 Explicit FO(PFP) schema (ATM/configuration simulation) — auditable at configuration level

[deduction] I give an explicit **schema** obtained by the standard PSPACE-capture simulation of the
polynomial-time alternating TM `M` of Claim A on `A_w`. The auditable content is: (i) a fixed
polynomial space bound, (ii) a fixed FO encoding of one configuration, and (iii) a fixed FO/PFP
definition of alternating acceptance.

**Step A — polynomial work bound and addressing.** `M` uses space `s(N) <= c * N^2` for some fixed
constant `c` (enough for the `n x n` ternary poset matrix, pair/counter registers, control). On an
ordered domain of size `N`, `d`-tuples with the lexicographic order form a linearly ordered address
space of size `N^d`; choose fixed `d` with `N^d >= p(N)` for a polynomial `p >= s` and a polynomial
time bound `t(N)` (e.g. `d=4` suffices comfortably for `O(N^3)` time/`O(N^2)` space). Let `\bar u`
range over `d`-tuples of element variables (a "cell/time index").

**Step B — configuration relation (single-step state).** A configuration of `M` is encoded by fixed-arity
relations over `D^d` (constants depending only on `M`, not on `w`):
- `Q_q(\bar u)` / state encoding (or a bounded tuple of unary state bits) indicating control state when
  the head/index is `\bar u` as appropriate; concretely, a fixed finite set of relation symbols
  `State_1,...,State_r` of arity `d` or `0` coding the finite control and head position;
- `T_a(\bar u)` for each tape/work symbol `a` in the finite alphabet `Gamma` (including markers for the
  poset-matrix cells, the budget counter, and blank), meaning "cell `\bar u` holds `a`";
- `Head(\bar u)` meaning the head scans `\bar u`.
The intended invariant (one symbol per cell, exactly one head/state) is an FO property `Conf(C)` where
`C` abbreviates this relation vector.

**Step C — FO local transition and game modes.** Because a TM step is local, there are FO formulas
`Init(C, A_w)` asserting `C` is the initial configuration encoding input `(n,k)` and the empty poset on
`Elem`, `Acc(C)` asserting an accepting (sorter-won / total-order-reached-within-budget) configuration,
`Rej(C)` asserting a rejecting (budget exhausted, not total) configuration, and for the transition:
- `Exist(C)` / `Univ(C)` — FO tests of whether `C` is an existential (sorter chooses a pair) or
  universal (adversary chooses orientation) configuration, determined by the finite control component;
- `Step(C, C')` — an FO formula stating `C'` is one legal successor configuration of `C` under `M`'s
  finite transition table (local consistency on changed cells, equality elsewhere). `Step` is FO because
  it only inspects `C`/`C'` at each `\bar u` and its finitely many `<`-neighbors in the tuple order.

**Step D — alternating acceptance by inflationary/partial fixpoint.** Define a relation variable `W`
("winning configurations") of the same arity/shape as the configuration encoding (a product, written
schematically as one relation or a fixed tuple). Consider the operator
```
Phi(W)(C)  :≡  Acc(C)
            ∨ (Exist(C) ∧ ∃C' (Step(C,C') ∧ W(C')))
            ∨ (Univ(C)  ∧ ∀C' (Step(C,C') -> W(C'))).
```
Read strictly, `∃C'/∀C'` quantify over configuration *relations* (second order). The standard fixpoint
simulation removes this second-order quantification by encoding `C'` as the current tuple assignment to
the configuration variables inside the fixpoint stage: introduce relation variables `Cconf` for the
current configuration and define the PFP/IFP iteration over a relation `WinConf` marking configurations
(on the `D^d` address space) reachable/winning by the backward (or stage-bounded forward) acceptance
rule. A standard explicit form is the least/inflationary fixpoint of "accepting or can move to a
winning configuration in one alternation step", evaluated over the finite configuration graph whose
nodes are `D^(d * m')`-encodable but whose edge relation `Step` is FO. Equivalently, use the
Immerman/Vardi–Abiteboul-Vianu normal-form simulation of an alternating polynomial-time machine:
configurations are `p(N)`-tuples over an ordered domain, `Step` and mode predicates are FO, and
acceptance is `[PFP_{W,\bar x} \psi(W,\bar x)](\bar t_{init})` for an FO formula `\psi` expressing
"accepting, or existential with some `Step`-successor in `W`, or universal with all `Step`-successors
in `W`".

**Schema (FO(PFP) sentence).**
```
Phi_SORT-U  :=  ∀\bar t ( InitConf(\bar t) -> [PFP_{W,\bar x} WinStep(W,\bar x)](\bar t) )
```
where `InitConf(\bar t)` is the FO definition of the initial configuration of `M` on `A_w`, and
```
WinStep(W,\bar x) :≡
    AccConf(\bar x)
  ∨ (ExistsConf(\bar x) ∧ ∃\bar y (StepConf(\bar x,\bar y) ∧ W(\bar y)))
  ∨ (UnivConf(\bar x)  ∧ ∀\bar y (StepConf(\bar x,\bar y) -> W(\bar y)) ∧ Move(\bar x)),
```
with `StepConf/AccConf/ExistsConf/UnivConf/Move` FO formulas over `<,One,Hash` (and the fixed encoding)
expressing one alternating move of the budgeted poset game / ATM `M`. `PFP` is used (rather than LFP)
in accordance with the general PSPACE capture; on the polynomially-bounded configuration graph induced
by `M` the iteration reaches its limit in at most exponentially-many-in-`p(N)` stages, which PFP
provides, while monotonicity is not assumed a priori for the raw configuration-update view.

This is an **explicit formula schema**: plugging the finite transition table of the Claim-A ATM into the
FO definitions of `InitConf, StepConf, AccConf, ExistsConf, UnivConf` yields a fully closed FO(PFP)
sentence over the fixed signature `{<,One,Hash}`.

### 2.3 What "derived from the budgeted-game characterization" means here

[deduction] The derivation chain is: `S(n)<=k` ⇔ sorter wins `G(n,k)` (§1/game) ⇔ the Claim-A ATM
accepts `(1^n#1^k)` (poly alternations/time over poset-matrix configurations) ⇔ `A_w ⊨ Phi_SORT-U` by
the PFP configuration-acceptance semantics. The game objects appear concretely as the intended meaning
of work-tape components inside `StepConf`: an `n x n` relation `P(i,j)` for `i,j ∈ Elem`, a budget
counter over `Bud`, and the control phases "pick incomparable pair / branch on answer / close
transitively / test total-or-budget". Hence the schema is game-derived, even though its syntax is the
machine-simulation normal form.

### 2.4 Obstruction to a fully explicit, *object-level* (poset/transcript) auditable formula

[deduction — precise technical obstruction] A more directly auditable witness would define the game
*extensionally* over poset states, e.g. a relation `Win(R,b)` meaning "partial order `R ⊆ Elem^2` is
winning with `b ∈ Bud` steps left", and express
`Win(R,b) ↔ Total(R) ∨ (b>0 ∧ ∃x,y∈Elem (Incomp(R,x,y) ∧ Win(Closure(R,x<y), b-1) ∧ Win(Closure(R,y<x), b-1)))`,
iterating on `b` along `Bud`. Two obstacles prevent this from being an immediate explicit FO(IFP)/FO(PFP)
formula over `A_w` without the configuration encoding above:

1. **State quantification/representation.** `R` ranges over (exponentially many) partial orders on `n`
   elements. FO over the fixed domain `D` can quantify over elements/tuples, not over arbitrary binary
   relations as first-class values, except by encoding a relation as part of a larger fixed-arity stage
   object addressed over `D^d` — which is exactly the configuration/matrix encoding of §2.2 (and then
   transitive closure/update must be internalized into FO/FP over those addresses).
2. **Transitive-closure/update inside the state.** Each move requires `R' = TC(R ∪ {(x,y)})`.
   Transitive closure is FO(LFP)-definable on ordered structures, but here it must be applied to a
   *dynamically represented* state relation encoded in the configuration, uniformly along the alternating
   play. This is expressible in the machine-simulation schema (closure is a polytime subroutine of `M`,
   hence folded into `StepConf`) but inflates an object-level formula into a low-level bitwise/configuration
   description.
3. **Depth vs fixpoint kind.** The game depth is `k <= N` (polynomial). A direct induction on budget is
   a `k`-stage iteration — suggestive of LFP/P-time — but it iterates over *state properties*; combined
   with (1) the global object is a PSPACE alternating computation over exponentially many states, so the
   correct general capture is FO(PFP) via configurations. Deriving a genuine FO(IFP)/LFP object-level
   sentence would mean `SORT-BOUND-U ∈ P`, a major new upper bound not established here and not claimed.

**Conclusion of obstruction.** There is no known obstacle in principle (existence follows from
`SORT-BOUND-U ∈ PSPACE` + capture), but there is a concrete **auditability/explicitness obstruction**:
any fully spelled-out formula is either (a) the configuration-level PFP simulation of the ATM — explicit
as a schema and mechanically instantiable from `M`'s finite transition table, but low-level relative to
poset objects — or (b) an object-level game formula that requires encoding arbitrary poset states and
their closure dynamics into fixed-arity relations, which is equivalent work and cannot avoid the
configuration blow-up. I do **not** claim impossibility of a shorter object-level formula; I claim it is
not obtained "for free" from the informal recurrence and requires the encoding work in (1)-(2).

## 3. Correctness / correspondence argument

[deduction, conditional on Claim A and standard capture machinery]
1. **Input correspondence:** `A_w` FO-encodes exactly `(n,k)` from `1^n#1^k` with the unique `#`.
2. **Game correspondence:** `A_w ⊨ Phi_SORT-U` iff the encoded ATM `M` has an accepting alternating
   computation on `(n,k)` iff the sorter wins `G(n,k)` iff `S(n) <= k` iff `w ∈ SORT-BOUND-U`.
   The middle equivalences are Claim A / the game identity; the first/last are the semantics of the
   FO(PFP) acceptance schema and of the input encoding.
3. **Resource/capture correspondence:** `M` runs in alternating polynomial time in `N`, so the
   configuration graph and `StepConf` are polynomially bounded/addressable in `D^d`; FO(PFP) expresses
   acceptance of such alternating/polyspace computations on ordered structures [literature].
4. **No class strengthening:** the argument uses only the known PSPACE upper bound; it does not yield
   FO(IFP)=P or ESO=NP membership.

Gaps kept explicit: a fully formal, symbol-by-symbol instantiation of `M`'s transition table inside
`StepConf` (finite but lengthy) is not written out here; correctness of that instantiation would require
a line-by-line audit against a fixed TM specification of Claim A. The correspondence therefore holds at
the level of a *uniform explicit schema* parameterized by `M`.

## 4. Falsification

[deduction/experiment-style checks to attempt]
- **Encode/decode:** verify FO definitions recover `n,k` and reject malformed strings (no/extra `#`).
- **Small exact instances:** for `n <= 6` (and known values tabulated in `docs/research-plan.md`), the
  intended game predicate agrees with `S(n)`; e.g. `(n,k)=(4,5)` should be accepted, `(4,4)` rejected,
  `(6,10)` accepted, `(6,9)` rejected. A fully instantiated formula/simulator could be checked against
  these finite truths.
- **Boundary/monotonicity:** acceptance must be monotone in `k` for fixed `n` (`S(n)<=k => S(n)<=k+1`),
  and trivial-accept when `k >= U(n)` (merge-sort bound) — properties the game/ATM has and any correct
  instantiation must preserve.
- **Non-tightness awareness:** the information bound alone is insufficient at `n=12` (`S(12)=30>29`), so
  any object-level shortcut that equates win with the entropy/counting bound would be falsified; the
  schema here relies on the full game, not on `log2(n!)`.
- **Auditability stress:** the main falsifiable weakness of this deliverable is *instantiation fidelity* —
  an error in `StepConf` (closure/update/counter) would break correspondence while leaving the high-level
  schema plausible. Detecting that requires expanding the schema to a concrete formula/TM table and
  checking it on small instances.

No counterexample to existence is found; the realistic failure mode is an incorrect or non-auditable
instantiation, not a refutation of `SORT-BOUND-U ∈ FO(PFP)` on ordered structures.

## 5. Consequence

[deduction] Conditional on the standard ordered-structure capture theorems and Claim A, `SORT-BOUND-U`
is definable in **FO(PFP)** over the ordered word structure encoding `1^n#1^k`, and §2 gives an explicit
game/ATM-derived **schema** for such a sentence (configuration-level PFP acceptance). This is a concrete
descriptive-complexity witness aligned with the known PSPACE upper bound, **not** a new upper bound: it
does not imply FO(IFP)/P, ESO/NP, or any separation. The precise remaining technical gap for a fully
auditable, object-level formula is the explicit fixed-arity encoding of exponentially many poset states
and their transitive-closure updates inside the fixpoint (§2.4). Therefore the honest outcome is: **explicit
schema produced (configuration simulation), with a clearly identified obstruction to a compact object-level
explicit/auditable formula.**
