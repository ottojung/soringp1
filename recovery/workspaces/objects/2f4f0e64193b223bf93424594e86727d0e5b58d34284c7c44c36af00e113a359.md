## 5. Explicit finite state/transition abstraction (reconstructed, for feasibility assessment)

Because exact paper internals are unavailable, I give a **minimal explicit abstraction schema** `A(SG)` intended to be faithful to the cited "group insertion with coupled interval containers" description at the level needed for framed-certificate/state-count analysis. This is an **inferred abstraction**, not a claim that Sergeev's proof uses this exact formalism.

### 5.1 State

A global control state is a tuple
`σ = (F, C, G, R, κ)` where:

- `F` **(frame/permutation):** a permutation/bijection on `n` labelled slots (or an explicit placement of currently ordered elements into slots), as in framed certificates. Size: `O(n log n)` bits if explicit.
- `C = {C_1,...,C_m}` **(ordered container structure):** a partition/cover description of pending keys into `m` containers placed relative to `F` (e.g. each `C_i` associated with an interval/region of the current ordered skeleton or index range). For finite explicitness, let `b_i = |C_i|`, `∑ b_i = r ≤ n`, and let the container-to-skeleton attachment be given by boundary indices in `[0,n]`.
- `G ⊆ C×C` (or a constraint hypergraph) **(coupling):** explicit inter-container dependencies/constraints induced by group insertion (e.g. shared boundaries, relative order/occupancy constraints, or joint feasibility relations between elements/ranks across containers). This is the component making containers "coupled" rather than independent.
- `R` **(local order/knowledge inside containers):** for each container, the certified partial information among its elements and/or between container elements and frame anchors required to justify next comparisons (may be empty, chain-like, or structured by the algorithm).
- `κ` **(phase/control):** finite program counter / recursion stage / group index selecting the next local insertion/comparison routine.

**State-size parameters:** `n` (keys), `m` (active containers/groups), `r` (pending keys), `B = max_i b_i` (container size), `d` (coupling degree/description size per container, e.g. number of coupled neighbors or joint-constraint tuples represented), and `q` = number of distinct control phases. A fully explicit finite encoding has bit-size roughly
`|σ| = O(n log n + m log n + r log n + |Enc(R)| + |Enc(G)| + log q)`.
Polynomial-size state/count requires this to be `n^{O(1)}` and, for a DAG/certificate view, the number of reachable non-equivalent `σ` under the chosen join relation to be `n^{O(1)}` (or polynomial in unary `N`).

### 5.2 Transitions (comparisons/updates)

A comparison action is `a = cmp(u,v)` on keys/slots determined by `(F,κ,C,R,G)`. Given outcome `o ∈ {<,>}`:

1. **Local knowledge update:** `R -> R'` by adding the comparison outcome and taking the closure required by the local routine (transitive closure within the represented scope, per framed-certificate semantics).
2. **Container update:** elements may move/split/merge containers, be inserted into `F`, or change attachment intervals: `(C,G) -> (C',G')`.
3. **Frame update:** `F -> F' = π_o ∘ F` by an explicit slot permutation when insertion/placement occurs (or identity for pure query steps), as in a framed permutation certificate.
4. **Control update:** `κ -> κ'` according to the group-insertion schedule.
5. **Feasibility:** transition exists only if outcome `o` is consistent with the current certified invariant `I(σ)` (soundness).

Formally, `δ(σ,(u,v,o)) = σ'` is a deterministic/explicit local update rule once the algorithm is fixed. A run is a root-to-leaf path with total comparisons equal to path length.

### 5.3 Join / framed invariant (feasibility condition)

For framed-certificate feasibility, a join operator `⊔` on states reached at a common control point must be **sound**:

- `I(σ ⊔ σ') �subseteq I(σ) ∩ I(σ')` as guaranteed order/placement facts (or, equivalently, it certifies only facts valid on every feasible incoming history), and
- `I(σ ⊔ σ')` must remain sufficient for all future transitions used by the strategy/certificate from that join (completeness relative to the strategy).

A **polynomial-state join-closed abstraction** would provide: (i) a polynomial-size encoding of `σ` (or of its join-relevant invariant), (ii) polynomially many join-equivalence classes over all valid runs, and (iii) polynomial-time local verification of `δ` and `⊔` against the frame/order semantics.

## 6. Assessment: plausibility and extracted obstructions

### 6.1 Plausibility conditions (concrete)

`[inferred/deduction]` A positive polynomial framed abstraction consistent with Sergeev-style group insertion is plausible **only if** there exist parameters/schedules such that:
- `m, B, d, q, |Enc(R)|, |Enc(G)| = n^{O(1)}` along all valid runs;
- coupling `G` admits a **join-closed summary** `J(C,G,R)` with `n^{O(1)}` possible values that preserves every comparison/placement fact needed for future `o(n)`-surplus continuations; and
- the number of distinct `(F`-relative skeleton attachments, container shapes, coupling summaries, phases`)` is polynomially bounded after quotienting by the sound join.

This would constitute the requested positive falsifier/witness if instantiated for the actual Thm. 3 construction.

### 6.2 Obstruction O1: independent per-key/per-container envelopes are insufficient for coupled containers (concrete)

`[inferred/deduction from "coupled" + framed join soundness; not a direct paper theorem]`

Let `Π_ind` be any abstraction class that, at join points, retains only a Cartesian/independent product of per-container or per-key summaries (e.g. independent rank/value intervals or envelopes relative to `F`) and discards inter-container coupling constraints in `G` except what follows from each component alone.

- **Coupling semantics:** "coupled interval containers" means there exist feasible global configurations `(x_1,...,x_r)` constrained by joint relations `Φ_G` not equal to `∏_i Φ_i` (some assignments individually feasible by local summaries are jointly infeasible).
- **Unsound weakening:** replacing `Φ_G` by `∏_i Φ_i` enlarges the certified feasible set; a comparison/transition justified only on the enlarged set may be infeasible for the true coupled state, violating soundness.
- **Sound join loses progress:** a sound join can keep only facts valid on all incoming arcs. If different histories realize different non-equivalent couplings needed for the next local routine, the only sound common independent summary is a coarsening that forgets coupling; this either blocks the intended continuation (incompleteness for that strategy) or forces case splits that distinguish coupling histories.
- **State consequence:** to remain faithful and sound without representing coupling, the abstraction must refine states by coupling history/configuration. Therefore `Π_ind` cannot be a polynomial-state join-closed faithful abstraction of a genuinely coupled-container architecture unless the algorithm's required coupling is trivial/redundant on all valid runs.

*Concrete obstruction form:* exhibit any two valid reachable states with identical `F`-relative independent container envelopes but different feasible joint continuations because of `G`; no sound join in `Π_ind` can identify them while preserving the correct continuation. (Instantiation requires paper-level coupled states; not constructed here.)

### 6.3 Obstruction O2: superpolynomial distinct coupled configurations (conditional schema)

`[open/inferred]` A concrete superpolynomial obstruction would be established by showing, for the actual Sergeev group-insertion transition system `T_n`:
- a family of valid runs producing `M(n)` pairwise non-joinable coupled configurations at some comparable control points, with `M(n)` superpolynomial in `n`; and
- for any sound framed invariant `J`, `J(σ_p) != J(σ_q)` whenever the required future comparison/placement behavior differs on valid extensions (or equivalently, join identification forces unsoundness/incompleteness).

Plausible sources of explosion in this abstraction schema are: exponential-in-`r` joint occupancy/placement assignments consistent with local container bounds but distinguished by `G`, or superpolynomially many coupling graphs/attachments across phases. **However, without the paper's exact `m,B,d,G` evolution and schedule, neither `M(n)` nor non-joinability is proved here.** Sergeev's `o(n)` surplus implies high information efficiency but does not by itself imply polynomially many join-closed global states.

### 6.4 Comparison to known polynomial framed constructions

`[paper/repo, audit-pending constructions]`
- Merge sort: global merge state effectively `(a,b)` over queue remainders with a strong prefix+two-queues invariant; `O(n²)` comparison states, joinable by exact invariant (`docs/research-framed-certificate-frontier.md` §2), but linear comparison deficit vs information bound for powers of two.
- Ford–Johnson/rank-envelope sketch: per-element relative rank windows admit sound relaxed joins in that setting (`§3`), but bound is not `S(n)` and architecture differs.

`[deduction]` These show framed DAGs can be polynomial for specific invariants; they do **not** transfer to coupled interval containers unless an analogous coupling-preserving (or safely collapsible) join-closed invariant exists.

## 7. Conclusion

- **Stated in Sergeev (reliable here):** group-insertion algorithm achieving `S(n)=log₂(n!) + O(n/(log n)^(1/5))` (TR20-096 Thm. 3 / abstract).
- **Extracted explicit abstraction (inferred, finite schema):** `σ=(F,C,G,R,κ)` with frame, interval/container decomposition, coupling constraints, local knowledge, and control phase; comparison transitions update `(F,C,G,R,κ)` locally; framed feasibility requires a sound, future-sufficient, join-closed invariant.
- **Feasibility assessment:** polynomial-size join-closed framed realization is **not established** from available information. It is plausible only under a strong explicit coupling-compression invariant (polynomial `|Enc(G),|Enc(R)|`, polynomial join classes).
- **Concrete obstruction (class-level, from abstraction):** any abstraction that discards inter-container coupling into independent envelopes/rank intervals (class `Π_ind`) is not a faithful sound join-closed encoding of genuinely coupled containers (Obstruction O1). A full architecture-level superpolynomial state explosion remains **open/conditional** pending primary-source details (Obstruction O2 schema).
- **Falsifiers:**
  1. give an explicit polynomial `σ/J,δ,⊔` instantiation for Sergeev's actual Thm. 3 coupled-container procedure with verified sound joins and `o(n)` surplus; or
  2. from the paper's actual container/coupling rules, produce valid runs and prove superpolynomial non-joinable coupled configurations (or an unavoidable unsound/incomplete join under any polynomial invariant).

**Net:** primary-source extraction in this environment is partial; a concrete abstraction and a concrete coupling-based obstruction class were identified, but decisive all-`n` feasibility/obstruction for Sergeev's exact construction remains unresolved without the paper's internal state/transition details.
