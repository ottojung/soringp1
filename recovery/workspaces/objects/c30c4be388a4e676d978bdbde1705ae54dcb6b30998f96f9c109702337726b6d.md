## 3. Method (total move coverage, no heuristic dominance)

Added `scripts/total_coverage_bb.py`. `[definition,deduction,experiment]`

- **State:** tuple of successor bitmasks, exact transitive closure after each answer (`extend`/TC same as repo DFS scripts).
- **Total move coverage:** for every explored non-total, nonzero-budget node `(P,b)`, the search iterates over **all** `Inc(P)` in canonical `(i<j)` order and records each move’s answer statuses (`lt`,`gt`) and derived move status.
- **Semantics (exact, no dominance heuristic):**
  - a move is `sorter_win` iff **both** adversary answers lead to sorter-win states (sorter can force win by that move);
  - a move is `refuter_win` iff **at least one** answer leads to a refuter-win state (adversary can answer that move);
  - node is `sorter_win` if any move is `sorter_win`; else `refuter_win` if no move is `unknown`; else `unknown`.
  - The early recognition of a `sorter_win` move is sound (exact game value), **not** a heuristic dominance/pruning of adversary answers; all moves were still enumerated for coverage in this implementation’s accounting path.
- **Memoization:** exact identity keys `(succ_tuple,budget)`. **Poset congruence/canonicalization is NOT used** for certified claims: color refinement is incomplete in general and full `S_n` canonicalization is infeasible at `n=12` (`12!` per state). The script reports this explicitly.
- **Caps:** explicit `--node-cap`, `--time-cap`; on cap, node/move statuses become `unknown`, `certified=false`, and a `blocking_frontier` with `first_cap_path` is recorded.
- **No auto-claim for n=12:** the script never emits `S(12)>29` or `S(12)<=30`; small-n claims only when fully certified under caps.

## 6. Why G(12,29)/G(12,30) are infeasible beyond a small fragment (measured)

1. **Total move coverage cost.** Root has 66 incomparable moves; each must be resolved for a refuter certificate (`∀` sorter moves) and, in the worst case, both answers explored. At depth 29/30 the game tree/state graph is far beyond 50k/500k-node caps (`[experiment]`: 50k nodes cover only 56k–57k move examinations at root-proximal depth, all still unknown).
2. **No certified congruence in this run.** Identity memo gave 50k memo entries / 56k hits at cap on `n=12` but did not resolve root moves. Full `S_n` congruence is `12!` per state (infeasible); color refinement/pruned canonicalization would need an explicit soundness proof per shared key and an implementation/canonical representative discipline (cf. failed/cautioned canonical C4 attempt in `g1229-c4-compression-test`). Not used.
3. **State universe.** `[literature/deduction, cited]` labelled posets on 12 are `A001035(12)` (astronomical); even restricted reachable/optimal-play states are unknown and, per prior notes, no short total-coverage refuter object is known for `G(12,29)`.
4. **Known obstruction context.** `[literature]` `S(12)>29` is strategic/non-scalar (information bound tightness gap first at 12 in this family); published proofs are exhaustive searches, not compact independently checkable short certificates in the repo’s framed/refuter formats.
