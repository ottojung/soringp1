# exec-report: compress-exact-space-evaluator

**Front ID:** compress-exact-space-evaluator

**Date:** 2026-11-17

## 1. Question (all-n, falsifiable)

Can `S(n)` be computed by a *uniform deterministic* algorithm using asymptotically
fewer than `O(n log^2 n)` bits of work space (numeric `n`), i.e. `O(n)` or
`polylog(n)`, while keeping the worst-case time in `2^{O(n log^2 n)}` (up to
polynomial factors)? Equivalently, is the transcript-only budgeted DFS of
`docs/research-budgeted-dfs.md` §5.2 space-tight only for that one algorithm, or
is the path stack forced on *every* exact evaluator?

Consequence if answered positively: a smaller uniform space bound for
`SORT-BOUND-U` (and `S_unary`), refining the PSPACE membership without a
class separation. If answered negatively: the `O(n log^2 n)`-bit upper bound
gains a matching barrier for the backtracking-DFS family.

## 2. Baseline established in the repository

- `research-budgeted-dfs.md` §5.2: transcript-only DFS uses `O((d+n) log(n+2))`
  bits, `d <= U(n)=O(n log n)`, hence `O(n log^2 n)` bits for `S(n)`; decision
  `SORT-BOUND-U in DTIME(2^{O(N log N)}) ∩ DSPACE(O(N log N))` for input length
  `N = n+k+1` (§5.3).
- `research-budgeted-dfs.md` §5.2 item 5: reachability workspace can be lowered
  from `O(n log n)` (BFS) to `O(log^2 n)` via Savitch, at quasi-polynomial
  per-query time (absorbed by the exponential node count). This removes only the
  additive `+n` term; the leading `d log n` term remains.
- Prior front runs of the same ID (Oct 2026) concluded: canonical root-replay
  (store a DFS-node rank, regenerate from the root) does *not* yield a justified
  improvement — the rank needs `O(k log n)` bits (same order as the path stack)
  and naive regeneration costs `2^{O(k^2 log n)}` time, not `2^{O(k log n)}`.

## 3. What I tried (this run)

1. **`O(n)` / polylog space via root-replay with checkpoints.** Store the full
   transcript at `O(1)` checkpoints and recompute each frame from the nearest
   checkpoint. A checkpoint must record the complete transcript prefix up to that
   depth, i.e. `O(t log n)` bits for depth `t`; with `Θ(sqrt(d))` checkpoints
   the total is `O(d^{3/2} log n)` bits — *worse* than `O(d log n)`, not
   better. With `O(1)` checkpoints, recomputation from the root costs up to the
   full subtree below the checkpoint, i.e. `T^{O(d)}` time = `2^{O(d^2 log n)}`
   (the same blow-up as the naive root-replay of §2). No intermediate schedule
   achieves both `o(d log n)` space and `2^{O(d log n)}` time: either a
   checkpoint stores at least the transcript (≥ `Ω(d log n)` bits) or
   regeneration reintroduces the superpolynomial time factor.

2. **Compressing the transcript itself.** A transcript entry is an ordered pair
   of labels in `[n]`; there are `Θ(n^2)` possible comparisons, so each entry
   needs `Θ(log n)` bits information-theoretically. The counting argument of
   `transcript-only-space-tightness` (Nov 2026) shows an explicit comparison path
   of length `t = Θ(n log n)` requires `Ω(t log n) = Ω(n log^2 n)` bits.
   Re-encoding by pair index, combinadic, or variable-length coding cannot beat
   `log_2 binom(n,2) = Θ(log n)` bits per entry in the worst case. A Savitch
   substitution only removes the additive `n log n` reachability scratch.

3. **State-count / canonical-form compression.** The winning-frontier barrier
   (`research-winning-frontier-barrier.md`) gives
   `2^{(1/4-o(1)) n log^2 n}` pairwise nonisomorphic *winning* states at a
   single depth. This does **not** by itself force distinct configurations for an
   arbitrary evaluator (all those states have the same Boolean answer `True`),
   so I do not claim a universal `Ω(n log^2 n)`-bit lower bound for every RAM
   algorithm. What it does force is that any evaluator whose live configuration is
   a *function of the current poset alone* (canonical form) must distinguish
   `2^{Ω(n log^2 n)}` states, hence needs `Ω(n log^2 n)` bits. An evaluator
   that instead keeps the history path has the same cost by (2). Thus the two
   natural representation routes (state form vs. history form) both land at
   `Ω(n log^2 n)`.

4. **Hidden recursive stack-space check.** I re-examined the transcript-only
   implementation accounting for (a) the incomparable-pair cursor per frame
   (`ceil(log_2(binom(n,2)+1))` bits), (b) the single shared reachability
   workspace, and (c) whether recursion depth could exceed `d+1`. Instrumentation
   in `scripts/transcript_dfs.py` confirms max stored path length equals depth
   `d` and a single workspace (no per-frame matrix). No hidden stack-space
   violation beyond the documented `O((d+n) log n)` accounting. The one safe
   tightening is the Savitch substitution of §2 (already documented).

## 4. Concrete state family (falsifier, first horn)

Take the winning-frontier family of `research-winning-frontier-barrier.md` at
depth `t = S(n) - c n` (for the small constant `c` from Sergeev's bound,
`S(n)-C(n)=o(n)`), yielding
`2^{(1/4-o(1)) n log^2 n}` pairwise nonisomorphic posets `P` on `[n]` such
that `CanSort(P, S(n)-t) = True`. For any evaluator that (i) represents the
current state by a canonical form of `P` and (ii) must correctly continue the
minimax search from `P` with the remaining budget, the live configuration must
encode which of these nonisomorphic states is current; that requires at least
`log_2` of their count = `(1/4-o(1)) n log^2 n` bits. Hence such a
representation cannot be `O(n)` or polylog. This is a barrier against
canonical-form compression; it does not prove the same for arbitrary
history-dependent algorithms (see §5).

## 5. What this does NOT establish (honest limits)

- No **universal** `Ω(n log^2 n)`-bit lower bound for *every* deterministic RAM
  algorithm computing `S(n)`. The state-count argument of §4 applies only to
  state-representing evaluators; a genuinely different algorithmic paradigm
  (not tree search, not canonical state) is not ruled out. Such a lower bound
  would need a technique not available here (and would be unusual for a function
  in PSPACE / P/poly).
- No `O(n)` or polylog algorithm found.
- No complexity-class consequence: `SORT-BOUND-U` remains in PSPACE; no
  separation is claimed.
- The Savitch tightening is an accounting improvement, not a new algorithm.
- No Lean or repository changes; only this report and one board post.

## 6. Conclusion / decisive obstacle

The proposed compact representations (root-replay, checkpointing,
canonical-form compression) each fail to beat `O(n log^2 n)` bits without a
superpolynomial time blow-up (`2^{O(d^2 log n)}`) or a larger space cost.
The path-stack information bound (`Ω(n log^2 n)` bits for any explicit
comparison path) and the winning-frontier state count (barrier against
canonical forms) jointly obstruct the two natural routes. The only concrete,
safe improvement available is the Savitch reachability substitution, which removes
the additive `+n log n` term. **Whether an entirely non-backtracking evaluator
can use `o(n log^2 n)` bits remains open.**
