# SoringP1 #301 (billy-dev): computable exact-search window bound (exec report)

**Research front:** "computable exact-search window bound"  
**Date:** 2026-11-17  
**Scope:** Unary encoding / `SORT-BOUND-U` context per `AGENTS.md`; model and encodings per `docs/problem.md`.  
**Constraint:** No repository/Lean/PR changes except this report.

## 1. Question (all `n`, falsifiable)

Is there any **explicit, polynomial-time computable** function `W(n)` (on unary input `1^n`) such that

`S(n) <= C(n) + W(n)` for all `n`,

with `W(n)` provably `o(n)` or even `O(n / log^c n)` from known results; **or** can one show that extracting such an effective bound from current proofs (Sergeev / merge-insertion analyses) is blocked by a specific non-effective step?

This is distinct from merely stating Sergeev's asymptotic `O(·)` excess: it asks for an **effective finite/explicit** window bound or a **precise extraction obstruction**. State consequences for narrowing the exact threshold search for `SORT-BOUND-U`.

## 2. Fixed definitions and baseline facts

- **[definition/literature]** `S(n)` is the minimum worst-case height of a deterministic adaptive comparison decision tree sorting every permutation of `n` distinct labelled keys. `C(n) = ceil(log2(n!))` is the information-theoretic lower bound, so `C(n) <= S(n)`. (`docs/problem.md`, `docs/literature.md`)
- **[definition]** `SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`, input length `N = n + k + 1`. Informative thresholds lie in a window of width `O(n)` in numeric `n` (e.g. between `C(n)` and standard comparison-sort upper bounds). (`docs/problem.md`, `docs/research-certificates-barriers.md`)
- **[literature]** Exact values are known for `n <= 22` in the cited literature baseline; `n=12` is the first non-tight case at the information bound (`C(12)=29`, `S(12)=30`). (`docs/literature.md`, `docs/research-plan.md`)
- **[literature]** Merge insertion / Ford–Johnson gives an **explicit finite** upper bound for every `n` (a concrete comparison count/function computable from `n`), but its excess over `log2(n!)` is `Theta(n)` in the regimes relevant here, so it does **not** supply `W(n)=o(n)`. (`docs/literature.md`, `docs/research-sergeev-asymptotic.md` context)
- **[literature]** Sergeev (ECCC TR20-096, 2020; journal 2021) proves constructively that

  `S(n) = log2(n!) + O(n / (log n)^(1/5))`,

  via a group-insertion sorting algorithm (Theorem 3 as cited in `docs/research-sergeev-asymptotic.md`). This implies `S(n) - C(n) = o(n)` asymptotically. (`https://eccc.weizmann.ac.il/report/2020/096/`, `docs/research-sergeev-asymptotic.md`, `docs/research-plan.md`)

## 3. Analysis: effective finite/extractable window bound?

### 3.1 What is required

- **[deduction]** An "effective exact-search window bound" of the requested kind means: a total function `W : N -> N` (or `R`) given by an explicit formula/algorithm, computable in time polynomial in `|1^n| = n`, such that for **all** `n >= 0`, `S(n) <= C(n)+W(n)`, and with a proved asymptotic rate `W(n)=o(n)` or `O(n/log^c n)` (for some fixed `c>0`) derived from known results. Equivalently, for all `n` the threshold question is confined above by `k <= C(n)+W(n)`.

### 3.2 Status from known results in scope

- **[literature/deduction]** Sergeev's stated theorem is an asymptotic big-`O` bound: it guarantees existence of constants `M, n0` with `S(n)-log2(n!) <= M*n/(log n)^(1/5)` for all sufficiently large `n`, but the published asymptotic form does not by itself present an explicit `M, n0` nor a single closed-form finite `W(n)` certified for every `n`. `docs/research-sergeev-asymptotic.md` records: "The asymptotic big-O alone does not supply explicit constants or a finite computable upper-bound function for every input. Extracting such a bound from the constructive group-insertion proof is a separate task." 
- **[deduction]** Because `C(n)` is explicitly computable in polynomial time on unary input `1^n` (by computing/log-summing or bounding `n!`/`log2(n!)` to sufficient precision, or directly via standard arithmetic on `poly(n)`-bit values), any explicit polynomial-time `W(n)` would make the upper endpoint `U_eff(n)=floor(C(n)+W(n))` an explicit polynomial-time computable search cap. No such `W(n)` with `o(n)` rate is identified in the provided project literature/docs. Merge-insertion yields an explicit cap but only `Theta(n)` excess.
- **[open]** Therefore, **no explicit, polynomial-time computable `W(n)` with provably `o(n)` (or `O(n/log^c n)`) for all `n` is established by the known results surveyed here**. The weaker asymptotic existence `S(n)-C(n)=O(n/(log n)^(1/5))` is known [literature], but it is not the requested effective finite bound.

### 3.3 Extraction obstruction (from current proofs, as characterizable here)

- **[deduction]** A precise obstruction to reading an effective all-`n` bound directly off Sergeev's asymptotic theorem/proof presentation (as available in the cited sources/docs) is the **non-effective/implicit quantification in the asymptotic analysis**: hidden constants and a sufficiently-large-`n` regime (parameter/group-size choices optimized asymptotically) are not instantiated as an explicit finite function valid for every `n`. Consequently, one cannot mechanically obtain `W(n)` for all `n` without reworking the constructive group-insertion analysis to track constants and small/base cases.
- **[conjecture, methodological]** Sergeev's construction is algorithmic, so a finite effective `W(n)` may be *extractable in principle* by a careful re-analysis of the group-insertion proof (making parameters and constants explicit and covering all `n`), but this is not accomplished by the asymptotic statement alone and is recorded in-repo as a separate research task (`docs/research-sergeev-asymptotic.md`: "derive a finite effective group-insertion bound..."). This report does **not** claim a proof that extraction is impossible, only that current asymptotic results/proofs as stated do not yield the requested effective bound and that the missing explicit constants/regime handling is the specific blocking step.
- **[deduction]** For merge-insertion analyses, the obstruction is different: they are already effective/explicit but give linear-scale excess, so they fail the `o(n)` rate requirement rather than effectiveness.

## 4. Consequences for narrowing the exact threshold search for `SORT-BOUND-U`

Let `U_std(n)` be any explicit standard upper bound with `S(n) <= U_std(n)` and `U_std(n)-C(n)=O(n)` (e.g. merge-insertion / merge-sort-style explicit bounds).

- **[deduction]** **Current effective situation:** exact determination/localization of `S(n)` (hence deciding `SORT-BOUND-U` by search over `k`) can be confined to an explicit integer window `k in [C(n), U_std(n)]` of width `Theta(n)`. Known exact values for `n <= 22` [literature] pin the answer there without search, but provide no all-`n` window shrinkage.
- **[deduction]** **If an explicit poly-time `W(n)=o(n)` (or `O(n/log^c n)`) were extracted:** the window narrows to width `W(n)` for all sufficiently large `n` (or all `n`, if finite). Consequences: (i) fewer candidate thresholds to bracket/check for the value of `S(n)`; (ii) for any exact procedure whose cost depends on the budget/height parameter `k` or on searching near the optimum, this reduces the relevant `k` range (potentially improving practical/instance-sensitive cost and sharpening certificates localized to the top of the window). 
- **[deduction, with caution]** **No change to established worst-case complexity classifications by itself:** the project's known upper bounds for evaluating/deciding in this model are game/DFS-style (e.g. `SORT-BOUND-U ∈ PSPACE`, budgeted DFS bounds in `docs/research-plan.md`) and are dominated by the minimax/state structure rather than merely scanning a `Theta(n)`-wide numeric interval. Shrinking the numeric threshold window to `o(n)` does not, by itself, imply `SORT-BOUND-U ∈ NP`, membership below PSPACE, or a polynomial-time evaluator; conversely it is compatible with all currently open upper-bound questions. It is a **search/localization refinement**, not a complexity-class collapse.
- **[deduction]** **Falsifiability:** producing a concrete, explicit `W(n)` (formula/algorithm), a proof that `S(n)<=C(n)+W(n)` for all `n`, and a proof/routine check that it is computable in `poly(n)` time on unary input with `o(n)` (or stated `O(n/log^c n)`) growth would positively settle the first alternative. Exhibiting a fully explicit-constant, all-`n` rederivation from Sergeev's construction would do so; failure confined to missing constants/small-`n` handling would corroborate the extraction-obstruction characterization.

## 5. Summary answer

- **Known [literature]:** `S(n)-C(n)=O(n/(log n)^(1/5))=o(n)` asymptotically (Sergeev 2020). `C(n)` and merge-insertion caps are explicit/finite.
- **Requested effective bound [open/not found from known results]:** no explicit, polynomial-time computable `W(n)` with `S(n)<=C(n)+W(n)` for all `n` and `W(n)=o(n)` or `O(n/log^c n)` is available from the surveyed known results/asymptotic statements.
- **Extraction obstruction [deduction, grounded in cited sources]:** Sergeev's asymptotic bound/proof as stated carries implicit constants and a large-`n` regime, so obtaining an all-`n` effective `W(n)` is blocked by the need to **explicitize constants/parameters and cover finite/base cases** (a separate extraction task), not by a demonstrated impossibility. Merge-insertion is explicit but rate-insufficient.
- **Consequence [deduction]:** the exact threshold search for `SORT-BOUND-U` remains confined only to an explicit `Theta(n)`-width window in general; an effective `o(n)` window would narrow localization of `S(n)` but would not by itself settle the main complexity questions about computing `S(n)`.
