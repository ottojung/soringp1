# Exec report: dfs-transcript-space-lowerbound

## Scope and claim discipline

- **Question addressed.** For the exact budgeted DFS deciding `CanSort(∅,d)` in the adaptive comparison game (correct backtracking over both adversary answers and over the sorter's search over incomparable pairs), determine whether `Ω(d log n)` bits of mutable path information are required in the worst case at `d = Θ(S(n))`, by an information-theoretic/combinatorial configuration-distinguishing argument; or else construct a provably correct simulation using `o(d log n)` bits with explicit space accounting. (Front brief.)
- **Model / encoding.** Adaptive comparison decision trees on `n` distinct labelled keys; game `G(n,k)` / recurrence `CanSort(P,d)` as in `docs/problem.md`, `docs/research-certificates-barriers.md` §0, `docs/research-budgeted-dfs.md` §2–3. Active encoding is unary: input `1^n#1^k`, `N=n+k+1`, with `d=k`; function regime `S_unary(1^n)` has `d=Θ(S(n))=Θ(n log n)` in the decisive range. Work space is mutable Turing-machine work tape; read-only input is excluded. `[definition]`
- **Baseline.** Transcript-only DFS stores one comparison per frame plus control and recomputes comparability, using `O((d+n)log(n+2))` bits (BFS reachability) or `O(d log n + log^2 n)` bits (logspace reachability, prior exec report `/home/lubko/soring301-exec-compress-exact-space-evaluator-20261117e/exec-report.md`, Candidate B). Both are `O(n log^2 n)` bits at `d=Θ(S(n))`; neither is claimed tight and no class separation follows (`SORT-BOUND-U ∈ PSPACE` already known). `[literature/deduction, repository docs]`
- **No overclaim.** This report does **not** establish a universal `Ω(d log n)` lower bound, **not** exhibit a correct `o(d log n)`-bit simulation, and **not** separate complexity classes. Results are conditional/negative where stated. `[deduction/open]`

## DFS configuration: what mutable path information is actually needed

`[definition/deduction]` Write the standard pure DFS of `docs/research-budgeted-dfs.md` §2 with a fixed total order `≺_idx` on index pairs (e.g. lexicographic on `(i,j), i<j`):

```
CanSort(σ, d):  // σ is current transcript, P(σ) its closure
  if total(P(σ)): return True
  if d==0: return False
  for (i,j) in Incomp(P(σ)) in order ≺_idx:   // sorter's OR, resumable scan
    append (i,j) to σ;  a := CanSort(σ,d-1);
    if a: replace last by (j,i); b := CanSort(σ,d-1); pop; if b: return True
    else: pop
  return False
```

A complete, sufficient configuration for correct backtracking at depth `t = |σ| <= d` is:
- **Action/path history:** the ordered transcript `σ=((a1,b1),..., (at,bt))`, or an equivalent representation from which the current `P(σ)` and the exact inverse of each appended step are recoverable. Each action is an oriented comparison among `2·C(n,2)=n(n-1)` possibilities, so an explicit encoding costs `Θ(log n)` bits per step, `Θ(t log n)` total. `[deduction]`
- **Control state (per active level):** enough to resume the sorter's scan after a child returns (cursor/next candidate in `≺_idx`, or equivalent) and the adversary-branch phase (first/second answer tried). A fixed-order cursor is `⌈log2(C(n,2)+1)⌉=O(log n)` bits and phase is `O(1)` bits per frame; `O(d log n)` total. This is mutable path/control information, not recomputation workspace. `[deduction]`
- **Recomputation workspace:** temporaries to test `total/incomparable/reachable` from the stored path (e.g. BFS `O(n log n)` or logspace reachability `O(log^2 n)` bits in the transcript representation). This is workspace but not path information and can be allocated/released per query (`docs/research-budgeted-dfs.md` §5.2, prior report). `[deduction]`

Correctness of the recursion depends only on the current state `P(σ)` and remaining budget (`§3` proof), but **backtracking** of this DFS depends on restoring the parent configuration after exploring a child: transcript prefix and parent control must be available again. `[deduction]`

## Information-theoretic / combinatorial analysis

### A. Undo/history necessity for stack backtracking `[deduction]`

For a depth-first search that returns control to the parent by undoing the last move, the mutable state on return from a child at depth `t>=1` must equal the parent state at depth `t-1`. If the parent state includes (or implies) the last action `m_t ∈ M_t` and the algorithm does not retain an equivalent record nor a way to infer it from smaller state, then it cannot in general restore the parent. Therefore any *undo-based* simulation requires, at the point before returning from depth `t`, mutable information sufficient to distinguish the executed action `m_t` among those that could have produced the current child from that parent (an "undo record").

In the comparison game, from the antichain/root many pairs are incomparable (`C(n,2)` at `t=0`) and the first comparison can be any of `n(n-1)` oriented outcomes reached along legal move/answer choices; more generally, along realizable paths the per-step action alphabet remains `Ω(log n)` bits in the worst case whenever `Ω(n^2)` ordered choices are possible at that step. An explicit per-level record is thus `Ω(log n)` bits in such steps. **This yields a conditional lower bound:** a simulation that stores an explicit independent undo/action record per DFS level needs `Ω(t log n)` bits on paths of length `t` with `Ω(log n)`-bit step entropy. `[deduction]`

### B. Why simple configuration-counting arguments fail to force `Ω(d log n)` for the actual DFS state `[deduction/open]`

The front asks to show failure of *simple configuration-counting arguments* to force `Ω(d log n)` for the actual DFS state needed. Several natural counting attempts are insufficient:

1. **Total node/counting of the search tree.** The DFS may visit up to `(2·C(n,2))^d = 2^{O(d log n)}` nodes, but a depth-first traversal needs only the current root-to-node path, not simultaneous storage of all nodes. Tree size bounds time, not path space. `[deduction]`

2. **All length-`d` ordered comparison sequences.** There are at most `(n(n-1))^d = 2^{O(d log n)}` ordered transcripts total, giving an information-theoretic upper bound `O(d log n)` on naming a transcript, but not a lower bound on *mutable* state if many transcripts are never on realizable DFS paths, if different transcripts are equivalent for future/control, or if the algorithm can reconstruct parts from the read-only input and smaller state. Conversely, realizability constraints may reduce the count below `2^{Ω(d log n)}` on some branches. `[deduction]`

3. **Reachable-poset/state counts.** The induced poset state `P(σ)` ranges over a large set overall (A001035(n) labelled posets are reachable in general; `docs/research-certificates-barriers.md` §5), but (i) the DFS can recompute `P(σ)` from a transcript instead of storing a poset object, and (ii) a lower bound on the number of *possible states* does not imply each current configuration must store `log(#states)` bits if the state is generated/reconstructible from a shorter mutable history. Also, `S_n` quotient/canonical forms are not known to compress the *path* needed for backtracking. `[deduction/open]`

4. **Control-state counting is algorithm-dependent.** A cursor is needed for this fixed-order implementation, but a different but equivalent DFS order, implicit enumeration, or recomputation of "next untried pair" from the transcript and parent phase could in principle trade time for control bits. Without fixing the traversal policy, raw configuration counting of one implementation does not force `Ω(d log n)` for every correct simulation of `CanSort`. `[deduction/open]`

5. **Distinguishing DFS configurations vs distinguishing game states.** The minimax value depends on `P(σ),d`, but a backtracking evaluator's configuration also depends on unexplored siblings/phase. Simple arguments that identify only `(P(σ),d)` undercount control, while arguments that identify all implementation tuples overcount nonessential encoding choices. Bridging this gap to an intrinsic `Ω(d log n)` bit lower bound on mutable path information for *every* correct exact DFS simulation is exactly what is missing. `[open]`

Net: simple global counting arguments either target the wrong object (whole tree, all sequences, static state count) or are sensitive to traversal/representation choices; they do not by themselves establish a worst-case `Ω(d log n)` lower bound for the actual mutable path information required by all correct budgeted-DFS simulations at `d=Θ(S(n))`. `[deduction/open]`

## Candidate `o(d log n)`-bit simulations considered (falsification attempts)

### C1. Store `P(σ)` (closure matrix / canonical poset) instead of transcript `[deduction]`

- **Accounting.** An explicit labelled closure is `n(n-1)/2` relation bits (or `n^2` in matrix form), far larger than `d log n` for relevant `d` except tiny `n`; canonical unlabelled encodings of arbitrary posets still need `Θ(n^2)` bits in general. Not `o(d log n)`. `[deduction/literature]`
- **Backtracking issue.** Closure alone does not record which comparison edge was added last, so it is not by itself an undo stack; augmenting with last-action records returns to `Θ(d log n)` path bits. **Falsified as `o(d log n)` improvement.** `[deduction]`

### C2. Compressed/canonical transcript (transitive reduction, path code) `[open]`

- **Idea.** Store a generating set or compressed code of `σ`/`P(σ)`.
- **Accounting obstacle.** Even if some prefixes compress, a worst-case family would need to force incompressibility of the *action history needed for undo* across `d` levels while preserving exact backtracking. No all-`n` `o(d log n)` bound is proved. A transitive reduction can still be large and, crucially, may omit the chronological last action; to undo correctly one must recover the specific appended comparison, not merely current comparability. **Not established; no construction.** `[open]`

### C3. Recompute control/cursor without storing it `[deduction/open]`

- **Idea.** Derive the next untried incomparable pair from `σ` (or `P(σ)`), current budget/depth, and a fixed deterministic rule, avoiding an explicit cursor.
- **Accounting.** This can plausibly remove or reduce the separate cursor field but does not remove the need to represent the path/history `σ` (or equivalent undo information) for backtracking and for recomputing `P(σ)` in the transcript model. At best constant-factor or lower-order savings in control bits, not asymptotic `o(d log n)` below the action-history term unless the history itself is compressed. **Falsified as a route to `o(d log n)` total mutable path information (given current knowledge).** `[deduction/open]`

### C4. Catalytic / reversible / recomputation-only backtracking `[open]`

- **Catalytic.** Catalytic space allows auxiliary memory initially filled with arbitrary data that must be restored; it is a nonstandard resource and not the same as reducing ordinary mutable work space. No catalytic simulation of this exact DFS with proved ordinary mutable `o(d log n)` bits is known here. `[open]`
- **Reversible (Bennett-style).** Reversible simulation can make steps undoable but typically stores trace information or increases time/space to preserve reversibility; standard pebbling/reversible tradeoffs do not yield an evident `o(d log n)` mutable-bit exact DFS for an adaptive branching game tree. No concrete scheme found. `[open]`
- **Conclusion.** No correct catalytic/reversible/compressed simulation with explicit `o(d log n)`-bit accounting is exhibited. `[open]`

## Findings

1. **`[deduction]` (configuration decomposition).** For exact budgeted DFS with correct backtracking, mutable state decomposes into path/action history (or equivalent undo-capable state), control/cursor/phase, and recomputation workspace. The known transcript simulations use `Θ(d log n)` mutable path/control bits plus `O(n log n)` or `O(log^2 n)` recomputation workspace, i.e. total `O(d log n + n log n)` / `O(d log n + log^2 n)`.
2. **`[deduction]` (conditional necessity).** Any undo-based simulation that records an explicit action per level incurs `Ω(log n)` bits on steps with `Ω(n^2)` possible oriented comparisons, hence `Ω(t log n)` on such paths. This is a representation/traversal-conditional argument, not a universal theorem over all correct evaluators.
3. **`[deduction/open]` (simple counting arguments insufficient).** Global counts over search nodes, all transcripts, or all posets do not force `Ω(d log n)` for the actual DFS mutable path information needed, because they conflate time with path space, ignore recomputation/restorability, or depend on implementation/traversal choices.
4. **`[open]` (no `o(d log n)` construction).** No provably correct simulation of exact budgeted DFS using `o(d log n)` mutable path bits (via compressed transcript, catalytic, reversible, or other explicit scheme) was found; compressing chronological undo information while preserving exact backtracking remains the key difficulty.
5. **`[deduction]` (status vs frontier).** At `d=Θ(S(n))=Θ(n log n)`, the leading known workspace is `O(n log^2 n)` bits; improving it below `O(d log n)=O(n log^2 n)` would require a genuinely new path/state representation or a strong intrinsic lower bound showing the transcript-length term is unavoidable.

## Obstacles

- **Intrinsic lower bound gap.** Need a model that quantifies "mutable path information required for correct backtracking" over all uniform exact simulations (not one DFS encoding) and proves `Ω(d log n)` at `d=Θ(S(n))`, or isolates the exact information-theoretic quantity (decision-tree/communication complexity of resuming the game DFS). `[open]`
- **Undo vs state equivalence.** Current `P(σ)` determines future minimax value but not necessarily the chronological undo record; any compression must preserve restorability of the precise parent configuration or simulate it indirectly. `[open]`
- **Adversarial/worst-case family.** A lower bound needs a realizable family of depth-`Θ(S(n))` DFS configurations with high incompressible path entropy under the actual game constraints, not merely unconstrained sequences. `[open]`
- **Time-space tradeoffs.** Removing path bits may force recomputation of history/control in ways that are hard to bound without changing the algorithmic model. `[open]`
