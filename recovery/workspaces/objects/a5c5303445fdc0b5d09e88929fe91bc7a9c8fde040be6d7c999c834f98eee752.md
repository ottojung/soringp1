# Merge-sort framed DAG certificate (n=4)

## Question / front
Independent audit for `merge-sort-framed-dag-n4-check`: construct an explicit permutation-framed strategy DAG certificate for adaptive merge sort on `n=4` per [`docs/research-framed-certificate-frontier.md`](docs/research-framed-certificate-frontier.md) §2 and verify soundness with [`scripts/check_framed_strategy.py`](scripts/check_framed_strategy.py).

## Construction basis (per §2)
- **Model:** deterministic adaptive comparison sorting of 4 distinct labelled elements in slots `0..3`, framed certificate checked by propagated guaranteed strict partial orders with slot permutations and intersection at joins (checker semantics).
- **Merge schedule (binary merge sort):**
  1. Merge pair `(0,1)` (lengths `p=1,q=1`): 1 comparison.
  2. Merge pair `(2,3)` (lengths `p=1,q=1`): 1 comparison.
  3. Merge sorted halves `(slots 0,1)` and `(slots 2,3)` (lengths `p=2,q=2`): at most 3 comparisons.
- **Pair merges (compare-exchange frames):** compare heads `i,j`; `lt (i<j)` keeps identity permutation; `gt (j<i)` applies explicit swap permutation so the post-state guarantees `slot_i < slot_j`. The two outcomes compose into a single completed half (sequential composition into the next query).
- **Top merge states `(a,b)`:** remaining queue lengths with `1 <= a <= p`, `1 <= b <= q`, prefix length `t = 4-a-b`. Invariant: slots `0..t-1` are the output prefix in increasing order; left remainder occupies `t..t+a-1` in original left order; right remainder occupies `t+a..3` in original right order. Query compares left head `i=t` vs right head `j=t+a`.
  - `lt`: winner is left head, permutation identity, transition to `(a-1,b)` at `t+1` (or terminal if `a-1==0`, append right queue with no comparisons).
  - `gt`: winner is right head, explicit full-slot permutation rotates it into position `i` (`old j -> i`, `old k -> k+1` for `k in [i,j)`, others fixed), transition to `(a,b-1)` at `t+1` (or terminal if `b-1==0`).
- **State sharing / DAG joins:** merge states are identified by `(a,b)` (same slot meanings/prefix boundary), so distinct comparison paths may reach the same merge node; shared child `(1,1)` is reached from `(1,2)` and `(2,1)`. Nodes were topologically renumbered to satisfy the checker's forward-edge requirement (`v < next`).
- **Counts sanity (matches §2):** comparison states per merge `pq` give `1 + 1 + 4 = 6` comparison nodes total; path length `1 + 1 + 3 = 5 = S(4)` comparisons.

## Obstruction / confirmation
- No soundness obstruction found. The explicit slot permutations implement the required head-to-prefix moves/rotations; queue-empty completions are terminal leaves; shared merge state `(1,1)` is a valid DAG join under the checker’s incoming-relation intersection because the certified prefix/remainder slot invariant is path-independent.
- Note: this is an `n=4` instance check only. §2 states the all-`n` merge-sort construction remains an independent all-`n` implementation audit pending; this does **not** establish all-`n` completeness or exact optimality.
