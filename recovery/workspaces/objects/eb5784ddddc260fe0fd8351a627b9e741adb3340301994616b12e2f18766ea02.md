### 5. Interaction with `LowerStackPreservedExcept`

**Pass, with a clean separation of concerns.** `LowerStackPreservedExcept(c̄)`
(sym-closure §3.1) preserves `Parent`, frame modes/returns/controls, `HasSel/HasCur`,
`UsedF/SelA/SelB/CurA/CurB/PosF` for live frames `z̄!=c̄`. It does **not**
mention the global relation `Top`. Therefore:
- it cannot by itself establish or clear `Top'` — exactly the source of
  `[SYM-TOP]`;
- it does not conflict with the fix, because the fix supplies explicit global
  `Top'` constraints (`Top'(d̄)`, `¬Top'(c̄)`, `∀z̄(Top'(z̄)->z̄=d̄)`);
- for `z̄!=c̄`, the fix implies `Top'(z̄)` can hold only when `z̄=d̄`; this is
  consistent with the push creating a fresh/non-lower-stack active child and does
  not contradict preserved lower-stack frame contents.

A useful clarification (not a new failure): since `ChildFrameBase` now gives a
global `∀z̄(Top'(z̄)->z̄=d̄)` clause, it is stronger than merely exempting `c̄`.
That is intended and safe: no other frame should become top in a single push
transition.
