## Scope

Audit whether the concrete FO(PFP) encoding is *concrete and sound* for
`SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }` on the ordered word structure
`A(1^n # 1^k)`, focusing on:

- signature, interpretation, domain, configuration relations;
- `Init`, `Acc`, `Mode`, `Yield`, `TC`, and PFP/alternating-acceptance semantics;
- exact remaining obstacles, especially bare-word/no-interpretation arity,
  key/counter sizing, `time <= k`, and malformed cases.

## Summary judgment

The document is a **reasonable schematic FO(PFP) encoding plan**, and its
overall logical route is consistent with the SoringP1 basis:
`G(n,k)` characterizes `S(n) <= k` and the unary ATM/game argument gives
`SORT-BOUND-U ∈ PSPACE` (`research-certificates-barriers.md`, Claim A); on
ordered finite structures FO(PFP) captures PSPACE (literature). Relative to the
earlier formula scheme, it is more concrete: it fixes `σ_w = (<,One,Hash)`,
gives an interpreted key/counter domain, states an incremental FO `TC`/`Step`
formula, and writes explicit `Init/Acc/Mode/Yield_∃/Yield_∀0/1` and `ψ/Φ`
schemas.

However, it is **not yet a fully closed, formally sound FO(PFP) definition**.
The main gaps are not the existence claim but the *formal closure* of the
configuration coding and PFP semantics:

1. The fixed “configuration signature” lists relations (`P,T,A1,A2,M,Q,H`) but the
   PFP is written over a tuple `C=(P,t,a,b,m)` and component access `P_C`,
   without a fixed FO/PFP tuple encoding or a precise declaration of the PFP
   relation variable(s). This is the critical concreteness gap.
2. The PFP semantics argument is too weak/incomplete for soundness as written:
   `ψ` is not justified as a monotone/stratified operator under a precise
   semantics, and the note appeals to capture-theorem simulation without giving
   the actual specialized operator proof.
3. Time/budget bookkeeping is inconsistent (`time/budget used or remaining`,
   `t <= k` vs. suffix counter value, and existential guard `∃s SuccCtr(t,s)`
   with universal `SuccCtr(t,t1)`), so the `time <= k` condition is not yet a
   sound fixed encoding.
4. `WellFormed_w` is only sketched and has an alphabet/quantifier issue in the
   displayed form; malformed inputs and several edge cases (`n<=1`, `k=0`,
   exhausted budget, null pair, total initial state) are not fully discharged.
5. The bare-word/no-interpretation presentation remains schematic: the note
   correctly identifies the `n^2`-bit poset/arity representation issue and uses
   interpretation, but does not produce the final FO interpretation back to
   `A(w)` as explicit formulas with fixed arities.

**Net:** plausible and directionally sound as a capture-theorem instantiation
sketch; **not yet concrete/sound enough to count as an explicit closed FO(PFP)
definition** of `SORT-BOUND-U` on `A(1^n#1^k)`.

## Comparison with the formula scheme

The concrete-encoding note improves on
`fopfp-explicit-formula-sortbound-u.md` in several ways:

- Fixes the word signature explicitly: `σ_w = (<,One,Hash)` (scheme had
  `{<,U_1,U_#}` and discussed structure choices).
- Gives a direct interpreted key/counter domain over positions of `A(w)` rather
  than only an abstract product structure `B(n,k)`.
- Makes `TC`/poset update concrete with the incremental FO formula `Step`,
  justified by maintained transitive closure of `P` — a good, problem-specific
  simplification.
- Expands `Init/Acc/Mode/Yield_∃/Yield_∀0/1` and an alternating acceptance
  operator `ψ`/sentence `Φ_SORTBOUND_U`.

But it inherits and partially sharpens the scheme’s main obstacle: the
configuration/poset-state encoding must be made formally explicit. The scheme
stated that using a PFP relation whose stage variable encodes ATM configurations
as tuples is standard but not fully expanded; the concrete note still does not
close that expansion. The scheme’s warning that a time-stratified attractor is
IFP/LFP-shaped in time but ranges over exponentially many poset codes is more
careful than the concrete note’s PFP paragraph, which should not be read as a
completed soundness proof.

## Component-by-component audit

### 1. Signature

`σ_w = (<,One,Hash)` is a reasonable fixed ordered-word signature. It is
compatible with the task’s `A(1^n # 1^k)` target and is sufficient, in
principle, to FO-define the hash split and prefix/suffix positions.

**Issues:** minor/repairable. The note should fix the exact alphabet semantics:
whether `Hash`-position has `One`, whether suffix uses `One` or an implicit
unary symbol, and whether empty blocks are allowed by format. These choices
affect `WellFormed_w` but do not block the intended model.

### 2. Interpretation and domain

The key domain `Key(x) := ∃h(HashPos(h) ∧ x < h ∧ One(x))` and counter domain
`Ctr(x) := Hash(x) ∨ Suf1(x)` are natural and FO-definable in `A(w)`. This is
an improvement in concreteness over the scheme.

**Issues (important):**

- **Key/counter sizing is not fully tied to the formal PFP state space.** The
  note correctly observes `P ⊆ Key×Key` has `n^2` possible bits and cannot be
  represented as domain elements by fixed arity. It then says “formally this is
  the standard configuration-coding step…” but does not give that coding. Thus
  the interpretation defines *indices* (`Key`, `Ctr`) but not the final
  configuration universe/relations used by `[PFP_{A,C} ψ(A,C)]`.
- **Counter includes hash as zero.** Using `HashPos` as `Zero` is workable only
  if counter successor/order and the intended budget meaning are made consistent.
  As written, `MaxCtr(x)` is the last suffix position, not a representation of
  numeric `k` except by cardinality/order conventions; `Acc` uses
  `CtrLe(t, MaxCtrConst)` but `MaxCtrConst` is undefined.
- **No final interpretation back to `A(w)` is written.** The sentence
  `Φ_SORTBOUND_U` is stated over `A(w)`/interpretation, but the actual
  interpretation formulas (domain formula, equality, order, and translated
  atomic relations for the PFP schema) are missing. For a closed definition on
  `A(1^n#1^k)`, this is required.

### 3. Configuration relations

The intended configuration `C(P,t,a,b,m)` is clear at the game level, but the
formal relation-variable declaration is not.

**Issues (critical concreteness/soundness gap):**

- The text lists `P,T,A1,A2,M,Q,H` with fixed arities, then uses `C=(P,t,a,b,m)`,
  `Init(P,t,a,b,m)`, `Acc(C)`, `P_C`, and `A(P,t,a,b,m)`. These are not the same
  encoding. A fixed FO(PFP) formula must specify exactly which relation
  variables the PFP binds, their arities, and how tuple components are encoded.
- `P` is a 2-ary relation over keys — appropriate. But if `A` in the PFP ranges
  over “configurations”, the note must encode `P` inside that configuration
  coding (standard, but nontrivial) or restructure `ψ` so that the fixed-point
  variable has the right arity/meaning. Writing `A(C)` where `C` contains a
  relation `P` is second-order-looking unless translated into the standard
  first-order-over-configurations coding.
- Null/irrelevant pair `(a,b)` is used (`a=b` in `Init`, “next pair irrelevant”)
  but `Inc(P,a,b)` requires `a != y` and the pair to be incomparable; guards are
  not uniformly specified.

### 4. `TC` / `Step`

This is the strongest concrete part.

`Step(P,a,b;u,v) := Key(u) ∧ Key(v) ∧ (P(u,v) ∨ ((u=a ∨ P(u,a)) ∧ (b=v ∨ P(b,v))))`
is **sound under the stated invariant** that `P` is already a transitive strict
partial order and the added comparison is between currently incomparable keys
(`Inc(P,a,b)`). The path-shortening justification is correct.

**Caveats:**

- The formula should not be used when `a,b` may be null/equal unless guarded.
- It assumes the game updates by transitive closure after each answer — this
  matches the `G(n,k)` definition in SoringP1 docs.
- Full TC as `FO(LFP)` is mentioned appropriately; not needed given the
  incremental invariant.

### 5. `Init`

The intended initial state (empty poset, zero time, sorter mode) matches
`G(n,k)`.

**Issues:**

- `a=b` as a null pair conflicts with key/pair invariants unless a dedicated
  null encoding is added. Better: include an explicit null predicate or omit
  pair relevance in sorter-initial mode.
- `SmallN_Acc` / `n <= 1` handling is only prose. Since `S(0)=S(1)=0`, the
  sentence should accept exactly when the input encodes such `n` and has valid
  unary threshold form with `k >= 0`; this is easy in FO but must be fixed.
- Initial acceptance when the poset is already total (`n<=1`, or any total state)
  should follow from `Acc/Total`.

### 6. `Acc`

Acceptance by reaching `Total(P)` within budget is the right game condition.

**Issues:**

- `CtrLe(t, MaxCtrConst)` is not defined; and budget meaning is ambiguous (see
  §8 on `time <= k`).
- `Acc` allows `ModeAcc ∨ ModeChk ∨ ModeSort ∨ ModeAdv` whenever `Total(P)`.
  That is harmless if such configurations are reachable/terminal, but the
  transition system should make total states sinks to avoid unintended loops or
  semantic dependence on PFP convention.
- A rejected exhausted-budget non-total state should be explicitly non-accepting.

### 7. `Mode`

The finite mode set (`Sort, Adv, Chk, Acc, Rej`) is adequate.

**Issues:** the encoding of modes as fixed tuples/constants is not given.
`ModeSort(C)`/component access is schematic. This is easy to fix but necessary
for a closed formula.

### 8. `Yield_∃` and `Yield_∀0/1`

The alternation shape is right: sorter makes an existential choice of an
incomparable pair; adversary produces two universal outcomes.

**Issues (soundness-relevant):**

- **Budget/time off-by-one and convention mismatch.** `Yield_∃` requires
  `∃s SuccCtr(t,s)` (some budget remains) but does not increment `t`.
  `Yield_∀0/1` requires `SuccCtr(t,t1)` and increments the counter. Thus exactly
  `k` comparisons are possible only if the counter range and guards are chosen
  carefully. The document also says “time/budget used or remaining…” — this must
  be fixed to one convention.
- **Exhausted budget after last move:** `Yield_∀0/1` sets `ModeRej` when
  `¬∃s SuccCtr(t1,s) ∧ ¬Total(P1)`. If `t1` is already the maximum counter
  representing `k` used comparisons, this rejects a state that consumed the
  `k`-th comparison but did not become total — which is correct for `S(n) <= k`.
  But the same guard can misfire if zero/max conventions are off by one.
- **Successor-mode disjunction is too permissive.** `ModeSort(m1) ∨ (Total(P1) ∧
  ModeAcc(m1)) ∨ ... ModeRej(m1)` allows implementations to choose modes not
  determined by the state. For an explicit transition formula, mode should be
  functionally determined where intended, or the semantics should quantify over
  legal moves appropriately. Otherwise `Yield` under-specifies the game graph.
- **Carryover of irrelevant pair fields.** `Key(a1) ∧ Key(b1)` after a universal
  move is arbitrary; better set to a defined null.

### 9. PFP / alternating-acceptance semantics

The intended equation is the standard alternating acceptance/backward-induction
for `G(n,k)`.

**Issues (critical):**

- `[PFP_{A,C} ψ(A,C)]` is not well-formedly specified because `C`/`A`/`P_C` are
  not given fixed arities/encodings. PFP syntax binds a relation variable of
  fixed arity over the structure.
- The note acknowledges `ψ` is “not presented as monotone in an arbitrary
  declaration order” and defers to capture-theorem simulation. That is
  acceptable as a research pointer, but **insufficient as a soundness argument
  for this concrete formula**. A sound audit needs either: (a) a precise PFP
  operator on a precisely coded configuration domain with a proof it computes
  alternating acceptance; or (b) a monotone/stratified IFP/LFP/PFP form with the
  required expressiveness justified without smuggling in exponentially many
  state elements.
- The direct stratified attractor
  `Win_d(P) := Total(P) ∨ (d>0 ∧ ∃a∃b(Inc(P,a,b) ∧ Win_{d-1}(Step(P,a,b)) ∧
  Win_{d-1}(Step(P,b,a))))` is semantically right but, as the earlier scheme
  warns, quantifying/ranging over `P` as arbitrary poset states is not directly
  a first-order fixed point over `N` elements unless configurations are encoded
  by the interpretation. The concrete note mentions this but does not complete
  it.

## Soundness for `SORT-BOUND-U` on `A(1^n # 1^k)`

**Conditional soundness claim:** if the interpretation/configuration coding is
completed with fixed arities, if `WellFormed_w` rejects exactly malformed unary
threshold inputs, if budget counting enforces “at most `k` comparisons”, and if
the PFP operator is given the standard alternating-acceptance semantics over the
encoded game graph, then
`A(w) ⊨ Φ_SORTBOUND_U` iff `S(n) <= k`.

**Current status:** this conditional claim is plausible but **not established by
the document as written**. The game characterization is faithful
(`research-certificates-barriers.md`/problem model context), and `Step` is sound
under its invariant; the remaining risk is in formalization details (PFP
variable/coding, budget off-by-one, malformed/edge cases), not in an obvious
model mismatch with adaptive comparison sorting.

## Exact remaining obstacles

1. **Bare-word / no-interpretation arity (primary formal obstacle).** A closed
   fixed-arity FO(PFP) formula cannot represent the `n^2`-bit poset state as
   individual elements of the `N`-element word universe. The document must
   either (a) give an explicit FO interpretation from `A(w)` to a
   polynomial-size configuration structure and translate the PFP sentence
   through it, or (b) give a standard configuration-coding where the PFP
   relation ranges over fixed-arity tuples coding ATM/game configurations over
   `A(w)`. The current text does (a)/(b) only at prose/schematic level.

2. **Fixed PFP relation declaration and tuple coding.** Specify the exact
   relation variable(s), arities, and whether `P`/mode/time/pair are encoded as
   arguments, separate relations in an interpreted structure, or cells of an ATM
   configuration. Resolve the mismatch between `P,T,A1,A2,M,Q,H` and
   `C=(P,t,a,b,m)`/`A(P,t,a,b,m)`.

3. **Key/counter sizing and counter semantics.** Define `Key` and `Ctr` so that
   keys represent `[n]` and the counter represents exactly comparisons
   `0..k` (or remaining budget `k..0`) with no off-by-one. Replace undefined
   `MaxCtrConst`; make `Zero`, `SuccCtr`, and exhaustion tests correspond to the
   input’s `k` suffix length.

4. **`time <= k` discipline.** Fix one convention: comparisons used so far, or
   comparisons remaining. Make `Yield_∃`, `Yield_∀0/1`, `Acc`, and terminal
   reject/accept conditions mutually consistent. In particular, a total order
   reached after the `k`-th comparison should be accepted; a non-total state
   after `k` comparisons with no budget left should be rejected.

5. **Malformed cases and prelude.** Give a complete `WellFormed_w`: exactly one
   `Hash`, all non-hash positions in the intended alphabet, and the intended
   split into `1^n # 1^k` (including whether `n=0`/`k=0` are represented). State
   rejection/acceptance behavior for malformed words. The displayed
   `∀x ((x < h -> One(x)) ∧ (h < x -> One(x)) ∧ ¬One(h))` should be checked
   against the actual signature semantics.

6. **Edge cases.** Fully specify `n<=1`, `n>=2, k=0`, already total/antichain
   initial state, null pair encoding, and terminal sink behavior. These are
   small but necessary for a sound sentence over all ordered `σ_w`-structures or
   at least over all well-formed `A(w)`.

7. **PFP soundness proof for the concrete operator.** Either prove the concrete
   `ψ` computes alternating acceptance under the chosen PFP semantics on the
   encoded finite game graph, or replace it by the standard ATM-configuration PFP
   simulation specialized to this ATM and prove equivalence to `G(n,k)`. The
   current appeal to FO(PFP)=PSPACE is a justification of existence/plausibility,
   not a completed proof of this formula.

8. **Final sentence on `A(w)`.** Produce the actual FO(PFP) sentence over
   `σ_w` (after interpretation translation), not only `Φ_SORTBOUND_U` containing
   interpreted predicates/modes/configuration components named informally.

## Recommended minimal repair path

1. Fix `WellFormed_w`, `Key`, `Ctr`, and one explicit budget convention.
2. Choose a standard configuration coding (ATM tape/config relation over
   interpreted domain, or fixed game-state relations with explicit arity).
3. Rewrite `Init/Acc/Yield/Step/ψ` using only those fixed relations and FO
   quantification over domain elements/tuples.
4. Give a short soundness lemma chain: `A(w) ⊨ Φ` iff encoded ATM accepts iff
   sorter wins `G(n,k)` iff `S(n)<=k`.
5. Falsification-test the semantic reading against known small `S(n)` values and
   the `time <= k` boundary cases.
