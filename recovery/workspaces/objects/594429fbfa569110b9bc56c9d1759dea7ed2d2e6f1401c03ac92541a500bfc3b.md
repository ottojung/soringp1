# Space separation for exact `SORT-BOUND-U` evaluation (all-n question)

**Status:** research note (paper analysis). Not Lean-checked. Every item
labelled `[definition]`, `[literature]`, `[deduction]`, `[experiment]`,
`[conjecture]` or `[open]`.

Companion program: `scripts/transcript_dfs.py` (the current `O(N log N)`
machine; `space_accounting` for the bit accounting). The question is the
**Space** open item of `research-plan.md` ("can the `O(N log N)` work space be
reduced, for example to `O(N)` or polylogarithmic in `N`?"), in the uniform
unary-input-length encoding.

## Question (falsifiable, all-n) `[definition]`

A uniform deterministic machine `M` with work space `s(N)` bits on the unary
input `w = 1^n#1^k`, `N = n+k+1`, decides exactly the language
`SORT-BOUND-U = {1^n#1^k : S(n) <= k}`. Give `M` with `s(N) = o(N log N)` on
all inputs of length `N` — target `O(N)` or polylog(N) — **or** give the
space-separation lemma below.

**Falsifier / space-separation lemma `[definition, target].** For the family

`A = {1^n#1^{S(n)}}` (so `N = n + S(n) + 1 = Theta(n log n)`),

every uniform machine `M` deciding `SORT-BOUND-U` has, during some accepting
computation of `M` on some `w in A`, a moment where the simultaneously-live
data (work tape in the standard TM space model; input tape is read-only and
not counted) occupies `omega(N log N)` bits. Equivalently: no uniform
evaluation of the language exists in `O(N)` or polylog(N) space.
[A strengthening to `Omega(N log N)` would additionally separate the current
`O(N log N)` bound of `docs/research-budgeted-dfs.md` §5.2.]

## Model, current bound, target `[definition][deduction][literature]`

- `F(P)` = minimax remaining comparisons of the poset game; `S(n) = F(empty)`;
  `CanSort(P,d) = F(P) <= d` [deduction; `docs/research-budgeted-dfs.md`
  §2–3; Lean `S_eq_adv_univ`, `SoringP1/Minimax.lean`:357].
- Information bound: `S(n) >= ceil(log2 n!)` `[literature]` — standard
  adversary potential over the `n!` linear extensions of the empty poset;
  recorded in `docs/research-pruning.md` §4.1; the smallest repo-known gap is
  `S(12) = 30 > 29 = ceil(log2 12!)` (`docs/research-plan.md`).
- Current bound: transcript-only DFS, `docs/research-budgeted-dfs.md` §5.2
  `[deduction]`: `O((d+n) log n)` bits, `d <= U(n) = n * ceil(log2 max(2,n))
  = O(n log n)` → `O(n log^2 n) = O(N log N)` on `A`.
- Sanity `[experiment]`: `python3 scripts/transcript_dfs.py --max-n 5` →
  `S(0..5) = 0,0,1,3,5,7`; `max_edges = S(n)` on the boundary family (the DFS
  path has length `S(n)`).

## Machine attempts ("bucketing with constant-depth workspace")

**(a) Transcript DFS — the current machine `[deduction]`.** The machine
stores the path: a stack of at most `d+1` frames, each an ordered pair
(2 labels of `ceil(log2(n+1))` bits) plus a loop cursor (`ceil(log2 B+1)`
bits, `B = binom(n,2)`). Obstruction: the accepting DFS path on `A` has
length `m >= S(n) = Omega(n log n)` `[experiment: max_edges = S(n)`;
literature: information bound]. At depth `t` the machine queries
`P_t = closure` of the transcript prefix (`is_total`, `incomparable`): each
level's machine decision is one of the `B` incomparable pairs; the "choice
record" of any storage that distinguishes the game's continuations per level
needs `Omega(log n)` bits.

**(b) Poset-as-generating-relation + reachability `[deduction]`.** Same
obstruction: the generating DAG of `P_t` that the machine needs for
reachability queries has size at least the transitive-reduction size of the
closure of the transcript prefix; the adversary can force the transcript
prefix itself to be essential, so the live data is again `Omega(S(n) log n)`.

**(c) Constant-depth workspace `[observation]`.** The game witness tree
(Fact 1 below) has height `S(n)`; a machine that follows the game to
acceptance reaches game depth `S(n)`. Any depth-bounded evaluation that
accepts on `A` must therefore carry, or recompute, depth-`S(n)` state —
recomputation within the same space budget is itself depth-bounded below.

## Obstruction analysis `[deduction][observation]`

**Fact 1 (witness height).** `[deduction]` `CanSort(empty, S(n)) = true` and
`CanSort(empty, S(n)-1) = false` (minimality of `S(n)` = least `k` with
`CanSort(empty,k) = true`; budgeted-dfs §2). The DFS witness tree `T` of the
root acceptance has height `<= S(n)`; a witness tree of height `<= S(n)-1`
would witness `CanSort(empty, S(n)-1) = true`, contradiction; hence
`height(T) = S(n)` exactly.

**Fact 2 (depth is large).** `[literature]` `S(n) >= ceil(log2 n!) =
Omega(n log n)` (Model section).

**Fact 3 (the machine must reach the depth).** `[observation]` To accept on
`w_n`, the machine's accepting computation must justify acceptance by the game
semantics — the witness tree `T` of height `S(n)` exists; for the machines
that verify via the game recursion (the natural class), the accepting path
reaches game depth `S(n)`.

**Key obstruction.** `[analysis]` Combining the facts:

- DFS-style machines (a),(b): live data `Omega(S(n) log n) = Omega(n log^2 n)`
  on the accept family — the `O(N log N)` bound of §5.2 is tight for this
  machine class.
- A general separation requires ruling out clever machines (below).

**Obstruction attack toward the separation `[conjecture]`.** Goal: show no
uniform machine with `s(N) = o(N log N)` accepts on `A`.

Step 1 `[observation]`: the witness path of `T` is the game path
`P_0 = empty, P_1, ..., P_m` with `m = S(n)` and `P_{i+1} = P_i + p_{i+1}`
(`p_{i+1}` the witness pair at depth `i`).

Step 2 `[target, to prove]`: in any accepting computation of any uniform
machine `M` on `w_n`, the machine's live data must at some point be
"functionally equivalent" to `P_t` for the game path at depth `t` — i.e. the
machine cannot hold a compact summary that replaces the depth-`t` state while
still deciding the remaining verification correctly.

Step 3 `[target, to prove]`: from Step 2, summing over a suitable milestone
sequence `0 <= t_1 < ... < t_m` of the accepting computation, the live data
mass is `Omega(S(n) * log n)`-ish; refine to the user's `omega(N log N)` floor
via the winning-frontier family (below).

Both steps are the open core of the separation; the milestone argument needs
a formal notion of "the machine cannot compress the path away" (Step 2) and a
milestone-counting argument (Step 3).

## The linear-extension DP state family `[definition][literature]`

- The repo's linear-extension DP (`docs/upper-bound.md`;
  `docs/research-series-decomposition.md` §1; Lean `adv`, Minimax.lean:83):
  state = poset `P`; `F(P) = adv` over the linear extensions `L(P)`. The
  reachable state family for `F(empty) = S(n)` is the set of labelled posets —
  `A001035(n) = 2^{Theta(n^2)}` `[measured: docs/research-state-compression.md]`.
- The winning-frontier family (`docs/research-winning-frontier-barrier.md`):
  `2^{(1/4 - o(1)) n (log n)^2}` nonisomorphic winning states at depth
  `S(n)` (finite witness: `n = 224`, `> 2^39` winning states at depth 524,
  each sortable within the remaining 907 comparisons).
- Claim-2 reading of the falsifier: a machine that must carry the DP state
  family as live data is stuck in `omega(N log N)`. The obstruction analysis
  shows why *tracking the frontier* is not obviously avoidable: the frontier
  family is the game state family itself. The separation still requires ruling
  out non-DP evaluations (the `[open]` Step 2/3 above).

## Falsifier summary `[deduction]`

- If the separation lemma holds (`Omega(N log N)` or stronger): no machine in
  `O(N)`/polylog exists; the transcript DFS of §5.2 remains the best known
  shape; space-reduction needs new ideas (next obstacles below).
- If a machine exists in `o(N log N)`: it avoids the witness tree entirely;
  the machine-side open question replaces the separation.

## Next obstacle `[open]`

1. **Milestone argument toward the separation.** Formalize Step 2 ("the
   accepting computation must hold, functionally, the depth-`t` game state"),
   and attempt the proof or find a counterexample.
2. **Alternative machine attack.** Characterize `F_k(empty)` (the AND-OR
   formula of `docs/research-budgeted-dfs.md` §2) so it is decidable by a
   small-space mechanism other than the transcript path (e.g. a
   characterization of the accepting set of the game without storing paths);
   experimentally test space-bounded variants on small `n` via a
   space-accounted simulator (cf. `scripts/transcript_dfs.py`'s accounting
   helper).
3. **Weaker separation target.** Prove `s(N) = Omega(S(n))` on `A` — or the
   natural stronger floor `Omega(S(n) log n)` — as a starting separation.
