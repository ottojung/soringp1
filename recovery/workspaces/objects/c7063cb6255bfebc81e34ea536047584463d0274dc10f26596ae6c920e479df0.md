# Space complexity of exact budgeted DFS / evaluation of `S(n)` and `SORT-BOUND-U`

**Scope.** Unary encoding only, per `AGENTS.md`. Input for threshold decision is `w = 1^n # 1^k`, `N = |w| = n+k+1` (`[definition]`, `docs/problem.md`). I address the falsifiable question: can budgeted DFS / exact evaluation of `S(n)` or `SORT-BOUND-U` be performed in `o(N log N)` space (e.g. `O(N)` or polylog `N`) by recomputation/pebbling/stack compression while retaining a provably correct exact algorithm and a stated (subexponential-target) time bound?

All claims are labelled **[definition]**, **[literature]**, **[deduction]**, **[conjecture]**, or **[open]**. No Lean, no PR, no repository-wide edits.

## 1. Claim

**[deduction, conditional on `docs/research-budgeted-dfs.md` §2–5.3] Main claim (negative for known transcript-DFS methods).** For the known exact budgeted-DFS method of `docs/research-budgeted-dfs.md`, the decisive per-call state is the current comparison transcript (a root-to-node path in the minimax game tree) of length `d <= k` comparisons. Representing one comparison as an ordered labelled pair needs `Theta(log n)` bits, so the transcript alone occupies `Theta(d log n)` bits. On the nontrivial decision instances selected by mergesort-clamp preprocessing (`k < U(n) = n*ceil(log2 max(2,n))`, else accept immediately; `[deduction]`, §5.3/§7 of that note), we have `n <= N` and `k <= N`, while `d = k` may be `Theta(N)` and `log n = Theta(log N)` in the regime `n = Theta(N)` (e.g. fixed small `k` is trivial, but more generally instances with `n,k = Theta(N)` exist with `k < U(n)` when `n` is large enough). Hence the path-storage term is `Omega(N log N)` bits in worst-case over valid nontrivial unary instances, and the standard transcript-only DFS is **not** an `o(N log N)`-space algorithm; it is `DSPACE(O(N log(N+2)))` (`[deduction]`, §5.3).

**[deduction] Concrete algorithmic scheme (recomputation of closure, not path).** A provably correct exact variant keeps the same transcript/path and replaces the closure-matrix workspace by on-demand reachability recomputation (BFS/DFS over transcript edges), giving peak space
`S(n,k) = O((k+n) log(n+2)) <= O(N log(N+2))` and time `2^{O(k log(n+2))}*poly(N) <= 2^{O(N log(N+2)))}` for `SORT-BOUND-U`. Using Savitch-style reachability for the subroutine (`[literature]`, Savitch 1970: `st-REACH in DSPACE(log^2 m)` on an `m`-vertex graph) can reduce the *reachability workspace* term from `O(n log n)` to `O(log^2 n)` bits but, with the standard simulation, increases per-query time to `n^{O(log n)} = 2^{O(log^2 n)}` and **does not** remove the `O(k log n)` transcript/path term. Therefore this recomputation/space-compression of the reachability component does **not** achieve `o(N log N)` total space while preserving the same subexponential-time accounting except in regimes where `k log n = o(N log N)` already (not all-`n`, all-`k`).

**[open/conjecture] Sub-`N log N` exact evaluation.** I do not obtain a concrete all-instance algorithm achieving `o(N log N)` space and stated subexponential time for `SORT-BOUND-U` or for exact evaluation of `S(n)` by recomputation/pebbling/stack compression of known methods. I also do not obtain an unconditional lower bound separating `SORT-BOUND-U` from `o(N log N)` space (that would be a strong uniform space lower bound). The obstruction below is method-specific/information-theoretic for path-storing game-tree DFS, not a proof that no other exact algorithm exists.

## 2. Correctness sketch

**[definition/literature/deduction] Budgeted DFS game.** States are transitively closed strict partial orders on `[n]`; start at antichain. Sorter picks an incomparable pair, adversary answers one orientation, state becomes transitive closure. `S(n) <= k` iff sorter wins within `k` comparisons (`[deduction]`, minimax recurrence, `docs/upper-bound.md`, `docs/research-budgeted-dfs.md` §1–3; kernel correspondence `S_eq_adv_univ` noted in repo docs, `[literature/kernel-checked in project]`).

**[deduction] Scheme A (baseline transcript DFS, §5.2–5.3 of budgeted note).**
- Invariant: stack holds exactly current transcript `sigma = ((a_1,b_1),..., (a_t,b_t))`, `t <= d`, and cursor state needed to resume pair enumeration.
- `P(sigma)` is the poset induced by `sigma` (acyclic because only incomparable pairs are compared). Comparability `x <_{P(sigma)} y` iff `y` reachable from `x` in digraph `([n],sigma)`; tested by graph search recomputed from `sigma`.
- Totality/incomparability predicates computed from reachability are identical to those from explicit transitive closure, so recursive correctness follows by induction on remaining budget `d-t`: base `d-t==0` returns total?true:false; step returns OR over incomparable pairs of AND over both adversary answers on `sigma` extended by that answer.
- Backtracking: pop last comparison restores parent transcript exactly. No child state retained. Therefore decision result equals `CanSort(empty,d)`.

**[deduction] Scheme B (Savitch-compressed reachability workspace).** Replace each BFS/DFS reachability query in Scheme A by a deterministic recursive midpoint-path (Savitch) test on the implicit graph with edges from `sigma`. Correctness of reachability is unchanged (`[literature]` Savitch), hence the minimax decision value is unchanged. Space becomes `O(d log n + log^2 n)` but time per reachability query becomes `n^{O(log n)}` in the standard analysis.

**[deduction] Scheme C (recompute poset/closure by replay, not saving matrices).** A frame may store only `(a_i,b_i)` and recompute needed comparability from prefix `sigma_1..i` when accessed. This is the same object as Scheme A phrased as recomputation/pebbling of closure values from the path: it saves `n^2` matrix bits per frame but cannot discard the path itself without losing the current game node. Correctness identical to Scheme A.

## 3. Space/time analysis

Let `B = C(n,2)`, budget/depth `d=k` for `SORT-BOUND-U` after clamp, and `N=n+k+1`.

| Scheme | Exact? | Space (bits) | Time | Notes |
|---|---|---:|---:|---|
| Memoized poset DP (`docs/upper-bound.md`) | yes `[deduction]` | `2^{Theta(n^2)}` states | `2^{O(n^2)}*poly(n)` numeric | not path-storing; huge space. |
| Transcript DFS + matrix/frame (naive) `[deduction]` | yes | `O(d*n^2)` | `2^{O(d log n)}*poly(n)` | recompute not needed but bad space. |
| Transcript DFS + reachability recomputation (Scheme A) `[deduction]` | yes | `O((d+n)log(n+2)) <= O(N log(N+2))` | `2^{O(d log n)}*poly(n) <= 2^{O(N log(N+2))}` | current stated unary decision bound. |
| Scheme A + Savitch reachability (Scheme B) `[literature]+[deduction]` | yes | `O(d log n + log^2 n) <= O(N log(N+2))` | `2^{O(d log n + log^2 n)}*poly(N) <= 2^{O(N log(N+2))}` | shrinks workspace term only; path dominates. |
| Hypothetical transcript compression/pebbling to `o(d log n)` `[open]` | unknown | target `o(N log N)` | must retain correctness and stated time | no concrete scheme found; see obstruction. |

**[deduction] Why reachability recomputation helps only partially.** The peak has two additive components: transcript/path `P_path = O(d log n)` and one live workspace `P_ws`. BFS/DFS gives `P_ws=O(n log n)`; Savitch gives `P_ws=O(log^2 n)` at quasi-polynomial query overhead. Total is `P_path + P_ws`; reducing `P_ws` below `P_path` does not change asymptotic total when `P_path` dominates (e.g. `d = Theta(n log n)`, `n=Theta(N/log N)` impossible together with `N=n+d+1` except special cases, but directly `d=Theta(N), n=Theta(N)` gives both terms `Theta(N log N)`; `d=Theta(N), n=o(N)` gives path-dominated `Theta(N log n)` and still not `o(N log N)` unless `log n=o(log N)` which conflicts with nontrivial large `n`). A uniform all-instance `o(N log N)` result would require `P_path = o(N log N)`.

## 4. Falsification / limits

**[deduction] Information-theoretic/path-description obstruction for path-storing DFS.** At each of the `t` levels on the current branch the algorithm has selected (i) a sorter move: one incomparable pair among up to `B_t <= C(n,2) < n^2` possibilities, and (ii) observed an adversary answer in `{<,>}` (for the AND test it must be able to resume/consider both over time, but the current recursive position when exploring a child is a specific answer branch). To resume after returning from a child, a standard DFS frame must remember at least which pair/cursor position and which adversary branch has been completed: this is `Omega(log B_t + 1)=Omega(log n)` bits per level in worst case when many pairs remain incomparable. Over a path of length `d`, any method that explicitly stores the current root-to-node control path therefore needs `Omega(d log n)` bits in the worst case. This lower bound is **for the method class "store/resume the explicit move path"**, not for all possible exact algorithms for `SORT-BOUND-U`.

**[deduction] Why naive pebbling/recomputation of the transcript does not apply.** Classical time-space pebbling/recomputation arguments trade repeated evaluation for less stored intermediate values when values are recomputable from fixed inputs. Here the transcript prefix is not a recomputable intermediate of a fixed-size circuit from `(n,k)` alone; it encodes dynamic choices/results encountered along the current search branch (including adversary answers being tested). To be at node `v` the algorithm must know `v` or an equivalent description; discarding and "recomputing" `v` from scratch would require knowing which branch to recompute, which is the same information.

**[deduction] Stack compression limits (method).** Generic stack-compression of deterministic straight-line call stacks (save checkpoints and replay) trades space for time multiplicatively/exponentially in depth unless the computation has special reversibility/structure. Budgeted DFS has branching factor `Theta(n^2)` and depth `d`, with a game-theoretic AND/OR dependence; a replay-to-checkpoint strategy that discards `r` transcript symbols would, in general, force recomputation of up to `(2B)^r`-scale subsearches to regenerate state/position, destroying the subexponential `2^{O(d log n)}` time accounting. No structure theorem in provided docs justifies a lossless compressed representation of arbitrary reachable transcripts below `Theta(d log n)` bits.

**[open] Possible escape routes not ruled out (but not constructed).** (a) A non-DFS exact algorithm (not following/storing one transcript path) with smaller workspace. (b) A succinct canonical encoding of reachable posets/transcripts using symmetry, decomposition, or game structure proved complete for the exact minimax value. (c) A different complete certificate/search representation whose verifier/search state is `o(N log N)`. None is supplied by the cited notes; `research-winning-frontier-barrier.md` and plan state that avoiding frontier/transcript enumeration would need new structure.

**[definition] Subexponential target.** Interpreted as time `2^{N^{1-c}}*poly(N)` or at least `2^{o(N log N)}` / existing `2^{O(N log N)}`-type bounds depending on context; the report states bounds explicitly per scheme. Any proposal below `O(N log N)` space must be checked against this time target; Scheme B keeps the same exponential-in-`N log N` form but worsens polynomial-in-exponent factors.

## 5. Consequence

**[deduction] For the central question.** The existing transcript-only budgeted DFS already places `SORT-BOUND-U` in `DSPACE(O(N log(N+2))) ∩ DTIME(2^{O(N log(N+2))})` (`§5.3`), polynomial space and subexponential-in-`N log N` time. A genuine improvement to `o(N log N)` space *with* a stated subexponential exact time bound would sharpen the uniform space upper bound for exact evaluation of `SORT-BOUND-U` beyond the known path-storage accounting and would likely require new structural control over reachable game states/transcripts (not mere closure recomputation or reachability-workspace compression). Conversely, establishing that every correct exact method in a natural class needs `Omega(N log N)` bits would be a barrier/structural result, but only a method-specific barrier follows from this report.

**[deduction] No complexity-class separation.** None of the schemes or obstructions here implies `P!=PSPACE`, `NP!=PSPACE`, membership/separation for NP/coNP, or any unconditional super-polynomial lower bound for `SORT-BOUND-U`; such conclusions are outside scope per `AGENTS.md`/`docs/problem.md`.
