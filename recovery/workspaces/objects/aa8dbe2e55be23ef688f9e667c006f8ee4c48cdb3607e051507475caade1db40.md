# Exec report #301 — certificate join compression (all-n test)

**Front:** "certificate join compression all-n test" (billy-dev)
**Date:** 2026-11-17
**Deliverable:** `exec-report.md` (this file). No other repository changes.

## 1. Question (all n, falsifiable)

Can the known `O(n²)` Ford–Johnson framed certificate construction be
compressed to `O(n)` nodes for large `n` by replacing its fixed merge
schedule with a single join that merges all pending insertion leaves at
once (a "multi-way join"), while preserving exact optimal height `S(n)`?

A positive answer would give a polynomial-size (indeed linear-size)
framed certificate at height `S(n)` for all `n`, hence
`SORT-BOUND-U ∈ NP`. A negative answer must identify a concrete
obstruction.

**Consequence tested:** whether linear-node framed certificates can exist at
all at height `S(n)`.

## 2. Evidence labels

- `[definition]` Framed certificate grammar and checker:
  `scripts/check_framed_strategy.py`. Each node is either a leaf or one
  binary comparison `compare: [a,b]` with two outcomes (`lt`, `gt`); each
  outcome carries a forward edge and a permutation frame. A node may be the
  target of several incoming edges; its guaranteed relation is the
  intersection of the incoming feasible relations (the "join").
- `[definition]` `S(n)` = minimum worst-case number of adaptive pairwise
  comparisons to sort `n` distinct labelled keys
  (`docs/problem.md`). Information bound:
  `ceil(log₂ n!) ≤ S(n)`. Upper bound: `S(n) ≤ O(n log n)` (merge sort).
- `[deduction]` In any acyclic framed DAG, a root-to-leaf path cannot
  contain the same node twice (nodes are topologically ordered and edges go
  forward). Every internal node contributes exactly one comparison, so the
  height of any path is at most the number of internal nodes, hence at most
  the total node count `V`.
- `[experiment]` Small checker runs below.

## 3. Construction attempt and verification

### 3.1 Proposed compression

Idea: keep one comparison node per "stage" and let a single join merge all
pending insertion leaves simultaneously, instead of expanding each binary
search over ranks into `O(n)` query nodes. This would reduce node count
from `O(n²)` to `O(n)`.

### 3.2 Obstruction: node count vs. height (decisive)

The checker's depth is the longest path in the DAG. Because the DAG is
acyclic, any path uses distinct nodes, so

```
height(DAG) ≤ (# internal nodes) ≤ V.
```

Therefore a certificate with `V = O(n)` nodes has height `O(n)`.

But sorting requires

```
S(n) ≥ ceil(log₂ n!) = Θ(n log n),
```

and `S(n) ≤ O(n log n)`, so `S(n) = Θ(n log n)`. For every sufficiently
large `n`,

```
ceil(log₂ n!) > C n
```

for any fixed constant `C`. Hence no framed DAG with `O(n)` nodes can have
height `S(n)`: its height would be at most `O(n) < Θ(n log n) = S(n)`.

Equivalently, by the leaf-count bound: unfolding a binary DAG with `V`
internal nodes yields at most `2^V` leaves; a correct sorter needs at least
`n!` leaves, so `V ≥ log₂(n!) = Θ(n log n)`. This is independent of the
join semantics and of whether the join is "multi-way": a join merges
incoming relations but does not add outgoing branches; each node still has
at most two outcomes.

### 3.3 Experimental check (checker)

A direct attempt with `O(n)` nodes cannot sort: for `n = 4`, `S(4) = 5`,
but a 4-node DAG has height at most 3; for `n = 5`, `S(5) = 7` but a
5-node DAG has height at most 4. A minimal chain certificate was run
through the checker:

```
n=4: REJECT: leaf 3 does not sort 0,1
n=5: REJECT: leaf 4 does not sort 0,1
```

(script: `scripts/check_framed_strategy.py`, 4/5 nodes, identity frames).

The information-theoretic table:

| n | S(n) | ceil(log₂ n!) | max height with n nodes |
|---|------|---------------|--------------------------|
| 4 | 5    | 5             | 3                        |
| 5 | 7    | 7             | 4                        |
| 8 | 16   | 16            | 7                        |
| 12| 30   | 29            | 11                       |

For `n ≥ 4`, `ceil(log₂ n!) > n`, so even `n` nodes are insufficient;
asymptotically `ceil(log₂ n!) / n → ∞`.

## 4. Conclusion

**Obstruction identified:** a height/leaf-count (information-theoretic)
obstruction, not merely a forgetting-cost or soundness issue. Any framed
certificate at height `S(n)` requires `Ω(n log n)` nodes, because (a)
height `S(n) = Θ(n log n)` and height ≤ node count in an acyclic DAG, and
(b) `n!` leaves require `≥ log₂(n!)` nodes. Therefore compression to
`O(n)` nodes is impossible, with or without a multi-way join. The
multi-way join idea cannot bypass the binary branching count of pairwise
comparisons.

The `O(n²)` Ford–Johnson construction remains the best known framed
certificate size; reducing it further is bounded below by `Ω(n log n)`,
and whether `O(n log n)` (or any sub-quadratic) framed certificates exist
at height `S(n)` is left open.

## 5. Limits

- This report does not construct an `O(n log n)`-node certificate; it only
  rules out `O(n)`.
- It does not address join soundness or forgetting cost of specific
  multi-way proposals; those are moot once the node-count lower bound
  applies.
- It relies on the standard bounds `ceil(log₂ n!) ≤ S(n) ≤ O(n log n)`,
  not on exact values of `S(n)` for `n ≥ 23`.
