## 0. Verdict

`[literature,deduction]` **Known in principle:** `SORT-BOUND-U ∈ PSPACE` (Claim A, `research-certificates-barriers.md`; alternating game `G(n,k)` in `ATIME(poly(N))`, Chandra–Kozen–Stockmeyer 1981) and FO(PFP) captures PSPACE on ordered finite structures (Abiteboul–Vianu; Vardi). Therefore an FO(PFP) definition of `SORT-BOUND-U` on the ordered word structure exists in principle.

`[deduction]` **Unified explicit layer achieved here:** the ordered-word interpretation, malformed handling, key/counter sizing, budget discipline `<=k`, finite mode tags, control tuple, all transition predicates (`StepPos`, `Init`, `Acc`, `YieldE`, `YieldA0/A1`), and the alternating acceptance shape are given as one non-superseded fixed schema. `TimeOf/AOf/BOf/ModeOf` are expanded as explicit first-order accessors on a fixed tuple; `EncodesElt` is explicit by direct component equality/projection.

`[deduction]` **Precise remaining blocker (not resolved):** `PosOf`/`P_C` cannot be made an FO decoding from a fixed-arity configuration code `d̄ ∈ W^r` over the `|W|=N`-element word domain while representing arbitrary game states, because `G(n,k)` has up to `2^{\Theta(n^2)}` poset states and `N=n+k+1`. Consequently the natural acceptance formula
```text
ψ(AC,d̄) uses P_C(d̄,·,·) decoded from d̄
```
is not a closed fixed-tuple coding over `W` as stated. If instead `P_C` is supplied as an external/state relation independent of `AC`, then `ψ` is positive in `AC` but no longer defines acceptance of arbitrary encoded poset states by a single fixed PFP over `W^r`. A complete closure therefore requires one of: (i) an explicit simultaneous PFP over configuration-plus-cell relations on an FO-interpreted structure in the standard PSPACE-capture normal form, carried out concretely for `G(n,k)`; (ii) an explicit interpreted configuration domain whose elements represent the exponentially many states (not polynomial over `W$ alone); or (iii) a different explicit fixed-arity finite-model encoding proved equivalent to the ATM simulation. This note does **not** claim that (i)--(iii) has been fully expanded.

No smaller complexity class for `SORT-BOUND-U` is claimed. In particular, positivity/stratification of the game operator does **not** imply `SORT-BOUND-U ∈ P`, FO(LFP) on the bare word, or NP/coNP membership.

## 1. Fixed problem facts

`[definition]` `SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`, input length `N=n+k+1` (`docs/problem.md`).

`[definition]` `S(n)` is the minimax height of a deterministic adaptive comparison decision tree that sorts every permutation of `n` distinct labelled keys. `S(n) <= k` iff the sorter wins the alternating comparison game `G(n,k)` from the empty partial order within budget `k`.

`[literature,deduction]` `SORT-BOUND-U ∈ PSPACE` by the ATM/game formulation of `G(n,k)` (`research-certificates-barriers.md`, Claim A). `SORT-BOUND-U` is sparse and not many-one NP-hard unless `P=NP` (Mahaney barrier, same note); this is a barrier, not membership in P/NP.

## 2. Ordered word structure and malformed handling

`[definition]` Signature `σ_w = (<, One, Hash)` where `<` is a binary linear order and `One,Hash` are unary.

For intended `w=1^n#1^k$, let
```text
A(w) = (W,<^W,One^W,Hash^W),  W={1,...,N}, N=n+k+1,
Hash^W={n+1},  One^W=W \ {n+1}.
```
Equivalent alphabet conventions are FO-interdefinable after adjusting `WellFormed_w`.

`[definition]` FO word predicates:
```text
HashPos(h)      := Hash(h) ∧ ∀z(Hash(z) -> z=h).
ExactlyOneHash  := ∃h HashPos(h).
Prefix(x,h)     := x < h.
Suffix(x,h)     := h < x.
WellFormed_w    := ExactlyOneHash ∧ ∀h(HashPos(h) -> ∀x(One(x) <-> x!=h)).
Malformed       := ¬WellFormed_w.
```

`[definition]` Final sentence form:
```text
Φ_SORTU := WellFormed_w ∧ Φ_game.
```
Malformed `σ_w$-strings/structures are rejected; membership in `SORT-BOUND-U` is defined only for well-formed unary encodings.

## 3. Explicit key/counter sizing

Assume `WellFormed_w$ and let `h$ be the unique hash.

`[definition]`
```text
Key(x)      := ∃h(HashPos(h) ∧ x < h).
Ctr(t)      := ∃h(HashPos(h) ∧ (t=h ∨ h < t)).
Zero(t)     := HashPos(t).
MaxK(t)     := Ctr(t) ∧ ¬∃s(Ctr(s) ∧ t < s).
SuccCtr(t,s):= Ctr(t) ∧ Ctr(s) ∧ t < s ∧ ¬∃z(Ctr(z) ∧ t < z ∧ z < s).
CtrLe(t,s)  := Ctr(t) ∧ Ctr(s) ∧ (t=s ∨ t < s).
```

`[deduction]` Sizing: `|Key|=n`, `|Ctr|=1+k`, `|W|=N=n+k+1`. `Zero$ represents 0 comparisons used; every `Ctr$ value represents a number of comparisons used in `{0,...,k}` by its position in the `Ctr$ order. `MaxK$ represents `k` comparisons used.

## 4. Unified control tuple and explicit component access

This construction uses one fixed control/configuration-code tuple
```text
d̄ = (d_t, d_a, d_b, d_m1, d_m2, d_m3) ∈ W^6.
```
It contains all control components. The poset component is **not** claimed to be decodable from `d̄$ alone; see §7.

### 4.1 Finite mode encoding (`ModeOf` expanded)

`[definition]` Use three boolean mode bits in the tuple (six mode patterns available; five used):
```text
MS, MA, MChk, MAcc, MRej ⊆ {0,1}? -- implemented by formulas over d_m1,d_m2,d_m3
```
Let `BitTrue(x)$ be any fixed FO-definable nontrivial predicate on a distinguished value? No: `W$ has no constants in the signature except through FO definitions. Use the order-relative encoding
```text
IsMin(x) := ∀y (x=y ∨ x<y).
NotMin(x):= ¬IsMin(x).
```
Define mode tags by a fixed finite table:
```text
ModeOf(d̄,MS)  := NotMin(d_m1) ∧ IsMin(d_m2) ∧ IsMin(d_m3).
ModeOf(d̄,MA)  := IsMin(d_m1) ∧ NotMin(d_m2) ∧ IsMin(d_m3).
ModeOf(d̄,MChk):= IsMin(d_m1) ∧ IsMin(d_m2) ∧ NotMin(d_m3).
ModeOf(d̄,MAcc):= NotMin(d_m1) ∧ NotMin(d_m2) ∧ IsMin(d_m3).
ModeOf(d̄,MRej):= NotMin(d_m1) ∧ IsMin(d_m2) ∧ NotMin(d_m3).
ExactlyOneMode(d̄):= ModeOf(d̄,MS)∨ModeOf(d̄,MA)∨ModeOf(d̄,MChk)∨ModeOf(d̄,MAcc)∨ModeOf(d̄,MRej)
                   and pairwise exclusion follows from the table.
```
(Any fixed finite partition by FO formulas is acceptable; this one avoids dependence on `N>=k$ except existence of min/non-min. If `|W|=1$, handle as a degenerate well-formed/malformed edge case by `WellFormed_w$ and key/counter cardinality; `N>=2$ for the intended `1^0#1^0$ encoding.)

### 4.2 `TimeOf/AOf/BOf` expanded (`EncodesElt` explicit)

`[definition]` Direct component access (the explicit form of `EncodesElt$ is equality/projection):
```text
EncodesElt_W(d_i,x) := x = d_i.
TimeOf(d̄,t)         := EncodesElt_W(d_t,t) ∧ Ctr(t).
AOf(d̄,a)            := EncodesElt_W(d_a,a) ∧ Key(a).
BOf(d̄,b)            := EncodesElt_W(d_b,b) ∧ Key(b).
```
Thus `t_C(d̄,t):=TimeOf(d̄,t)$, `a_C(d̄,a):=AOf(d̄,a)$, `b_C(d̄,b):=BOf(d̄,b)$, `m_C(d̄,μ):=ModeOf(d̄,μ)$ are fully explicit FO formulas.

### 4.3 `PosOf` / `P_C`: explicit status

`[definition]` The intended decoded poset component is
```text
P_C(d̄,u,v) := Key(u) ∧ Key(v) ∧ PosOf(d̄,u,v).
```
**No superseded sketch:** this note does not claim an explicit `PosOf(d̄,u,v)$ from `d̄∈W^6$ alone for arbitrary `G(n,k)$ states. The precise dependency is stated in §7.

## 5. Decoded transition predicates (fully explicit given `P_C/t_C/a_C/b_C/m_C`)

The formulas below are the unified game logic. They are FO over `σ_w$ plus the component predicates listed as parameters.

`[definition]` Poset/order predicates:
```text
Inc_C(d̄,x,y)   := Key(x)∧Key(y)∧x!=y ∧ ¬P_C(d̄,x,y) ∧ ¬P_C(d̄,y,x).
Total_C(d̄)      := ∀x∀y ((Key(x)∧Key(y)∧x!=y) -> (P_C(d̄,x,y) ∨ P_C(d̄,y,x))).
PValid_C(d̄)    := (∀x ¬P_C(d̄,x,x))
                 ∧ (∀x∀y∀z ((P_C(d̄,x,y)∧P_C(d̄,y,z)) -> P_C(d̄,x,z)))
                 ∧ (∀x∀y (P_C(d̄,x,y) -> (Key(x)∧Key(y)))).
```

`[definition]` Incremental transitive-closure step. For a selected answer adding `a<b$ (with `Inc_C(d̄,a,b)$ and `PValid_C(d̄)$), the updated closure is
```text
StepPos(d̄,a,b; u,v) :=
    P_C(d̄,u,v)
  ∨ ((u=a ∨ P_C(d̄,u,a)) ∧ (b=v ∨ P_C(d̄,b,v))).
```
`[deduction]` This is the standard FO incremental TC update for adding one incomparable edge to a transitively closed strict partial order.

`[definition]` Control/state helpers:
```text
SameTime(d̄,ē) := ∀t (TimeOf(d̄,t) <-> TimeOf(ē,t)).
NullPair(ē)   := ∃z (IsMin(z)∧Key(z)∧AOf(ē,z)∧BOf(ē,z)).
HasBudget(d̄)   := ∃t∃s (TimeOf(d̄,t) ∧ SuccCtr(t,s)).
```
`NullPair$ is an inert placeholder used only when the pair is semantically irrelevant. It is never used to satisfy `Inc_C$.

`[definition]` Initial/accepting/mode conditions:
```text
Init(d̄) :=
    (∀u∀v ¬P_C(d̄,u,v))
  ∧ ∃t (TimeOf(d̄,t) ∧ Zero(t))
  ∧ ModeOf(d̄,MS)
  ∧ NullPair(d̄)
  ∧ (¬∃x∃y (Key(x)∧Key(y)∧x!=y) -> Total_C(d̄)).

Acc(d̄) := Total_C(d̄).
```

`[definition]` Existential sorter yield:
```text
YieldE(d̄,ē) :=
    ModeOf(d̄,MS) ∧ ¬Total_C(d̄) ∧ HasBudget(d̄)
  ∧ ∃a∃b (AOf(ē,a) ∧ BOf(ē,b) ∧ Inc_C(d̄,a,b))
  ∧ SameTime(d̄,ē)
  ∧ ModeOf(ē,MA)
  ∧ SamePoset(d̄,ē).
```
`SamePoset(d̄,ē) := ∀u∀v (P_C(d̄,u,v) <-> P_C(ē,u,v))$ is explicit given `P_C$.

`[definition]` Universal adversary yields (two outcomes of the selected pair):
```text
AdvanceTime(d̄,ē) := ∃t∃s (TimeOf(d̄,t) ∧ SuccCtr(t,s) ∧ TimeOf(ē,s)).

ModeAfterAdvance(ē) :=
    (Total_C(ē) ∧ ModeOf(ē,MAcc))
  ∨ (¬Total_C(ē) ∧ HasBudget(ē) ∧ ModeOf(ē,MS))
  ∨ (¬Total_C(ē) ∧ ∃t(TimeOf(ē,t)∧MaxK(t)) ∧ ModeOf(ē,MRej)).

YieldA0(d̄,ē) :=   -- outcome a < b
    ModeOf(d̄,MA)
  ∧ ∃a∃b (AOf(d̄,a) ∧ BOf(d̄,b) ∧ Inc_C(d̄,a,b))
  ∧ AdvanceTime(d̄,ē)
  ∧ (∀u∀v (P_C(ē,u,v) <-> StepPos(d̄,a,b;u,v)))
  ∧ NullPair(ē)
  ∧ ModeAfterAdvance(ē).

YieldA1(d̄,ē) :=   -- outcome b < a
    ModeOf(d̄,MA)
  ∧ ∃a∃b (AOf(d̄,a) ∧ BOf(d̄,b) ∧ Inc_C(d̄,a,b))
  ∧ AdvanceTime(d̄,ē)
  ∧ (∀u∀v (P_C(ē,u,v) <-> StepPos(d̄,b,a;u,v)))
  ∧ NullPair(ē)
  ∧ ModeAfterAdvance(ē).
```

## 6. Budget/time `<=k` discipline

`[deduction]` `TimeOf(d̄,t)$ means `t$ comparisons have been used, `t∈Ctr={0,...,k}$.
- `Init$ sets `Zero(t)$.
- `YieldE$ requires `HasBudget(d̄)$, so a sorter move is possible only when `t <= k-1`.
- `YieldA0/A1$ require `AdvanceTime$, so they consume exactly one comparison and set `s=t+1 <= k`.
- Any total state reached by `Init$ or by `YieldA0/A1$ is within budget.
- A non-total state after consuming the `k$-th comparison (`MaxK$) becomes `MRej`.
Therefore the construction enforces worst-case comparison depth `<=k$ and does not need a separate global conjunct beyond the transition invariant.

Edge cases `[falsification target]`: `n<=1$ accepts if total initially; `k=0$ permits acceptance only for already total states; becoming total exactly on the `k$-th comparison must take the `MAcc$ disjunct of `ModeAfterAdvance$.

## 7. `AC`/`P_C` decoding dependency and monotonicity (explicit)

The proposed acceptance operator is
```text
ψ(AC,d̄) :=
    Acc(d̄)
  ∨ (ModeOf(d̄,MS)  ∧ ∃ē (YieldE(d̄,ē)  ∧ AC(ē)))
  ∨ (ModeOf(d̄,MA)  ∧ ∃ē1∃ē2 (YieldA0(d̄,ē1) ∧ YieldA1(d̄,ē2) ∧ AC(ē1) ∧ AC(ē2)))
  ∨  ModeOf(d̄,MAcc).
```

`[deduction]` **Syntactic positivity:** `AC$ occurs only positively in `ψ$.

`[deduction]` **Semantic monotonicity condition:** the operator `F(X)=\{d̄\mid (A(w),X)\models ψ(AC,d̄)\}$ is monotone in `X$ **if** every predicate used inside `ψ$ except `AC$ is interpreted independently of `X$ (i.e., by fixed FO formulas/relations over `A(w)$ and fixed component access). In particular, `P_C/PosOf$ must not depend on `AC$.

This makes the dependency explicit:
```text
ψ monotone in AC  <=  P_C, t_C, a_C, b_C, m_C, Yield*, Acc do not mention AC.
```

### 7.1 Why the naive fixed-tuple decoding is blocked

`[deduction]` Suppose one tries to close the construction by setting
```text
P_C(d̄,u,v) := PosOf(d̄,u,v),   d̄ ∈ W^6,  |W|=N=n+k+1,
```
with `PosOf$ FO on `A(w)$ and intended to range over all relevant game states. A single control code `d̄$ has only `N^6$ possible values, but the game state includes an arbitrary transitively closed partial order on `n$ keys: in general there are `2^{\Theta(n^2)}$ labelled posets/states relevant to the minimax semantics (cf. A001035/poset DP state space). For large `n$ relative to fixed arity, `N^6 \ll 2^{\Theta(n^2)}$. Therefore no such `PosOf$ can represent all poset states needed by the full acceptance computation. This is the concrete fixed-tuple closure gap.

A variant that stores poset bits in additional tuple positions fails for the same reason: fixed arity gives `N^r$ codes, still polynomial in `N$.

### 7.2 Consequence

- The control formulas in §4--§6 are explicit and reusable.
- The operator in this section is positive in `AC$, but **not yet grounded** by an explicit `PosOf$ that makes `d̄$ a complete configuration over `W^r$.
- Therefore this document provides an explicit **decoded transition proof schema conditional on `P_C$**, and a precise blocker for the missing `PosOf$-as-configuration-content decoding.

## 8. Exact PFP/IFP/LFP form (no overclaim)

`[definition]` **PFP form (target capture-theoretic form).**
```text
Φ_game := ∃d̄ (Init(d̄) ∧ [PFP_{AC,\bar d} ψ(AC,\bar d)](d̄)).
Φ_SORTU := WellFormed_w ∧ Φ_game.
```
This is the correct syntactic form to invoke FO(PFP)=PSPACE on ordered structures, but only after supplying a complete, explicit configuration encoding and proof that the PFP over that encoding computes `G(n,k)$ acceptance.

`[definition]` **IFP/LFP form (game-operator form, conditional).** Because `ψ$ is syntactically positive in `AC$, whenever a complete finite game/configuration structure `(D, Acc, YieldE, YieldA0, YieldA1)$ is fixed with those relations independent of `AC$, the acceptance operator has a least fixed point:
```text
Win := [LFP_{AC,\bar d} ψ(AC,\bar d)]  (equivalently IFP for positive FO).
```
On a finite acyclic/stratified game this LFP/IFP stabilizes in finitely many stages (here `<= 2k+2$ on reachable control ranks, since every adversary outcome consumes one comparison).

`[deduction]` **No overclaim.** LFP/IFP of this positive game operator does not imply `SORT-BOUND-U ∈ FO(LFP)$ on the bare ordered word, does not imply `P$, and does not imply NP/coNP membership. The obstacle is exactly the representation of the exponentially many poset states and/or the full PSPACE configuration simulation. The only class consequence used here is the established one: `SORT-BOUND-U ∈ PSPACE` `[literature,deduction]`; FO(PFP)-definability follows in principle from capture theorems, not from the incomplete fixed-tuple `PosOf$ decoding.

## 9. Unified construction summary (no superseded sketches)

1. Input structure: ordered word `A(w)$, reject unless `WellFormed_w$.
2. FO parameters: `Key, Ctr, Zero, MaxK, SuccCtr$ with explicit sizes `n,1+k$.
3. Control code: `d̄=(d_t,d_a,d_b,d_m1,d_m2,d_m3)\in W^6$.
4. Explicit accessors: `TimeOf=d_t$, `AOf=d_a$, `BOf=d_b$, `ModeOf$ by fixed 3-bit table.
5. Poset interface: `P_C(d̄,u,v)$ required; not decoded from `d̄$ alone (blocker).
6. Explicit transitions: `Inc_C, Total_C, StepPos, Init, Acc, YieldE, YieldA0, YieldA1$ with budget `<=k$.
7. Acceptance: positive alternating `ψ(AC,d̄)$; monotone in `AC$ only when `P_C$ and transitions are `AC$-independent.
8. Exact logical form: PFP target `Φ:=WellFormed_w ∧ ∃d̄(Init(d̄)\wedge [PFP_{AC,\bar d}ψ](d̄))`; LFP/IFP only as conditional game fixed point.

## 10. Precise remaining blocker and completion obligation

`[open]` **Remaining blocker.** Provide an explicit, fixed finite FO(PFP) encoding of the full `G(n,k)$ configuration space on `A(w)$ such that:
- every reachable configuration `(P,t,a,b,m)$, with `P$ a transitively closed strict partial order on `Key$, is represented;
- `PosOf/TimeOf/AOf/BOf/ModeOf$ (or an equivalent complete state decoding) are explicit FO formulas/relations in that encoding;
- the decoded `Yield*$ relations implement exactly the legal `G(n,k)$ moves with incremental `StepPos$ and budget `AdvanceTime$;
- `AC$ is positive/monotone in the chosen fixed-point evaluation and its PFP/IFP/LFP semantics is proved equivalent to sorter-winning alternating acceptance from `Init$.

A closure is insufficient if it keeps `P_C$ as an informal decoded relation, leaves `EncodesPair/PosOf$ unexpanded while relying on them for arbitrary posets, or asserts monotonicity without establishing `AC$-independence of the full configuration decoding. A closure is sufficient only with the complete encoding and semantic equivalence proof above.

`[falsification target]` Any proposed completion should be checked against: malformed inputs; `n<=1$; `k=0$; total reached exactly at `k$; null-pair inertness; preservation of `PValid_C$; agreement with the `G(n,k)$/minimax definition of `S(n)$; and known small values where available.
