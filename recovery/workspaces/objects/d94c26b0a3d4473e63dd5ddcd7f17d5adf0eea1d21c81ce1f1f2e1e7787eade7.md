# Optimal-play leaf/merge lower bounds for permutation-framed DAG certificates

**Research front:** SoringP1 #301 (billy-dev), “optimal-play leaf merge lower bounds”  
**Date:** 2026-11-17  
**Deliverable:** local analysis report only (`exec-report.md`), no repo/Lean/PR changes.

## Question (all `n`, falsifiable)

> In any sound permutation-framed DAG certificate for a height-`S(n)` exact optimal sorting strategy, derive or refute a lower bound on the number of terminal states/leaves or on required merge/forgetting events as a function of `n` (e.g. must remain `n!` total orders up to representation, or can be compressed). Use the certificate entropy/forgetting framework and small-`n` evidence; identify concrete obstruction to polynomial-size compression if one exists.

**Consequence for `S(n)` (why this matters).** [**deduction**] A permutation-framed DAG certificate of explicit size `poly(n)` and height `k = S(n)` is checkable in time polynomial in its length and `n` (soundness/local-check claim in `docs/research-framed-certificate-frontier.md` §1), so an all-`n` existence theorem for such certificates at the exact optimum would imply `SORT-BOUND-U ∈ NP` (`docs/problem.md`, frontier doc). Conversely, any theorem forcing superpolynomial terminal/outcome structure or superpolynomial unavoidable forgetting/merge structure in every sound exact-optimal framed certificate would be a barrier to this NP-certificate route.

## Model and evidence labels

- [**definition**] Adaptive comparison sorting of `n` distinct labelled keys; `S(n)` is the minimax worst-case comparison count (`docs/problem.md`).
- [**definition/literature (project docs)**] A sound permutation-framed DAG certificate: acyclic directed graph of comparison instructions; arcs carry comparison outcome and a permutation of current slots; root guarantee `R = ∅`; arc extends `R` by outcome + transitive closure then applies permutation; join intersects guaranteed relations of feasible incoming arcs; every terminal guarantee is a total order; longest execution path has at most `k` comparisons (`docs/research-framed-certificate-frontier.md` §1).
- [**literature**] Exact values/bounds used as small-`n` anchors: `S(n)=⌈log₂ n!⌉` for `1 ≤ n ≤ 11`, `S(12)=30`, etc. (`docs/research-plan.md`, `docs/literature.md`, Peczarski/Wells/Stober–Weiß as cited there).
- [**deduction**] Logical consequences derived below from the certificate semantics and standard information identities.
- [**experiment (small-n arithmetic)**] Direct counting/inequality calculations in this report from cited exact `S(n), n!` values.

No new Lean proof, no new computational search, and no primary-source audit beyond the repository docs was performed here.

## 1. Terminal states/leaves: exact outcome lower bound

### 1.1 Derivation

[**definition**] Let `Π_n` be the set of all `n!` total orders (permutations) of the `n` distinct labelled input keys. For input order `π ∈ Π_n`, a deterministic adaptive strategy induces a unique comparison-outcome path consistent with `π`.

[**definition/deduction**] Soundness of the framed certificate means every real input order is included in the abstract set represented by the guarantee `R` along its feasible execution, and joins/intersections never add unjustified knowledge. Correct termination requires that at a terminal node the resulting guarantee is a **total order**. Therefore, for each `π ∈ Π_n`, the certificate must admit at least one feasible root-to-terminal path whose terminal guarantee `R_T` is compatible with `π` and is total; the only total order compatible with `π` is `π` itself, hence `R_T = π`.

[**deduction**] Define a *terminal outcome* as a terminal guarantee/annotation equal to some total order. Since every `π ∈ Π_n` must appear as `R_T` for some terminal reached on a `π`-consistent path, the set of terminal outcomes contains all of `Π_n`. Distinct total orders cannot be represented by the same exact total-order guarantee. Consequently:

> **Theorem (terminal outcome lower bound).** In any sound, correct permutation-framed DAG certificate for sorting `n` distinct keys (in particular any height-`S(n)` exact optimal strategy), the number of distinct terminal total-order outcomes is exactly `n!`. In particular it is `>= n!` and cannot be compressed below `n!` as outcomes.

[**deduction**] This is independent of DAG sharing of *internal* states, of path length (except correctness/height), and of the representation of nonterminal guarantees: sharing can merge histories only while the guarantee remains a partial order consistent with multiple inputs; once a node asserts a total order it fixes a single input order.

### 1.2 What can still be “compressed”

[**deduction**] The `n!` lower bound applies to *semantic terminal outcomes*, not automatically to syntactic artifacts in a weaker sense: one cannot merge two different total orders, but a representation could in principle name terminals implicitly. However, a checkable certificate that distinguishes which of `n!` inputs occurred must, explicitly or implicitly, encode `n!` distinct terminal results; this is an `Ω(n! log n!)` information content in the outcome mapping, not polynomial in `n`.

## 2. Entropy / forgetting framework: what it forces (and does not)

Using `docs/research-framed-certificate-frontier.md` §4 notation: node annotation `P`, `m=e(P)` linear extensions, feasible outcome `b` with `m_b=e(TC(P+outcome_b))`, `q_b=m_b/m`, child annotation `Q`, forgetting loss `λ_b = log₂(e(Q)/m_b) >= 0`, outcome entropy `H = -∑_b q_b log₂ q_b`.

### 2.1 Global resolution requirement

[**deduction**] For each root-to-terminal edge on a path realizing some input, `log₂ e(Q)-log₂ e(P)=log₂ q_b + λ_b` (paper identity, doc §4). Summing from root (`e=n!`) to a correct terminal (`e=1`) gives, for that realized path, `∑ (log₂ q_b + λ_b) = -log₂ n!`. Equivalently, total information resolved along the path is `log₂ n! = ∑ (-log₂ q_b - λ_b)` in that realized-outcome accounting, while `λ_b >= 0` represents information discarded by making `Q` coarser than the exact post-comparison state. Because the terminal must be exact (`e=1`), **all `log₂ n!` bits of input identity are ultimately resolved**; forgetting can occur only transiently and must be repaid by later distinguishing comparisons on every affected execution.

[**deduction**] This does **not** by itself force many merge nodes: a full decision tree has no DAG merges/forgetting (`λ_b=0` in the exact annotation sense, `Q = TC(P+outcome_b)`) and already resolves `n!` outcomes by `n!` leaves. The framework constrains *inefficiency* (`1-H`, `λ`) relative to depth/information bound, not the existence of polynomial sharing.

### 2.2 Auxiliary-walk bound (doc §4)

[**literature/deduction from doc**] For the auxiliary random walk that samples arcs with probability `q_b` computed from the current annotation, `E[∑ (1 - H + λ_b)] = E[D] - log₂(n!) <= k - log₂(n!)`, with `1-H >= 0`, `λ_b >= 0`. On an annotation-majority path, `∑ (log₂(2q_b)+λ_b)=D-log₂(n!) <= k-log₂(n!)`.

[**deduction, implication**] At `k=S(n)`, the total “slack” is `S(n)-log₂(n!)`. For `1 ≤ n ≤ 11` this slack is `0` in the worst-case count (`S(n)=⌈log₂ n!⌉`), so on a length-`S(n)` majority path the nonnegative terms force `H=1` and `λ_b=0` at every step on that path (a perfectly balanced, non-forgetting exact annotation path). For `n=12`, `S(12)-log₂(12!) < 1` (`≈0.625` bits total), so only very small cumulative imbalance/forgetting is compatible with exact optimal height on such paths. Asymptotically [**literature**: Sergeev, as cited in docs] `S(n)-log₂(n!)=o(n)`, so any exact-optimal certificate has only sublinear expected/majority-path total imbalance+forgetting in this measure — but this is a **necessary condition**, not a proof of polynomial DAG size, and `e(P)` counting is #P-hard so not a polytime verifier rule.

### 2.3 No forced compression below outcome identity

[**deduction**] Forgetting/merging reduces *state description* only when different histories become equivalent for all future allowed continuations under the certificate’s invariant. But terminal correctness requires eventual separation of all `n!` inputs. Therefore merges cannot identify distinct input permutations; at best they identify histories that are currently indistinguishable relative to a sound invariant before final resolution. The framework gives no mechanism to make `n!` terminal outcomes polynomial, and §1 shows they cannot be.

## 3. Small-`n` evidence (exact arithmetic)

[**experiment (arithmetic from literature values in docs)**]

| `n` | `n!` (terminal outcomes, forced) | `S(n)` | `⌈log₂ n!⌉` | slack `S(n)-log₂ n!` (approx) | note |
|---:|---:|---:|---:|---:|---|
| 1 | 1 | 0 | 0 | 0 | trivial |
| 2 | 2 | 1 | 1 | 0 | one comparison resolves 2 orders |
| 3 | 6 | 3 | 3 | 0 | 6 terminal total orders required |
| 4 | 24 | 5 | 5 | ~0.415 | 24 terminals; small total imbalance budget |
| 5 | 120 | 7 | 7 | ~0.093 | near-tight |
| 6 | 720 | 10 | 10 | ~0.491 | 720 terminals unavoidable |
| 7 | 5,040 | 13 | 13 | ~0.299 | |
| 12 | 479,001,600 | 30 | 29 | ~0.625 | first gap at info bound; still 4.79e8 outcomes |

[**deduction**] Even where `S(n)` equals the information lower bound, the certificate must end in exactly `n!` distinct total orders; “optimal play” cannot merge leaves. For `n=12`, optimal height is one above `⌈log₂ 12!⌉`, so the entropy/forgetting slack is < 1 bit in aggregate on majority paths, yet terminal outcomes remain `12!`.

## 4. Merge/forgetting events: lower bounds and obstruction

### 4.1 What is *not* a valid lower bound

[**deduction, caution aligned with doc §3 warning**] Exponentially many nonisomorphic reachable histories or states do **not** imply a large forgetful DAG is necessary: the pendant/anchor example in `docs/research-framed-certificate-frontier.md` shows many isomorphism types can be safely coarsened at small logarithmic cost. Also `docs/research-winning-frontier-barrier.md` gives `2^{Ω(n log² n)}` nonisomorphic winning states but explicitly states this is **not** a time lower bound and does **not** exclude selective/symbolic/DAG methods. Therefore one cannot infer “many merge/forgetting events required” merely from large frontier/state counts.

### 4.2 Concrete obstruction to polynomial-size compression (identified)

[**deduction**] **Obstruction O1 (terminal identity obstruction):** any sound exact sorting certificate must realize the bijection `π ↦ π` at termination over all `π ∈ Π_n`, hence must distinguish `n!` outcomes. Therefore no representation whose explicit terminal structure enumerates or individually certifies terminal outcomes can be polynomial-size; polynomial-size compression, if possible at all, cannot occur at terminals and must (also) avoid any form of per-outcome materialization.

[**deduction**] **Obstruction O2 (exact-optimal slack is tiny):** at height `k=S(n)`, `k-log₂(n!) = S(n)-log₂(n!)` is `0` for `n ≤ 11` and `o(n)` asymptotically [**literature**: Sergeev bound as cited]. By the auxiliary/majority-path identities, large cumulative forgetting or imbalance is incompatible with exact optimal height; a proposed compressed DAG must be “almost information-tight” in this aggregate sense. This is a strong necessary condition on any exact-optimal polynomial certificate but not known to be sufficient or impossible.

[**deduction**] **Obstruction status:** O1 is an unconditional lower bound on *terminal outcomes* (`n!`). O1/O2 together identify concrete barriers to naive compression, but they do **not** constitute a proof that no polynomial-size sound framed DAG certificate exists at height `S(n)` for all `n`. The docs state this exact-optimal all-`n` polynomial-size completeness remains open (`research-framed-certificate-frontier.md` §1, §5).

### 4.3 On “required merge/forgetting events”

[**deduction**] There is no general lower bound forcing `>= f(n)` merge/forgetting events from the stated semantics alone: a decision tree (no merges) is a valid sound certificate shape in DAG terms if represented without sharing, with `n!` leaves and zero forgetting. Merges/forgetting are a *compression device* (with soundness risks at joins per doc §1), not a logical necessity; the necessary quantity is resolution of `n!` outcomes. Thus the robust all-`n` lower bound is on **terminal outcomes (`n!`)**, while required merges/forgetting are **instance/representation-dependent and potentially zero** (at the cost of exponential tree size).

## 5. Implications

- [**deduction**] **Refutation of terminal compressibility:** terminal states/leaves qua total-order outcomes cannot be compressed below `n!` for any `n` in any sound permutation-framed DAG certificate for an exact sorting strategy. This holds at height `S(n)` in particular.
- [**deduction**] **No unconditional poly-size obstruction from this argument alone:** because internal merges can in principle compress nonterminal structure and the entropy identities permit near-tight behavior, the result here does not settle `SORT-BOUND-U ∈ NP` via framed certificates nor refute it. It sharpens the target: any positive NP-certificate construction must implicitly cover all `n!` outcomes without enumerating terminal outcomes.
- [**literature/deduction context**] Known constructions give all-`n` polynomial DAGs for some *non-optimal* procedures (merge-sort/rank-envelope upper bounds) but not at exact `S(n)` (`research-framed-certificate-frontier.md` §§2–3,5). The winning-frontier barrier rules out enumerating winning states, not all selective/DAG certificates (`research-winning-frontier-barrier.md`).
- **Falsifiable next check (suggested, not performed):** exhibit, for some fixed `n`, a sound framed DAG certificate at height `S(n)` whose explicit representation avoids per-terminal materialization in a verifiable way, or prove that every sound local-checkable join scheme at slack `S(n)-log₂(n!)` forces superpolynomial structure. Either would materially update the frontier.

## 6. Summary

| Quantity | Lower bound / status | Evidence |
|---|---|---|
| Distinct terminal total-order outcomes | **`= n!` (hence `>= n!`)**, all `n` | [**deduction**] from soundness + total-order terminals |
| Terminal compressibility below `n!` outcomes | **Refuted** | [**deduction**] |
| Required merge/forgetting events | **No universal `>0` lower bound**; representation-dependent (0 in tree) | [**deduction**] |
| Cumulative imbalance+forgetting at height `S(n)` | **`<= S(n)-log₂(n!)`** on auxiliary/majority accounting; very tight/small | [**literature/deduction**] doc §4 + known `S(n)` |
| Polynomial-size exact-optimal framed certificate for all `n` | **Open**; O1–O2 are concrete obstructions/constraints, not a refutation | [**deduction**] + project docs |

**Bottom line:** the certificate cannot avoid the `n!` terminal outcomes of sorting; it may only try to compress the *path structure* leading to them. The entropy/forgetting framework limits how much loss/imbalance an exact-optimal (`S(n)`) certificate can tolerate but, absent a new all-`n` theorem, does not yet force superpolynomial merge/forgetting structure. The decisive obstruction identified here is unconditional terminal outcome identity (`n!`); the decisive open obstruction is whether nonterminal DAG structure can remain polynomial at exact optimal height.
