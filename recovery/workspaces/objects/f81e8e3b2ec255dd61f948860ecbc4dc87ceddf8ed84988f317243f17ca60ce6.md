# Exec report: reachability-graph succinct certificates for exact `S(n)`

**Front:** SoringP1 #301 (billy-dev), "reachability-graph succinct certificates".  
**Date:** 2026-11-17.  
**Scope:** unary decision language `SORT-BOUND-U = {1^n # 1^k : S(n) <= k}` unless stated otherwise; model and encodings as in [docs/problem.md](docs/problem.md) and [AGENTS.md](AGENTS.md).  
**Repo changes:** this file only (`exec-report.md`), as requested.

## 0. Question, falsifiability, and consequence

**[definition] Question (all `n`, falsifiable).** Can exact height-`S(n)` strategies be certified by a succinct reachability/graph representation (e.g. a compact description of the strategy DAG, implicit reachability, or a proof-carrying state graph), with polynomial-time verification in the unary input length, other than explicit framed DAG enumeration?

**[deduction] Consequence for `SORT-BOUND-U` in NP.** For an instance `(1^n,1^k)` with `N=n+k+1`, a certificate `w` such that `|w| <= poly(N)` and a deterministic verifier `V(1^n,1^k,w)` running in `poly(N)` with
- completeness: `S(n) <= k => ∃w. V accepts`, and
- soundness: `V accepts => S(n) <= k`,
would imply `SORT-BOUND-U ∈ NP`. Conversely, failure of every such representation family for optimal budgets `k=S(n)` (a barrier/obstruction) would explain why the natural witness route does not establish NP membership; it would not by itself prove `SORT-BOUND-U ∉ NP` (AGENTS.md: unconditional separations from NP/PSPACE for this tally/sparse unary language are out of scope).

## 1. Precise certificate and verifier (explicit reachability/state graph)

The following is the baseline explicit reachability/graph certificate, instantiated as the permutation-framed strategy DAG already studied in this repo.

### 1.1 Object

**[definition] Framed reachability certificate** `C = (n,k,G)` where `G=(V,E)` is a finite DAG with a distinguished root `r`, nodes topologically ordered, and every node either a leaf or a comparison node. A comparison node `v` specifies:
- a compared pair `(a_v,b_v)` of current slot indices in `{0,...,n-1}`,
- for each outcome `o ∈ {lt,gt}` (`a_v<b_v` or `b_v<a_v`) an outgoing edge to `next(v,o)` together with a permutation/frame `π_{v,o}:[n]->[n]` relabelling slots.

Each node `v` carries an abstract *guaranteed strict partial order* `R_v ⊆ [n]^2` (the verifier computes it; it need not be stored except as implied by the check). `R_r = ∅`.

**[definition] Local transition semantics.** For a comparison node `v` with relation `R_v` and outcome `o`, let `R'_v = TC(R_v ∪ {outcome_o(a_v,b_v)})` if consistent (acyclic), else the branch is infeasible. Let `R_{v,o} = rename(R'_v, π_{v,o})`. A feasible path is a root-to-node path using only feasible outcomes.

**[definition] Reachability/join rule.** For every node `u`,
`R_u = ⋂ { R_{v,o} : (v,o)->u feasible }` if `u` has incoming feasible edges, and `R_r=∅`. (Intersection is sound: every real input order compatible with any feasible incoming history is compatible with facts known on all of them.)

**[definition] Acceptance conditions.**
1. *Structural:* topological/DAG, valid indices/permutations, every comparison node has both outcome edges specified.
2. *Soundness/reachability:* infeasible outcomes are recognized (or never claimed feasible); each feasible transition applies transitive closure and frame correctly; joins are intersections.
3. *Correctness:* every reachable leaf `l` has `R_l` a total strict order on `[n]`.
4. *Budget:* every feasible root-to-leaf path has length `<= k`.

### 1.2 Verifier

**[definition/literature+deduction, aligned with `scripts/check_framed_strategy.py`]** `V` performs a forward DAG pass in topological order, maintaining `R_v` (as an `n×n` bit relation) and max feasible depth `d_v`:
- closure/rename/intersection are polynomial in `n` per edge;
- total time is polynomial in `n` and `|G|` (hence polynomial in the explicit certificate size);
- rejection on cyclic order, invalid frame, non-forward edge, non-total reachable leaf, or depth `>k`.

This is a proof-carrying reachability check: the graph is the reachability object, frames carry the state renaming proof obligations, and the verifier replays local proof steps.

### 1.3 Size notions

**[definition]** Let `|C|` be the bitlength of an explicit encoding (nodes, pairs, child indices, permutations, budget). A family is *polynomially succinct* for `SORT-BOUND-U` if for true instances with optimal or relevant `k` (`k <= n log2 n` window, `problem.md`) it has `|C| <= poly(n,k) = poly(N)`.

## 2. "Other than explicit framed DAG enumeration": candidate succinct reachability representations

| Candidate | [status] | Description | Verification/size obstacle |
|---|---|---|---|
| Explicit framed reachability DAG | **definition/deduction** | List all comparison states/edges/frames explicitly. | Poly-time verifiable in `|G|`; succinctness requires `|G|<=poly(N)` (open at `k=S(n)`). |
| DAG with merged states (same reachability, fewer nodes) | **deduction/open** | Share nodes when reachable abstract states/guarantees can be joined soundly. | Still explicit unless a compact state naming/compression theorem exists; size = number of represented states/joins. |
| Implicit graph by successor program/circuit | **deduction/conjecture** | Certificate gives a program `Next(v,o)` and root/acceptance predicates; reachability is induced. | Verifier must establish budget/correctness over all feasible reachable states. For succinct/implicit graphs this is a model-checking/invariant problem typically as hard as PSPACE in the represented graph; deriving an NP (short-witness) verifier requires an additional polynomial invariant/proof object. Not known to give poly-time verification for all `n`. |
| Symbolic reachability (BDD/SAT/SMT-style encoding) | **open** | Encode states/transitions symbolically. | Symbolic size can blow up; a polynomial-size symbolic encoding verifiable in poly time is exactly the missing succinctness/proof claim in another syntax. |
| Proof-carrying state graph with invariants | **deduction/open** | Augment nodes with inductive invariants ranking progress toward a total order within `k`. | Sound if invariants are locally checkable, but supplying invariants strong enough for all optimal plays is equivalent in difficulty to finding a succinct certificate; no all-`n` polynomial invariant family is known. |
| Full strategy enumeration | **deduction** | Explicit adaptive decision tree. | Not succinct: at least `2*n! - 1` nodes for a correct/reduced tree (`research-certificates-barriers.md` Claim C). |

**[deduction]** "Succinct reachability/graph representation" changes the *presentation* but not the underlying obligation: a polynomial-time verifier must be convinced, for every feasible execution permitted by the graph/program, that a total order is reached within `k`. Without a polynomial bound on represented states or a polynomial inductive proof, implicit reachability tends to move cost from certificate size to verification/search.

## 3. Feasibility tests and known constructions

### 3.1 Small executable checks (explicit framed reachability DAG)

**[experiment]** Using the repo checker `scripts/check_framed_strategy.py` (`python3 scripts/check_framed_strategy.py --bubble n`):

| `n` | witness | depth | nodes | accepted |
|---|---|---:|---:|---|
| 1 | triangular bubble | 0 | 1 | yes |
| 3 | triangular bubble | 3 | 4 | yes |
| 4 | triangular bubble | 6 | 7 | yes |

This confirms the certificate/verifier semantics are implementable on small explicit graphs. The bubble witness is all-`n` and polynomial-size in the path form implemented by the script (`n(n-1)/2` comparison nodes) but has non-optimal depth for `n>=4` (e.g. depth 6 at `n=4` while `S(4)=5`), so it is feasibility evidence for the *format/verifier*, not for optimal succinctness.

### 3.2 Known small optimal values (context)

**[literature]** Exact values relevant to feasibility (`docs/research-plan.md`, `docs/literature.md`, OEIS A036604 context): `S(1..6)=0,1,3,5,7,10`, `S(7)=13`, `S(8)=16`, `S(12)=30 > ceil(log2 12!)=29`. Any proposed exact-height reachability certificate must reproduce these budgets on those `n`.

**[deduction]** For `n <= 6`, an explicit optimal decision tree is tiny in absolute terms but already has `2*n! - 1` nodes/leaves in reduced form (`research-certificates-barriers.md` Claim C experiment: `1,3,11,47,239,1439`), matching "enumerate all reachable leaves/permutations" rather than a compressed state graph. Thus explicit tree enumeration is feasible only as a tiny-`n` sanity object, not as an all-`n` succinct certificate.

### 3.3 All-`n` constructive witnesses (non-optimal or pending audit)

**[literature/paper construction, per `docs/research-framed-certificate-frontier.md`; not independently audited here]**
- *Adaptive merge sort:* polynomial explicit framed DAG, `O(n^2)` comparison nodes and `O(n log n)` path length for balanced merges, but comparison count exceeds `S(n)` for all sufficiently large powers of two (Sergeev gap argument in that note). Feasible as a sound polynomial certificate for the merge-sort upper bound, not for exact `S(n)`.
- *Ford–Johnson/rank-envelope pending insertions:* plausible `O(n^2)` framed certificate for the standard Ford–Johnson upper bound `F_FJ(n)=Σ ceil(log2(3j/4))`, subject to independent frame/boundary/recursive audit; `F_FJ(n)` is not `S(n)` for every `n`.

**[deduction]** These give existence of polynomial-size, poly-time-checkable reachability certificates for some *valid* upper bounds `k >=` algorithm cost, but do not answer the decisive optimal case `k=S(n)`.

## 4. All-`n` argument or concrete obstruction

### 4.1 No known all-`n` succinct optimal certificate (open)

**[open]** No construction, implicit representation, or proof-carrying reachability scheme is known that yields, for every `n`, a certificate of size `poly(n,S(n))=poly(N)` verifiable in `poly(N)` and proving `S(n) <= S(n)` (or proving `S(n) <= k` at the exact threshold for every true instance). In particular, the decisive question stated in `docs/research-framed-certificate-frontier.md` remains open: does some optimal root sorter for every `n` admit a polynomial-size sound framed certificate at height `S(n)`?

### 4.2 Concrete obstructions

1. **[deduction, literature] Explicit strategy/tree obstruction.** Any correct comparison tree distinguishes all `n!` permutations and (after standard pruning) has `2*n! - 1` nodes (`research-certificates-barriers.md` Claim C). With informative unary `k=Θ(n log n)`, `n!=2^{Θ(N)}` and with informative binary length `Θ(log n)`, `n!=2^{2^{Θ(m)}}`; explicit enumeration is not a polynomial witness except in trivial cases.

2. **[literature, paper theorem cited in repo docs] Winning-frontier obstruction.** `docs/research-plan.md`/`docs/research-winning-frontier-barrier.md` record `2^{(1/4-o(1)) n log^2 n}` nonisomorphic winning states at one depth, including at budget `S(n)` (via Sergeev's `S(n)-C(n)=o(n)` context). Therefore methods that enumerate or explicitly materialize the full winning frontier/reachable winning-state set are ruled out even at the exact optimum.

3. **[experiment/literature, repo baseline] Full reachable-state obstruction.** The memoized minimax DP visits all labelled posets (OEIS A001035, `2^{Θ(n^2)}` states) for small tested `n` (`research-certificates-barriers.md` §5), so "all posets" is not a succinct reachability graph.

4. **[open, concrete falsifiable target] Optimal-play confinement gap.** A succinct reachability certificate could still exist if optimal plays confine the strategy to `poly(n)` distinct states/joins. This is not known either way. `research-certificates-barriers.md` §8 identifies the concrete next measurement: count distinct poset states on *some* height-`S(n)` optimal play for `n<=10` and compare to `n!`, A001035, and `poly(n)`. Superpolynomial growth would be strong evidence against succinct explicit reachability/DAG certificates; polynomial growth would make a succinct-certificate route plausible.

5. **[deduction] Implicit-reachability verification gap.** Replacing explicit enumeration by an implicit successor description does not by itself produce a poly-time verifier: the verifier must still certify the universal reachability property "every feasible play reaches a total order within `k`". Without an added polynomial inductive proof/invariant, this is the same missing succinctness in verification form.

### 4.3 Bottom line

**[deduction/open]** Concrete answer: **no all-`n` polynomial-time-verifiable succinct reachability/graph certificate for exact `S(n)` is currently established**, and explicit/tree/frontier enumerations face concrete exponential obstructions. The question remains open in the only direction that could still work: a polynomially confined optimal-play reachability object (or an equivalent polynomial inductive/proof-carrying invariant) with a direct local verifier.

## 5. Implications for `SORT-BOUND-U` in NP

- **[deduction]** *If found:* an explicit or implicitly-described but polynomially certified reachability/strategy object, sound and complete at budget `k`, with `|w|,T(V)<=poly(n+k+1)`, would place `SORT-BOUND-U` in `NP`.
- **[deduction]** *Current status:* known explicit witnesses are too large in general (tree) or not optimal (merge sort / plausible Ford–Johnson upper bounds). Known reachable/winning-frontier counts are exponential in relevant regimes. Therefore the reachability/graph-certificate route does **not** currently establish `SORT-BOUND-U ∈ NP`.
- **[deduction/literature, AGENTS.md/problem.md]** *Non-implications:* lack of a known succinct certificate is not evidence of `SORT-BOUND-U ∉ NP`; proving `SORT-BOUND-U ∉ NP` would imply `NP ≠ PSPACE`. `SORT-BOUND-U` is sparse/tally, so many-one NP-hardness would imply `P=NP` (Mahaney barrier) and circuit lower bounds cannot separate it from `P/poly`.
- **[open]** NP membership of `SORT-BOUND-U` remains open; coNP membership and any hardness above `P` also remain open per the repo baseline.
