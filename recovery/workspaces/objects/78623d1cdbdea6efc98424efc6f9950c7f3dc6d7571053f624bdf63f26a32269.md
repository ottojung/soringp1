## 1. Question

Can a polynomial-time **approximate balancing oracle** — in the sense of Bubley–Dyer (rapidly mixing Markov chain / FPRAS for linear extensions), later FPRAS refinements, or the Haeupler et al. partial-information sorter — certify the **exact** worst-case threshold `S(n) <= k` for the antichain root, or can it certify only a **near-optimal upper bound**?

Consequence if exact certification were possible: a polynomial-time verifiable upper-bound certificate at height exactly `S(n)`, supporting (but not by itself proving) `SORT-BOUND-U ∈ NP`. If only near-optimal: approximation yields only `S(n) + Θ(n)` (or worse) bounds, and NP membership remains open.

Falsifier sought: an `n`-family where any polynomial-time approximation with stated error cannot distinguish `S(n) <= k` from `S(n) > k`, or a proof that the approximation guarantee suffices.

## 3. Findings

### 3.1 What the oracles actually provide (literature)

- **[literature] Bubley–Dyer (1999).** A Markov chain on linear extensions of a poset `P` that is rapidly mixing (mixing time polynomial in `n` and `1/ε`), giving approximate uniform sampling. Via self-reducibility of linear extensions (remove a minimal element), this yields an **FPRAS** for `e(P)`: an estimate `ê(P) ∈ (1±ε) e(P)` in time `poly(n, 1/ε)`. It does **not** compute `S(P)` and does not decide `CanSort(P,k)`.
- **[literature] Haeupler, Hladík, Iacono, Rozhoň, Tarjan, Tětek (Algorithmica 88(3), 2026).** Polynomial-time sorting under partial information performing `O(log e(P))` comparisons, concretely at most `(1+ε) log2 e(P) + O_ε(n)` comparisons in `O(n^{2.5})` time (and `O(log n · log e(P))` in `O(n²)` time). "Optimal" here means **constant-factor optimal in comparison count**, not exact.
- **[literature] Sergeev (ECCC TR20-096, 2020).** `S(n) = log2(n!) + O(n/(log n)^{1/5}) = log2(n!) + o(n)`. This bounds comparisons, not evaluation time, and gives no explicit constant.

### 3.2 Why `e(P)` alone cannot certify `S(P)` (deduction + experiment)

**[experiment, verified this run]** Two 5-element posets with identical extension counts but different exact costs:

```
P1 = (8, 12, 8, 0, 12):   e(P1)=8,  F(P1)=3
P2 = (26, 0, 10, 0, 8):  e(P2)=8,  F(P2)=4
```

Re-run in this worktree: `linear_extensions(P1)=8, minimax(P1)=3`; `linear_extensions(P2)=8, minimax(P2)=4`. Hence `S(P)` is **not** a function of `e(P)` (Proposition 5.1 of `research-hardness-boundaries.md`). An oracle that only approximates `e(P)` sees `P1` and `P2` as identical up to relative error and cannot distinguish `F(P1) <= 3` from `F(P2) <= 3`. This is a direct counterexample to exact certification from any `e`-approximating oracle on general states.

**[experiment, verified this run]** `Merge(2,4)` (disjoint union of a 2-chain and a 4-chain): `n=6`, `e=15`, `ceil(log2 15)=4`, `F=5`. The information bound is non-tight by one comparison even though `e` is known exactly. Balancing by `e` alone attains only the information bound `4`, which is **below** the true `S(P)=5`; no valid sorter of height 4 exists for this poset.

### 3.3 Why the antichain root is not certified either (deduction)

For the antichain (`P = ∅`, `e = n!`), `e(P)` is trivial (no approximation needed), so the FPRAS error is not the obstruction. The obstruction is **structural**:

- The balancing methods of Kahn–Saks / Kahn–Kim / Cardinal et al. produce a comparison tree of height at most `(1+ε) log2 e(P) + O_ε(n)` (Cardinal et al.) or `O(log e(P))` with a constant factor (Kahn–Saks: split ratio in `[3/11, 8/11]`, i.e. height `≤ log_{11/8}(n!) ≈ 2.18 log2(n!)`).
- Sergeev gives the true value `S(n) = log2(n!) + O(n/(log n)^{1/5}) = log2(n!) + o(n)`.
- The balancing slack is **linear in `n`**: either a multiplicative constant `> 1` (Kahn–Saks, giving `Θ(n log n)` slack) or an additive `O_ε(n)` term (Cardinal et al.) whose constant grows as `ε → 0`. The true gap is only `O(n/(log n)^{1/5}) = o(n)`.

Therefore for all sufficiently large `n`, the balancing upper bound strictly exceeds `S(n)` by `Θ(n)` (or `Θ(n log n)` for the weaker Kahn–Saks constant), so the produced tree does **not** have height `≤ S(n)`. It certifies `S(n) <= S(n) + Θ(n)`, a near-optimal bound, not the exact threshold.

The `n = 12` datum is the smallest concrete instance: `S(12) = 30` but `ceil(log2 12!) = 29`; the information bound is non-tight by one comparison. A balancing oracle aiming at `≈ 29` comparisons cannot produce a valid 29-comparison sorter (none exists), so it cannot certify `S(12) <= 29`; it must use at least 30. This is exactly the regime where approximation/balancing stops helping, matching the budget-pruning observation that the `e(P) > 2^d` cutoff fails at `n = 12`.

### 3.4 The FPRAS error does not rescue exactness (deduction)

Even setting the structural slack aside, the FPRAS introduces a multiplicative `(1±ε)` error in `e(P)`. One can choose `ε = 1/n²` in polynomial time, making `ε log2(n!) = O(log n / n) → 0`, so the **approximation error** can be made negligible compared with the true gap. But this does not remove the **structural** balancing slack `O_ε(n)`, whose constant depends on `1/ε` and stays `Θ(n)` for any polynomially feasible `ε`. The two sources of slack are independent: the FPRAS error is controllable to `o(1)` in the exponent, but the balancing trade-off (`(1+ε)` factor vs. `O_ε(n)` additive term) is not. Hence exact certification is not achieved by combining an FPRAS with existing balancing.

### 3.5 Conditional completeness theorem (conditional)

**Theorem (conditional, paper-level).** Let `B` be a polynomial-time balancing procedure that, given `P`, returns an incomparable pair `{x,y}` whose split satisfies

```
1/2 - δ(n) ≤ e(P+x<y)/e(P) ≤ 1/2 + δ(n)
```

with `δ(n) = o(1/log n)` (equivalently `δ(n) log2 e(P) = o(n/(log n)^{1/5})`... more precisely `δ(n)·log2 e(P) = o(S(n)-log2(n!))` when the gap is nonzero), and whose recursion incurs additive slack `A(n) = o(n/(log n)^{1/5})`. Then the induced decision tree has height

```
log2(n!) + δ(n) log2(n!) + A(n) = log2(n!) + o(n/(log n)^{1/5})
```

which is `≤ S(n)` whenever `S(n) - log2(n!)` is at least that large, certifying `S(n) <= k` for `k = S(n)`.

**Status of the hypotheses.** No known polynomial-time method satisfies both hypotheses simultaneously:
- Kahn–Saks gives `δ = O(1)` (constant, not `o(1/log n)`).
- Cardinal et al. give `δ = O(ε)` and `A = O_ε(n)` with an `ε`-dependent constant; making `δ = o(1/log n)` forces `ε = o(1/log n)`, which makes `A = O_{1/log n}(n)` grow (the constant blows up), so `A` is not `o(n/(log n)^{1/5})`.
- The FPRAS can estimate `δ` to `o(1/log n)` in polynomial time, but cannot improve the *existence* of a comparison with such `δ` (that is a property of the poset, not of the estimate); and it does not reduce `A`.

Thus the conditional theorem states what would suffice, and the counterexample (§3.2–3.3) shows the sufficiency conditions are not met by the cited oracles. **No NP membership is claimed from an approximate oracle alone.**

## 5. Complexity implication

- Exact certification of `S(n) <= k` by an approximate balancing oracle would require the oracle's tree to have height `≤ S(n)`, i.e. slack below Sergeev's gap `o(n)`. The cited oracles have slack `Θ(n)` (or worse), so they certify only **near-optimal upper bounds** `S(n) + Θ(n)`.
- This does **not** imply `SORT-BOUND-U ∉ NP` or any separation; it only rules out this particular family of oracles as a route to exact certificates. NP/coNP membership remains open, consistent with `docs/problem.md` and `docs/research-certificates-barriers.md`.
- The non-reduction (§3.2) additionally shows that even an *exact* `e(P)` oracle cannot certify exact thresholds for arbitrary poset states, so the obstruction is not merely an approximation artifact.

## 6. Stop condition

No new theorem, barrier, or improved bound was proved. The result is a **decisive no-go for a major route** (approximate balancing as exact certifier), which is a legitimate publication-gate item, but it changes no complexity classification. The open question remains: find a compact canonical object for optimal play (framed DAG, invariant, or potential) with sublinear slack, or prove a barrier against one.
