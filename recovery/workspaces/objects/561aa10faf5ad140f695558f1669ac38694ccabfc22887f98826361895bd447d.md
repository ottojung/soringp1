# Exec Report: T(4) Uniform Tightness Threshold (n≤7 certified, n=8 partial)

**Date:** 2026-11-18
**Agent:** billy-dev (exec-t4-n7)
**Context:** Unary SORT-BOUND-U, uniform tightness threshold T(r) (docs/research-obstruction-next.md §2)

## Hypothesis

**H:** T(4) = 12 for all finite posets — every finite poset P with e(P) ≤ 12
satisfies m(P) ≤ 4. Equivalently, no poset (on any number of labelled elements)
has e(P) ≤ 12 and m(P) ≥ 5.

**Consequence if true:** The uniform small-budget base case for r = 4 would extend
from "certified for n ≤ 6" to "certified for all n," strengthening the pruning
criterion in §4.1 of research-obstruction-next.md from e ≤ 7 (r = 3) to e ≤ 12
(r = 4). This would certify T(4) = 12 exactly, matching the experimental table
(T(4) = 12 for n ≤ 6) and the first-failing-e value of 13.

**Consequence if false:** A single counterexample P with e(P) ≤ 12 and m(P) ≥ 5
would be a decisive structural witness, breaking the e-only uniform tightness
at r = 4 and providing a new "local frontier" poset for the minimax game.

## Method and sources

- **Model:** Labelled posets on n elements, represented as transitive-closure
  successor bitmasks succ[i] (elements strictly greater than i). e(P) = number
  of linear extensions (DP over downsets). m(P) = minimax remaining comparisons
  (recursive, memoized, capped at 5 for the threshold test).
- **Prior evidence:** Antonina #301 (2026-11-17): exhaustive n ≤ 6 gives 0
  counterexamples (certifies T(4) ≥ 12 on n ≤ 6); partial n = 7 checked
  1,000,000/6,129,859 posets (178,287 with e ≤ 12) with 0 counterexamples.
- **Utilities reused:** `scripts/obstruction_probe.py` (poset model, `all_posets`,
  `linear_extensions`, `minimax`, `add_relation`). Independent C reimplementation
  for speed and memory efficiency.
- **Primary sources:** Hanamura–Iwata 2011 (T(3) = 7); Kahn–Saks 1984 (good
  comparison); research-obstruction-next.md §§2–4 (uniform tightness definition,
  pruning criterion, no-go results).

## Results

### n = 7: EXHAUSTIVE CERTIFICATION

- **Total labelled posets on 7 elements:** 6,129,859 (matches OEIS A001035(7)).
- **Posets with e(P) ≤ 12:** 522,060.
- **Counterexamples (e ≤ 12, m ≥ 5):** 0.
- **Runtime:** 17 seconds (C, -O2).
- **Method:** Complete DFS enumeration from the antichain, adding relations in
  both directions, deduplicating via open-addressing hash set (2^23 slots).
  m(P) computed recursively with memoization, capped at 5 (returns min(m,5));
  capping is sound because we only need to distinguish m ≤ 4 from m ≥ 5.
- **Verification:** Total count 6,129,859 matches the known value and the prior
  partial run's denominator. Candidate count 522,060 is consistent with the
  prior partial evidence (178,287 at 1M/6.1M posets ≈ 17.8%; full count 522,060/6,129,859 ≈ 8.5%, lower because later posets are more constrained — actually the partial run's rate was an artifact of DFS ordering; the full enumeration is authoritative).

**Conclusion for n ≤ 7:** T(4) ≥ 12 is now exhaustively certified for n ≤ 7.
No poset on ≤ 7 labelled elements has e(P) ≤ 12 and m(P) ≥ 5.

### n = 8: PARTIAL SEARCH (time-limited)

- **Total labelled posets on 8 elements:** 431,723,379 (OEIS A001035(8)).
- **Posets visited:** 56,142,924 (≈ 13.0% of total).
- **Posets with e(P) ≤ 12 found:** 2,208,749.
- **Counterexamples found:** 0.
- **Pruned subtrees:** 2,208,749 (every candidate had m ≤ 4, so all descendants
  also have m ≤ 4 and were pruned without expansion).
- **Runtime:** 300 seconds (hard time limit; search terminated by built-in
  timeout, not by completion).
- **Method:** Same DFS enumeration with pruning rule: when e(P) ≤ 12, compute
  m(P); if m(P) ≤ 4, prune the entire subtree (monotonicity of m under
  relation addition guarantees descendants have m ≤ 4); if m(P) ≥ 5, report
  counterexample. Hash set: 2^29 slots (open addressing). Memo table: 2^28 slots.
- **Coverage limitation:** Only ~13% of the poset lattice was traversed. The
  search was DFS-ordered from the antichain; posets with many relations (and
  hence e ≤ 12) are deep in the lattice, so the early termination means many
  high-relation-count posets were not reached. The 2.2M candidates found are
  those reachable within 56M visited posets.

**Conclusion for n = 8:** No counterexample found in the searched portion.
This is partial evidence only; it does not certify T(4) ≥ 12 for n = 8.

## Strongest argument / obstacle

**For T(4) = 12 (all-n):** The n = 7 exhaustive certification extends the
evidence from n ≤ 6 to n ≤ 7 with zero counterexamples among 522,060
candidates. Combined with the n ≤ 6 certification, this covers all posets on
up to 7 elements. The monotonicity of m under relation addition (if m(P) ≤ 4
then all descendants have m ≤ 4) means that once a poset is certified, its
entire downset is certified. The pruning rule is sound and reusable.

**Obstacle to all-n proof:** The n = 8 search demonstrates that posets with
e ≤ 12 are numerous (2.2M found in only 13% of the lattice) and the full
enumeration is computationally expensive (432M posets). More fundamentally,
there is no known structural theorem guaranteeing T(4) = 12 for all n. The
Kahn–Saks balance (3/11–8/11) is insufficient: it certifies T(3) = 7 but
does not extend to r = 4. The no-go results in research-obstruction-next.md
§4.2 show that low-dimensional invariants (e, width, #min, #max) cannot
determine m, so a case-by-case or invariant-based proof is not available.
Hanamura–Iwata 2011 proves T(3) = 7 for all n via a specific poset property
(e = 7), but no analogous result is known for e = 12.

## Consequence for T(4) = 12 all-n

- **Status:** T(4) = 12 is now certified for n ≤ 7 (exhaustive) and has
  partial (13%) evidence for n = 8 (no counterexample). It remains a
  **conjecture** for all n.
- **What changed:** The evidence base extended from n ≤ 6 to n ≤ 7. The pruning
  criterion in §4.1 can now use e ≤ 12 as a certified base case for n ≤ 7
  (previously only for n ≤ 6).
- **What did not change:** No all-n theorem. No structural proof. The n = 8
  gap (and beyond) remains open.
