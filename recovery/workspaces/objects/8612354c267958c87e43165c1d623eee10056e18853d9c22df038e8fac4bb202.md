Rows 1–19 form the intended partition: global halt; `M_Eval` terminal root/non-root accept/reject; `M_Eval` non-terminal `CtrlSort` NI push; `M_Eval` `CtrlAdv` A0 push; `M_BackE` RetAcc/RetRej with root/non-root and RetRej NI/NNI; `M_BackA0` RetRej root/non-root and RetAcc→A1; `M_BackA1` RetAcc/RetRej root/non-root. ### 3.2 Exhaustivity gaps / misleading explanation

1. **`CtrlSort` no-next / reject-eval text.** `[falsification test: no witness found; proof text issue]`
   Candidate §3.3 states: “`CtrlSort` ... gives `NextIncomp_c` or sort exhaust handled by `RejectEval_c/NoNextIncomp_c` path (row 6)”. Row 6 is `D_sort_pick` and requires `NextIncomp_c`; it does **not** handle `NoNextIncomp_c`. The intended handling is: a `CtrlSort` non-total state with no next incomparable is a reject-exhaust evaluation, so `RejectEval_c` should hold and rows 3/5 apply (or a dedicated reject-eval terminal). The candidate also defines `RejectEval_c` in §1 to include `(CtrlSort(c̄)∧¬Total_c∧Budget_c∧NoNextIncomp_c)`. Thus exhaustivity can be repaired by proof obligation: on `I_{M_D}`-reachable `M_Eval, CtrlSort, ¬Total_c, Budget_c`, either `NextIncomp_c` (row 6) or `RejectEval_c` via `NoNextIncomp_c` (rows 3/5). The current explanation is incorrect as written but not an explicit reachable witness.

2. **`CtrlAdv` requires `Incomp_c(a,b)`.** `[open]`
   Row 7 includes `HasSel(c̄)∧SelA(c̄,a)∧SelB(c̄,b)∧Incomp_c(a,b)`. Exhaustivity for reachable `M_Eval,CtrlAdv,RetNone` states needs `I_{M_D}` (or the transition that set `CtrlAdv/HasSel`) to guarantee the selected pair remains incomparable in the current `PosF`. This is plausible because `PosF` is preserved except A0/A1 child construction and children are separate frames, but it must be proved as an invariant/transition consequence. No witness found.

3. **Back* + `RetNone` top.** `[open]` Candidate §3.4/§5(1) correctly excludes `M_BackA0/A1/E ∧ RetNone` as a consuming top and marks it a falsifier if reachable. I found no explicit witness, but the closure proof must show every path that sets a parent to `M_Back*,RetNone` immediately makes a fresh child the unique `Top'`, and no transition leaves a Back* RetNone frame as top except through an invariant violation.

4. **`M_Eval` + `RetAcc/RetRej` top.** `[open]` Excluded by marker discipline; `MarkRet*On` targets Back* parents in pop-return rows. No witness found. Must follow from the fact that only Back* parents receive `MarkRet*On` and Eval frames are created/preserved with `RetNone`.

5. **`CtrlAdv` without selection / cursor coherence.** `[open]` Excluded by `I_{M_D}` control/cursor coherence. No witness found.

## 4. MarkRet / BackE NI-NNI audit

`MarkRetRejOn` (BackE row, §2.6) sets `RetRej` on parent `p̄` and preserves non-marker fields. After that, rows 10–12 are the only BackE `RetRej` consumers: row 10 requires `NextIncomp_c(CurA,CurB;x,y)`; rows 11/12 require `NoNextIncomp_c(CurA,CurB)` and split on `Root/Parent`. NI/NNI are complements on the same cursor snapshot, so the split is mutually exclusive and exhaustive **provided** that snapshot is total/meaningful for the BackE parent.

**Critical obligation.** `[open]` The pop/mark preserves BackE cursor fields of `p̄` (`PreserveNonMarkerFields` includes `HasCur/CurA/CurB` unless case changes them). Therefore NI/NNI is evaluated on the preserved parent cursor — correct for “after child returned reject, try next incomparable after the one that spawned that child”. This depends on `SetParentBackE_Advance` having advanced the cursor when the child was pushed (rows 6/10 templates), and on that cursor remaining intact across child execution and pop. The casewise claim in §4 says lower stack preserved except designated sets; pop return sets `S={p̄,c̄}` and marker preserves cursor. So the design is coherent. A proof must show no intervening path mutates `p̄`'s cursor before rows 10–12 consume the mark.

No explicit witness found.
