## 1. Model and DP under study `[definition]`

States are transitively closed strict partial orders `P` on the `n` labelled
keys, represented as successor bitmasks (probe): `succ[i]` has bit `j` set iff
`i < j`.

DP (probe `minimax_values`; `docs/upper-bound.md`; Lean `adv`):

```
F(P) = 0                                                     if P is total,
F(P) = 1 + min_{(i,j) incomparable} max(F(P+i<j), F(P+j<i))  otherwise.
```

`S(n) = F(empty)`.  The board notes `S(n) = adv(univ)` (kernel-checked,
`S_eq_adv_univ`), so `F` here is the "minimax sorting strategy" value.

Canonical strategy (probe `SinglePolicyDAG`, "first optimal move"): at a
non-total state `P`,

```
opt(P) = { (i,j) ∈ incomparable(P) : 1 + max(F(P+ij), F(P+ji)) == F(P) }
π(P)   = min(opt(P))          # lexicographically smallest optimal pair
```

## 3. FO(TC) formalization of the strategy program `[definition]`

FO(TC) = first-order logic + transitive closure.  Board context
(`uniform-nc1-depth-sorting-number/docs/research-fo-tc-strategy-barrier.md`):
on finite ordered structures FO(TC) captures NL; fixed-variable fragments are
more restrictive; fixed-width branching programs and fixed-variable FO(TC)_v
strategy programs are not expected to capture the all-n minimax optimal
strategy (winning frontier, §3.2 below).

Requested program (per n, sketch):

```
Structure: universe = reachable posets of the empty poset of {0..n-1};
           total posets are terminal states.

Definitions (intended):
  total(P)      := ∀i,j: comparable(P,i,j)                     [FO]
  incomparable(P,(i,j)) := ¬ comparable(P,i,j)                [FO]
  succ(P,Q)     := Q = extend(P, π(P))                        [to define]
  E(P,Q)        := succ(P,Q)                                  [transitions]
  F(P)          := 0 if total(P) else 1 + min over incomparable (i,j)
                   of max(F(P+ij), F(P+ji))                   [to define]
  π(P)          := min{ (i,j) ∈ incomparable(P) :
                   1 + max(F(P+ij), F(P+ji)) = F(P) }         [to define]
```

Notes on what is FO(TC)-definable vs not:

- Successor relations for FIXED pairs: `Q = extend(P, i, j)` is FO(TC)-
  definable on the poset universe (the successor is a specific poset; closure
  of `P`'s relations plus `i<j` gives `Q`; you can write the FO+TC formula
  "Q is the unique poset with i<j ∈ Q, (i,j) incomparable in P, and for all
  k,l: k<l ∈ Q iff k<l ∈ P or implied by i<j", with totality/closure via TC).
- `total(P)`, `incomparable(P,·)`: FO definable given the poset relations.
- **The blocker**: `F` and `π` are not FO(TC)-definable (see §4).

## 4. First obstacle (deliverable 2): the DP value `F` is not FO(TC)-definable

**[deduction]** The DP is a well-founded recursion on the poset DAG with
unbounded depth (the DAG height is up to ~O(n²); F(empty) = S(n) grows with
n).  The first obstacle is computing/defining the minimax value `F` itself —
the user's suggested example, "m(P) is minimal among optimal comparisons",
is the *second* obstacle (below).

Why `F` is beyond FO(TC) uniformly in n:

1. **Only TC as fixpoint.**  FO(TC) provides transitive closure as its only
   closure/fixpoint mechanism (board: "FO(TC)_v … on finite ordered
   structures FO(TC) captures NL"; the board's recurrence/compiler barriers:
   "Exact minimax recurrence needs e(P) — #P-complete").  There is no general
   LFP/PFP or arithmetic over depths in FO(TC).

2. **Game value needs an unbounded least depth.**  By the attractor
   characterization verified in §2 (`attr_eq`):
   `F(P) = 0` iff total, and `F(P) ≤ d+1` iff `∃` incomparable pair
   `(i,j)`: `F(P+ij) ≤ d ∧ F(P+ji) ≤ d`.  So
   `F(P) = min{d : P ∈ W_d}` where `W_0 = total`,
   `W_{d+1} = W_d ∪ {P : ∃ pair: P+ij ∈ W_d ∧ P+ji ∈ W_d}`.
   For each FIXED d, `W_d` is FO-definable by unrolling d levels.  But the
   *least* d is not: there is no operator in FO(TC) that picks the least
   depth over the unbounded family; you cannot write "F(P) = min{d : φ_d(P)}"
   as one FO(TC) formula, because the formula would have to vary with d.

3. **Uniformity in n.**  For each fixed n the DP values are definable by
   unrolling to depth O(n²) (the poset DAG is finite).  But the strategy
   program must be *uniform*: as n grows the unrolling depth grows without
   bound, and FO(TC) has no way to capture the growth ("the least d such that
   empty ∈ W_d" as a function of the structure).  This matches the board's
   view that a fixed-compression strategy cannot capture the all-n minimax
   strategy (§4.1 below).

Consequence: the "strategy program" as requested (canonical optimal
comparison as a total function of the state) is **not** an FO(TC)-definable
program: even the *definition* of the transitions requires `F`, which is not
FO(TC)-definable.

**The user's object-level example, resolved:** "m(P) is minimal among optimal
comparisons" is a second-order reachability property: given `F`,
`optimal(P,(i,j)) := 1 + max(F(P+ij), F(P+ji)) = F(P)` is FO(TC)-definable
(with `F`), and `m(P) = min{optimal pairs}` is FO-definable; the problem is
that `F` is already beyond FO(TC) — the minimality test itself is fine, the
values it needs are not.

**Specific objects needing formulation beyond FO(TC):**

- the DP value table `{F(P) : P reachable}` (bounded by O(n²), 130023 states
  at n=6) and the induced optimal-pair sets `opt(P)`;
- the game-value semantics `F(P) = least d with P ∈ W_d` (unbounded least
  depth);
- any formulation route that goes through linear-extension counts `e(P)`:
  Claim E (board): the greedy-optimal rule is #P-complete to count;
- the alternating-time semantics: Claim A (board): SORT-BOUND-U ∈ PSPACE via
  ATM — FO(TC) ⊆ NL, so the DP is provably *not* FO(TC)-definable while still
  being computable in PSPACE; that is the cleanest "compactness fails"
  statement.

### 4.1 Board barrier connections

- **Winning frontier** (`docs/research-winning-frontier-barrier.md`): for
  infinitely many n = 2^(2r) there are ≥ 2^{(1/4−o(1)) n (log₂n)²}
  nonisomorphic reachable posets, all winning at the same comparison depth
  (n=224 → > 2^39).  Obstacle: the strategy graph is too large for any
  fixed-width or fixed-variable-memory encoding; board FO(TC) barrier doc
  (§3, §Verdict): "The obstruction is unbounded arity/width of the strategy
  graph's state space (the winning frontier) relative to fixed finite
  memory/variable budget", "FO(TC)_v (fixed v) does not capture the all-n
  minimax optimal strategy without super-polynomial resources".
- **Claim C** (`docs/research-certificates-barriers.md`): explicit tree
  witnesses have ≥ 2n!−1 nodes — superpolynomial in the unary input length;
  board open: "program computing the strategy | poly possible | [open]".
- **Claim E** (same doc): the greedy-optimal rule (minimize
  `max(e(P+xy), e(P+yx))`) needs #P-complete linear-extension counting — a
  specific route barrier; note our canonical rule uses values `F`, not
  extension counts, but computing `F` via `e(P)` is blocked by Claim E, and
  the board's "recurrence/compiler barriers" note "Exact minimax recurrence
  needs e(P) — #P-complete".
- **Claim A** (same doc): SORT-BOUND-U ∈ PSPACE via ATM
  (`2^{O(N log N)}` time, `O(N log N)` space) — the DP is computable under
  alternating-time semantics.
- **Sparsity barrier (Claim B)**: blocks many-one NP-hardness of
  SORT-BOUND-U; orthogonal to the FO(TC) program question but part of the
  board's barrier set.

## 5. Restricted families (deliverable 3): sub-goal status `[experiment] + [deduction]`

Attempted sub-goal: "the 'no-inversion canonical strategy' when Claim C
holds".

Findings:

1. **No such strategy is documented on the board.**  Searches for
   "no-inversion", "inversion-free", "inversion" in `soring301/docs`, the two
   front repos, and `scripts`: no hits except
   `docs/research-n12-nontightness.md:291` ("the n=20/n=22 inversion" of the
   H1 tightness phenomenon — unrelated to strategy encodings).  So the
   sub-goal as phrased is not on the board; the analysis of its natural
   variants follows.

2. **Greedy-lexicographic family probe** (`greedy_probe.py`): the pure
   lexicographic-greedy strategy (always pick the lexicographically smallest
   incomparable pair — the probe's `incomparable_pairs` order — with no
   optimality test) is FO(TC)-expressible (local lex-min over the
   incomparable relation), but:

   | n | S(n) | greedy height | optimal |
   |---|------|---------------|---------|
   | 0 | 0    | 0             | yes     |
   | 1 | 0    | 0             | yes     |
   | 2 | 1    | 1             | yes     |
   | 3 | 3    | 3             | yes     |
   | 4 | 5    | 6             | **no**  |
   | 5 | 7    | 10            | **no**  |
   | 6 | 10   | 15            | **no**  |

   So the pure greedy is a *restricted-family success on the FO(TC)
   expressibility side* (it is expressible) but fails the canonical-
   optimal goal (it is not optimal even at n=4).  Data point for the
   analysis, not a sub-goal success.

3. **Value-based canonical family** (the user's): needs `F` — first
   obstacle = the §4 obstruction.

4. **Why no other natural restricted family succeeds:**
   - any rule using minimax values `F` (or linear-extension counts, or
     strategy-path properties, or "minimal among optimal" comparisons)
     inherits the §4 obstruction (Claim E for extension counts; the
     not-FO(TC)-definable `F` for value-based rules);
   - any fixed-memory/fixed-variable encoding (branching programs, FO(TC)_v)
     is blocked by the winning frontier + FO(TC)_v barrier (§4.1);
   - a family whose rules use only local poset structure can be made
     FO(TC)-expressible (e.g., lex-min greedy), but such local rules cannot
     produce the canonical optimal strategy on all n (the probe shows
     suboptimality by n=4), because the optimal move depends on the global
     minimax values.

**Conclusion:** no sub-goal succeeded in this session.  The first obstacle
(deliverable 2) — the DP value `F` not being FO(TC)-definable uniformly in
n — stands, and the user's suggested example is the second obstacle.

## 6. Machine-cost bridge proposal (deliverable 4, optional) `[deduction]`

Proposal for `docs/kernel-results.md`-style bridge, two routes:

- **DP route (informal sketch → machine cost).**  The memoized DP
  (`minimax_values`) over reachable posets uses ≤ A001035(n) states
  (1,1,3,19,219,4231,130023 for n=0..6; Kleitman–Rothschild gives
  A001035(n) = 2^{O(n²)}); per state O(n²) work (bitmask `extend`), values
  O(log S(n)) bits.  Proposed bridge theorem (informal):
  `S(n) = F_DP(empty)`; `F_DP` computable in time O(A001035(n)·poly(n)) and
  space O(A001035(n)·poly(n)) — hence SORT-BOUND-U ∈ DSPACE(2^{O(n²)}),
  matching the informal DP bound of `docs/upper-bound.md`.  Formalization
  obligation per `docs/kernel-results.md` open item 1 ("Machine-time
  complexity bridge"): connect the informal DP to a machine model with the
  poset representation (succ bitmasks, O(n²) `extend`), and bridge
  `S_eq_adv_univ` (kernel-checked) to the DP's cost bound; prove
  `A001035(n) ≤ 2^{n(n-1)/2}` on the state-count table for the machine
  bound.

- **ATM route.**  Claim A already gives ATIME(poly(n,k)) = PSPACE for
  SORT-BOUND-U; bridging that to `SORT-BOUND-U ∈ PSPACE` is the board's
  established result — no new bridge needed there.

- **Negative bridge (compactness fails).**  SORT-BORT-U ∈ PSPACE (Claim A,
  board) while the strategy program is not FO(TC)-definable (§4); the
  definability analysis above is the bridge between the two facts.
