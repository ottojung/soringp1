# exec-report: node-local global optimal tree

**Worktree:** `soring301-exec-node-local-global-tree-20261117`, HEAD `6a96398`, clean tree.
**Question (all n):** Does every `n`-element antichain admit a height-`S(n)` comparison tree in which every internal node's chosen comparison satisfies the node-local condition `d(P)+F(P) <= S(n)` (local viability)? Equivalently, can an optimal global tree be built using only locally viable states, or does optimal-play reachability require a stricter ancestor condition?

**Result (short):** Yes. For `n=3..6` a constructive search finds an optimal comparison tree all of whose internal nodes are locally viable (`can_build_root=True`). In fact this holds for all `n` by a short argument: every state occurring in any optimal height-`S(n)` tree is locally viable, because its BFS depth `d(P)` is at most its tree depth. Thus the refutation direction fails: the local condition is not too weak to construct a tree. What remains stricter is *classification* of states: local viability `(c)` over-approximates optimal-play reachability `(d)`, as the viable-counting front already showed (`700` labelled failures at `n=5`, `7500` at `n=6`).

## 2. Definitions and method

State = transitively closed labelled poset `P` on `[n]`, `succ[i]` bitmask of elements strictly greater than `i`. Root = antichain `(0,...,0)`.

- `F(P)` = exact minimax remaining comparisons (`minimax`); `F(root)=S(n)`.
- `e(P)` = number of linear extensions (not needed for this question).
- `d(P)` = BFS distance from the antichain root in the poset lattice, where an edge adds one comparison outcome. This is the most permissive (shortest) depth.
- Locally viable `(c)`: `d(P)+F(P) <= S(n)`.
- Optimal comparison at `P`: `F(P)=1+max(F(P+i<j), F(P+j<i))`.
- Optimal-play reachable `(d)`: occurs in the all-optimal DAG.

**Constructive search.** Define `build(P)`:
- if `P` is total: success;
- otherwise, for each incomparable pair `(i,j)`, compute children `L,R`;
- keep the comparison only if it is optimal at `P` and both `L,R` are locally viable;
- succeed if some such comparison has `build(L)` and `build(R)` both true.

Memoized over states. This asks exactly whether an optimal tree can be assembled using only locally viable nodes. Also computed viable counts as a cross-check.

## 4. Construction / obstruction

**Construction principle (all n).** Take *any* optimal height-`S(n)` comparison tree. At a node at tree depth `t` with state `P`:

- `d(P) <= t` (BFS depth is shortest, so no larger than the actual path length);
- the subtree below `P` has height at most `S(n)-t`, and is a valid sorting tree, so `F(P) <= S(n)-t`.

Hence `d(P)+F(P) <= t + (S(n)-t) = S(n)`. Every internal node is locally viable. Therefore the refutation direction is impossible for every `n`, and the constructive search above merely verifies the finite cases.

**Why (c) is not enough for classification.** Local viability is a single-state condition; optimal-play reachability is a path condition requiring every ancestor comparison to be minimax-optimal. The viable-counting front quantified this gap: `(c)` states that are not `(d)` are `700` at `n=5` and `7500` at `n=6` (unlabelled: `10`, `23`). So `(c)` over-approximates `(d)`, but it does contain at least one optimal tree's nodes, so it is sufficient for *existence* of a viable optimal tree.
