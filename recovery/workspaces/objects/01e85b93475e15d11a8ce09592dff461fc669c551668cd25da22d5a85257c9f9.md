# Framed DAG witness for n=6 at exact height S(6)=10 (exec-report)

**Status:** computational/experimental report (no completion claimed for the open problem). Claims below are **experiment** or **deduction from tool output** unless marked otherwise.

## 1. Problem statement and S(6) baseline

- **Open target (SoringP1 #301, unary focus):** characterize/determine the uniform complexity of optimal adaptive comparison sorting via `S(n)` / `SORT-BOUND-U = {1^n # 1^k : S(n) ≤ k}` (see `docs/problem.md`, `AGENTS.md`).
- **Front (this run):** `framed-dag-witness-n6-exact` (falsifiable, independent). Question: does there exist an explicit, checkable permutation-framed strategy DAG certificate of exact height `S(6)=10` for `n=6`, and what is its concrete size/depth/profile compared to polynomial envelopes?
- **Certificate format/checker:** acyclic comparison strategy DAG with per-edge slot permutations and partial-order propagation/intersection at joins, checked by `scripts/check_framed_strategy.py` (soundness as implemented; polynomial in explicit graph size and `n` per script/doc). See `docs/research-framed-certificate-frontier.md`.
- **Baseline (literature, recorded in repo):** `S(6)=10` (`docs/problem.md`, `scripts/strategy_dag_probe.py` `KNOWN[6]=10`; consistent with `scripts/evaluate.py` model). An information lower bound is `ceil(log2(6!))=10`.

Construction method (experiment): exact minimax over transitively closed posets (successor bitmasks) for `n=6` to obtain `F(empty)=S(6)` and, for each reachable state in one chosen optimal policy, a comparison `(i,j)` with `1+max(F(P+i<j),F(P+j<i))=F(P)`. Serialized as an **unshared decision tree** in the framed-certificate JSON format with forward edges, `lt` = outcome `i<j`, `gt` = outcome `j<i`, and identity slot permutations on every edge (no relabelling, no join merges). Each leaf is a total order reached within budget 10.

## 3. Concrete results / witness

**Result:** produced and saved an explicit, checkable permutation-framed strategy DAG certificate for `n=6` at exact height budget `10`.

- Witness file: `witness_n6_h10_tree.json`
- Measurements/data: `witness_n6_h10_measurements.json`
- Format: `{"n":6,"budget":10,"nodes":[ ... ]}` accepted by `scripts/check_framed_strategy.py`.

**Checker output (evidence):**
```
ACCEPT: n=6, depth=10, nodes=1439
```

**Exact counts/profile (from construction/measurement):**
| Quantity | Value |
|---|---:|
| `n` | 6 |
| `S(6)` (computed by minimax, matches baseline) | 10 |
| certificate budget | 10 |
| verified depth (longest reachable path) | 10 |
| total nodes | 1439 |
| internal (comparison) nodes | 719 |
| leaf nodes | 720 (= 6!) |
| directed edges | 1438 (= 2 × internal, tree) |
| root comparison | `[0,1]` |

**Nodes per depth level:** `{0:1, 1:2, 2:4, 3:8, 4:16, 5:32, 6:64, 7:128, 8:240, 9:416, 10:528}` (a full binary expansion through depth 7, then narrowing as states become total earlier on some branches but depth capped at 10).

**Structural observations (experiment):**
- The witness is a pure unshared decision tree with identity permutations and no DAG join/merge nodes in the framed-certificate sense (each comparison node has out-degree 2 to distinct forward children; 720 distinct leaves correspond to the 6! permutations).
- For this chosen single optimal policy, the **hash-consed poset-state DAG** (sharing identical successor-bitmask posets) has **1439 nodes** as well — i.e. no poset-state repetition occurred along this optimal policy (`hash_cons_poset_dag_single_policy_nodes = 1439`, `hash_cons_poset_dag_single_policy_leaves = 720`). Thus poset-equality sharing alone gives no compression for this witness/policy at `n=6` (cf. `n<=5` probe where `unshared(1)==DAG(1)` for the probed single policies).
- Compared to polynomial envelopes for *non-optimal* constructions in `docs/research-framed-certificate-frontier.md` (e.g. bubble/triangular `O(n^2)` comparison nodes at quadratic path length, merge-sort merge-DAG `O(n^2)` nodes at `O(n log n)` path length): this exact-height-`S(6)` witness is a depth-10, 1439-node tree — concrete and small at fixed `n=6`, but it is an optimal decision tree with `n!` leaves, not evidence of a polynomial-size all-`n` certificate at height `S(n)`. No all-`n` completeness claim follows.

## 4. Verification performed

- `python3 scripts/check_framed_strategy.py --bubble 4` → `ACCEPT: n=4, depth=6, nodes=7` (sanity check of tool).
- `python3 scripts/check_framed_strategy.py witness_n6_h10_tree.json` → `ACCEPT: n=6, depth=10, nodes=1439` (witness sound per checker: local outcome/frame checks, transitive-closure propagation, intersection-at-joins logic, leaf total-order checks, depth ≤ budget).
- Minimax recomputation gave `S(6)=F(empty)=10` for `n=6` (consistent with known baseline).
- Independent of Lean/kernel checking; this is an explicit-certificate check only.

## 5. Open questions / next falsifiable step

- **Merges/sharing:** can a framed strategy DAG with nontrivial joins (intersection) or non-identity permutations represent an exact-height-10 strategy for `n=6` with **fewer than 1439 nodes**? Falsifiable by constructing a smaller certificate that still passes the checker at budget 10.
- **Policy dependence:** does any other single optimal policy for `n=6` admit poset-state sharing (`DAG(1) < unshared(1)`) or a smaller framed DAG after relabelling/joins?
- **All-optimal union / symmetry quotient:** measure `DAG(all)` and `S_n`-quotient sizes for `n=6` (feasible next experiment) to compare with the `n<=5` data in `strategy_dag_probe.py`.
- **Scaling (frontier, not resolved):** does there exist a family of polynomial-size, sound framed certificates at exact height `S(n)` for all `n`? A positive all-`n` theorem would imply `SORT-BOUND-U ∈ NP` (per `docs/research-framed-certificate-frontier.md`); this report provides only a concrete `n=6` instance and does not address all-`n`.
- **Next falsifiable step:** attempt to synthesize a join-merged framed DAG for `n=6, k=10` (e.g. by aligning isomorphic subproblems via permutations and intersecting guarantees) and verify with `scripts/check_framed_strategy.py`, comparing node count to 1439.
