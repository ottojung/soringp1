# exec-report: framed-DAG witness for n=4 at height 5

## 1. Problem statement and S(4) baseline

- **Target:** `SORT-BOUND-U` instance for `n=4`, i.e. whether `S(4) <= 5`.
- **Known exact value (literature/Lean `SmallValues`):** `S(4) = 5`.
- **Information lower bound (definition):** `ceil(log2(4!)) = ceil(log2 24) = 5`, so no
  comparison strategy can sort 4 distinct labelled keys in fewer than 5 worst-case
  comparisons. Hence an upper-bound witness of height 5 is exact.
- **Question addressed:** Does there exist an explicit, checkable
  permutation-framed strategy DAG certificate of height exactly `S(4)=5` for `n=4`,
  and what is its size/depth/profile?

This report does **not** claim any new all-`n` theorem. It supplies a finite,
checker-verified witness at the exact optimal height.

## 2. Methods, tools, and commands

Tools used:
- `scripts/check_framed_strategy.py` — polynomial-time soundness checker for framed
  comparison DAGs (transitive closure, permutation frames, infeasible-branch pruning,
  DAG joins by intersection, depth accounting, leaf totality).
- `scripts/strategy_dag_probe.py` — reference poset-state minimax DAG sizes for
  comparison of node counts.
- Known exact values `S(4)=5` from the repository's Lean/library baseline.

Construction method:
1. Start from the standard 5-comparator sorting network for 4 elements:
   `(0,1), (2,3), (0,2), (1,3), (1,2)` (0-indexed slots).
2. Encode each comparator as a compare-exchange: on `lt`, identity permutation;
   on `gt`, swap the two compared slots. This guarantees that after each
   comparator the smaller compared value occupies the lower slot.
3. Expand the network as a full binary decision tree of depth 5 (63 nodes), then
   quotient nodes whose incoming guaranteed relations are identical. Nodes are
   shared only where the checker's join preserves the needed relation; two leaves
   remain because they represent two distinct final total orders.
4. Verify the resulting 9-node DAG with the soundness checker.

Commands run:

```sh
python3 scripts/check_framed_strategy.py witnesses/framed_dag_n4_height5.json
python3 -m unittest tests.test_framed_strategy tests.test_strategy_dag
```

## 3. Concrete results / witness

Saved witness: `witnesses/framed_dag_n4_height5.json`  
Saved measurements: `witnesses/framed_dag_n4_height5.measurements.json`

Checker result:

```text
ACCEPT: n=4, depth=5, nodes=9
```

Measurements:
- `n = 4`
- verified height / worst-case depth = `5 = S(4)`
- budget = `5`
- nodes = `9`
- edges = `14` (7 internal nodes, each with 2 outgoing edges)
- internal nodes = `7`
- leaves = `2`
- distinct final total-order classes = `2`

Structure:
- Depth 0: 1 node, comparator `(0,1)`.
- Depth 1: 1 node, comparator `(2,3)`.
- Depth 2: 1 node, comparator `(0,2)`.
- Depth 3: 2 nodes, comparator `(1,3)`.
- Depth 4: 2 nodes, comparator `(1,2)`.
- Depth 5: 2 leaf nodes.

The first three comparators are shared across all outcome histories because their
compare-exchange permutations make the guaranteed relation after each comparator
independent of the branch. The two branches split at depth 2 and again at depth 3,
reflecting two genuinely different guaranteed relations; they rejoin partially at
depth 4/leaves where relations coincide.

Comparison with baselines:
- Triangular bubble certificate for `n=4`: 7 nodes but depth/budget `6`, not
  optimal.
- Unquotiented network tree: 63 nodes, depth 5.
- Leaf-sharing only: 32 nodes, depth 5.
- Quotiented framed DAG: 9 nodes, depth 5.
- Poset-state single-policy DAG (`strategy_dag_probe.py`) for `n=4`: 47 labelled
  poset states; its symmetry quotient has 7 classes. The framed DAG has 9 nodes,
  close in scale but not a direct node-for-node correspondence because framed nodes
  carry slot permutations and may represent joins.

This witness is polynomial in size for this fixed `n` (constant 9 nodes), but it
is a finite construction. It does not by itself establish an all-`n`
polynomial-size framed certificate.

## 5. Open questions / next falsifiable step

1. **Minimality:** Is 9 the minimum number of framed-DAG nodes for an exact
   height-5 certificate at `n=4`, or can a different 5-comparison strategy (or
   a different quotient) use fewer? A brute-force search over framed DAGs up to
   8 nodes would falsify or confirm minimality.
2. **All-`n` scaling:** Does the quotiented compare-exchange construction scale
   to polynomial size for all `n` while preserving exact height `S(n)`? The
   standard sorting-network construction gives `O(n^2)` comparators and height
   `O(n log n)`, but exact `S(n)` is lower than network depth for large `n`;
   exactness is the unresolved part.
3. **Join safety:** The 9-node DAG relies on joins of identical guaranteed
   relations. Documenting which joins are equality joins versus lossy joins may
   help identify a general "join-safe" normal form.

Next falsifiable step: attempt a height-`S(5)=7` framed DAG for `n=5` using the
same quotiented compare-exchange method, measure node/edge/depth counts, and check
whether the node count follows the `n=4` pattern or explodes. If it explodes or
fails verification, that is evidence against naive network-quotient certificates
for exact optimal height.
