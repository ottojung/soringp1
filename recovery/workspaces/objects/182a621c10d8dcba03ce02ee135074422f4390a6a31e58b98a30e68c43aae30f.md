# T(6) uniform tightness threshold (all finite posets): evidence report

**Task question.** Is the universal tightness threshold `T(6)` exactly `33`, i.e. does every finite poset `P` with `e(P) <= 33` satisfy `m(P) <= 6`? Falsifier: a finite poset with `e(P) <= 33` and `m(P) >= 7`.

**Model/notation** [definition]. `e(P)` = linear extensions; `m(P)` = exact minimax comparison depth from state `P`; `T(r) = max{E : e(P)<=E => m(P)<=r}`.

## Result

**No counterexample found. `T(6) = 33` is supported by exact enumeration.**

Independent re-run of the core census (`exec-core-threshold-review-20261107/scripts/core_threshold_census.py --E 33 --h 6`), in a clean checkout of this worktree's base, produced:

- 1,053 cores with `e(P) <= 33` (levels `n=2..33`, counts `1,2,8,31,106,201,244,172,99,52,32,24,19,18,19,5,5,1,1,...,1`);
- **0 failures** at comparison budget 6 (every core sortable in `<= 6` comparisons).

Upper witness: the staircase `S_8` has `e = 34`, `m = 7`, so `T(6) <= 33`. Hence `T(6) = 33` exactly.

## Why this is a complete enumeration (not just sampling)

- [paper proof, `research-core-threshold.md` §1] Lemma 1: universal elements do not change `e` or `m`, so every poset reduces to a core with identical `(e,m)`. Thus a core census decides `T(r)`.
- [paper proof, §2-3] Lemma 4: every core is generated from the 2-antichain by (i) adjoining a maximal element above a proper ideal of a core, or (ii) ordinal sums; Lemma 5: every core has `e(P) >= |P|`, so cores with `e <= 33` have at most 33 elements and level-by-level generation up to size 33 is complete.
- [experiment] The generator's minimax decision procedure `sortable(exts, budget)` is the exact comparison game on extension sets with the sound information pruning `max child size <= 2^(budget-1)`; controls match known values (antichain4->5, Merge(2,4)->5, etc.).
- [literature/experiment] Dual-generator cross-check (Viche Executive, board #301, 2026-11-07) agreed exactly on the complete `E=33` set (1,053 classes) and `E=54` set (4,829 classes).

## Falsifier outcome

Attempted to exhibit a finite poset with `e(P) <= 33` and `m(P) >= 7`. **Not found.** The enumeration exhausts all cores (hence all posets) in range.

## Honest limits

- This is a **finite verified instance**, not a proof of the all-`n` Fibonacci statement `e(P) >= F_{m(P)+2}` (equivalently `T(r)=F_{r+3}-1` for all `r`). That statement reduces to the unproved balancing Lemma A (every poset with `m>=2` has a comparison whose two children both have depth `>= m-2`), which remains open. The finitely verified `r=2..7` do not imply it.
- No complexity-class consequence: `T(r)` bounds concern the minimax game on partial orders; the root state of `S(n)` is the antichain with `e=n!`, far outside this threshold range for `n>=6`.
- The census is conditional on implementation faithfulness; the ranges `n=9..33` rest on the generator (audited against an independent all-poset enumeration only through `n=8`, plus dual-generator agreement on the full set).

## Conclusion

`T(6) = 33` exactly: every finite poset with `e(P) <= 33` is sortable in 6 comparisons, and `S_8` (`e=34`) is not. Falsifier direction (counterexample) not met; proof direction rests on the paper reduction plus exact enumeration, with the all-n Lemma A still open.
