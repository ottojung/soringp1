## Reconstructed argument

Model [definition]: S(n) is the minimum worst-case number of adaptive pairwise comparisons to sort n distinct labelled keys (n-antichain minimax value). S(n) is attained by some decision tree T_n^* of height S(n) (finite minimum over finite trees).

Claim: S(n+1) - S(n) <= ceil(log2(n+1)) for all n>=2, equivalently S(n+1) <= S(n) + ceil(log2(n+1)).

Proof [paper proof, independently reconstructed]:

1. Let T_n^* be an optimal sorting tree for n keys, height S(n).
2. Construct a tree T_{n+1} for n+1 keys:
   a. Phase 1: run T_n^* on a chosen subset of n "old" keys, comparing only old keys. These comparisons are valid in the (n+1)-key setting and their outcomes are independent of the (n+1)-th key. After S(n) comparisons the total order of the old keys is known. Worst-case cost S(n).
   b. Phase 2: insert the remaining "new" key into the now-sorted list of n old keys by binary search. There are n+1 possible insertion positions; binary search finds the position in at most ceil(log2(n+1)) comparisons (verified: standard mid=floor((lo+hi)/2) binary search has worst-case exactly ceil(log2(n+1)) for m=n+1 positions; checked n=1..200).
3. T_{n+1} sorts all n+1 keys with worst-case cost <= S(n) + ceil(log2(n+1)). Hence S(n+1) <= S(n) + ceil(log2(n+1)), i.e. S(n+1)-S(n) <= ceil(log2(n+1)).

Soundness [deduction]: The construction is a legitimate adaptive comparison tree for n+1 distinct labelled keys; phase 1 uses only comparisons among old keys (valid), phase 2 uses comparisons between the new key and old keys (valid). The cost bound is a worst-case bound (phase 1 always S(n) by using an optimal tree; phase 2 at most ceil(log2(n+1))). Since S(n+1) is the minimum worst-case cost, the inequality follows.

## Gap naming (minor, non-fatal)

- The original post's sentence "The insertion game has n+1 outcomes, so any insertion tree has depth >= ceil(log2(n+1))" is the information-theoretic *lower* bound for insertion; it is not needed for the *upper* bound (which uses binary search achieving that value). It is correct but slightly mixes lower/upper reasoning. No effect on validity.
- "standard binary search attains ceil(log2(n+1))" is true for the simple mid=floor((lo+hi)/2) variant, as verified computationally (n=1..200). (For some split variants the bound may be off by one; the simple variant is the one achieving it.) The post should name the variant, but the claim holds.
- Existence of an optimal tree T_n^* of height exactly S(n) is required; this is standard (finite min over finite trees) and Lean-checked in this repo as attainment (SoringP1/Attainment.lean). No issue.
- The proof gives a weak, non-optimal upper bound (insertion sort style); it does not improve on Ford-Johnson or imply anything about S(n) beyond S(n)=O(n log n), already known. It is a true but elementary inequality.

## Lean formalization note

If formalized, the needed pieces are: (i) existence/attainment of an optimal comparison tree of height S(n) (already in SoringP1/Attainment.lean); (ii) validity of running an n-key tree on a subset of an (n+1)-key input (permutation symmetry / relabelling); (iii) binary search cost lemma ceil(log2(n+1)) for insertion (finite, could be proved by induction or by the information lower bound + construction). The cost bridge is the main obligation: Lean's height S(n) is a natural number, and the construction composes trees, so a theorem S(n+1) <= S(n) + ceil(log2(n+1)) is a clean arithmetic statement once the tree-composition lemma is in place. No model-fidelity issue: S is the function, keys distinct labelled, adaptive trees. No new axiom or sorry needed.
