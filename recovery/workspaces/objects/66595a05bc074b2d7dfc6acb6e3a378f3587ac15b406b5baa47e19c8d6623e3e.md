## 1. Lemma A: fixed-variable FO(TC)_v combined complexity

### 1.1 Syntax/semantics and fixed global variable set

The fragment fixes `v >= 2` once for the whole query-program fragment (not per subformula). All bound and free variables, including nested TC formulas and additional local bound variables, are drawn from the same globally fixed set of at most `v` names, with `a+2m <= v` at TC nodes (`a` context width, `m` endpoint width). This is a standard finite-variable restriction (in the spirit of `FO^v`/fixed-variable fragments), and it is stated explicitly. The semantics of `[TC_{x,y} theta](s,t)` as reflexive transitive closure, separately for each fixed assignment to context `z`, is clear. Reflexive-transitive versus transitive closure does not affect the polynomial evaluation claim.

**Assessment:** sound as a definition. The requirement that any formula with extra local bound variables must fit in the same global set prevents hidden variable reuse beyond `v`; alpha-renaming within those `v` names is harmless.

### 1.2 Explicit tabulated relations and arity

Input structures have domain size `N = Theta(n+k+1)`, fixed relational vocabulary of arity at most `v`, and explicitly tabulated input/store relations; oracle/succinct relations are excluded. This is the right explicit-encoding assumption for a combined-complexity/evaluation bound. It also makes initial store/history construction `O(N^v)+O(|p|)` plausible.

**Assessment:** sound, with the usual schematic caveat that the exact vocabulary encoding of keys/positions/query history is not fully spelled out. That caveat does not create a refuting gap for the core claim: *for any* explicit structure of this form and *any* `FO(TC)_v` formula of the stated syntax, evaluation is polynomial as claimed.

### 1.3 Table memoization and counting

The proof uses bottom-up truth tables memoized by syntax occurrence and assignment to that subformula’s free variables, with no re-evaluation inside a parent loop. For a subformula with `f <= v` free variables this gives `N^f` entries. Atomics scan assignments and look up explicit relation tuples; Booleans are entrywise with harmless projection/renaming; first-order quantifiers scan `N` values per assignment, `O(N^(f+1)) <= O(N^(2v))`.

**Assessment:** sound. The syntax-occurrence memoization is the key point that avoids recomputing a child under many parent assignments. In a tree representation each node is charged once; in a DAG/occurrence model the stated memoization gives the same total effect.

### 1.4 TC Floyd–Warshall cost and `a+3m <= 2v`

For a TC node, `a+2m <= v`. For each of `N^a` contexts, the graph has at most `N^m` endpoint nodes, so Floyd–Warshall gives `O(N^(3m))` per context and edge-table construction/lookups are `O(N^(a+2m))` total (or per-context as organized by the proof’s table access). Thus `O(N^a * N^(3m) + N^(a+2m)) = O(N^(a+3m))`.

The inequality in the document is
`a+3m <= 2(a+2m) <= 2v`.
This is algebraically valid: `2(a+2m)-(a+3m)=a+m >= 0`, and `a+2m <= v`. A tighter direct bound is also available (`a+3m <= v+m <= 3v/2` since `m <= (v-a)/2`), so the stated `2v` exponent is safe.

The proof must assume that all edge answers `theta(source,target,context)` are available from the memoized table for `theta`. This is true because `theta` is a subformula evaluated bottom-up and its free variables are contained in the global `v`-set; thus one table over assignments to `theta`’s free variables supplies every needed edge for every context/source/target. Nested TC nodes are handled the same way by bottom-up memoization.

**Minor exposition repair (optional but helpful):** state explicitly that `theta`’s truth table is materialized/indexed so that, for fixed context and endpoints, edge membership is obtained by table lookup/projection from the already-computed subformula table. The cost bound is intended to include this access pattern under the stated indexing model.

**Assessment:** mathematically sound. No refuting gap.

### 1.5 Unit-cost indexing assumption

The proof states the standard unit-cost table-indexing assumption for `O(log N)`-bit tuple indices, or the conventional deterministic RAM/TM implementation with a polylogarithmic factor absorbed by `N^epsilon`. It also notes counting table accesses as unit-cost operations to retain the literal exponent.

**Assessment:** sound and appropriately disclosed.

### 1.6 Clock/total-runtime accounting

Here a precision repair is needed.

- Definition: `T=(n+k+|p|+2)^c` is introduced for fixed `c`, and the verifier simulates `U` for at most `T` charged steps.
- Lemma A proof: “Choose the fixed clock exponent `c` large enough to dominate that overhead…” and total runtime is `T` times a per-evaluation polynomial.
- Corollary: `QWIN_{v,c}` is claimed in `Sigma_2^P` for any fixed polynomial bound `b(n+k)` and fixed verifier clock exponent as above.

The tension is that `c` is described as fixed, but the proof language reads as choosing `c` after inspecting overhead. Also “charged steps” can be read as counting one expensive FO(TC)_v evaluation as one step, which would be misleading unless the cost model is defined accordingly.

**Exact repair:** define the verifier with a universal fixed clock exponent `c_{v}` (depending only on the fixed fragment parameter `v` and the fixed machine/evaluation implementation, not on `n,k,p,phi`) large enough to cover: parsing `p`, constructing explicit tables, at most polynomially many rule applications, each rule’s FO(TC)_v evaluation `O(|phi|N^{2v})` under the stated indexing model, store/history updates, permutation validation, and final output check. Alternatively, state `QWIN_{v,b,g}`/`QWIN_{v,c}` with `c` quantified as “there exists a fixed `c` (equivalently, a fixed polynomial time bound) for the fragment such that…” and avoid presenting `c` as both arbitrary/fixed and chosen later. The text’s final sentence in the paragraph (“polynomial verifier clock, not a claim that the whole program costs just one formula-evaluation bound”) is directionally correct and should be retained.

**Impact:** minor repair. It does not refute polynomial-time verification; it repairs the formal shape of the clock parameter.

### 1.7 No FO(TC)=NL capture misuse

The document explicitly states: “The `FO(TC)=NL` capture theorem is not used.” It cites Immerman only as background and proves the combined bound directly by table construction/Floyd–Warshall. This is correct, because Immerman’s FO(TC)=NL capture concerns fixed formulas on ordered finite structures in the data-complexity/capture setting, not the needed combined program/formula/structure bound in this verifier argument.

**Assessment:** sound.

## 2. Lemma B: scoped barriers

### 2.1 B1 (explicit trees)

A correct comparison sorting tree for `n` distinct keys has at least `n!` leaves, because distinct permutations reaching the same leaf would receive the same total-order output and be wrong for at least one permutation. Therefore any compiler that emits the explicit optimal tree outputs `Omega(n!)` nodes.

**Assessment:** sound (standard Knuth/decision-tree counting). Correctly scoped to explicit tree emission.

### 2.2 B2 (two specified methods)

First method: a greedy child-`e` selector that chooses `{x,y}` minimizing `max(e(P+xy),e(P+yx))` by explicitly counting linear extensions invokes `e(P)`. Brightwell–Winkler (1991) is used only for #P-completeness of that explicit counting function. The document explicitly does **not** infer that the exact minimax recurrence
`F(P)=1+min_{x,y} max(F(P+xy),F(P+yx))`
needs `e(P)`, and does **not** claim exact minimax evaluation or optimal comparison selection is #P-hard.

Second method: the winning-frontier barrier (`docs/research-winning-frontier-barrier.md`) exhibits `2^{(1/4-o(1)) n (log n)^2}` nonisomorphic winning posets at a common depth (including the exact-optimal-budget extension in that note). The audit of the cited note’s statement is consistent with the use here: it rules out methods whose work requires explicitly listing the entire frontier at that depth, even modulo isomorphism. It does not force every memoizing/selective/symbolic/parametric method to enumerate those states and is not a time/space/hardness lower bound for computing `S(n)`.

**Assessment:** sound and properly scoped. The conclusion “scoped method barriers, not a hardness claim about computing `S(n)` or about the sparse unary `SORT-BOUND-U`” is correct.

## 3. Conditional/non-claims and model discipline

The document’s conditional and negative claims were checked:

- **Sigma2^P claim is restricted:** only for the represented subclass/predicate `QWIN_{v,c}` (or the corresponding fixed-bound restricted language), defined by `exists` polynomial-size program / `forall` permutation / polynomial-time verifier. **Soundness** is stated: acceptance implies `S(n)<=k`. **Completeness for unrestricted `SORT-BOUND-U` is OPEN** and repeatedly disclaimed.
- **No unrestricted claims:** no NP or Sigma2^P membership for unrestricted `SORT-BOUND-U`; no completeness for unrestricted `SORT-BOUND-U`; no hardness of computing `S(n)`; no unrestricted-FO(TC) polytime evaluation.
- **Sparsity/Mahaney caution:** the document states “no unconditional lower bound for the sparse unary language is claimed” and follows `AGENTS.md`/project constraints. This is the essential caution in context. A small strengthening could cite Mahaney explicitly (many-one NP-hardness of a sparse language would imply P=NP), but absence of that citation is not a refuting gap and does not weaken the existing non-claims.
- **Model fidelity:** uses the adaptive comparison-sorting model, decision language `SORT-BOUND-U`, and treats `S(n)` as the numeric function/threshold target consistently with `docs/problem.md`. No binary-encoding overclaim and no sorting-network/advice confusion is introduced.

**Assessment:** sound as stated.
