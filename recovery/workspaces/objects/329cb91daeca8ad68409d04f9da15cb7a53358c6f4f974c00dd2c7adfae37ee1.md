## 4. No `M_Eval+Ret*` marker on consuming top `[deduction][falsification]`

**Claim.** Under (E3), no consuming `M_Eval`-top state has `RetAcc` or
`RetRej`:
```text
I_{M_D}(E) ∧ EvalTop(E,c̄) -> RetNone(E,c̄) (on the consuming eval domain)
                         -> ¬(RetAcc(E,c̄) ∨ RetRej(E,c̄)).
```

**Row-level justification.** Rows 2–7 all read `M_Eval(c̄)` at `Top(c̄)` and
either require `RetNone` explicitly (row 6,7) or consume eval evaluation
terminals whose local semantics are defined for eval states; (E3) forbids a
reachable consuming eval top carrying a return marker. `MarkRetAccOn/MarkRetRejOn`
are applied by pop-return rows to Back* receivers `p̄` (rows 4,5 apply to `p̄`
after popping `c̄`, not as eval markers on `c̄`), and eval children/templates
set `RetNone`.

**Falsifier shape.** `[falsification]`
```text
I_{M_D}(E*) ∧ Top(E*,c̄) ∧ M_Eval(E*,c̄) ∧ (RetAcc(E*,c̄) ∨ RetRej(E*,c̄)).
```
This is the normalized `No_Eval_RetMarker_Top` witness: it falsifies eval/return
separation and can make eval consumption overlap or leave a gap if no row
consumes such a top.

## 5. `CtrlSort_Exhaustive_On_IMD` with BackE v2 NI/NNI `[deduction][open][falsification]`

Let
```text
Guard_pre(E,c̄) := EvalTop(E,c̄) ∧ M_Eval(E,c̄) ∧ CtrlSort(E,c̄) ∧ RetNone(E,c̄).
```

**Lemma schema (`CtrlSort_Exhaustive_On_IMD`, v2).** `[open]` For every
`I_{M_D}`-reachable `E` and unique consuming top `c̄`,
```text
Guard_pre(E,c̄) ->
    CfgAcc_c(E,c̄)
  ∨ RejectEval_c(E,c̄)
  ∨ (¬Total_c(E,c̄) ∧ Budget_c(E,c̄) ∧ NI_c(E,c̄)),
```
and the three disjuncts are pairwise disjoint on `I_{M_D}`-reachable
`Guard_pre` states.

**Proof shape (conditional).** `[deduction]`
- `CfgAcc_c` is a terminal accept branch.
- Otherwise, if `CfgRej_c` or `CtrlSort∧¬Total_c∧¬Budget_c`, then
  `RejectEval_c` holds by its first/second disjunct.
- Otherwise, under `CtrlSort∧¬Total_c∧Budget_c` and (E5),(E6), the cursor is
  coherent and gives either `NI_c` or `NNI_c`: `NI_c` is
  `¬CurExhausted ∧ CurNormalState ∧ ∃x∃y NextIncomp_c` (row 6 branch);
  `NNI_c` is `CurExhausted ∨ (¬CurExhausted ∧ CurNormalState ∧ NoNextIncomp_c)`
  (third `RejectEval_c` branch, fix-1 path to rows 3/5). `CurExhausted` is
  excluded from `NI_c` and routed to `NNI_c`.
- Pairwise disjointness is intended by local semantics: `CfgAcc_c` vs reject
  forms, and the non-terminal `CtrlSort` pick form requires `¬Total_c∧Budget_c`
  and `NI_c` while reject's third disjunct requires `NNI_c` in that form.
  Formal exclusion of `CfgAcc_c` from reject/NI branches is an (E7)/(I_M_D)
  semantic obligation.

**Fix-1 NNI reject path to rows 3/5.** `[deduction]` Row 6 is NI-only:
`D_sort_pick` requires `NI_c`. Therefore `NNI_c` in the `CtrlSort,¬Total_c,
Budget_c` case is not consumed by row 6 and must be consumed by `RejectEval_c`:
row 3 if `Root(c̄)`, row 5 if `NonRoot(c̄)`. This is the normalized fix-1
replacement for the misleading “row 6 handles no-next” text.

**Falsifier shapes.** `[falsification]`
```text
-- CtrlSort exhaustivity gap
I_{M_D}(E*) ∧ Guard_pre(E*,c̄)
∧ ¬CfgAcc_c(E*,c̄) ∧ ¬RejectEval_c(E*,c̄)
∧ ¬(¬Total_c(E*,c̄) ∧ Budget_c(E*,c̄) ∧ NI_c(E*,c̄)).

-- NI/NNI non-total or CurExhausted leak into NI
I_{M_D}(E*) ∧ Guard_pre(E*,c̄) ∧ CtrlSort(E*,c̄) ∧ ¬Total_c ∧ Budget_c
∧ ( (¬NI_c ∧ ¬NNI_c) ∨ (NI_c ∧ NNI_c) ∨ (CurExhausted(c̄) ∧ NI_c) ).

-- fix-1 miss: NNI reaches sort-pick or no eval row
I_{M_D}(E*) ∧ Guard_pre(E*,c̄) ∧ CtrlSort(E*,c̄) ∧ ¬Total_c ∧ Budget_c ∧ NNI_c
∧ (D_sort_pick(E*,c̄) ∨ (¬D_root_rej(E*,c̄) ∧ ¬D_eval_rej_ret(E*,c̄))).

-- CtrlSort overlap
I_{M_D}(E*) ∧ Guard_pre(E*,c̄) ∧
( (CfgAcc_c ∧ RejectEval_c) ∨ (CfgAcc_c ∧ D_sort_pick) ∨ (RejectEval_c ∧ D_sort_pick) ).
```

## 6. Pairwise disjoint total consumption of `M_Eval` tops (rows 2–7) `[deduction][open][falsification]`

Define eval row classes on `EvalTop(E,c̄)`:

### 6.1 Pairwise disjointness (schema/semantic obligations)

`[deduction][open]`
- `A` vs `R`: terminal accept vs reject-eval are intended disjoint by (E7);
  otherwise overlap is a semantic falsifier.
- `A` vs `P`: `P` requires `¬Total_c∧Budget_c∧NI_c` in `CtrlSort` search mode;
  if `CfgAcc_c` can hold there, local eval semantics conflict (falsifier).
- `A` vs `V`: `V` is `CtrlAdv` with selected incomparable pair; `CfgAcc_c` is a
  terminal/eval-accept class — disjoint by control/semantic discipline (E2,E7).
- `R` vs `P`: in the `CtrlSort,¬Total_c,Budget_c` region, `RejectEval_c` uses
  `NNI_c` while `P` uses `NI_c`; BackE v2 gives `NI_c => ¬CurExhausted` and
  `NNI_c`/`NI_c` complementary form, so `R∧P` is excluded modulo E5,E6.
- `R` vs `V`: `CtrlSort`-based `RejectEval_c` disjuncts require `CtrlSort`;
  `V` requires `CtrlAdv`; `ExactlyOneCtrl` (E2) excludes both. `CfgRej_c`
  overlap with `CtrlAdv` is a control/semantic falsifier.
- `P` vs `V`: `P` requires `CtrlSort`; `V` requires `CtrlAdv`; `ExactlyOneCtrl`
  excludes.

## 7. Verdict `[deduction][open]`

focused rows 2–7, the normalized `Enc` + fix 1 + BackE v2 NI/NNI discipline
provides a coherent pairwise-disjointness argument: row 1 absorbs halts; rows
2–5 consume `M_Eval` terminal accept/reject by `Root/NonRoot`; row 6 is

stated `I_{M_D}` assumptions (E0–E7), this gives `CtrlSort_Exhaustive_On_IMD`
and a total pairwise-disjoint partition schema for consuming `M_Eval` tops by
`A/R/P/V`.

**Not proved/refuted by an explicit `I_{M_D}` witness here.** No explicit
`I_{M_D}`-reachable falsifying witness was found in the audited refs. The
claims remain `[open]` as `I_{M_D}` reachability/semantic obligations where
assumptions E2–E7, cursor coherence on eval tops, parent functionality for
non-root pop rows, and local semantic disjointness/totality of
`CfgAcc_c/RejectEval_c/Total_c/Budget_c/Incomp_c/Ctrl` are not discharged.

**Refutation trigger.** Any explicit `I_{M_D}`-reachable witness matching a
falsifier in §§4–6 refutes the corresponding target-3 claim at the named locus
