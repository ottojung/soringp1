# Framed DAG witness attempt for n=10 (exact height S(10)=22)

## 1. Problem statement and S(10) baseline

- **Task/front:** `framed-dag-witness-n10-exact` (falsifiable, independent). Question: does there exist an explicit, checkable permutation-framed strategy DAG certificate of exact height `S(10)=22` for `n=10`, and what is its concrete size/depth/profile compared to polynomial envelopes (e.g. `O(n^2)` nodes, `O(n log n)` path length)?
- **Model/certificate grammar (from `docs/research-framed-certificate-frontier.md`, `scripts/check_framed_strategy.py`):** A certificate is an acyclic directed graph of comparison instructions on `n` slots. Root has empty guaranteed strict order `R`. Each non-leaf node compares `(a,b)` and has `lt` (`a<b`) and `gt` (`b<a`) outgoing edges to forward nodes with explicit slot permutations `perm` (old index -> new index). The checker extends `R` by the outcome, transitively closes, renames by `perm`, and at joins intersects guaranteed relations of all feasible incoming arcs. Leaves must guarantee a total order. Depth is the longest feasible path (max over nodes of path length). Soundness is local/polynomial in explicit graph size; all-`n` polynomial-size completeness for optimal strategies is open.
- **Baseline values (literature / repo references):** `S(10)=22` is the known exact sorting number (e.g. `scripts/upper_witness.py` table includes `10:22`; Peczarski/Knuth line of results). Ford–Johnson worst-case bound `M(n)=\sum_{i=1}^{n}\lceil \log_2(3i/4)\rceil` gives `M(10)=22` (computed via `scripts.upper_witness.fj_upper_bound`), so the standard Ford–Johnson strategy attains the exact optimal comparison count for `n=10` in worst-case height. This does **not** by itself provide an explicit framed-DAG certificate in the checker's format.

## 3. Concrete results / witness or obstruction with evidence

### 3.1 Verified framed certificate (height not optimal)

- **`witness_bubble_n10.json`** (generated by `triangular_bubble_certificate(10)`): **ACCEPTED** by `check_framed_strategy.py`.
  - `n=10`, `depth=45`, `budget=45`, `nodes=46`, `edges=90` (45 compare nodes × 2 outcomes), **tree/path structure** (no joins/sharing beyond linear chain of compare-exchange steps as encoded). Node/edge counts are `O(n^2)` (`n(n-1)/2 + 1` nodes) but depth is `45 = n(n-1)/2`, far above `S(10)=22` and above `O(n log n)` path length.
- This is an explicit, checkable permutation-framed witness, but **not** at exact height 22. It serves as a soundness-checked baseline artifact.

### 3.2 Exact-height-22 target: not constructed/verified

- **No explicit, checkable framed DAG certificate of height 22 for `n=10` was produced.**
- **Positive structural hint (not a certificate):** `M(10)=S(10)=22` means a Ford–Johnson strategy achieves the exact comparison budget; `docs/research-framed-certificate-frontier.md` §3 states a *plausible* all-`n` polynomial framed certificate for the standard Ford–Johnson upper bound subject to complete recursive frame/boundary audit, but no implemented generator/certificate is present.
- **Direct optimal-tree enumeration infeasible here:** `scripts/generate_optimal_tree.py` explores states as sets of all permutations (exponential in `n!`/state space) and is practical only for very small `n`; `scripts/strategy_dag_probe.py` builds exact minimax/poset DAG data only up to small `n` (`n<=5/6` in experiments). `n=10` has `10!` leaves and exact optimal strategy search/explicit extraction was not feasible with available tooling/resources in this session.

### 3.3 Attempted lower-height construction (merge-sort framed tree) and obstruction evidence

- **Construction idea:** encode top-down merge sort as framed comparisons on current slots. Merge step compares heads at positions `(p, p+a)` of remaining runs; `lt` keeps left head in place (`perm=id`, advance prefix), `gt` moves right head at `p+a` to `p` by slot-rotation permutation `perm[p+a]=p, perm[k]=k+1 for k∈[p,p+a)`. Sequential phases composed by substituting continuation into leaves.
- **Naive unshared-tree realization (no DAG joins):** composition duplicates the continuation subtree at every leaf, so node count explodes while path depth equals comparison depth. Verified accepted instances:
  - `n=4`: depth `5`, nodes `47`
  - `n=5`: depth `8`, nodes `239`
  - `n=6`: depth `11`, nodes `1439`
  - `n=7`: depth `14`, nodes `10079`
  (depths match standard merge worst-case comparison counts 5,8,11,14; node counts match `2·n!−1`-scale unshared-tree growth seen in strategy-DAG experiments for those `n`.)
- **`n=10` attempt:** the same naive sequential-composition generator did **not complete within a 120s timeout** (command exceeded timeout; no `witness_mergesort_tree_n10.json` produced). Standard merge sort for `n=10` needs 25 comparisons on the worst path (depth target ~25 > 22), but even this non-optimal depth could not be emitted in unshared framed-tree form at `n=10` by this naive method.
- **Evidence/obstruction (falsifiable, concrete):** for this certificate grammar, *path efficiency does not imply small explicit size without sharing/joins*. An unshared framed tree obtained by naive sequential composition of efficient sub-strategies exhibits exponential node blow-up (measured 47→239→1439→10079 for `n=4..7`), blocking explicit construction at `n=10` despite moderate depth. Achieving the frontier's claimed envelopes (e.g. merge-sort `O(n^2)` nodes, `O(n log n)` depth; or any exact-height-22 witness) appears to require a **shared DAG with correct join/intersection annotations** (and, for FJ/exact-optimal, a complete recursive frame construction) rather than tree duplication. This is consistent with §1–§3 of the frontier note (merge certificate relies on shared `(a,b)` states/joins; FJ embedding needs audited rank-envelope frames/joins).

## 5. Open questions / next falsifiable step

1. **(Primary, falsifiable)** Implement an explicit generator for the §2 adaptive merge-sort framed DAG with shared `(a,b)` merge states and composed merge schedule for `n=10`; verify with `check_framed_strategy.py` and record exact `(depth, nodes, edges)`. Hypothesis to test: depth `25` (or standard merge bound) with nodes `O(n^2)` (concretely small, ≪ unshared tree) — would confirm polynomial-size/non-optimal-depth envelope in executable form.
2. **(Exact optimality)** Construct/audit a complete framed certificate for Ford–Johnson at `n=10` (recursive winner-sort frame coupling, rank-envelope joins for pending insertions, Jacobsthal order, odd element) per §3; verify height `22`. Success would yield an explicit exact-height framed witness; failure/ambiguity should isolate the first non-locally-checkable join or frame step.
3. **(Representation barrier)** Formalize/measure the minimum node count of *any* framed DAG/tree realizing a given comparison-depth strategy under naive sequential composition vs join sharing (extend the `n=4..7` table) to bound when explicit witness emission becomes infeasible without joins.
4. **Out of scope caution:** a height-22 framed certificate for `n=10` alone does not imply all-`n` `SORT-BOUND-U ∈ NP`; and unary `SORT-BOUND-U` remains subject to the sparse-language/Mahaney barrier for many-one NP-hardness (see frontier/strategy notes). Claims above distinguish verified artifacts from literature baselines and conjectural constructions.
