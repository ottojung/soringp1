## 1. Sharp question (as posed)

> Does every height-`S(n)` optimal adaptive comparison-sorting tree for the
> `n`-element antichain necessarily encounter, at some depth, a reachable winning
> state `P` with positive information excess, i.e. `F(P) > ceil(log2 e(P))`?

with the sub-question: is this forcing true for all `n >= 12`, or only for
infinitely many `n`? (The rectangular-chain winning-frontier family of the
22:14Z post was already answered "not forced"; the open part is whether
**non-tightness itself** is forced.)

## 2. Definitions fixed for this pass

- `[definition]` State = transitively closed strict partial order `P` on the
  labelled keys; `e(P)` = number of linear extensions; `L(P) = ceil(log2 e(P))`;
  `F(P)` = minimax remaining comparisons (repo: `adv`).
- `[definition]` Winning state on an optimal tree: reached after `t` outcomes on
  a root-to-leaf path of a height-`S(n)` tree with `F(P) <= S(n) - t`; tight =
  `F(P) = L(P)`; excess = `F(P) > L(P)`.
- `[definition]` All-tight optimal tree = height-`S(n)` tree all of whose
  reachable states are winning *and* tight.

## 3. Known data (literature / experiment)

`S(n)` exact for `n <= 22` (Peczarski 2012; Stober-Weiss 2023; OEIS A036604);
`C(n) = ceil(log2 n!)` information bound. Root-excess (`S(n) > C(n)`) holds for
`n = 12..19, 22`; root-tight (`S(n) = C(n)`) holds for `n <= 11, 20, 21`.

When `S(n) > C(n)`, **every** height-`S(n)` optimal tree necessarily contains the
antichain root with excess `S(n) - C(n) > 0` — forcing is thereby established for
those `n` (trivially at depth 0; the deep analysis of the 22:14Z rectangular family
is moot there).

## 5. Falsification and status

- **Refutation (partial, hard):** for `n = 5, 6, 7` there is an optimal height-`S(n)`
  tree whose reachable states are ALL information-tight. Hence "every optimal
  tree must encounter an excess-positive state" is **false** as a blanket all-`n`
  statement, even inside the root-tight regime.
- **No all-tight tree** exists whenever `S(n) > C(n)` (in particular `n = 12..19, 22`),
  because the antichain root itself has excess; this is the forced case.
- **Open (n >= 12):** `n = 20, 21` have `S = C` (root-tight), so the forcing
  question is *not* settled by the root. Whether an all-tight optimal tree exists
  there is computationally out of reach in this pass; the sharp all-`n` question
  therefore remains open, and the answer "forced for all n >= 12" is **not
  established** by this pass.

## 6. Precise obstruction to forcing (state it)

- Forcing at depth `0` reduces to the root-excess data above — exact and settled.
- Forcing at depth `> 0` requires an all-tight strategy; the obstruction found in
  small `n` is *not* present (all-tight trees exist), so no deep structural
  obstruction to avoiding excess is known. The open question is whether the
  tight-child branching can be pursued all the way to the antichain for large `n`.
