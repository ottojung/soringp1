# Sergeev group-insertion: constructive/effective certificate audit for `SORT-BOUND-U`

**Status:** local research audit (paper analysis). **Not Lean-checked.** No unconditional separation claims.

**Task framing (SoringP1 #301).** Falsifiable question: can Igor S. Sergeev's group-insertion proof (ECCC TR20-096, 2020) be turned into an *explicit constructive/effective* certificate or a *computable finite threshold/witness* for an exponent-level bound of the form

> `S(n) <= log2(n!) + f(n)`, with `f(n) = O(n / (log n)^(1/5))` or an explicit all-`n` effective `f`,

certifiable with resolved parameters / a finite `n0` or a direct verifier? If not, identify the exact nonconstructive/effectivity blocker with primary-source evidence.

**Bottom line (defensible).** **No effective/certifiable finite bound is extracted from TR20-096 by this audit.** The proof is algorithmic in framework (group insertion, comparison strategies, LP/strategy constraints, interpolation) and establishes the asymptotic theorem `S(n)=log2(n!)+O(n/(log n)^(1/5))`, but *as stated* it does **not** supply a computable all-`n>=n0` inequality `S(n) <= log2(n!) + f(n)` with all constants, all integer schedules, all rounding/container losses, and an explicit finite basis `n0` resolved. A finite effectivization is **not ruled out** by this analysis; it remains an open extraction/reproof task.

## Model and scope

- `S(n)` is the minimum worst-case number of adaptive pairwise comparisons to sort `n` distinct labelled keys (decision-tree height). `[definition/model]`
- `SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`, unary input length `N = n+k+1`. `[definition]`
- Sergeev's result is an **upper bound on `S(n)` / a comparison-sorting procedure**, not an algorithm that computes exact `S(n)` and not a uniform complexity-class separation. `[deduction]`
- An effective finite Sergeev bound would narrow a unary threshold window; it would **not** by itself prove `SORT-BOUND-U ∈ NP/P`, disprove it, or imply `P != PSPACE` / `NP != PSPACE`. `[deduction]`

## What TR20-096 establishes (primary theorem chain)

`[literature]` Key statements (TR20-096 numbering as reported in the PDF analyses):

| Item | Claim (semantic) | Role |
|---|---|---|
| Lower bound | `S(n) >= log2(n!)`. | Baseline. |
| (4),(5) | `Q(a)=2^floor(log a)`; `P(a)` has explicit integer/half-integer forms. | Base insertion primitives. |
| Lemma 1 (p.9) | Constructive interpolation inside strategy LP feasible regions with explicit rate. | Technical/constructive. |
| Lemma 2 (pp.10–13) | Strategy + LP feasibility + parameters `(r,m,phi,...)` yields lower bound on `P_m(...)` / interval length (18) under (17). | Main bridge from strategies to group insertion. |
| Lemma 3 / Thm 1 | Concrete example gives `S(n) <= log(n!) + 0.09*n + o(n)`. | Intermediate constant; still `o(n)`. |
| Lemma 4 (p.27) | For `s>=20`, explicit universal-strategy parameters `d,mu,lambda,eps,y_i,v_i`; `v in T(sigma[s])`, `u=v/2 in T^eps(sigma[s])`. | Supplies feasible data for Lemma 2. |
| Thm 2 (p.28) | For `a>=2`, `2^(a/4)<=m<=2^(a/2)`, `P_m(a) >= 2^(a+1/2) - O(a^(-gamma)*2^a)`, `gamma` small enough (say `1/5`). Proof absorbs `a<100` into hidden constant; assumes `a>=100`; sets `s=ceil(2*gamma log a)`, `phi=log(m*eps/(4*a^2))`. | Asymptotic pair/group capacity. |
| Cor. 2 (p.29) | `Q_{2m}(a) >= 2^a - O(a^(-1/5)*2^a)` under the same regime. | Converts to ordinary insertion. |
| Thm 3 (p.29) | `S(n)=log(n!)+O(n*log^(-1/5) n)`. Uses Ford–Johnson start, `n0=n/log n`, `m ≈ sqrt(n)/log n`, groups over intervals `L_t=2(n0+tm)-m`, `rho_t=log L_t + O(log^(-1/5)n)`, last group binary; recurrence `s(n)<=s(n/2)+O(n log^(-1/5)n)` for `s(n)=S(n)-log(n!)`. | Target asymptotic upper bound. |

`[deduction]` The leading `Theta(n log n)` scale is already explicit via `log2(n!)`; the non-effective content is the lower-order term and its finite validity.

## Candidate (A): explicit constructive/effective certificate / finite threshold

An (A) answer would require, at minimum:

1. **Computable bound:** explicit `f` (formula or algorithm) and `n0` with
   `S(n) <= U_eff(n) := ceil(log2(n!)) + f(n)` for all `n >= n0` (or all `n`, with finite base handled). `[open]`
2. **Resolved schedules:** explicit integer/computable `n0(n), m(n), m_eff, group partition, L_t, a_t`, and all Thm 2/Lemma 4 parameters (`s, gamma, phi, d, eps, lambda, mu, h, w, R, ...`) where used. `[open]`
3. **Explicit constants/slacks:** every hidden `O`, every approximation (`≈`), and every rounding/container/`exp(...)`/`1/d`/positivity/information loss bounded by explicit computable terms. `[open]`
4. **Finite basis:** explicit treatment of `a<100` (Thm 2), small `n`, and all cases where asymptotic schedules are invalid; a checkable table/computation is acceptable if sound and reproducible. `[open]`
5. **Verifier:** a direct verifier can check either (i) the finite certificate data/proof objects, or (ii) the finite base plus a complete effective tail proof. Naming Thm 3 alone is not a verifier. `[open]`

## Exact nonconstructive/effectivity blockers (primary-source grounded)

The following are the specific places where TR20-096, as an asymptotic proof, does not by itself yield the finite inequality required above.

### B1. Hidden constant and small-`a` absorption in Theorem 2
- `[literature]` Theorem 2 states `P_m(a) >= 2^(a+1/2) - O(a^(-gamma)*2^a)` for `a>=2` but the proof says values `a<100` are absorbed by a sufficiently large hidden constant and assumes `a>=100`.
- `[deduction]` No explicit `a0, C2` is given with `P_m(a) >= 2^(a+1/2) - C2*a^(-1/5)*2^a` for all admissible `a,m`. This blocks an all-`a` computable certificate. An effectivization must either produce `C2,a0` from the full inequality chain or certify the finite/low-`a` regime separately.

### B2. `a`-dependent parameter schedule after asymptotic balancing
- `[literature]` Theorem 2 sets `s=ceil(2*gamma log a)` and `phi=log(m*eps/(4*a^2))`; Lemma 4 parameters depend on `s` (`d=2s, eps=1/(25*2^s), lambda ~ 2^(-s/2), mu ~ 2^(-s), h=2s+3, w<=s+4`), and `m` is constrained by `2^(a/4)<=m<=2^(a/2)`.
- `[deduction]` The proof uses asymptotic simplifications (`Theta`, `O`, approximation of `a` by `r+y_i`, large-`a` behavior). An effective bound needs a closed inequality after substitution, or a computable certified parameter family covering all required `(a,m)`.

### B3. Lemma 2 finite losses (rounding, containers, positivity/information)
- `[literature]` Lemma 2 is algorithmic but includes real/non-integer rounding “in some direction”, container capacity/counting (rough bounds such as `phi*2^phi` effects in the proof narrative), free parameters/choices (`r,m,phi,delta,L,q,...`), and side conditions including (17), `n+2m < 2^(r+2)`-type information/positivity assumptions and reduced-tree bookkeeping.
- `[deduction]` Each finite loss must become an explicit additive/multiplicative term in the final bound. Hidden-direction rounding and rough container accounting are not directly checkable as a final numeric inequality.

### B4. Universal-strategy certification (Section 6 + Lemma 4(i))
- `[literature]` Lemma 4 gives explicit formulas and slack checks; Lemma 4(i) is supported by the substantial universal-strategy construction in Section 6 with target `Y(a)`, discretization/correction, and sufficient parameter constraints.
- `[deduction]` For an effective theorem, the feasible data `(v,u,eps,R,lambda,mu,s,d,h,w)` must be certified for every `s(a)`/case actually used (analytic tail plus finite cases, or an explicit all-cases lemma). “Built to satisfy” is not by itself a finite verifier artifact.

### B5. Theorem 3 global schedule and hypothesis matching
- `[literature]` Theorem 3 uses `n0=n/log n`, `m ≈ sqrt(n)/log n`, group interval lengths `L_t=2(n0+tm)-m`, and `rho_t = log L_t + O(log^(-1/5)n)` via Corollary 2; the last group may be smaller and is handled by binary insertion.
- `[deduction]` The asymptotic schedule must be replaced by explicit integer functions and every use of Corollary 2/Thm 2 must satisfy their hypotheses for those integers. This is a schedule-validity proof/certificate, not a cosmetic change.

### B6. Recurrence closure and explicit finite basis for all `n`
- `[literature]` Theorem 3 gives `s(n)<=s(n/2)+O(n log^(-1/5)n)` for `s(n)=S(n)-log(n!)` and solves it asymptotically.
- `[deduction]` An effective result needs an explicit closed `f(n)` (or a computable recurrence bound) and an explicit `n0`. For `n<n0`, a sound finite check against known exact values/verified upper bounds is required; this is finite and plausible in principle, but not provided by Theorem 3.

## What would count as a constructive/effective certificate

`[deduction]` Acceptable evidence for a future positive answer:

- A theorem with explicit numeric/computable objects: `C, n0, p` or `f,n0`, and integer schedules, such that every step is a finite inequality.
- A primary-source-checked line-by-line effectivization of Thm 2 -> Cor. 2 -> Thm 3 (or an independent effective proof inspired by TR20-096).
- A machine-checkable finite basis for `n<n0` and/or finite parameter cases, with deterministic inputs/outputs and sound comparison to `S(n)`.
- For the unary `SORT-BOUND-U` window use-case: an explicit computable `U_eff(n)` and `n0`, plus the statement that for `n>=n0`, `k < ceil(log2(n!))` is NO and `k >= U_eff(n)` is YES; only the middle window remains.

## Consequence for `SORT-BOUND-U`

`[deduction]` If an effective `U_eff(n)=ceil(log2(n!))+f(n)` were obtained:
- **Useful:** narrows finite verification/search for large `n`; may support computable witnesses for the `k >= U_eff(n)` side.
- **Not a complexity-class breakthrough:** `SORT-BOUND-U` is already in PSPACE and has stronger known algorithmic upper bounds in the project; a threshold-window certificate does not place it in NP or P and does not address the out-of-scope separations `P!=PSPACE`, `NP!=PSPACE`.
- **Not a proof of optimality:** it upper-bounds `S(n)`; exact evaluation or lower certificates are separate.

## Final assessment

| Question | Assessment |
|---|---|
| Can TR20-096 be used *as stated* as an explicit constructive/effective certificate or computable finite threshold/witness for exponent-level/all-`n` bound extraction? | **No, not by this audit.** The asymptotic proof leaves constants, finite base, schedules, and finite losses unresolved. |
| Is there an exact nonconstructive/effectivity blocker? | **Yes: several concrete blockers** (B1–B6), chiefly hidden constants/small-base absorption in Thm 2, asymptotic parameter schedules, Lemma 2 finite losses, universal-strategy certification for all used cases, Thm 3 hypothesis-matching schedules, and recurrence/finite-basis closure. |
