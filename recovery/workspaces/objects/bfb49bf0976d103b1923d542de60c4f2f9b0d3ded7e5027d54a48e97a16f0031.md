# Ford–Johnson implementation: proved upper bound, not exact height

## Status

**Inconclusive on the requested identity as an all-n exact worst-case height.**
The argument below proves the implemented `fj_sort` uses at most
`M(n) = Σ_{j=1}^n ceil(log2(3j/4))` comparisons. It does **not** prove that
this height is attained for every n. In particular, the former argument that
forced every insertion to position zero did not establish a consistent total
order across the recursively paired keys; its purported lower bound and every
“exact worst case” conclusion are withdrawn.

The identity `M(n) = Σ ceil(log2(3j/4))` is an identity defining the familiar
Ford–Johnson upper-bound formula, not a claim here about exact realized height
or `S(n)`. No primary source was accessed for the exact recurrence.

## Algorithm conventions

These describe `scripts/upper_witness.py`:

* Pair `k=floor(n/2)` disjoint pairs, one comparison per pair, and recursively
  sort their k winners.
* A loser whose winner is in 1-based rank j in sorted-winner order is pending
  index j. If n is odd, the unpaired straggler is pending index `K=k+1` with
  no winner; otherwise `K=k`.
* Let `J_0=0, J_1=1, J_r=J_{r-1}+2J_{r-2}`. The schedule descends through
  blocks `{J_{r-1}+1,…,J_r}` for r=3,4,…, preceded by `{1}`; truncate at K.
  Put `q(j)=min{r≥1:J_r≥j}`.
* A regular index binary-searches the current chain strictly below its paired
  winner. The odd straggler searches the full chain. The half-open binary
  search on m positions has at most `f(m)=ceil(log2(m+1))` comparisons.

## Theorem 1: uniform insertion-cost upper bound

For n≥0, define U(0)=U(1)=0 and

```
U(n) = U(floor(n/2)) + floor(n/2)
       + sum_{j=1}^{ceil(n/2)} (q(j)-1).
```

Then the comparison count of the implemented `fj_sort` on every input of n
distinct keys is at most U(n).

**Proof.** Let `b_j` be the number of earlier schedule entries before index j.
For a regular j, its winner begins at zero-based position j−1 among the
recursively sorted winners. Each earlier insertion can increase this position
by at most one. Thus the searched interval has size
`m ≤ j−1+b_j`. If `j` is in block r, then
`b_j = J_{r-1} + min(J_r,K)-j`, so
`m+1 ≤ J_{r-1}+min(J_r,K) ≤ J_{r-1}+J_r = 2^{r-1}`.
Consequently `f(m) ≤ r−1 = q(j)−1`.

For odd n, write `k=floor(n/2)`, `K=k+1`, and `q=q(K)`. Before the
straggler, exactly `J_{q-1}` scheduled entries have been inserted. The chain
length is therefore `L=k+J_{q-1}`. Since `K≤J_q`,
`L+1=K+J_{q-1}≤J_q+J_{q-1}=2^{q-1}`. Hence its full-chain binary search
uses at most `ceil(log2(L+1))≤q−1` comparisons. Pairing costs k, recursion
costs at most U(k), and summing the insertion bounds proves the recurrence.
∎

### Corrected straggler inequality

The useful statement is

```
ceil(log2(L+1)) ≤ ceil(log2(3n/4)),
```

not `L+1≤3n/4` and not `L+1≤ceil(log2(3n/4))`.

The first inequality follows from the exact integer derivation above together
with `q(k+1)−1 = ceil(log2(3(2k+1)/4))`. For completeness, that last
Jacobsthal threshold identity is also checked by the verifier for odd n≤400;
the present note does not supply an independent all-n derivation of that
threshold identity. Thus the all-n upper bound proved here is U(n); identifying
U(n) with the displayed M(n) still requires the algebraic identity below.

Counterexample to the false length inequality: n=3 gives k=1, K=2, q=3,
L=2; `L+1=3` is not ≤ `floor(9/4)=2`, nor ≤ `ceil(log2(9/4))=2`.
For n=343, L+1=343 while floor(3n/4)=257.

## Algebraic identification with M(n): machine checks only; proof incomplete

Set `B(n)=Σ_{j=1}^n ceil(log2(3j/4))`. The exact-integer verifier checks
for n≤2000 that

```
B(n)-B(floor(n/2))-floor(n/2)
    = sum_{j=1}^{ceil(n/2)} (q(j)-1).
```

That is finite computational evidence, not an all-n proof. The previous
version's purported hand derivation (D1–D5) contained gaps and placeholder
algebra; it is withdrawn. Therefore this document does **not** assert
`U(n)=B(n)` for all n, nor that actual worst-case height equals B(n).
