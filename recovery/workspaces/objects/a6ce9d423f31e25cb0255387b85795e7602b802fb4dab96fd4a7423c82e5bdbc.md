## 2. Uniformity

### 2.1 What TR20-096 gives

- `[literature]` Theorem 3 states: “For any `n`, `S(n)=log(n!)+O(n log^(-1/5)n)`”.
  This is an asymptotic upper bound on the comparison complexity of sorting
  `n` elements; the proof describes a comparison procedure (group insertion
  using Corollary 2 / Ford–Johnson / binary insertion). As an algorithmic
  framework it is uniform in the usual informal sense (the same method for
  all sufficiently large `n`, with parameters depending on `n`/`a`).
- `[literature]` However, the proof is not presented as an explicit finite
  construction with all integer schedules/constants certified for every `n`.
  It uses `≈`, `O(...)`, “sufficiently large values of the constant hidden
  behind the symbol O” (Theorem 2, p.28), asymptotic parameter choices
  (`n0=n/log n`, `m ≈ sqrt(n)/log n`, `s=ceil(2γ log a)`), and a recurrence
  solved asymptotically.

### 2.2 Uniformity needed for an effective finite bound

- `[deduction]` To claim an **effective finite bound** `S(n) <= U_eff(n)` for
  all `n >= n0` with computable `U_eff,n0`, the proof obligations are stronger
  than asymptotic uniformity: every schedule must be an explicit integer
  function of `n` (or `a`), every hidden constant/slack/rounding/container
  loss must be bounded explicitly, every hypothesis (`2^(a/4)<=m<=2^(a/2)`,
  `s>=20`, `a>=100`, Lemma 2 condition (17), positivity/information
  assumptions, admissible `r,y_i`) must be checked for that schedule, and the
  recurrence must be closed to an explicit `f(n)`.
- `[correction]` The audited file says “constructive in form / uniform in the
  usual informal sense” only implicitly. It should state the distinction more
  sharply: **asymptotically constructive/uniform is not the same as
  effectively finite and all-`n` certified**. The bottom-line conclusion is
  still right.

### 2.3 Relation to the project “effective frontier” title

- `[model]+[correction]` The task/repo name contains “effective-frontier”, and
  `docs/problem.md` distinguishes uniform evaluation of `S(n)` from one-off
  sorting. Sergeev's theorem gives an **upper bound on `S(n)` itself** (an
  existential comparison-sorting complexity bound), not a uniform algorithm
  that computes the exact value of `S(n)` or decides `SORT-BOUND-U`. Making
  Sergeev's bound *effective* would give an effective upper window/certificate
  source for large `n`, but that is different from making the exponent of an
  algorithm for computing `S(n)` effective. The audited file's “model
  consequence” is careful enough on this point; this distinction should remain
  explicit.

## 3. What would make the exponent / bound effective

The phrase “make the exponent `O(n log n)` effective” is easy to misread.
`[correction]` The relevant asymptotic object in TR20-096 is

    S(n) = log2(n!) + O(n / (log n)^(1/5)),  with log2(n!) = Θ(n log n).

The **leading exponent/scale** `n log n` is already explicit in `log(n!)`.
The non-effective part is the **lower-order term** `O(n/(log n)^(1/5))`: it
has no explicit constant, no explicit finite basis `n0`, and relies on
non-explicit parameter schedules. Effectivizing that term means:

1. **Explicit tail inequality.** `[deduction]`
   Find computable `C, n0, p` (TR20-096 gives `p=1/5` asymptotically) or
   computable `f(n)` with
   `S(n) <= log2(n!) + f(n)` for all `n>=n0`, and `f(n)=O(n/(log n)^p)` if
   preserving the asymptotic form.
2. **All integer schedules fixed.** `[deduction]`
   Replace `n0(n)=n/log n`, `m ≈ sqrt(n)/log n`, “last group may contain less
   than m”, and Theorem 2's `s,ϕ,ε,d,h,w,λ,μ` by explicit integer/computable
   functions with stated domains.
3. **Explicit constants in Theorem 2 / Corollary 2.** `[deduction]`
   Produce `a0,C2` (or `C2(a)` computably bounded) with
   `P_m(a) >= 2^(a+1/2) - C2*a^(-1/5)*2^a` under explicit admissibility, and
   propagate to `Q_{2m}`. This requires an effective Lemma 2 after
   substituting Lemma 4 parameters, including the `exp(...)` term, `1/d`
   slack, rounding directions, container count/capacity, and `n+2m<2^(r+2)`
   justification.
4. **Finite basis `n0` / finite `a<a0`.** `[deduction]`
   Handle the `a<100` absorption in Theorem 2 and all small-`n` cases either
   by an explicit larger `n0`/`a0` with a complete proof, or by a finite table
   / finite computation checked against sound upper bounds or exact values.
5. **Computable witness/certificate.** `[deduction]`
   A computable witness could be: (i) the explicit functions/constants
   `(f,C,n0,schedule,...)` together with a finite proof/certificate; or (ii)
   a verifier script for the finite base plus a paper proof for the tail.
   Merely naming Theorem 3 is not a computable witness of an all-`n>=n0`
   inequality.

**Unary `SORT-BOUND-U` consequence if done.** `[model]+[deduction]` For input
`1^n # 1^k` (`N=n+k+1`), known exact/literature or computed `S(n)` values and
any effective `U_eff(n)` narrow the threshold window to
`[ceil(log2(n!)), U_eff(n)]` for large `n`; answers outside it are immediate.
This is finite-search/window narrowing. It does **not** give NP membership, P
membership, or a separation, and is consistent with `SORT-BOUND-U ∈ PSPACE`
and the project barriers in `docs/problem.md`.

## 5. Bottom line

`[deduction]` The audited file's **B verdict is correct as stated**: Sergeev
TR20-096 proves the asymptotic improvement
`S(n)=log2(n!)+O(n/(log n)^{1/5})` with a constructive comparison framework,
but it does **not** supply an explicit computable `f(n)` and finite `n0` with
`S(n)<=log2(n!)+f(n)` for all `n>=n0`, nor the fully resolved schedules and
constants required for a unary `SORT-BOUND-U` threshold-window certificate.
An effective finite version is **not ruled out** by this audit; obtaining it
would require a separate finite-effectivization (explicit Theorem 2/Corollary 2
constants and domains, explicit Theorem 3 schedule, recurrence closure, and a
finite basis). No claim stronger than window narrowing for `SORT-BOUND-U`
should be made from such a bound.
