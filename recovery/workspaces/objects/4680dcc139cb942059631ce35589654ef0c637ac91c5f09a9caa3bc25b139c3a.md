## 2. `[open:CKS-AV-Δ_D/SYM-TOP]` (restated)

`[definition]` (audit). In every push case, the pre-fix realization creates a
fresh child top but does not constrain the previous top to become false.
`ChildFrameBase(d̄,c̄)` asserted `Top'(d̄)` but not `¬Top'(c̄)` or
`∀z̄(Top'(z̄)->z̄=d̄)`. The affected push disjuncts
`Δ_sort_pick_push`, `Δ_backE_rej_next`, `Δ_adv_push_A0`,
`Δ_backA0_acc_push_A1` add `PushChildE/PushChildA` and parent-backtrack helpers,
none of which negated `Top(c̄)`. `LowerStackPreservedExcept(c̄)` preserves only
relations for `FrameLive(z̄)∧z̄!=c̄`, so it does not constrain `Top'(c̄)`. A
primed interpretation could therefore satisfy a push disjunct while keeping
`Top'(c̄)` alongside `Top'(d̄)`, violating `ExactlyOneTop`/`I_{M_D}.4` and
breaking determinism/functionality and invariant preservation.

**Contrast (already correct).** Pop returns determine `Top` uniquely:
```text
PopTo_base(p̄,c̄) :=
  Top'(p̄) ∧ ∀z̄(Top'(z̄)->z̄=p̄) ∧ FrameLive'(p̄) ∧ ¬FrameLive'(c̄)
  ∧ (∀z̄((FrameLive(z̄)∧z̄!=c̄) -> FrameLive'(z̄))) ∧ CurBase'=CurBase
  ∧ LowerStackPreservedExcept(c̄).
```
(`sym-closure.md` §§3.1,3.4). The fix makes push transitions use the same
unique-`Top` discipline.

## 3. Exact symbol-level FO formula fix

### 3.1 `ChildFrameBase` (canonical fix)

`[definition]` Replace the pre-fix `ChildFrameBase(d̄,c̄)` of
`sym-closure.md` §4 by:
```text
ChildFrameBase(d̄,c̄) :=
    FrameLive'(d̄)
  ∧ Parent'(d̄,c̄)
  ∧ Top'(d̄)
  ∧ ¬Top'(c̄)                      -- SYM-TOP: clear old top
  ∧ ∀z̄(Top'(z̄) -> z̄ = d̄)          -- SYM-TOP: enforce unique Top'
  ∧ ∃b̄(CurBase(b̄) ∧ d̄ = b̄)
  ∧ ∃b̄∃b̄'(CurBase(b̄) ∧ SuccCell(b̄,b̄') ∧ CurBase'(b̄')).
```
All other conjuncts are unchanged. This is the single canonical location: both
`PushChildE` and `PushChildA` include `ChildFrameBase(d̄,c̄)` and therefore
inherit unique `Top'` determination.

### 3.2 `PushChildE`, `PushChildA` (inherited consequence)

`[definition]` `PushChildE(d̄,c̄,x,y)` and `PushChildA(d̄,c̄,a,b,side)` remain
textually as in `sym-closure.md` §4, except that their `ChildFrameBase(d̄,c̄)`
conjunct is now the formula in §3.1. No local semantic field is changed:
`PosF/UsedF/Sel/Cur/Ret/Mode/Ctrl/PostBudget` updates are identical to the base
SYM realization.

### 3.3 Affected push cases (explicit amended forms)

`[definition]` The four push disjuncts are amended only through the fixed
`ChildFrameBase`; their surrounding structure is unchanged. For completeness:

```text
Δ_sort_pick_push :=
  ¬HaltAcc ∧ ¬HaltRej
  ∧ ∃c̄∃a∃b∃x∃y(
      Top(c̄) ∧ FrameLive(c̄) ∧ M_Eval(c̄) ∧ CtrlSort(c̄)
      ∧ ¬Total_c ∧ Budget_c
      ∧ CurA(c̄,a) ∧ CurB(c̄,b) ∧ NextIncomp_c(a,b;x,y))
  ∧ ∃d̄( FreshChild(d̄) ∧ PushChildE(d̄,c̄,x,y) )   -- includes ChildFrameBase with SYM-TOP
  ∧ SetParentBackE_Advance(c̄,x,y)
  ∧ ¬HaltAcc' ∧ ¬HaltRej' ∧ ¬EmptyStack'
  ∧ LowerStackPreservedExcept(c̄) ∧ FrameLive'(c̄).

Δ_backE_rej_next :=
  ¬HaltAcc ∧ ¬HaltRej
  ∧ ∃c̄(Top(c̄) ∧ FrameLive(c̄) ∧ M_BackE(c̄) ∧ RetRej(c̄) ∧ CtrlSort(c̄)
      ∧ ∃a∃b∃x∃y(CurA(c̄,a)∧CurB(c̄,b)∧NextIncomp_c(a,b;x,y)))
  ∧ ∃d̄(FreshChild(d̄) ∧ PushChildE(d̄,c̄,x,y))   -- SYM-TOP via ChildFrameBase
  ∧ SetParentBackE_Advance(c̄,x,y)
  ∧ ¬HaltAcc' ∧ ¬HaltRej' ∧ ¬EmptyStack'
  ∧ LowerStackPreservedExcept(c̄) ∧ FrameLive'(c̄).

Δ_adv_push_A0 :=
  ¬HaltAcc ∧ ¬HaltRej
  ∧ ∃c̄∃a∃b(Top(c̄) ∧ FrameLive(c̄) ∧ M_Eval(c̄) ∧ CtrlAdv(c̄)
      ∧ HasSel(c̄) ∧ SelA(c̄,a) ∧ SelB(c̄,b) ∧ Incomp_c(a,b))
  ∧ ∃d̄(FreshChild(d̄) ∧ PushChildA(d̄,c̄,a,b,0)) -- SYM-TOP via ChildFrameBase
  ∧ SetParentBackA0(c̄) preserving Sel/PosF/UsedF/Cur of c̄
  ∧ ¬HaltAcc' ∧ ¬HaltRej' ∧ ¬EmptyStack'
  ∧ LowerStackPreservedExcept(c̄) ∧ FrameLive'(c̄).

Δ_backA0_acc_push_A1 :=
  ¬HaltAcc ∧ ¬HaltRej
  ∧ ∃c̄∃a∃b(Top(c̄) ∧ FrameLive(c̄) ∧ M_BackA0(c̄) ∧ RetAcc(c̄)
      ∧ HasSel(c̄) ∧ SelA(c̄,a) ∧ SelB(c̄,b))
  ∧ ∃d̄(FreshChild(d̄) ∧ PushChildA(d̄,c̄,a,b,1)) -- SYM-TOP via ChildFrameBase
  ∧ SetParentBackA1(c̄) preserving Sel/PosF/UsedF/Cur of c̄
  ∧ ¬HaltAcc' ∧ ¬HaltRej' ∧ ¬EmptyStack'
  ∧ LowerStackPreservedExcept(c̄) ∧ FrameLive'(c̄).
```

**Why `c̄` is the old top.** In every amended push case, the precondition
includes `Top(c̄)`. By `I_{M_D}.4` / `ExactlyOneTop` on the source state, this
`c̄` is the unique pre-state top. The added conjuncts `¬Top'(c̄)` and
`∀z̄(Top'(z̄)->z̄=d̄)` therefore clear exactly that old top and make exactly
the fresh child `d̄` top. No additional quantification ambiguity is introduced
because `c̄` is the same witness quantified by the case.

**Equivalent case-level form (not required).** Adding the same two conjuncts to
each push case body, outside `PushChild*`, is equivalent given the unique `c̄`
witness; the canonical fix above places them in `ChildFrameBase` so no push path
can omit them.

## 4. Corrected proof sketch (SYM-TOP discharged)

### 4.1 `ExactlyOneTop` / `I_{M_D}.4` preservation

`[deduction]` Assume `I_{M_D}(Rbar)`, `¬HaltAcc∧¬HaltRej`, and
`Δ_{M_D}^{sym,top}(Rbar;Rbar')`, where `Δ_{M_D}^{sym,top}` is the SYM closure
formula with §3.1 applied.

- **Halt / root-halt cases:** unchanged; they set `NoActiveFrames'` and halt, so
  `I_{M_D}.3` applies and there is no live-top requirement after halting.
- **Pop-return cases:** unchanged. `PopTo_base(p̄,c̄)` already enforces
  `Top'(p̄) ∧ ∀z̄(Top'(z̄)->z̄=p̄)` and `FrameLive'(p̄)`; `c̄` is removed from
  live frames. By `I_{M_D}.7`, `p̄` is live and unique as the parent below the
  popped top, so `ExactlyOneTop` holds in `Rbar'`.
- **Push cases (`Δ_sort_pick_push`, `Δ_backE_rej_next`, `Δ_adv_push_A0`,
  `Δ_backA0_acc_push_A1`):** let `c̄` be the unique source top (`Top(c̄)` and
  `ExactlyOneTop`). `FreshChild(d̄)` is `CurBase(d̄)` with unique `CurBase`
  (`I_{M_D}.8`), so `d̄` is determined. The amended `ChildFrameBase(d̄,c̄)`
  gives `Top'(d̄)`, `¬Top'(c̄)`, and `∀z̄(Top'(z̄)->z̄=d̄)`. No other case
  conjunct asserts `Top'` on any `z̄!=d̄`; `LowerStackPreservedExcept(c̄)` does
  not mention `Top`. Therefore `ExactlyOneTop(Rbar')` holds with witness `d̄`,
  and `FrameLive'(d̄)` holds. The old top `c̄` remains `FrameLive'(c̄)` in these
  push cases (it becomes a waiting backtrack frame), which is correct and does
  not create a second top because `¬Top'(c̄)`.

Thus `I_{M_D}.4` is preserved in all cases.

### 4.2 Determinism / functionality

`[deduction]` The SYM-closure determinism argument (`sym-closure.md` §7.4) is
restored: for push transitions, the target `Top'` was previously underdetermined
(allowing `Top'(c̄)` to remain true). With §3.1, push cases uniquely determine
`Top'(d̄)`, `¬Top'(c̄)`, and `∀z̄(Top'(z̄)->z̄=d̄)`; they also uniquely
determine `d̄=CurBase`, `CurBase'=SuccCell(CurBase,·)`, the pushed child frame
contents, and the parent backtrack/cursor/marker updates, exactly as before. All
other components are determined by `LowerStackPreservedExcept(c̄)` and the
unchanged non-push cases. Therefore
```text
Δ_{M_D}^{sym,top}(Rbar;Rbar') ∧ Δ_{M_D}^{sym,top}(Rbar;Rbar'')
  => Rbar' = Rbar''
```
as interpretations, for states satisfying the relevant source conditions.

### 4.3 Other `I_{M_D}` clauses

`[deduction]` The fix does not alter frame contents, `PosF/UsedF`, `StepPosBit`,
`SuccCtr`, `PostBudgetFrom`, selected pairs, cursors, return markers on
backtrack frames except as already specified, `Parent` links, allocator
monotonicity, mode/control coherence, or halting flags. Hence the remaining
`I_{M_D}` preservation arguments of `sym-closure.md` §7.5 are unchanged:
incremental TC for `PushChildA`, unique `UsedF` successors, `PostBudgetFrom`
control resolution, preserved parent snapshots for `A0/A1`, and well-founded
`Parent` chains. The only previously broken clause was `ExactlyOneTop`, now
repaired.

### 4.4 Mutual exclusion and totality

`[deduction]` Mutual exclusion (`sym-closure.md` §7.2) and totality
(`sym-closure.md` §7.3) are unchanged in substance. The fix adds conjuncts to
push postconditions; it does not weaken or overlap preconditions. Mutual
exclusion still follows from unique source `Top`, exactly-one mode, root/non-root,
accept/reject/search-progress/adversary-push, return-marker, and next-incomp
partitioning. The fix removes the semantic non-functionality that made the
determinism claim fail on push transitions, strengthening the soundness of the
mutual-exclusion/determinism package.

### 4.5 No spurious transitions / no semantic change

`[deduction]` The fix introduces only `¬Top'(c̄) ∧ ∀z̄(Top'(z̄)->z̄=d̄)` in
push transitions. This constrains the global stack-top bookkeeping relation; it
does **not** change:
- local move semantics (`YieldE`, `YieldA0`, `YieldA1`, `Incomp_c`,
  `Total_c`, `CfgAcc_c/CfgRej_c`),
- `PosF` updates (only `PushChildA` uses `StepPosBit_c`, unchanged),
- `UsedF` updates (only `PushChildA` uses `SuccCtr`, unchanged),
- `PostBudgetFrom` / terminal resolution (unchanged),
- lex search (`NextIncomp_c`, `SuccLex2`, cursor advance, unchanged),
- adversary A0/A1 sequencing and parent snapshot preservation (unchanged),
- return propagation (`RetAcc/RetRej` on parents, unchanged),
- halting absorption (unchanged),
- `FreshChild/CurBase` monotone allocation (unchanged),
- A001035/`PACK-REPR` avoidance (`PosF` remains current-frame closure only).

The DFS evaluator `M_D^alt` semantics requires that after pushing a child frame
for evaluation, the child becomes the active top and the parent remains below it
awaiting backtrack; making the old top false and the fresh child uniquely top is
exactly that discipline. Thus every transition admitted by the amended formula
remains a legal semantic `M_D^alt` DFS step, and the amendment only removes the
spurious underdetermined `Top'` interpretations identified by the audit.

**Contrast with pops.** Pop-return cases already had the unique-`Top'` discipline
via `PopTo_base(p̄,c̄): Top'(p̄) ∧ ∀z̄(Top'(z̄)->z̄=p̄)`. The fix gives pushes
the symmetric discipline: `Top'(d̄) ∧ ∀z̄(Top'(z̄)->z̄=d̄)` and `¬Top'(c̄)`.
