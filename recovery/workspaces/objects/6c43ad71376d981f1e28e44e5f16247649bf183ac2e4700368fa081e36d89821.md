## Executive verdict

1. **`PosOf/P_C` blocker: confirmed (as stated, with scope).** `[deduction]` A fixed-arity configuration code `d̄ ∈ W^r` over the ordered word domain has only `|W|^r = N^r = (n+k+1)^r` possible values, while the `G(n,k)` state component that is a transitively closed strict partial order on `n` keys ranges over an exponentially large family in general (`2^{Θ(n^2)}` scale / A001035-level state space in the minimax/poset view). Therefore `PosOf(d̄,u,v)` cannot decode arbitrary poset content from the fixed tuple alone as a complete configuration-content encoding. This is a valid obstruction to the naive fixed-tuple closure; it is **not** an obstruction to FO(PFP) definability of `SORT-BOUND-U` in principle. `[literature,deduction]`
2. **AC-independent monotonicity: confirmed as a necessary dependency.** `[deduction]` The proposed acceptance schema is syntactically positive in `AC`, but semantic monotonicity / intended fixed-point meaning of the acceptance operator requires that `P_C/t_C/a_C/b_C/m_C`, `Acc`, and `Yield*` (in particular `P_C/PosOf`) be independent of `AC`, unless a fully specified simultaneous/stratified operator is proved monotone as a whole.
3. **No smaller-class overclaim: mostly upheld, but read closure claims narrowly.** `[literature,deduction]` The artifacts do not legitimately establish `SORT-BOUND-U ∈ P`, FO(LFP) on the bare ordered word, NP/coNP membership, or any separation below the known open-separation frontier. The only complexity consequence used legitimately is the established `SORT-BOUND-U ∈ PSPACE` / FO(PFP)-capture-in-principle context. `decode-explicit` is appropriately cautious; `fixed-tuple-closure` contains a useful normal-form framing but should not be read as a finished formula-level proof (as both audits note).
4. **Closure paths: none concretely discharged.** `[open,deduction]` No artifact provides a single complete, explicit, fixed FO(PFP) construction with fully expanded decoders and a proved equivalence to `G(n,k)` acceptance / `S(n)<=k`. The three named closure routes remain precisely open.

## 1. `PosOf/P_C` `N^r` vs. `2^{Θ(n^2)}` blocker

### Confirmed

`[definition]` On intended `w=1^n#1^k`, `A(w)$ has domain `W={1,...,N}` with `N=n+k+1`, `Hash^W={n+1}`, `One^W=W\{n+1}` (up to equivalent FO-interdefinable conventions). `Key` is the prefix and `Ctr` is hash plus suffix. (`decode-explicit`, `fixed-tuple-closure`, `problem.md`.)

`[deduction]` For fixed arity `r`, a tuple `d̄=(d1,...,dr)\in W^r` has at most
```text
|W^r| = N^r = (n+k+1)^r
```
possible values. This is polynomial in `N` for fixed `r`.

`[definition,deduction]` A `G(n,k)` configuration includes a transitively closed strict partial order `P` on `Key` (`|Key|=n`). The minimax/poset state space relevant to exact comparison sorting is exponential-scale in `n^2` in general (the repo context cites A001035/Kleitman–Rothschild; the minimax DP can reach all labelled posets in the `upper-bound`/`research-certificates-barriers` context). Thus for all sufficiently large relevant `n`, fixed `r` cannot make `N^r` index arbitrary poset states needed by the full game semantics.

**Conclusion.** The blocker is sound as a **fixed-tuple content-decoding / representation obstruction**: `PosOf/P_C` cannot be discharged by “decode arbitrary poset content from `d̄\in W^r` alone” while keeping the tuple as the complete configuration code. (`decode-explicit` states this correctly; `audit-1` confirms it; `closure-audit`’s bare-word/state-element distinction is consistent.)

### Scope limits (important)

- `[literature,deduction]` This does **not** refute FO(PFP) definability of `SORT-BOUND-U`. `SORT-BOUND-U ∈ PSPACE` is recorded in `research-certificates-barriers.md` (Claim A, ATM/`G(n,k)` + Chandra–Kozen–Stockmeyer), and FO(PFP) captures PSPACE on ordered finite structures (Abiteboul–Vianu; Vardi). The missing item is a complete explicit construction/equivalence proof, not a known in-principle impossibility.
- `[deduction]` This does **not** mean `P_C(u,v)` or `Pos(u,v)` is undefinable as a relation: a 2-ary relation over `Key×Key` can represent the current poset. The obstruction is to making that content recoverable from a single fixed control tuple without the required full configuration encoding.
- `[falsification target]` Any proposed fix must show how the `n^2`-scale poset information is represented: by explicit fixed-arity relations/cells over the word or interpreted structure, by a proved simultaneous PFP system, or by an explicit ATM/configuration encoding — with semantics proved equivalent to `G(n,k)`.

## 2. AC-independent monotonicity

### Confirmed

`[deduction]` In the schema
```text
ψ(AC,d̄) := Acc(d̄)
          ∨ (MS ∧ ∃ē (YieldE(d̄,ē) ∧ AC(ē)))
          ∨ (MA ∧ ∃ē1∃ē2 (YieldA0(d̄,ē1) ∧ YieldA1(d̄,ē2) ∧ AC(ē1) ∧ AC(ē2)))
          ∨ MAcc,
```
the symbol `AC` appears only positively. That is a necessary syntactic feature, but not a complete semantic closure.

The acceptance operator on the relevant lattice is monotone in the intended simple case only if every non-`AC` predicate used by `ψ` has a fixed interpretation independent of the `AC` iterate, in particular:
```text
P_C/PosOf, TimeOf/t_C, AOf/a_C, BOf/b_C, ModeOf/m_C, Acc, YieldE, YieldA0, YieldA1 are AC-independent.
```
If these decoders/transitions depend on `AC` (or on an unstratified auxiliary fixed-point state not discharged), positivity of the displayed `AC` occurrences is insufficient; the full operator system must be specified and proved monotone/semantically correct.

**Conclusion.** The dependency is explicit in `decode-explicit` and `audit-1`, and should be treated as a hard requirement for any completed closure. `fixed-tuple-closure`’s monotonicity/staging discussion is plausible but incomplete because the final decoding is not fixed.

## 3. No smaller-class overclaim

### Confirmed

`[literature,deduction]` No artifact here provides a sound basis for:
- `SORT-BOUND-U ∈ P` or `S_unary ∈ FP`;
- FO(LFP) definability of `SORT-BOUND-U` on the bare ordered word;
- `SORT-BOUND-U ∈ NP` or `∈ coNP`;
- `SORT-BOUND-U ∉ P`, `∉ NP`, or any unconditional separation (these would imply major separations given `SORT-BOUND-U ∈ PSPACE`; see `AGENTS.md` and `problem.md`).

The artifacts correctly stay within the established/conditional frame:
- `SORT-BOUND-U ∈ PSPACE` `[literature,deduction]` (Claim A context in repo docs).
- FO(PFP) definition on ordered structures is in principle from capture theorems `[literature]`, but not concretely discharged here `[open]`.
- A positive/stratified alternating acceptance operator on a completely encoded finite configuration structure may be LFP/IFP in that operator setting `[deduction, conditional]`; this must not be promoted to an FO(LFP)/P upper bound for the actual language on the bare word.

**Caveat.** `fixed-tuple-closure` states “closure achieved at the fixed-tuple interpreted level” and “not blocked as FO(PFP) definability.” Read together with its §11 and the two audits, this is at most a schematic/normal-form closure claim, not a finished proof. Any stronger reading would be an overclaim.

## Final cross-check judgment

The `PosOf/P_C` `N^r`-vs-`2^{Θ(n^2)}` diagnosis is **confirmed** as the concrete representation blocker for the naive fixed-tuple decode. The AC-independence requirement for monotonicity/semantics is **confirmed**. The artifacts make **no legitimate smaller-class overclaim** when read carefully, especially `decode-explicit`; any reading of `fixed-tuple-closure` as a finished concrete FO(PFP) sentence would be too strong. **No closure path is actually discharged**: simultaneous PFP on interpreted configuration/cell relations, an explicit interpreted domain for exponentially many states, and an explicit ATM encoding proved equivalent to `G(n,k)` acceptance all remain open.
