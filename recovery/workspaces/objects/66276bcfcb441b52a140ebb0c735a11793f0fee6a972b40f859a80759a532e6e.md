## Question tested

For a finite poset `P`, let `m(P)` be the exact minimax number of comparisons
needed to finish sorting it (partial-order minimax value). We tested:

> For every finite poset `P` with `m(P) >= 2`, does there exist an **optimal**
> first comparison `(a,b)` (i.e. `1 + max(m(P^{a<b}), m(P^{b<a})) = m(P)`)
> such that the worse child has depth `m(P)-1` and the other child has depth
> `>= m(P)-2`?

Equivalently: among optimal comparisons, one has child depths differing by at
most 1 (`{m-2, m-1}`).

## What was implemented

- `scripts/oracle.py` — first exact oracle: labelled posets enumerated by all
  3-orientations of pairs, transitive closure filter, memo keyed by
  `(n, labelled relation tuple)`.
- `scripts/gen.py` — recursive generator of labelled posets by adding a new
  element with a down-set below it and an up-set above it (each labelled poset
  once).
- `scripts/oracle3.py` — final oracle used for the headline result: generator
  from `gen.py`, isomorphism dedup via 1-WL colour refinement plus
  within-cell permutations, exact minimax with memo keyed by
  `(n, canonical form)`. This is the run reported below.
- `scripts/oracle2.py` — intermediate brute-force enumerator (superseded).

All minimax values are exact integers from the recurrence
`m(P) = 1 + min_{a||b} max(m(P^{a<b}), m(P^{b<a}))`, base `m(total order)=0`.

## Validation of the oracle

1. **Class counts.** For `n = 1..7` the number of isomorphism classes found was
   `1, 2, 5, 16, 63, 318, 2045`, matching the known unlabelled-poset counts.
2. **Antichain check.** `m(antichain_n) = 0,1,3,5,7,10,13` for `n=1..7`,
   matching known `S(n)`.
3. **Independent cross-check.** For all 4473 labelled posets on `n<=5`, the
   labelled-memo oracle `oracle.py` and the canonical-memo oracle `oracle3.py`
   agree on every minimax value (0 differences).
4. **Bug found and fixed (honesty note).** An earlier version of `oracle3.py`
   keyed the minimax memo by canonical form alone, omitting `n`. Since e.g. the
   empty poset on 1 and on 2 elements share the canonical form, this corrupted
   values when several `n` were processed in one process. That version's
   results were **discarded**; the final run uses key `(n, canonical form)` and
   was re-run from scratch for all `n`.

For `n<=6` we also measured, for every `P` with `m>=2`, the best possible
`min(child depths)` among optimal comparisons; it was always `m-2` or `m-1`,
never below `m-2`. This is consistent with the property.

## Honest limits

- This is a **finite computation**, not a theorem. Nothing here proves the
  property for `n >= 8`, let alone all `n`. A counterexample at `n>=8` remains
  logically possible.
- The oracle is a straightforward exact minimax recursion with memoization and
  a home-grown canonical labelling (1-WL + within-cell permutations). Its
  correctness rests on the validation above, not on an external checked
  library.
- The threshold induction in `research-core-threshold.md` actually needs the
  weaker statement "some comparison has both children of depth `>= m-2`". We
  checked the stronger optimal-comparison version asked here; the stronger
  version implies the weaker one but is not implied by it.
- No claim about `S(n)`, certificates, or complexity classes follows from this
  finite check alone.
