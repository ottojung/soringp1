## 0. Baseline `[literature]`+`[definition]`+`[deduction]`

- `S(n)` = minimax height of adaptive comparison sorting of `n` distinct labelled keys; `SORT-BOUND-U = {1^n#1^k : S(n) <= k}`, input length `N=n+k+1` (`docs/problem.md`).
- `S(n) >= ceil(log2(n!)) = Theta(n log n)` `[literature]`.
- Budgeted DFS `CanSort(P,d)`: depth `d`, branching `<= 2B_n` with `B_n=binom(n,2)=Theta(n^2)` per level, time `2^{O(d log n)}`; transcript-only space `O((d+n)log(n+2))` bits (path/cursors `O(d log n)` + one reachability workspace `O(n log n)`). For function evaluation `d <= U(n)=O(n log n)` gives `2^{O(n log^2 n)}` time and `O(n log^2 n)` bits; for decision `d=k` gives `2^{O(k log n)}` time and `O((k+n)log n)` bits (`docs/research-budgeted-dfs.md`).
- Prior barrier (`C_path`, path-storing exhaustive DFS): `Omega(S(n) log n)=Omega(n log^2 n)` bits on successful runs, since an explicit resumable transcript/path stores `Omega(log n)` bits per level over `Omega(S(n))` levels `[deduction, prior report]`.

## 1. Exhaustive game-search with checkpoint/replay: what must be stored/recomputed `[definition]`+`[deduction]`

State at depth `t` is `(sigma_t, c_t)` in the natural DFS execution: `sigma_t=((a1,b1,o1),...,(at,bt,ot))` the ordered comparison outcomes on the current root-to-node path (or equivalently the induced poset `P(sigma_t)` together with enough move identity), and `c_t` the local control state needed to resume at each ancestor (e.g. cursor over the deterministic enumeration of incomparable candidate pairs for the sorter move, and which adversary answer/child remains). To perform **exhaustive deterministic backtracking** correctly, whenever the algorithm returns to an ancestor at depth `i < t` it must be able to:

1. **Reconstruct the node**: obtain a representation sufficient to enumerate the same candidate move set in the same deterministic order as from `P(sigma_i)` (or to continue from the stored cursor in that order). This is equivalent to access to `P(sigma_i)` up to the algorithm's deterministic move-selection function.
2. **Resume control**: know the cursor/child index already explored at depth `i`, so it does not repeat or skip branches.
3. **Evaluate the minimax predicate**: for a sorter node, answer is OR over candidates of AND over two adversary answers; for an adversary answer, move to `closure(P(sigma_i), a_{i+1}<b_{i+1} or reverse)`.

A **transcript-only** algorithm stores `sigma_t,c_t` directly (`O(t log n)` bits) and recomputes comparability by reachability from `sigma_t` (one `O(n log n)`-bit workspace). A **state-snapshot** algorithm stores `P(sigma_i)` explicitly (`Theta(n^2)` bits) plus cursor. A **checkpoint/replay** algorithm stores selected checkpoints `K subseteq {0,...,t}` with representations `R(i)` and, to reconstruct a non-checkpointed ancestor or the current node, replays comparison transcripts/poset updates from the nearest checkpoint `j = max{i in K : i <= target}` forward by recomputing `R(j+1),...,R(target)` (or restarts from root and replays). **Path recomputation** is the extreme case with few/no intermediate checkpoints.

Crucially, replay reconstructs *state* but does not create *control history*: unless every ancestor cursor/child status is stored, replay from a checkpoint must also reproduce the DFS traversal decisions, which for exhaustive search means either storing the explored-branch bits/cursors along the path or deterministically re-exploring in the same order (which is the source of time blowup in time-space tradeoffs).

## 2. (a) Candidate `o(n log^2 n)`-bit algorithms in sub-`2^{O(n^2)}` time `[deduction]`

- **Store full transcript/path:** `Theta(d log n)=Theta(n log^2 n)` at `d=S(n)`; not `o(n log^2 n)` `[deduction]`.
- **Store closure matrices/snapshots:** `Theta(n^2)` per snapshot/frame, worse than transcript unless very sparse checkpoints, but sparse checkpoints force replay (see §3).
- **Savitch-style reachability on implicit configuration graph:** Savitch's theorem gives `DSPACE(s^2)` for nondeterministic `s` space reachability but with large time; applying it to the implicit game/configuration graph does not obviously represent minimax AND-OR evaluation of the comparison game, and known generic transformations do not yield `o(n log^2 n)` bits and `2^{O(n log^2 n)}` time simultaneously here `[open]`.
- **Cook–Mertz / tree-evaluation style compression:** Cook–Mertz (STOC 2024) and related catalytic/tree-evaluation results evaluate trees/circuits in very low space in specific models (often with tree/circuit given or with catalytic memory assumptions not matching this uniform read-only-input comparison-game search). No instantiation giving an exact uniform evaluator of `S(n)` in `o(n log^2 n)` bits and sub-`2^{O(n^2)}` time was identified `[literature/open]`.
- **Conclusion for (a):** no concrete uniform algorithm with correctness and explicit time/space analysis achieving `o(n log^2 n)` bits in the stated time regime was found. This is not a proof of impossibility.

## 3. (b) Time-space tradeoff for a checkpoint/replay DFS model `[deduction]` (conditional/model-specific)

### 3.1 Model `C_{chk}(s,T)` (deterministic exhaustive checkpoint-replay DFS)

Fix `n>=4`. Consider any uniform deterministic algorithm that decides `CanSort(empty_n,d)` (or evaluates `S(n)`, calling it at `d>=S(n)`) by exhaustive depth-first exploration of the minimax comparison game `G(n,d)` and satisfies:

- **Correct exhaustive DFS semantics:** it returns the exact minimax value `CanSort(P,d-t)` for explored states and, at every sorter node, tries candidate comparisons in a fixed deterministic order (depending only on `n` and the reconstructed state), stopping early only on a True OR-child whose both adversary AND-children are True; at adversary nodes it evaluates both outcomes as required.
- **Checkpoint/replay:** the algorithm may maintain an arbitrary set of snapshots/checkpoints in at most `s` bits total. A snapshot may contain any function of the current execution (poset, transcript prefix, cursor prefix, derived hashes, etc.). To access a non-stored ancestor/current control/state, it may replay from some stored checkpoint by recomputing forward along a stored/recomputed transcript segment; root is always available.
- **No free advice/nonuniformity:** snapshots are computed from the input `(n,d)` and explored outcomes only.

Let `T` be the worst-case number of elementary comparison-game node visits/replay steps (counting a reconstructed/replayed edge traversal as a step) over inputs `(n,d)` in the relevant regime.

### 3.2 Information lower bound at one successful path `[deduction]`

Let `R` be any root-to-leaf successful path of depth `d' >= S(n)` (exists when answer is True). For each level `i`, let `I_i in {1,...,M_i}` be the *resume index* needed at the ancestor after backtracking: it includes the selected sorter candidate index among `M_i <= B_n` (or equivalent cursor position) and which adversary child remains/returned, so `log2 M_i >= log2 B_n >= 2 log2 n - 2 = Omega(log n)` for `n>=4` (`B_n=n(n-1)/2`). The full successful-path control transcript is
`I(R)= (I_1,...,I_{d'})` with
`H_id(I(R)) := sum_{i=1}^{d'} log2 M_i >= d' * Omega(log n) >= Omega(S(n) log n) = Omega(n log^2 n)` bits.

This is an identity-level information quantity: without it, two different successful DFS positions consistent with all stored data are not distinguishable as resumable execution points in the same deterministic enumeration.

### 3.3 Replay-time lower bound under bounded stored resume information `[deduction]` (counting argument)

Let `q <= s` be the number of bits of information about the successful-path resume transcript `I(R)` that are available from storage/checkpoints when needed, in the worst case along `R`. The missing amount is `H_miss := H_id(I(R)) - q >= Omega(n log^2 n) - s`.

**Counting/replay assumption (explicit):** in deterministic exhaustive DFS, each unit of recomputation/replay step can be charged to re-establishing only `O(log(n+d')) = O(log n)` bits of resume/control information for the current traversal (it replays or re-decides comparisons/cursor moves in the fixed deterministic order), and recovering `b` missing bits of the ordered resume transcript on the active path requires re-traversing a corresponding set of previously determined branch choices. Since each sorter level has `Omega(log B_n)=Omega(log n)` bits of candidate choice and adversary branching factor 2, leaving `m` levels' resume information unstored forces, in the worst case over adversary-consistent exhaustive traversals, replay work exponential in `m`: `T >= poly(n) * 2^{Omega(m)}`. Converting bits to levels via `m >= H_miss / O(log n)` gives
`T >= 2^{Omega(H_miss / log n)} / poly(n) = 2^{Omega(n log n - s/log n)} / poly(n)` (for all sufficiently large `n`).

Equivalently, for `s <= c1 * n log^2 n` and large `n`,
`log2 T >= c2 * n log n - c3 * s/log n - O(log n)`, i.e.
` s + K (log n)(log2 T) >= Omega(n log^2 n * log n)` / rearranged as the **time-space tradeoff**
` (log n) * log2 T + Omega(s) >= Omega(n log^2 n)` in this model (constants model-dependent).

This is a standard DFS checkpoint/replay counting form made explicit for `C_{chk}`: you may trade stored per-level cursor/path bits for multiplicative replay, but each omitted `Theta(log n)` bits costs an exponential-in-levels recomputation factor.

### 3.4 Consequence for the requested regime `[deduction]`

- For `T <= 2^{O(n log^2 n)}` (the known budgeted-DFS time scale), `log2 T = O(n log^2 n)` and the tradeoff yields `(log n)*O(n log^2 n) + Omega(s) >= Omega(n log^2 n)`, which is **not** by itself sufficient to force `s = Omega(n log^2 n)`; thus a strict obstruction to `s=o(n log^2 n)` at that time bound does **not** follow from §3.3 alone.
- However, to achieve small space, e.g. `s = O(n log n)` or `s=o(n log^2 n)` with a large multiplicative gap, the tradeoff requires `log2 T >= Omega(n log^2 n - s/log n)`? more directly from `T >= 2^{Omega(H_miss/log n)}`: if `s <= (1-eps)*H_id(I(R)) = (1-eps)*Omega(n log^2 n)` then `H_miss = Omega(n log^2 n)` and `T >= 2^{Omega(n log n)}/poly(n)`; to push `s` down to `O(n log n)` needs `H_miss = Omega(n log^2 n)` as well, still giving `T >= 2^{Omega(n log n)}` but not exceeding known bounds. The tradeoff becomes quantitatively strong only when targeting `s = o(n log n)` or when bounding replay more tightly: `s = o(n log n)` would imply `H_miss >= Omega(n log^2 n)` and `T >= 2^{Omega(n log n)}` — consistent with known time but showing no space gain below the `O(n log n)` reachability-workspace/order term without also changing the model.
- For the coarser regime `T` sub-`2^{O(n^2)}` (`log2 T = o(n^2)`), §3.3 imposes no nontrivial constraint beyond `s >= 0`.
- Therefore, within `C_{chk}` under this counting assumption, **checkpoint/replay yields at best a time-space exchange but no proved reduction of space below `Theta(n log^2 n)` at the `2^{O(n log^2 n)}` time scale, and no proved obstruction of that form was derived here except the path-information lower bound `H_id(I(R))=Omega(n log^2 n)` on total resume information itself** (§3.2). Any actual `o(n log^2 n)`-bit scheme would have to avoid storing *or implicitly maintaining* that resume information while still resuming correctly.

This is a **model-specific** lower bound: it assumes exhaustive deterministic DFS with replay counted as recomputation and measures `q` as stored resume/control information for a successful depth-`S(n)` path. It does **not** rule out non-DFS exhaustive paradigms, algorithms that avoid explicit resume by a different exact evaluation method, or models with different primitives (see §4).

## 4. Caveats and open points `[open]`+`[deduction]`

- **Not a universal theorem for all checkpoint/replay evaluators:** a fully general time-space lower bound for every possible deterministic exact method in the stated time regime is not proved. In particular, schemes that restructure the search (symmetry quotienting without stored path, algebraic/BDD-like compression of frontier states, or tree-evaluation/catalytic techniques adapted to this AND-OR game) could in principle change the information accounting; none with the requested bounds is exhibited or known here.
- **Savitch/tree-evaluation note:** Savitch-style recursion stores segment endpoints/paths of length related to log depth in reachability but squares time; minimax game evaluation is not plain reachability. Cook–Mertz-style space compression has strong model preconditions and does not directly give the stated uniform bounds for `S(n)` `[open/literature]`.
- **Model gap:** §3.2 identifies `Omega(n log^2 n)` bits of resume/control information on a successful path, but §3.3 gives only a replay counting tradeoff under explicit assumptions; it does not prove that a checkpoint/replay algorithm cannot maintain/derive needed resume information in `o(n log^2 n)` bits while keeping `T <= 2^{O(n log^2 n)}`. The requested obstruction (e.g. ruling out `o(n log^2 n)` bits at sub-`2^{O(n^2)}` time) is therefore **not established here** for checkpoint/replay/path-recomputation beyond the path-storing class `C_path`.
- **No complexity-class separations, no NP/hardness claims, no optimality of the `O(n log^2 n)` upper bound** `[deduction]`.
- **Falsifier targets:** (i) for `C_path`, any `o(n log^2 n)`-bit correct exhaustive path-storing algorithm in sub-`2^{O(n^2)}` time; (ii) for checkpoint/replay, a uniform deterministic exact evaluator with `s=o(n log^2 n)` bits and `T <= 2^{O(n log^2 n)}` (or sub-`2^{O(n^2)}`) together with a complete correctness and cost proof.
