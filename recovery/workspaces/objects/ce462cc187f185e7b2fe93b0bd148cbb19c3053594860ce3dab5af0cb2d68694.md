## 2. Exact assumptions

Assumptions A1–A5 in the artifact are explicit and mostly sound:

- **A1 (adaptive, worst-case, pairwise, distinct keys):** matches `problem.md`.
- **A2 (transitively closed poset, exact `e(P)`):** matches model; `e(P)` is
  computed by downset/ideal DP in `one_ply_obstruction.linear_extensions`
  (`O(2^n)` table for `n` elements), exact for integer states.
- **A3 (Wells admissibility/caps, non-converse):** cap `2^(C-c)` after `c`
  comparisons is correct for a height-`C` tree. The heavier-child path argument
  is stated; converse not claimed. **Minor wording note:** the parenthetical
  "note 2^33 > 13!, so depth 0 is fine; depth 1 requires children <= 2^32 and
  `13!/2` fits" is mathematically right but slightly telegraphic; not misleading.
- **A4 (resource exhaustion inconclusive):** clearly stated and respected by the
  script/witness-search path.
- **A5 (local exact arithmetic / feasibility):** honest that full `n=13` exact
  minimax is not feasible here and `e(P)` is used for local checks only.

**Additional assumption surfaced by code:** depth>=2 `wells_levels` merges states
by `canon_key_shallow`, which the script explicitly labels "NOT a complete
canonical form" and an **upper bound on orbit counts**. For emptiness this is
safe (merging cannot create a false empty level? it can drop representatives
but never invent admissible states; an empty merged level would still mean no
admissible representatives were found among kept classes only if every
admissible state maps to some kept key — but `nxt[key]=h` keeps one per key, so
admissible states are preserved up to that lossy keying; however, the script
does not claim completeness of the merged search as a certificate). The artifact
correctly avoids claiming any obstruction from this run and reports the exact
orbit analysis separately in summary/tests.

## 5. Inconclusive / witness-search / resource-cap handling

**Generally sound, with notes:**

- **Depth<=2 non-empty levels:** correctly labeled inconclusive and explicitly
  "does not suggest `S(13)<=33`" — good.
- **Node-cap exhaustion:** returns `None`/inconclusive in witness search; A4 and
  printed notes forbid interpreting cap exhaustion as evidence either way.
- **`False` from witness search:** script distinguishes "complete False" from
  cap-hit and warns that completeness/audit are required before claiming
  `S(13)>33`. This is the right caution, because this DFS is a decision
  procedure over explored moves but is not packaged as an externally checkable
  completeness certificate.
- **`True` from witness search:** would mean a height-33 strategy exists in that
  search tree; the note says "a finite witness, in principle checkable by
  emitting the decision tree" and marks it unexpected. However, the script
  **does not emit** the strategy/certificate, so a `True` result would require
  instrumenting emission and independent verification before any claim. The
  current code path is acceptable as an exploratory probe but not a witness
  certifier.
- **Exactness of local checks:** `e_count`/`linear_extensions` are exact for
  `n=13`; admissibility compares exact integers to powers of two. No floating
  point affects decisions.
- **Shallow canonicalization in `wells_levels`:** can under-merge (upper bound on
  classes), never a verified obstruction certificate. The script avoids that
  claim. A future extension should use exact poset congruence/canonical
  labeling before treating an empty level as a certificate.
