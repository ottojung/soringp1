# Exec report: FO(TC)-definable optimal strategy programs (small n)

**Worktree:** `/home/lubko/soring-fronts/fotc-strategy-program-smalln-20261121` (base `6a96398`).
**Scope:** unary encoding; target `SORT-BOUND-U`; no repo/Lean changes.
**Question (all `n`):** can the optimal adaptive comparison strategy for `n` distinct keys be encoded as a polynomial-size, polynomial-time-executable program in a restricted FO(TC) language?

## 1. Prior context (literature/deduction)

- `SORT-BOUND-U ∈ PSPACE` is proved (game/alternating TM); by Immerman's capture theorem this implies an FO(PFP) definition on ordered structures, but an explicit formula is separate work (`docs/research-plan.md`, "Descriptive complexity").
- FO(TC) data complexity on ordered structures is NL; combined complexity is PSPACE-complete. A growing formula is a combined-complexity input, so "FO(TC) formula" is not by itself an upper bound (`docs/research-plan.md`; prior front `fo-tc-strategy-programs`).
- `POL-DEPTH` is coNP-complete for FO(TC)-expressible policies with polynomial single-order evaluation (prior front `fo-tc-policy-interpreter`): universal worst-case verification is hard even when single-order evaluation is polynomial.
- State space is exponential: labelled posets `2^{Θ(n²)}` (Kleitman–Rothschild; `docs/research-state-compression.md`); symmetry compression does not change the exponent.
- A single optimal policy tree has `2·n! − 1` nodes (`docs/research-strategy-certificates.md`).

## 2. Computation: the optimal policy for small `n` (experiment)

Using the memoized minimax recurrence of `scripts/state_compression.py` (`F(P) = 1 + min_{i,j incomparable} max(F(P+i<j), F(P+j<i))`), I extracted a deterministic optimal policy: at each poset `P`, choose the lexicographically smallest incomparable pair `(i,j)` attaining the optimum.

| `n` | `S(n)` | all reachable posets | states visited under optimal play (= `2·n!−1`) | isomorphism classes of visited states |
|---|---:|---:|---:|---:|
| 4 | 5 | 219 | 47 | — |
| 5 | 7 | 4231 | 239 | 19 |
| 6 | 10 | 130023 | 1439 | — |

For `n = 5`: `S(5) = 7`, and the policy visits 239 states (119 internal decision nodes + 120 total-order leaves), consistent with `2·5! − 1 = 239`. These 239 labelled states fall into only **19 isomorphism classes**, and the chosen comparison is equivariant: it depends only on the isomorphism type of the current poset (up to relabelling of keys).

The optimal policy is therefore a function

```
f : Poset_n  ->  {incomparable pairs} ∪ {halt},
```

with `f(P)` determined by the isomorphism type of `P`.

## 3. Attempted FO(TC) encoding for `n = 5` (paper proof + size measurement)

**Structure.** The current knowledge state is already a binary relation `Lt` on the key domain `[n]` (the transitive closure of comparisons). The FO(TC) formula receives this relation and must define the next comparison pair (or totality). The universe is the `n` keys; no separate state domain is introduced.

**Naive construction (state dispatch).** Enumerate the 119 internal posets `P_t` reachable under optimal play. For each, assert equality of the input relation `Lt` to `P_t`, then select the corresponding optimal pair. Equality of `Lt` to a fixed poset on `n` keys costs `n(n−1)` literals (for each ordered pair `(a,b)`, either `Lt(a,b)` or `¬Lt(a,b)`). The whole dispatch is a disjunction of 119 such conjunctions, followed by an existential selection of the pair.

Measured sizes:

| `n` | internal states (`n!−1`) | literals per state (`n(n−1)`) | naive formula size (literals) |
|---|---:|---:|---:|
| 5 | 119 | 20 | ≈ 2.4 × 10³ |
| 6 | 719 | 30 | ≈ 2.2 × 10⁴ |
| general | `n! − 1` | `n(n−1)` | `Θ(n! · n²)` |

The terminal (total order) case needs no enumeration: totality is the single FO sentence `∀a,b (a≠b → Lt(a,b) ∨ Lt(b,a))`, size `O(1)` symbols.

**Growth.** `Θ(n! · n²)` is super-polynomial (indeed exponential) in `n`, and `n` is `Θ(N)` where `N = n + k + 1` is the unary input length. Hence the naive encoding is **not** polynomial in `N`. For `n = 5` the constant is small, but a single instance never witnesses polynomiality: polynomiality is a statement about the uniform family's growth rate.

**Can the dispatch be compressed?** The 119 states collapse to 19 isomorphism classes, so in principle a 19-case dispatch suffices—*if* isomorphism type were FO(TC)-definable compactly. It is not:

- Poset isomorphism is GI-complete, and fixed-variable FO(TC) has NL data complexity; isomorphism type of an arbitrary poset is not known to be in NL (or even in P).
- Even the coarsest useful invariant tried in this project—linear-extension count `e(P)`—does **not** determine the minimax value (two 5-element posets with `e = 8` have `F = 3` vs `F = 4`; `docs/research-n12-nontightness.md`). So no scalar invariant compresses the dispatch.
- Symmetry compression does not reduce the exponent: both labelled and unlabelled poset counts are `2^{Θ(n²)}` (`docs/research-state-compression.md`).

Thus the only known FO(TC) route to the optimal policy is the exponential state dispatch, or an isomorphism test that FO(TC) cannot perform compactly.

**Algorithmic alternative.** Ford–Johnson is optimal for `n ≤ 11` (hence for `n = 5`) and has a compact imperative description with loops over indices. But translating it into fixed-variable FO(TC) requires (i) first-order definable index arithmetic and iteration (Jacobsthal numbers, binary-search midpoints) which FO(TC) on pure ordered structures does not directly provide, and (ii) a uniform polynomial combined bound (Lemma A of the project note), which constrains variable width and clocks. No such translation has been exhibited. This is a separate, also open, route.

## 4. Barrier: exponential state space (deduction)

Transitive closure (TC) can express reachability in a polynomial-size graph, but it cannot manufacture a polynomial-size graph from an exponential state space. Here:

- The state space of the sorting game is the set of labelled posets on `n` keys: `2^{Θ(n²)}` states.
- Even restricting to states reachable under *some* optimal policy, the count is `Θ(n!)` (one leaf per input permutation) for a single policy tree, and the optimal-play reachable set for `n = 5` is 239, for `n = 6` is 1439.
- TC over a polynomial domain (pairs of keys, or single keys) can only define relations on `O(n²)`-size (or `O(n)`-size) domains. It cannot, by itself, address `2^{Θ(n²)}` distinct states without an exponential blowup in formula size.
- Therefore, unless a polynomial-size complete invariant or decomposition for posets is found (none is known; series/ordinal-sum decompositions are exact but do not shrink the state space, `docs/research-series-decomposition.md`), FO(TC) does not yield a polynomial-size program for the optimal policy.

## 5. Blocker (precise)

**Missing construct:** an FO(TC)-definable, polynomial-size canonical form (or complete invariant) for finite posets under isomorphism, *or* equivalently a decomposition theorem that reduces the sorting-game state space to polynomial size while preserving the minimax value. Without this, the optimal comparison at a state cannot be selected by a formula of size `poly(n)`; the only definable selection is the exponential state dispatch of §3.

What would be needed to close it:
1. A polynomial-time (ideally NL) canonical form for posets, or a proof that none exists for fixed-variable FO(TC); and
2. A uniform recurrence/decomposition for optimal play whose control flow is polynomial in `n` (the Ford–Johnson route would require additionally first-order arithmetic and a combined-complexity certificate).

## One-line verdict
No polynomial-size FO(TC) optimal-strategy program is exhibited for `n=5`; the blocker is the exponential sorting-game state space together with the absence of a polynomial-size, FO(TC)-definable poset canonical form, forcing an `Θ(n!·n²)` state dispatch.
