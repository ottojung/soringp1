## 1. Question and consequence

Question (all `n`): can every optimal adaptive comparison sorter for `n` distinct keys, of worst-case depth `S(n)`, be encoded by a **polynomial-size FO(TC) strategy program** whose interpreter runs in **polynomial time**, with correctness

\[
\exists p\; \forall \text{ total input orders } X:\; \operatorname{Run}(p,X)\text{ sorts and uses }\le k\text{ comparisons},
\]

where comparisons are charged as oracle queries?

Consequences:

- If such programs existed with a **polynomial-time** verifier for the universal condition, then `SORT-BOUND-U` would be in `NP`.
- If they existed only as an existential `Σ_2^P`-style statement, the upper bound would be `SORT-BOUND-U ∈ Σ_2^P`, not `NP`.
- If no polynomial-size complete normal form exists, the FO(TC) strategy-program route does not improve the known `PSPACE` upper bound for `SORT-BOUND-U`.

The answer found here is: **no polynomial-time interpreter is available for unrestricted FO(TC) programs; and even under the polynomial single-order-evaluation premise, universal worst-case verification is coNP-complete.** Hence there is **no known** sound, complete, polynomial-size, polynomially checkable FO(TC) normal form for all optimal `n`-sorters. The remaining candidate is a restricted subclass such as framed DAGs, whose completeness is open.

## 2. Definitions: syntax, semantics, cost

### 2.1 Syntax

A **strategy program** `p` is not merely a sorting predicate. It is an adaptive comparison algorithm whose state is the current knowledge of the unknown order, not the order itself. Concretely, `p` is a tuple

\[
p=(\phi_{\text{cmp}},\phi_{\text{halt}},\phi_{\text{out}})
\]

of FO(TC) formulas/programs over structures whose non-hidden part is

\[
\mathcal S(P,H)=([n],P,H),
\]

where:

- `P` is the current transitively closed partial order (the comparison history's consequences);
- `H` is the transcript of previous comparison outcomes;
- the unknown total order `X` is **not** in the structure.

Thus `p` has no free access to `X`; comparisons are **oracle queries**. At each non-terminal state, `\phi_{\text{cmp}}` selects an incomparable pair `{i,j}` in `P` (or halts if `P` is total). `\phi_{\text{halt}}` tests totality; `\phi_{\text{out}}` returns the induced total order at termination.

An **FO(TC) strategy program** is one whose state transitions are definable in first-order logic plus transitive closure. A **polynomial-time strategy program** is one for which each transition is computable in time polynomial in `|p|+n`.

### 2.2 Semantics of `Run(p,X)`

Given `X`:

1. Start with `P_0` = antichain on `[n]`, empty transcript.
2. While `P_t` is not total:
   - query `p` for a pair `{i,j}` incomparable in `P_t`;
   - charge one comparison;
   - receive the answer from `X`;
   - update `P_{t+1}` by transitive closure;
   - if the comparison budget `k` is exceeded, stop with failure.
3. If `P_t` is total within budget, output its total order; otherwise fail.

`Run(p,X)` is correct iff it terminates with the order of `X` after at most `k` comparisons.

### 2.3 Cost accounting

- **Comparison cost:** number of oracle queries. This is the quantity bounded by `k` and by `S(n)`.
- **Program size:** `|p|` in bits, including any hard-wired formula structure.
- **Interpreter time:** time to evaluate `p` on one state.
- **Combined complexity:** time as a function of both `|p|` and `n` (and `k`), not just of `n` for a fixed program.

A **polynomial-size complete normal form** would require, for every `n,k` with `S(n)≤k`, a program `p` with `|p|=poly(n+k)`, a polynomial-time interpreter, and a polynomial-time verifier that `p` is sound and complete at budget `k`.

## 3. Combined complexity

### 3.1 Native FO(TC) complexity

For FO(TC):

- **Data complexity** (formula fixed): model checking is in `NL` (and NL-complete for some formulas) on ordered structures.
- **Combined complexity** (formula/program is part of the input): model checking is `PSPACE`-complete.

Therefore, for an arbitrary FO(TC) strategy program `p`, evaluating one transition `Run(p,X)` is **not** polynomial-time in the combined sense. The native interpreter is `PSPACE`, not `P`.

Consequence: the phrase "polynomial-time interpreter" is not a property of unrestricted FO(TC). It forces a restriction to a fragment whose combined complexity is polynomial (for example, fixed-formula/data-complexity evaluation, bounded-variable fragments, or a different normal form).

### 3.2 What a polynomial interpreter would imply

If one restricts to programs with a polynomial-time interpreter, then for a fixed program `p`:

- single-order evaluation `Run(p,X)` is polynomial-time;
- the universal statement `\forall X\; \operatorname{Run}(p,X)\text{ succeeds}` has an NP-verifiable counterexample (an explicit permutation `X` whose trace exceeds `k`).

Hence universal worst-case verification is in `coNP`. The prior front `fo-tc-policy-interpreter` proves more: for FO(TC)-expressible policies with polynomial single-order evaluation, the problem

\[
\mathrm{POL\!-\!DEPTH}=\{(p,1^n,1^k): \max_X \operatorname{depth}(p,X)\le k\}
\]

is **coNP-complete** (reduction from TAUTOLOGY). Therefore, unless `P=NP`, **no polynomial-time sound and complete verifier exists for the general FO(TC) policy class**, even when single-order evaluation is polynomial.

### 3.3 Upper bound if polynomial-size programs existed

If polynomial-size FO(TC) strategy programs with polynomial-time interpreters existed for all optimal `n`-sorters, then correctness

\[
\exists p\;(|p|=poly(n+k))\; \forall X\; \operatorname{Run}(p,X)\text{ succeeds}
\]

would place the representable subclass in `Σ_2^P`. It would **not** by itself place `SORT-BOUND-U` in `NP`, because the universal quantifier remains. NP membership would additionally require a polynomial-time verifier for the universal condition, which the coNP-hardness result rules out for the general FO(TC) class.

## 4. Sound, complete, polynomial-size normal form?

### 4.1 General FO(TC) policies

For unrestricted FO(TC) policies:

- combined interpreter complexity is `PSPACE`;
- universal verification is coNP-hard under the polynomial-evaluation premise;
- no all-`n` completeness theorem is known.

Thus the general FO(TC) route does not currently yield a polynomial-size proof-carrying normal form.

### 4.2 Framed DAGs as a restricted candidate

Framed comparison DAGs (`research-framed-certificate-frontier.md`) provide a sound, polynomial-time verifier for a given DAG. Their completeness at exact `S(n)` is open. The FO(TC) coNP-hardness reduction does not automatically apply to every restricted normal form; it applies to general FO(TC)-expressible policies. This leaves room for a restricted class, but no such class has been proved complete for all optimal sorters.

### 4.3 Evidence against automatic completeness

- Two-phase FO(TC) policies fail exactness at `n=5,9,10,17,\dots,21`.
- Exact-reset canonical forms are blocked for odd `n` by the `A_n \to V_n` obstruction.
- All-optimal strategy DAGs grow rapidly for `n≤6` (`DAG(all)` from 19 to 65551), and their symmetry quotients also grow (19 to 134). This is consistent with, but does not prove, super-polynomial complete-certificate size.
- `S(n)` is not determined by `e(P)` alone (`m(P)` can differ at equal `e(P)`, first at `n=5`, `e=8`), so simple potential-based compression is insufficient.

## 5. Independent checks

### 5.1 Arithmetic for the coNP-hardness reduction

For `m=6`, `n=2m=12`:

- binary-insertion cost `B_ins(12)=33`;
- compare-all-pairs cost `12·11/2=66`;
- threshold `k=m+B_ins(12)=39`;
- non-tautology depth `m+66=72 > 39`.

The gap grows with `m`, so the reduction's correctness is arithmetic, not merely asymptotic.

### 5.2 Brute-force policy check (reproduced)

For `m=3` (`n=6`), `k=14`, enumerating all `720` orders:

- tautology `v_0 ∨ ¬v_0`: 0 orders exceed `k`, max depth 14;
- non-tautology `v_0 ∧ v_1 ∧ v_2`: 630 orders exceed `k`, max depth 18;
- mixed `(v_0 ∧ v_1) ∨ v_2`: 270 orders exceed `k`, max depth 18.

This validates the branch-cost accounting used in the coNP-hardness construction.

### 5.3 Small sorter comparison

Known exact values and natural non-optimal programs:

| `n` | `S(n)` | insertion sort `n(n-1)/2` | binary insertion `B_ins(n)` | merge-sort bound `n⌈log_2 n⌉` |
|---|---:|---:|---:|---:|
| 2 | 1 | 1 | 1 | 2 |
| 3 | 3 | 3 | 3 | 6 |
| 4 | 5 | 6 | 5 | 8 |
| 5 | 7 | 10 | 8 | 15 |
| 6 | 10 | 15 | 11 | 18 |

Insertion sort is optimal only for `n≤3` among these; binary insertion matches `S(n)` for `n≤4` but not `n=5,6`. This illustrates that even simple polynomial programs are not exact optimal strategies, and an exact optimal program would need state-dependent decisions not captured by fixed insertion schedules.

## 6. Verdict

- **PROVED (literature/deduction):** Native FO(TC) combined complexity is `PSPACE`-complete; data complexity is `NL`.
- **PROVED (prior front, cited):** Under polynomial single-order evaluation, `POL-DEPTH` is `coNP`-complete for FO(TC)-expressible policies.
- **CONDITIONAL (deduction):** Polynomial-size FO(TC) programs with polynomial interpreters would give a `Σ_2^P` upper bound for the representable subclass, not `NP` membership.
- **REFUTED (as a general claim):** "FO(TC) policy plus polynomial single-order evaluation yields an NP certificate." The universal check is coNP-hard.
- **OPEN:** Whether any polynomial-size, sound, complete, polynomially checkable normal form exists for all optimal `n`-sorters; whether a restricted FO(TC) fragment can be both polynomial-time interpretable and exactly complete for all `n`.

## 7. Next decisive obstacle

The central remaining question is not whether general FO(TC) policies can be verified in polynomial time (they cannot, unless `P=NP`), but whether a **restricted subclass**—most plausibly framed DAGs with explicit joins and depth accounting—can be proved complete for exact `S(n)` for all `n`. The next useful result would be either:

1. a proof that some restricted normal form has polynomial size for all `n` and exact height `S(n)`; or
2. an all-`n` lower bound showing that every polynomial-time-checkable normal form in a stated fragment misses exact optimality (as two-phase policies already do for infinitely many `n`).
