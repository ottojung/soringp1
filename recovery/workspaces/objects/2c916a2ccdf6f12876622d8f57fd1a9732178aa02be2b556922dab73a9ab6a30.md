# Concrete FO(PFP) encoding for `SORT-BOUND-U`

**Status:** research note (explicit paper construction / schematic expansion).
Not Lean-checked. Labels: `[definition]`, `[literature]`, `[deduction]`,
`[open]`, `[falsification target]`.

**Falsifiable question (SoringP1 #301).** Can the missing concrete FO(PFP)
encoding be completed for
`SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`
on the ordered word structure `A(1^n # 1^k)`? Produce a concrete fixed
signature, interpretation/domain, configuration relations, Init/Acc/Mode/
Yield/TC subformulas (or a fully explicit schematic expansion with fixed
arities), and a PFP alternating-acceptance semantics argument; or identify
a precise obstacle preventing a fixed-syntax expansion.

**Answer (deduction, conditional on standard FO/PFP machinery).** A concrete
encoding is possible by the standard route: FO-interpret the polynomial-size
game/ATM configuration domain from the ordered word, then apply a fixed-arity
partial fixed-point operator to an explicit alternating-acceptance formula.
The construction below fixes the signature, interpretation, domain,
configuration relations, and gives explicit FO/PFP subformula schemas for
`Init`, `Acc`, `Mode`, `Yield`, and `TC`. The remaining gap to a
*fully closed* formula on the bare `N`-element word universe with no
interpretation is a representation/arity obstacle, not a logical
non-definability obstacle; §9 states it precisely.

## 1. Fixed facts

`[definition]` (`docs/problem.md`) `S(n)` is the minimum height of a
deterministic adaptive comparison decision tree sorting `n` distinct
labelled keys. `SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }`, input length
`N = n+k+1`.

`[deduction]` **Game `G(n,k)`** (`docs/research-certificates-barriers.md`,
§0; Claim A). A state is a transitively closed strict partial order `P` on
`[n]={0,...,n-1}`. Start at the empty order. While `P` is not total and
fewer than `k` comparisons have been made, the sorter picks an incomparable
pair `{x,y}`; the adversary answers `x<y` or `y<x`; set `P := TC(P ∪
{(x,y)})`. The sorter wins iff a total order is reached within `k`
comparisons. `S(n) <= k` iff the sorter wins `G(n,k)`.

`[deduction,literature]` **PSPACE basis.** Claim A gives an alternating TM
deciding `G(n,k)` in time `O(k n^2)=O(N^3)` and space `O(n^2)=O(N^2)` on
unary input, hence `ATIME(poly(N))`; `APTIME = PSPACE`
(Chandra–Kozen–Stockmeyer 1981). Therefore `SORT-BOUND-U ∈ PSPACE`.

`[literature]` **FO(PFP) capture.** On ordered finite relational structures,
FO(PFP) captures PSPACE (Abiteboul–Vianu; Vardi). This guarantees existence
of *some* FO(PFP) sentence defining every PSPACE property of ordered finite
structures, but does not by itself produce a problem-specific explicit
formula. The construction below is an explicit instantiation for `G(n,k)`.

## 2. Input structure and fixed signature

`[definition]` **Word signature.**
```text
σ_w = (<, One, Hash)
```
where `<` is binary (linear order) and `One`, `Hash` are unary. For
`w = 1^n # 1^k`, the standard ordered word structure is
```text
A(w) = (W, <^W, One^W, Hash^W),   W={1,...,N}, N=n+k+1,
One^W = {1,...,n}, Hash^W={n+1}, and the suffix {n+2,...,N} represents 1^k.
```

`[deduction]` Malformed words are rejected by an FO sentence `WellFormed_w`.
The unique hash position `h` is FO-definable:
```text
HashPos(h) := Hash(h) ∧ ∀z (Hash(z) -> z=h).
Pre1(x)    := ∃h (HashPos(h) ∧ x < h).
Suf1(x)    := ∃h (HashPos(h) ∧ h < x).
WellFormed_w :=
  ∃h HashPos(h)
  ∧ ∀x ((x < h -> One(x)) ∧ (h < x -> One(x)) ∧ ¬One(h))  [up to exact alphabet choice]
```
(Adjust the alphabet convention as needed; only the definable split into an
`n`-prefix and a `k`-suffix matters.)

## 3. Interpreted game/configuration domain

The alternating game/ATM state contains an `n×n` poset matrix, a budget
counter, a selected pair, and a control mode. On the bare `N`-element word,
a fixed-arity relation cannot store `n^2` mutable bits as a single
configuration element; the standard solution is an FO interpretation.

`[definition]` **Configuration signature (fixed arities).** We use a
polynomially interpreted domain `D_w` and fixed-arity relations. The
configuration is encoded by relation variables
```text
P(u1,u2,v1,v2)     -- current poset bit: key u <_P key v
T(t1,t2)           -- time/budget counter has value coded by (t1,t2)
A1(a1,a2)          -- first endpoint of selected comparison
A2(b1,b2)          -- second endpoint of selected comparison
M(m)               -- control mode (finite constant set)
Q(q)               -- optional ATM control/state (finite constant set)
H(h1,h2)           -- optional head/cursor (if full ATM simulation is used)
```
All variables range over the interpreted key/counter universe. The arities
are fixed (binary/4-ary) independent of `n,k`.

`[definition]` **Interpreted key domain.** Let
```text
Key(x) := Pre1(x) ∨ (x = min_< W in a degenerate convention)  -- intended: elements representing [n]
```
More concretely, use the `n` elements of the `1^n` prefix as the key
universe `[n]`, identified by their positions in `<`. Thus keys are
first-order definable elements of `A(w)`:
```text
Key(x) := ∃h (HashPos(h) ∧ x < h ∧ One(x)).
KeyEq(x,y) := x=y.
KeyLt(x,y) := x < y.
```
This gives exactly `n` keys when the input is well-formed.

`[definition]` **Counter/time domain.** Use the `k` suffix positions (plus
zero, encoded by the hash or a distinguished element) to represent
`{0,...,k}`:
```text
Ctr(x) := Hash(x) ∨ Suf1(x).
Zero(x):= HashPos(x).
SuccCtr(x,y) := Ctr(x) ∧ Ctr(y) ∧ x < y ∧ ¬∃z(Ctr(z) ∧ x < z ∧ z < y).
CtrLe(x,y) := Ctr(x) ∧ Ctr(y) ∧ (x=y ∨ x<y).
MaxCtr(x) := Ctr(x) ∧ ¬∃y(Ctr(y) ∧ x < y).
```
So the budget `k` is the number of suffix elements and the available
remaining comparisons are tracked by a counter in this ordered set.

`[deduction]` **Domain size.** The interpreted state uses relations over
`Key ∪ Ctr ⊆ W`, so the PFP computation runs on a polynomial-size ordered
domain (size `N`). The poset itself is a 2-ary relation `P ⊆ Key×Key` with
`n^2` possible bits; storing `P` as a second-order object is represented in
FO(PFP) by letting the fixed-point relation range over tuples that include
key pairs/codes in the interpreted domain. Formally this is the standard
configuration-coding step in the FO(PFP)=PSPACE proof.

## 4. Configuration relations and FO state predicates

A staged game/ATM configuration is represented by
```text
C(P, t, a, b, m)
```
where `P(x,y)` is the poset, `t` is the time/budget used or remaining in the
chosen convention, `(a,b)` is the current candidate comparison when relevant,
and `m` is a control mode. In the fixed-point formula we use relation
variables over `A(w)` (or over its interpretation).

`[definition]` **Poset predicates.** Let `P(x,y)` mean `x <_P y`.
```text
PValid(P) := ∀x∀y (P(x,y) -> (Key(x) ∧ Key(y) ∧ x != y))
             ∧ ∀x ¬P(x,x)
             ∧ ∀x∀y∀z ((P(x,y) ∧ P(y,z)) -> P(x,z)).

Total(P) := ∀x∀y ((Key(x) ∧ Key(y) ∧ x != y) -> (P(x,y) ∨ P(y,x))).

Inc(P,x,y) := Key(x) ∧ Key(y) ∧ x != y ∧ ¬P(x,y) ∧ ¬P(y,x).
```
`PValid` is FO; in the game it is maintained as an invariant (the move adds
one edge and takes transitive closure).

`[definition]` **Control modes (fixed finite set).** Use FO-definable mode
constants/predicates:
```text
ModeSort(m)  -- sorter selects an incomparable pair
ModeAdv(m)   -- adversary chooses outcome of selected pair
ModeChk(m)   -- check totality / terminal
ModeAcc(m)   -- accepting
ModeRej(m)   -- rejecting
```
These can be encoded by a fixed finite set of distinguished tuples, or by
unary tags in an expanded interpreted structure; the choice is immaterial as
long as the signature and arity are fixed.

## 5. TC subformula (poset closure update)

`[definition]` Adding comparison `a < b` to a transitive strict order `P`
gives
```text
Step(P,a,b; u,v)  iff  u <_{TC(P ∪ {(a,b)})} v.
```
Because `P` is already transitively closed, the incremental closure is FO:
```text
Step(P,a,b; u,v) :=
  Key(u) ∧ Key(v) ∧ (
    P(u,v)
    ∨ ((u=a ∨ P(u,a)) ∧ (b=v ∨ P(b,v)))
  ).
```

`[deduction]` **Correctness of `Step`.** Any path using the new edge `a->b`
in `P ∪ {(a,b)}` can be shortened to a prefix in `P` reaching `a` (or `u=a`)
followed by `a->b` followed by a suffix in `P` from `b` (or `b=v`), because
`P` is transitive. Conversely the right side clearly implies reachability.
The formula is FO, uses only `P` and the selected pair, and preserves strict
partial-order validity assuming `Inc(P,a,b)`.

`[definition]` **Two adversary outcomes.**
```text
Step0(P,a,b; u,v) := Step(P,a,b; u,v).      -- outcome a<b
Step1(P,a,b; u,v) := Step(P,b,a; u,v).      -- outcome b<a
```

`[literature,deduction]` Full TC is FO(LFP)-definable on ordered structures;
the incremental form above avoids an explicit nested LFP and is sufficient for
`G(n,k)`. If a non-closed input relation were used, `TC` would be supplied as
a standard FO(LFP) subformula:
```text
[ LFP_{R,u,v}  E(u,v) ∨ ∃z (R(u,z) ∧ E(z,v)) ](u,v).
```

## 6. Init, Acc, Mode, Yield subformulas

The formulas below describe the alternating game/ATM transition system. They
are schematic in the precise tuple coding of configurations, but each has
fixed logical shape and fixed arities.

`[definition]` **Init.** Initial configuration: empty poset, time/budget at
zero-used (or full budget), sorter mode.
```text
Init(P,t,a,b,m) :=
  (∀x∀y ¬P(x,y))
  ∧ Zero(t)
  ∧ Key(a) ∧ Key(b) ∧ a=b        -- or a distinguished null pair, if used
  ∧ ModeSort(m)
  ∧ PValid(P).
```
(For `n <= 1`, the outer sentence accepts immediately by an FO prelude:
`∀x∀y ((Key(x) ∧ Key(y)) -> x=y) -> AcceptEmpty`.)

`[definition]` **Acc.**
```text
Acc(P,t,a,b,m) :=
  Total(P) ∧ CtrLe(t, MaxCtrConst)   -- reached a total order within budget
  ∧ (ModeAcc(m) ∨ ModeChk(m) ∨ ModeSort(m) ∨ ModeAdv(m)).
```
Equivalently, acceptance is any reachable game configuration with `Total(P)`
before exhausting `k` comparisons. In the strict `k`-step form, include a
budget check `t <= k` using `CtrLe`.

`[definition]` **Mode predicates.** As above, `ModeSort/ModeAdv/ModeChk/
ModeAcc/ModeRej` partition control states. The transition relation is
guarded by mode:
```text
SortConf(P,t,a,b,m) := ModeSort(m) ∧ ¬Total(P) ∧ ∃t' SuccCtr(t,t').  -- budget remains
AdvConf(P,t,a,b,m)  := ModeAdv(m)  ∧ Inc(P,a,b).
Terminal(P)         := Total(P).
```
The `∃t' SuccCtr(t,t')` guard means fewer than `k` comparisons have been
used; if no successor exists at the maximum counter, the budget is
exhausted.

`[definition]` **Yield (sorter, existential move).** From a sorter state,
choose an incomparable pair `(a,b)` and pass it to the adversary without
changing `P` or `t`:
```text
Yield_∃((P,t,_,_,m), (P',t',a,b,m')) :=
  ModeSort(m) ∧ ¬Total(P) ∧ ∃s SuccCtr(t,s)   -- at least one comparison left
  ∧ Inc(P,a,b)
  ∧ (∀u∀v (P'(u,v) <-> P(u,v)))
  ∧ t'=t
  ∧ ModeAdv(m').
```
(If the game counts the comparison at the adversary step, keep `t'=t` here;
be consistent with the budget bound.)

`[definition]` **Yield (adversary, universal move).** From an adversary
state, the two legal outcomes produce two successor configurations. The
alternating acceptance formula uses two successor relations/instantiations:
```text
Yield_∀0((P,t,a,b,m), (P1,t1,a1,b1,m1)) :=
  ModeAdv(m) ∧ Inc(P,a,b)
  ∧ (∀u∀v (P1(u,v) <-> Step(P,a,b;u,v)))
  ∧ SuccCtr(t,t1)
  ∧ Key(a1) ∧ Key(b1)           -- next pair irrelevant until chosen
  ∧ (ModeSort(m1) ∨ (Total(P1) ∧ ModeAcc(m1)) ∨ (¬∃s SuccCtr(t1,s) ∧ ¬Total(P1) ∧ ModeRej(m1))).

Yield_∀1((P,t,a,b,m), (P2,t2,a2,b2,m2)) :=
  ModeAdv(m) ∧ Inc(P,a,b)
  ∧ (∀u∀v (P2(u,v) <-> Step(P,b,a;u,v)))
  ∧ SuccCtr(t,t2)
  ∧ Key(a2) ∧ Key(b2)
  ∧ (ModeSort(m2) ∨ (Total(P2) ∧ ModeAcc(m2)) ∨ (¬∃s SuccCtr(t2,s) ∧ ¬Total(P2) ∧ ModeRej(m2))).
```

`[deduction]` **Legality.** The precondition `Inc(P,a,b)` ensures both
adversary outcomes are consistent with `P`; `Step` then preserves
transitivity/strictness. This matches the transitive-closure update in
`G(n,k)`.

## 7. Alternating acceptance as a PFP formula

`[definition]` Let `C` abbreviate the configuration tuple `(P,t,a,b,m)`, and
let `A(C)` (or `A(P,t,a,b,m)`) be a fixed-point relation variable meaning
"`C` is accepting for the sorter". The alternating acceptance operator is:
```text
ψ(A, C) :=
  Acc(C)
  ∨ (ModeSort(C) ∧ ¬Total(P_C) ∧ ∃C' (Yield_∃(C,C') ∧ A(C')))
  ∨ (ModeAdv(C)  ∧ ∃C1∃C2 (Yield_∀0(C,C1) ∧ Yield_∀1(C,C2) ∧ A(C1) ∧ A(C2)))
  ∨ (Total(P_C) ∧ ¬ModeRej(C)).
```
with the obvious component access notation.

`[definition]` **PFP sentence.**
```text
Φ_SORTBOUND_U :=
  ¬WellFormed_w
  ∨ SmallN_Acc
  ∨ ∃C ( Init(C) ∧ [PFP_{A,C} ψ(A,C)](C) ).
```
Here `SmallN_Acc` handles `n <= 1` (and any fixed edge cases) by an FO
prelude: `S(0)=S(1)=0`, so accept iff `k>=0` as encoded.

`[deduction]` **PFP semantics argument.** Under standard partial fixed-point
semantics (Vardi/Abiteboul–Vianu), `PFP_{A,C} ψ(A,C)` is evaluated by
iterating `A0 := ∅`, `A_{i+1} := {C | ψ(A_i,C)}` on the finite configuration
space until a fixed point is reached, or yielding empty/undefined by the
chosen PFP convention if no fixed point is reached. For the alternating
acceptance of a polynomial-time alternating computation, the intended
accepting set is computed by the natural game/ATM iteration; the FO(PFP)
capture proof supplies the general simulation showing that PSPACE alternating
acceptance is definable in FO(PFP) on ordered structures.

The local operator `ψ` is not presented as monotone in an arbitrary
declaration order because of the mode/configuration encoding; monotonicity in
the usual attractor sense is restored by the stratified game interpretation
(budget decreases after adversary moves, total states are sinks). The
capture-theorem route therefore justifies the sentence through the standard
ATM-configuration PFP simulation. A direct monotone attractor form is:
```text
Win_d(P) := Total(P) ∨ (d>0 ∧ ∃a∃b (Inc(P,a,b) ∧ Win_{d-1}(Step(P,a,b)) ∧ Win_{d-1}(Step(P,b,a)))),
```
stratified by `d=0,...,k`; stratification is FO-definable from the ordered
counter. This is IFP/LFP-shaped in the time component but still quantifies
over poset relations/states through the interpreted encoding; it is not by
itself an LFP/P proof and must not be read as such.

## 8. Validation obligations

`[falsification target]` The construction is concrete at the level of
signature, interpretation, fixed arities, and explicit subformula schemas.
A fully machine-checkable/formally closed definition would additionally need:

1. A fixed FO(PFP) syntax (tuple coding for `C`, whether `P` is carried as
   relation arguments of the fixed-point variable or via an interpretation).
2. Complete expansion of finite mode tags/null-pair conventions and all edge
   cases (`n<=1`, `k=0`, exhausted budget, malformed input).
3. A proof that the chosen PFP iteration on the finite interpreted structure
   computes the intended alternating-acceptance set for `ψ` (the
   capture-theorem obligation specialized to this operator).
4. A proof that the FO interpretation from `A(w)` preserves satisfaction of
   `Φ_SORTBOUND_U`.
5. Independent falsification: test the semantic reading against known values
   of `S(n)` (`S(0)..S(6)` checked in-repo; literature values through
   `S(18)` as in `docs/literature.md`) and reject any encoding that changes
   the comparison model, input length, or transitive-closure rule.

## 9. Precise obstacles

1. **Representation/arity on the bare word (main obstacle to a no-interpretation closed form).** `[deduction]`
   The state includes `P ⊆ [n]×[n]`, i.e. `n^2` bits. A fixed-arity
   relation over `N=n+k+1` elements has `N^r` tuples; it cannot enumerate all
   poset states as domain elements for fixed `r`. Therefore an explicit
   fixed-syntax formula on the bare `N`-element word universe must encode
   configurations through polynomial-size relations over an interpreted domain
   (or an equivalent higher-level coding). This is an encoding obstacle, not
   an obstruction to FO(PFP) definability: Claim A plus FO(PFP)=PSPACE on
   ordered structures implies definability in principle.

2. **Alternation mapping.** `[deduction]` The sorter is existential and the
   adversary universal. In `ψ` this is the `∃C'` disjunct versus the
   `∃C1∃C2 (Yield_∀0 ∧ Yield_∀1 ∧ A(C1) ∧ A(C2))` conjunct. The universal
   branch is over the two FO-definable outcomes of a fixed selected pair, not
   an unbounded FO quantifier over all states.

3. **TC inside moves.** `[deduction]` Resolved concretely by incremental FO
   formula `Step(P,a,b;u,v) := P(u,v) ∨ ((u=a∨P(u,a)) ∧ (b=v∨P(b,v)))`,
   valid because `P` is maintained transitively closed.

4. **Order requirement.** `[literature]` FO(PFP)=PSPACE capture is used on
   ordered finite structures. `A(w)` supplies `<`; removing order would
   invalidate this capture route.

5. **No stronger-class claim.** `[deduction,open]` This does not give FO(LFP),
   P, NP, or ESO membership. Any such strengthening would be a new upper bound
   and is open.

## 10. Conclusion

`[deduction]` **Concrete schematic expansion achieved.** With fixed signature
`σ_w=(<,One,Hash)`, an FO-interpreted key/counter domain, fixed-arity
configuration relations, explicit `PValid/Total/Inc/Step` (`TC` update)
subformulas, explicit `Init/Acc/Mode/Yield_∃/Yield_∀0/Yield_∀1` schemas, and
a PFP alternating-acceptance sentence `Φ_SORTBOUND_U`, the FO(PFP) encoding
of `SORT-BOUND-U` is made concrete at the standard descriptive-complexity
level. The only non-cosmetic obstacle to a fully closed, no-interpretation
formula on the bare word universe is the fixed-arity representation of the
`n^2`-bit poset state; the interpretation resolves it in the usual way and is
FO-definable from the ordered word.
