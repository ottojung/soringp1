## Verdict

**The historical gap is genuinely present in the cited older MDALT realization, but not as a schema inconsistency in BackE v2.** The v2 schema is internally explicit about `CurExhausted`, its concrete exhausted value, cursor consumers, and row-by-row updates. However, the older `E(Rbar)` and `δ_{M_D^alt}^{sch}` encode and update the *old* `Rbar` with no `CurExhausted` component. Thus v2's added state and revised branch cannot be obtained from that realization merely by invoking its stated P1 compilation assumption: P1 compiles the tests/updates actually specified; it does not silently add a relation, tape field, or altered transition semantics.

This is a concrete **schema-to-realization component-closure mismatch**, not a demonstrated reachable counterexample to the v2 schema, not a proof that its invariants fail, and not a DET-SUCC refutation. Conversely, the mismatch does not establish that no revised DTM realization can be built: it appears straightforward to extend the encoding and macro-updates, but that extension and its proofs are obligations, not supplied facts. I found no basis to say that the older realization already encodes exhaustion: its `(MinKey,MinKey)` cursor is explicitly used as an ordinary normal starting cursor and there is no exhaustion bit/flag.

## Exact field comparison

The older realization's fixed `Rbar` is listed in `fopfp-cks-av-mdalt-dtm-realization.md` §1.2, lines 73–99:

`Top, CurBase, EmptyStack, HaltAcc, HaltRej; M_Eval, M_BackE, M_BackA0, M_BackA1; RetNone, RetAcc, RetRej; CtrlSort, CtrlAdv, CtrlAcc, CtrlRej; UsedF, HasSel, SelA, SelB, HasCur, CurA, CurB; PosF, Parent, FrameLive`.

Its `Fld`-equivalent live-frame encoding (§1.2) stores mode, return marker, control, `UsedF`, selection fields, `HasCur/CurA/CurB`, parent, and the `PosF` bit table (§1.2, lines 88–99). It has **no** `CurExhausted` field, tag, or alternative cursor-state constructor.

BackE v2 §1 (lines 47–68, 74–99) explicitly changes the configuration to:

`Rbar := (Top,CurBase,EmptyStack,HaltAcc,HaltRej, M_Eval,M_BackE,M_BackA0,M_BackA1, RetNone,RetAcc,RetRej, CtrlSort,CtrlAdv,CtrlAcc,CtrlRej, UsedF,HasSel,SelA,SelB, HasCur,CurA,CurB,CurExhausted, PosF,Parent,FrameLive)`

and the frame tuple to `Fld = ⟨Mode,Ret,Ctrl,UsedF,HasSel,SelA,SelB,HasCur,CurA,CurB,CurExhausted,PosF,Parent⟩`. `FrameFieldsEq'` includes the new component, and `FrameEq'` adds liveness equivalence. `CursorCoherent` partitions normal (`¬CurExhausted`, populated unique pair) from exhausted (`CurExhausted`, `HasCur`, pair encoded as `(MinKey,MinKey)`) states. Notably `(MinKey,MinKey)` alone cannot distinguish them: initialization and child frames use that same pair with `¬CurExhausted` (v2 §2, lines 142–190). The tag is semantically essential.

## Affected transitions and updates

The v2 §5 all-19-row table (lines 294–328) and independent audit §8 (lines 296–325) account for the new bit as follows. These are **schema clauses**, not existing clauses in the old realization:

| Rows | Required v2 effect on `CurExhausted` / cursor |
|---|---|
| 1 halt-absorb | Preserve all live-frame components via identity/lower-stack preservation. |
| 2, 3, 8, 11, 13, 16, 18 terminal | Clear live frames; no live cursor state remains. |
| 4, 5, 9, 12, 14, 17, 19 pop/return | Inactivate child; `MarkRet*On(parent)` preserves the receiver's `CurExhausted`, `HasCur`, `CurA`, `CurB` and other non-marker fields; preserve other lower frames. |
| 6 sort-pick push | Advance parent with `SetParentBackE_Advance`: non-last selected pair sets unique successor cursor and `¬CurExhausted`; last pair sets `CurExhausted` and sentinel `(MinKey,MinKey)`. New `PushChildE` initializes `HasCur`, pair `(MinKey,MinKey)`, `¬CurExhausted`. |
| 7 adversary A0 push | `SetParentBackA0` preserves parent cursor and exhaustion flag; `PushChildA` initializes child normal cursor/tag. |
| 10 BackE reject-next push | Same parent advance as row 6 and same child initialization as `PushChildE`. |
| 15 BackA0-to-A1 push | `SetParentBackA1` preserves parent cursor and exhaustion flag; `PushChildA` initializes child cursor/tag. |

Also required outside the transition rows: root initialization sets `¬CurExhausted` (v2 §2); the normal/exhausted consumer split changes NI/NNI and `RejectEval` (v2 §4); and all return-marker helpers plus generic frame equality must preserve the bit (v2 §1). The independent v2 audit enumerates these schema clauses and agrees they are present at schema level (audit §2–§9).

### Direct mismatch in the older realization

The comparison with the actual implementation specification is decisive:

* `fopfp-cks-av-mdalt-dtm-realization.md` §2.2, lines 182–199, initializes root `HasCur=true; Cur=(MinKey,MinKey)` but has no `CurExhausted` initialization.
* §3.2 rows `D_sort_pick` and `D_backE_rej_next` (lines 251, 254) call the old `SetParentBackE_Advance`; the exhaust rows (255–256) use `NoNextIncomp_c` on the stored cursor. No branch writes or reads `CurExhausted`.
* §3.2 lines 266–272 says `PushChildE` and `PushChildA` set `HasCur=(MinKey,MinKey)`; neither initializes an exhaustion tag.
* §3.1 lines 214–223's top-read list reads `HasCur/CurA,B/PosF` but no exhaustion component; §3.2's complete macro-case table likewise contains no update to one.
* The old normalized encoding, `det-succ-normalized-enc.md` §0 and §1.1 (lines 33–46, 66–80), likewise has no such component. Its sentinel convention (§1.5, lines 216–244) represents “no further” in the pair cursor rather than with a separate v2 bit.

The strongest counterargument—that the older sentinel `(MinKey,MinKey)` or `HasCur` already encodes exhaustion—fails against the text: the old initializer and `PushChildE/A` use that pair for a live starting/normal cursor, and old consumers define NI/NNI from `CurA,CurB` and `NextIncomp/NoNextIncomp` without a discriminator (realization §2.2, §3.2; normalized `Enc` §1.5). A single pair value therefore cannot stand for both ordinary initial cursor and exhausted cursor under those definitions. The v2 schema resolves this ambiguity *by adding* the tag; the older field family has no slot for it.

This shows an interface mismatch if the old realization is claimed unchanged as a realization of v2. It does **not** show the old sentinel formulation was necessarily invalid under its own old schema; nor does it rule out encoding the bit as a new field or a tagged variant in a revised realization.

## Schema consistency versus proofs

**Schema consistency (paper deduction, conditional on definitions).** V2's last-pair update gives the tagged exhausted state; NI requires `¬CurExhausted`, while NNI accepts it. For non-last pairs the strict successor cursor excludes reselection. Marker-return clauses preserve the receiver cursor, and the table supplies a determination for the new flag in each row. The independent audit finds no explicit `I_{M_D}`-reachable counterexample (audit §§3, 7–9, 11). I found no internal contradiction in these clauses. Some component definitions are schematic shorthand (for example “preserve every Fld component except Ret”), so a formal implementation still needs literal primed-field equations.

**Actual `E(Rbar)` encoding (not closed).** The v2 note itself leaves this open in §7.1(7), and the independent audit identifies the exact mismatch in audit §10(1): extend the live-frame tape encoding and update/read logic. A realizability proof must define whether the new bit is stored for every allocated frame or only live frames, how stale/inactive cells are handled, how the exhausted pair is represented in the finite alphabet/field layout, and show encoding/decoding preserves uniqueness and FO/DTM expressibility.

**Invariant preservation and reachability (not established).** The old realization's claimed Corollary 4.2 cites preservation for the old `I_MD`/old `Rbar` (realization §4, lines 312–317). It does not prove preservation of v2's strengthened `CursorCoherent` invariant. V2 §7.2(1), (3) and audit §10(2), (4) leave open induction over all rows, including initialized/eval-side cursor coherence, unique field interpretations, mode/top/path facts, and `RejectEval` exhaustivity. Correct table entries alone do not prove those reachability claims.

**DET-SUCC (not established).** The old realization's §3.3/§4 determinism arguments presuppose old `I_MD` and its 19-case partition. V2 changes the vocabulary, guards, and row updates, including rows 6/10 and 11/12. A revised proof must establish totality and pairwise exclusivity on revised reachable non-halting states and that each selected macro-update is single-valued and encoded. V2 §7.2(5) explicitly leaves this open. No claim that DET-SUCC is false follows from a missing proof.

## Strongest falsifier attempted

I tried to refute v2 by forcing a collision between the exhausted sentinel and the normal initial cursor: both carry `(MinKey,MinKey)`. This does not refute the *schema*, because v2 consumers consult `CurExhausted` and normal initialization explicitly sets it false. It does expose precisely why the older `E(Rbar)` cannot realize the revised schema unchanged: it stores the shared pair but not the distinguishing bit, and its NI/NNI readers have no such test. No reachable state witnessing an actual wrong branch follows without a defined old-to-new encoding map and a reachable trace; none is supplied. This is the strongest falsifier attempted, and it stops at the representation boundary rather than an invariant counterexample.

**Bottom line:** the v2 note has closed the specified *schema under-instantiation* for this cursor component, not the realization gap. The older realization cannot already represent the new distinction as written. A realizable extension is plausible but remains to be explicitly encoded and proved; the current evidence establishes neither a reachable bug nor DET-SUCC.
