# Exec report: n=7 framed DAG certificate search

## Question

Can a small permutation-framed DAG certificate certify `S(7) <= 13`? Known
`S(7) = 13` (literature). The certificate must be accepted by
`scripts/check_framed_strategy.py` at depth `<= 13` for `n = 7`.

## Method

1. **Exact minimax values over canonical posets.** Computed `F(P)` for
   partial orders up to isomorphism (`S_n` quotient) using the standard
   recurrence `F(P) = 0` if total, else `1 + min_{i<j incomparable}
   max(F(P+i<j), F(P+j<i))`, with child posets canonicalized by
   `make_refined_canon`. This yields `F(empty) = 13` for `n = 7` (1.19s).

2. **Minimal reachable-state selection.** For each canonical poset, selected
   the optimal comparison minimizing the size of the union of reachable
   canonical state sets (exact DP with memoization). This gives a
   (provably, within the canonical quotient) minimal-node optimal policy.

3. **Permutation framing.** Each quotient edge's child poset is
   canonicalized; a brute-force search over `7!` permutations finds the
   edge permutation mapping the exact child poset to its canonical
   representative, so joins are label-consistent.

4. **Topological reindexing.** Nodes were reordered (Kahn) so every edge
   points forward, as required by the checker.

## Result

Smallest verified certificate found: **19 nodes, depth 13, n = 7**.

File: `n7_height13_cert_19nodes.json`.

Verification:

```
$ python3 scripts/check_framed_strategy.py n7_height13_cert_19nodes.json
ACCEPT: n=7, depth=13, nodes=19
```

For comparison, the unquotiented state-sharing DAG (exact posets, single
optimal policy) has 10079 nodes; full symmetry quotient reduces this to
19 nodes.

## Limits

- The 19-node count is minimal among single optimal policies in the
  `S_n` canonical quotient. It is not proved minimal among all sound
  framed DAGs of height 13 (coarser joins / forgetting could in principle
  reduce further); no lower bound below 19 is established here.
- The certificate is for one fixed `n = 7`; it is not an all-`n`
  construction and does not imply `SORT-BOUND-U in NP`.
- Verification is by the Python checker only; no Lean formalization was added.
- No repo/Lean/PR changes other than the two files created in this
  worktree.
