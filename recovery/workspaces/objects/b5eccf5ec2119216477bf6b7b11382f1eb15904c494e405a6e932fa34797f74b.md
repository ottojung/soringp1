## 1. The exact no-instance / refuter question

`[definition]` `S(n)` is the minimum worst-case height of a deterministic
adaptive comparison decision tree that sorts all permutations of `n` distinct
labelled keys. `SORT-BOUND-U = { 1^n # 1^k : S(n) ≤ k }` has unary input length
`N = n + k + 1` (`docs/problem.md`).

`[definition]` In the finite comparison game `G(n,k)` (`docs/research-certificates-barriers.md`):
state is a transitively closed partial order on `[n]`; the sorter picks an
incomparable pair; the adversary answers `<` or `>` consistently; transitive
closure is taken. Sorter wins iff a total order is reached within `k`
comparisons. Then

> `S(n) <= k` iff the sorter wins `G(n,k)`.

`[deduction]` The no-instance/refuter side for the threshold claim `S(12) <= 29`
is

> `S(12) > 29` iff `1^12#1^29 ∉ SORT-BOUND-U` iff the adversary has a winning
> strategy in `G(12,29)`.

So a concrete refuter certificate is an explicit, finite object from which a
verifier can conclude that **every** sorter strategy of height `<= 29` fails on
some adversary-consistent branch.

`[literature]` Wells proved `S(12)=30 > 29 = C(12)=⌈log2 12!⌉`; Ford-Johnson
gives the upper bound `30`. Peczarski and Stober-Weiß give later exhaustive
lower-bound searches; Stober-Weiß report `sortable = no` for `n=12, h=29`
(`docs/literature.md`, `docs/research-n12-nontightness.md`).

## 2. Falsifiable task

Propose or reject a concrete short explicit certificate format for the refuter
claim `S(12)>29` (adversary wins `G(12,29)`) with an explicit finite verifier,
or give a precise verification/size obstruction. “Short” is not satisfied by
dumping exhaustive search output unless an explicit compression claim and
compressed verifier are supplied.

A positive answer would need: `(format, verifier, soundness argument, size
bound or measured size for n=12)`. A negative/obstruction answer for a format
needs a concrete reason that format is not short/sound/checkable as claimed; it
does **not** imply a complexity separation.

## 3. Candidate formats

### C1. Explicit adversary strategy tree

**Format `[definition]`.** A rooted tree `T` of depth `<= 29` whose nodes are
labelled by transitively closed partial orders `P` on 12 elements:
- root label is the antichain `P0`;
- an internal node `v` with non-total `P_v` contains, for **every** sorter move
  `m = {x,y}` with `x,y` incomparable in `P_v`, an adversary answer
  `a_m ∈ {x<y, y<x}` and a child edge to `P_v + a_m` (with transitive closure);
- every leaf at depth `d <= 29` is either non-total with no remaining valid move
  representation (impossible while non-total) or, more generally, the tree proves
  failure by exhausting all root-to-depth budget branches against all sorter
  moves at visited nodes.

Equivalently, for each visited sorter-decision point the certificate supplies a
*refutation function* from all legal sorter comparisons to a chosen adversary
outcome.

**Verifier `[deduction]`.** Finite deterministic check:
1. Root is antichain on 12 elements.
2. Every node stores a valid transitively closed antisymmetric partial order.
3. At every internal node `v`, the set/list of covered sorter moves is exactly
   the set of incomparable pairs of `P_v`.
4. Each child is the transitive closure of `P_v` plus the stated answer.
5. Tree depth `<= 29`; leaves satisfy the declared failure condition.

Soundness: if every sorter move at every visited state is answered by a child,
then no sorter strategy can force a win within depth 29, so adversary wins
`G(12,29)`.

**Size/obstruction `[open]`.** Explicit form is enormous: a node at which many
pairs are incomparable may branch over `Θ(n^2)` sorter moves. The whole object
is an explicit game refutation, not known to compress to polynomial size in
`N=42`. Therefore C1 is an explicit finite certificate format with an explicit
verifier, but **rejected as a known short certificate** absent a compression
proof.

### C2. Pruned search certificate (replayable refutation log)

**Format `[definition]`.** A certificate `W` is a sequence/file of records
describing a completed refutation search, e.g. states visited, sorter moves
considered, adversary replies chosen, backjump/pruning lemmas used, and a final
“refuted” mark for the root under budget 29. The verifier `V_W` replays each
record according to fixed rules.

**Verifier `[deduction]`.** Possible in principle if every record is explicit
and every pruning lemma is either omitted or itself recorded with a checkable
proof object.

**Obstruction `[deduction]`.** Raw exhaustive/pruned search output is not a
short certificate unless accompanied by an explicit compression claim and a
verifier for the compressed form. The known proofs for `S(12)>29` are
exhaustive computer searches (Wells, Peczarski, Stober-Weiß;
`docs/research-n12-nontightness.md`). C2 is therefore **rejected as short in raw
form**. It becomes a candidate only under an additional, currently missing
result:
> there exists a compressed refutation log for `n=12,k=29` of size `<= B` with
> verifier runtime `<= T`, both stated explicitly.

No such `B,T` is established here. `[open]`

### C3. Node-level invariant-only certificate

**Format `[conjecture/candidate]`.** Provide a scalar or local invariant `I(P,c)`
and show that after `c <= 29` comparisons every admissible line reaches a state
with `I(P,c)` false, or provide one comparison-by-comparison invariant refuting
height 29.

**Verifier `[deduction]`.** Would be short only if `I` is polynomial-time
checkable from `P,c` and a small proof object.

**Obstruction `[literature, deduction]`.** The standard node-level information
invariant `e(P) <= 2^(29-c)` is necessary but not globally sufficient as a short
standalone refuter explanation; the obstruction is strategic/non-scalar.
`research-n12-nontightness.md` records: efficiency pruning is equivalent to the
node-level information bound; sortability is not monotone in `e(P)`; the same
`e` can give different `m`; forced balanced prefixes occur at tight `n` values.
The `sortable=no` result for `n=12,h=29` is obtained by search, not by a known
published short invariant. Therefore C3 is **not currently realized** and is
rejected as a *known* short certificate; proposing it remains open and would be
falsified by any counterexample to the invariant's soundness or by failure to
separate `h=29` from `h=30`. `[open]`

### C4. Adversary strategy DAG with explicit canonicalization (concrete proposal)

**Format `[paper-level proposal]`.** A finite directed acyclic/refutation object
`D = (V,E,r,k)`:
- `r` is the antichain state on 12 elements; `k=29`.
- Each vertex `v` stores `P_v` (transitively closed partial order or an explicit
  canonical encoding), remaining budget `b_v`, and either a terminal refutation
  tag or a total refuter rule.
- A total refuter rule is a finite map `ρ_v : Inc(P_v) -> A(P_v)` from every
  incomparable pair (legal sorter move) to an adversary answer, such that for
  each move `m`, `E` contains an edge `v --(m,ρ_v(m))-> w` with
  `P_w = tc(P_v + ρ_v(m))` and `b_w = b_v - 1`.
- A vertex may be shared only when the certificate includes an explicit equality
  proof key: identical canonical state and identical budget (or a separately
  justified dominance relation; dominance is **not** assumed sound here unless
  its proof rule is included). Raw labelled-poset equality is the default sound
  sharing rule.

**Verifier `V_D` `[deduction]`.**
1. Parse `D`; check `r` is antichain on 12 and `b_r=29`.
2. Check acyclicity or well-founded budget decrease (`b_w=b_v-1` on edges).
3. For each internal vertex `v`, enumerate `Inc(P_v)` and check `ρ_v` is total
   on that exact set.
4. For each edge, recompute `tc(P_v + ρ_v(m))` and compare to `P_w` (or to its
   declared canonical key).
5. Check sharing/dominance uses only declared sound rules.
6. Accept if every path is covered to a terminal refuted state within budget.

All checks are explicit and finite. Runtime is polynomial in `|D|` plus
polynomial-in-`n` local poset operations per edge/rule.

**Soundness `[deduction]`.** Acceptance means every legal sorter comparison at
every reachable refuter state has a certified adversary answer and no branch
exceeds 29 comparisons before refutation/coverage is complete; therefore no
height-29 sorter strategy wins, so adversary wins `G(12,29)`.

**Shortness status `[open]`.** C4 is a **concrete, explicit, finite, checkable
certificate format**. However, this note does **not** claim a short instance for
`n=12,k=29`: no compressed `D` with a proved or measured polynomial/small bound
is exhibited here. Raw full expansion is not short. The open compression claim
is exactly
> `∃D : V_D accepts (12,29,D) and |D| <= B(12,29)` for a usefully small explicit
> bound `B`.

Without such `D,B`, C4 is a proposal with an explicit verifier and an unresolved
size question, not a demonstrated short certificate.

## 4. Precise verification/size obstruction

`[deduction]` The central obstruction for a short refuter certificate for
`S(12)>29` is:

1. **Universal sorter quantifier.** The certificate must refute *all* sorter
   first moves and, recursively, all sorter moves after every certified adversary
   answer. This is dual to the universal-adversary quantifier in yes-certificates
   (`docs/research-certificates-barriers.md`, ESO obstruction artifact).
2. **Strategic, non-scalar obstruction.** The information bound gives `C(12)=29`,
   so the refuter cannot rely only on `e(P) <= 2^(29-c)`; known proofs need
   strategic search (`[literature]` Wells/Peczarski/Stober-Weiß).
3. **State/object growth.** The underlying game has `2^{Θ(n²)}` labelled poset
   states in general; known `S(12)>29` proofs are exhaustive/structured searches
   rather than published short witnesses (`[literature, deduction]`).
4. **Compression burden.** Any claimed short C2/C4 instance must make the
   compression explicit and keep the verifier explicit. Raw search output is not
   acceptable as “short”. `[deduction]`

This is a verification/representation obstruction for currently known/proposed
short refuter certificates. It is **not** a proof that no short certificate
exists and **not** a complexity separation.

## 5. Bottom line

- **Rejected as short (without compression proof):** C1 explicit adversary tree
  in raw expanded form; C2 raw exhaustive/pruned search output.
- **Rejected as currently realized:** C3 invariant-only certificate, because no
  known short sound invariant separates `h=29` from `h=30` for `n=12`.
- **Concrete proposed format with explicit finite verifier:** C4 adversary
  strategy DAG / total refuter-rule certificate with recomputation checks. It is
  sound if accepted, finite, and explicitly verifiable, but **no short instance or
  compression/size bound for `S(12)>29` is established here**. `[open]`
- **Known fact:** `S(12)>29` is a literature/exhaustive-search result; a short,
  independently checkable refuter certificate for `G(12,29)` is not established
  by this note. `[literature, open]`
