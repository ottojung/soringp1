## 1. Repair 1: universal/existentially fixed clock exponent for QWIN — fixed

The draft had `T=(n+k+|p|+2)^c` with "for fixed `c`" but the Lemma A proof read "choose `c` large enough", leaving `c` both pre-fixed and post-hoc. The repair introduces `c_v`, stated to depend only on `v` and the fixed machine/evaluation implementation, explicitly "not on `n,k,p,phi,X`", adds the parenthetical "equivalently, one may existentially fix `c_v` large enough for the implementation; it remains independent of the instance/program/formula", renames the predicate to `QWIN_{v,c_v}` with `Verify_{v,c_v}`, and restates the corollary with "the fixed universal (existentially fixed for the fragment) verifier clock exponent `c_v`". This is exactly the repair prescribed in §1.6 and §4.1 of the prior audit; the Sigma_2^P reading (existentially fixed exponent for the fragment) is coherent since the machine is fixed and `QWIN_{v,c_v}` is a single fixed language.

## 2. Repair 2: charged rule applications vs total machine work — fixed

The draft's "simulates `U` for at most `T` charged steps" risked hiding one FO(TC)_v evaluation inside a unit step. The repair: (a) changes "charged steps" to "charged rule applications" throughout the definition and proof; (b) states the per-application costs explicitly — one FO(TC)_v evaluation, action validation, query answering from `X`, bounded store/history/output updates; (c) concludes total work = `T` × a fixed polynomial in `N+|phi|+|p|` plus polynomial input/permutation validation and final output checking, "hence by a fixed polynomial in `n+k+|p|`"; (d) adds "not a claim that ... an expensive FO(TC)_v evaluation is a unit-cost step". This carries out §4.2 of the prior audit. Mathematically it is the same sound accounting: `(n+k+|p|+2)^{c_v} · poly(N+|phi|+|p|)` is a fixed polynomial since all parameters are bounded by the instance size.

## 4. Residual minor issue

**R1 (exposition, non-blocking).** The verifier clock `T=(n+k+|p|+2)^{c_v}` counts charged rule applications, while the *total-work* polynomial is `T × poly(N+|phi|+|p|)`, i.e. a fixed polynomial with an effectively larger exponent than `c_v`. The text handles this correctly ("hence by a fixed polynomial"), but the corollary's Sigma_2^P argument quantifies only over `c_v`; a literal reading could ask which exponent indexes the verifier's running time bound in the Sigma_2^P predicate definition. Standard resolution: the verifier's time bound is *some* fixed polynomial, and the existentially fixed `c_v` (chosen per implementation, which already includes the interpreter overhead) is exactly the exponent of that polynomial; the repair note's "existentially fixed" clause covers this. Recommended one-sentence clarification only; no mathematical content changes and no claim is at risk. This does not rise to "explicit witness" or "new gap".
