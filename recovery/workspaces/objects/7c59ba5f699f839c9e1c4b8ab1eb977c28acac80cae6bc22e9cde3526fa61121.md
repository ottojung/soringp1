## Question

Can **frame normalization** (choosing edge permutations so joined histories have
compatible guaranteed posets) and/or **stronger join annotations beyond
C_id-loss** repair obstruction O1 for the `(12,30)` fragment or a small bounded
extension, while remaining **checker-acceptable** and with height `<= 30`? Or
is there a reproducible constraint showing that meet normalization cannot
preserve required disjunctions in that bounded class?

## Definitions `[definition]`

A **PGF certificate** (checker format) is an acyclic forward DAG: root state
`R(0)=∅`; a feasible comparison outcome adds `smaller < larger`, takes
transitive closure, and applies the edge permutation `perm`; a join has
`R(u)=⋂ R_in` over feasible incoming renamed guarantees. A leaf is accepted only
if `R(leaf)` is a total order. Max depth must be `<= budget`.

**C_id-loss** (bounded class): a join is taken with frames that do not make a
pair `(p,q)` uniformly certifiable in the meet, and a completing region still
requires `(p,q)`. By checker semantics, every such completion is rejected.

**Frame normalization (F-norm):** choose `perm` on join-incoming edges so that
the meet preserves the facts required below the join (i.e. incoming renamed
posets become compatible on all required pairs).

**Checker-acceptable stronger join annotation:** an extension of the certificate
that the existing `check_framed_strategy.py` format/checker accepts. The current
format has only `compare/lt/gt/leaf` with single edge permutations and
intersection at joins; it has **no** disjunctive/multi-state join field.
Therefore any "stronger join annotation" beyond meet is **not checker-acceptable**
unless the checker/format is extended (outside scope here).

### F1. C_id-loss at `(12,30)` is rejected (O1 active)

At `n=12,budget=30`, root compares `(0,1)`; branch `lt` gives `0<1`, branch
`gt` gives `1<0`; both compare `(2,3)` and join the `2<3` outcomes with
identity frames. Meet is `{2<3}` and loses `0v1`.

```text
REJECT A_idloss_n12k30: leaf 3 does not sort 0,1
REJECT 3_o1_idloss_n12k30_cannot_complete: leaf 3 does not sort 0,1
```

`[deduction]` Any C_id-loss completion requiring the lost pair is
checker-rejected. This is a local/fragment constraint at the hard-case
parameters, not a global PGF nonexistence proof.

### F2. Frame normalization repairs an isomorphic join (checker-accepted)

At `n=3,budget=3`, root compares `(0,1)`; `gt` uses swap frame so both branches
join to normalized `{slot0 < slot1}`. Completing to a total-order decision DAG
is accepted:

```text
ACCEPT 1_norm_join_complete_n3 depth=3 nodes=8
```

At `n=4,budget=5` (exact `S(4)=5` `[literature]`), the same idea is used:
after a normalized join on `(0,1)`, both normalized branches compare `(2,3)` and
join with the swap frame on the `gt` branch; the completed certificate sorts
all 4 elements:

```text
ACCEPT n4_norm_join_complete_fixed depth=5 nodes=25 budget=5
```

`[deduction]` F-norm is checker-acceptable and can repair O1 when the
*entire required residual obligation* below the join is compatible with the same
slot renaming (a join-stable/isomorphic residual in the chosen frame).

### F3. Frame normalization is blocked by conflicting downstream obligations

Construct non-isomorphic residual obligations (`n=6,12`, budgets 10/30):
root `(0,1)` gives `0<1` on `lt`, `1<0` on `gt`. `lt` compares `(0,5)` and gets
`0<5` => `R1={0<1,0<5}`. `gt` compares `(0,5)` and gets `0<5` => `R2={1<0,0<5}`.
Both facts `(0,1)` and `(0,5)` are required in any total order.

Try F-norm repair with swap on `gt` (preserves the `0v1` direction as `0<1`):

```text
REJECT 5_nonisomorphic_n6_swap_repair_fails: leaf 3 does not sort 0,2
REJECT 6_nonisomorphic_block_n12k30_swap: leaf 3 does not sort 0,2
```

Try identity (does not normalize `0v1`):

```text
REJECT 5b_nonisomorphic_n6_id_fails: leaf 3 does not sort 0,1
REJECT 6b_nonisomorphic_block_n12k30_id: leaf 3 does not sort 0,1
```

Avoid the join (duplication; not a meet repair):

```text
REJECT 5c_nojoin_preserves_both_n6: leaf 3 does not sort 0,2
```

(The n=6/n=12 rejects above report the first missing pair found by the checker
at a leaf; the structural reason is the meet loss computed below.)

## Finite constraint argument `[deduction]`

Let `R1={0<1,0<5}` and `R2={1<0,0<5}` be incoming guaranteed posets (slot
names before the chosen join edge frames `p1,p2`). The join is
`J = rename(R1,p1) ∩ rename(R2,p2)`. To preserve *both* required normalized
facts `0<1` and `0<5` in `J` with `p1=id`, `rename(R2,p2)` must contain
`0<1` and `0<5`, so
- from `1<0` in `R2`: `p2(1)=0, p2(0)=1` (to obtain `0<1`);
- from `0<5` in `R2`: `p2(0)=0, p2(5)=5` (to obtain `0<5`).

These require `p2(0)=1` and `p2(0)=0`, a contradiction. By symmetry, no pair
`(p1,p2)` of permutations can make the meet contain the original `0v1`
disjunction normalized consistently while also preserving the independent
`0v5` fact as required for a total completion in this bounded fragment.

Equivalently, the best swap repair gives
`rename(R2,swap(0,1))={0<1,1<5}` and `meet({0<1,0<5},{0<1,1<5})={0<1}`: the
`0v1` direction is repaired but the relation between the compared/normalized
slots and `5` is lost. Identity gives `meet({0<1,0<5},{1<0,0<5})={0<5}`: the
opposite loss.

**Conclusion of the bounded class:** for this C_id-loss-style fragment,
meet normalization cannot preserve the required disjunction/facts unless the two
histories are made join-stable by frames on *all* downstream-required
comparisons. When downstream comparisons create a non-isomorphic obligation
pattern relative to every possible single-poset meet, checker-acceptable F-norm
fails to complete to a total leaf. This is a reproducible **class-sensitive**
constraint, not a proof that no other `(12,30)` PGF exists.

## Can a small bounded extension at `(12,30)` be repaired?

- **Yes, conditionally (F2/F-norm):** if a proposed `(12,30)` join can be placed
  where all required residual facts are isomorphic under explicit edge frames,
  the existing checker can accept the normalized join (`n=4,S(4)=5` example).
- **No, for C_id-loss / non-isomorphic residuals (F1,F3,constraint):** if the
  join loses a required pair, or if no pair of edge frames preserves all
  downstream-required facts in a single meet, the existing checker rejects the
  fragment. The explicit `(12,30)` instances are `A_idloss_n12k30` and
  `6_nonisomorphic_block_n12k30_{swap,id}`.
- **Stronger join annotations beyond meet:** not tested as checker-acceptable
  repairs because the checker/format has no such annotation. Extending the
  format would change the certificate language and require new soundness/checker
  proofs; it is out of scope for existing checker logic.

No complete, accepted, exact-height-30 total-sorting PGF certificate for all
12 elements was constructed here (an explicit optimal `n=12` strategy is not
available as a small object in this environment). Therefore the note does **not**
claim that `(12,30)` is repaired or unrepairable in general.
