This audit assesses whether coNP/refuter-certificate formats, equivalence to `S(n)>k`, and class-specific obstacles are stated soundly, and whether the note avoids unconditional lower-bound/separation claims. No Lean, PR, main, or board actions were taken.

## Overall assessment

**Mostly sound, with a few precision caveats.** The note states the model and unary encoding correctly, presents the semantic refuter/NO equivalence in the right direction, distinguishes semantic existence from polynomial verifiability, and generally frames obstacles as class-specific rather than as separations. It explicitly disclaims `SORT-BOUND-U ∉ coNP` and does not claim unconditional super-polynomial lower bounds or complexity-class separations. The main issues are (1) one semantic completeness claim is stated too strongly for the explicit graph object as written, (2) the verifier discussion should distinguish local totality checks from the nontrivial global succinctness/checkability requirement more sharply in one place, and (3) a few quantitative/citation dependencies are inherited from existing project notes and should be read as such.

## Detailed findings

### 1. Model, encoding, and NO-instance framing — sound

The note fixes the intended adaptive comparison-tree model, defines

`SORT-BOUND-U = { 1^n # 1^k : S(n) <= k }` with `N = n+k+1`,

and identifies NO instances as `(1^n,1^k)` with `S(n)>k` (lines 5–11). This matches `docs/problem.md` and the unary-only active scope in `AGENTS.md`. The claim that a succinct polytime-verifiable coNP/refuter certificate uniform in `n,k` would mean `SORT-BOUND-U ∈ coNP` under standard witness verification measured in `N` is the standard definition-level statement and is sound given the fixed encoding.

The established-context paragraph (line 11) is consistent with repository baselines: `SORT-BOUND-U ∈ PSPACE`, sparsity/Mahaney consequences, and the non-succinctness of explicit tree witnesses on informative unary inputs are all aligned with `docs/research-certificates-barriers.md`. The note correctly treats NP/coNP membership as open.

### 2. Equivalence to `S(n)>k` — semantically sound, with a representation caveat

The core equivalence

`S(n) > k` iff the adversary has a winning strategy in `G(n,k)`

(A1, lines 35–43) is sound as the standard semantic value of the comparison/minimax game. It matches the game formulation used in `docs/research-certificates-barriers.md` and the project’s minimax framing (`S_eq_adv_univ` is cited elsewhere in the repo as the kernel correspondence; the audit target states this as a definition/deduction, not as a new Lean claim).

The refuter object definition (input history/state, answer consistent with the current poset, winning against every height-`≤k` sorter strategy) is an appropriate adversary-strategy format.

**Caveat (moderate precision issue):** A2 states “Completeness (semantic): if `S(n)>k`, some adversary strategy exists; its strategy graph witnesses NO” (lines 52–55). As a statement about the *existence of a semantic strategy*, this is fine. As a statement about the *explicit refuter DAG/decision graph encoding* defined in A2, it is too strong without a size/totality caveat: the strategy graph induced by a semantic adversary over all relevant sorter moves/transcripts can be exponentially large or non-explicit in the input, and A2 does not require a polynomial representation. The note partially repairs this in A3/A4 and the conclusion, but A2’s completeness bullet should be read as semantic completeness, not as existence of a succinct explicit certificate. This does not create an unconditional separation claim; it slightly overstates the certificate-format object.

### 3. Candidate certificate format and verifier — sound caution, good separation of concerns

A2/A3 are careful in the right place: they separate semantic soundness/completeness of a total adversary strategy object from polynomial-time verifiability in input length `N` (lines 45–67). The verifier checks `V1`–`V3` are natural for an explicit strategy graph. The note correctly observes that local checks per state do not make the whole certificate polynomial unless the representation is polynomial and the universal/totality obligations are polynomially checkable; compressed/program forms turn validity into a game/strategy question.

This section avoids claiming `SORT-BOUND-U ∈ coNP` and avoids claiming impossibility of all certificates. It correctly classifies the raw alternating game value as PSPACE evidence rather than a coNP witness.

### 4. Class-specific obstacles — generally sound

**B1 (explicit winning-frontier/enumeration certificates).** Sound as a class-specific obstruction. The note relies on labelled-poset/state growth (`2^{Θ(n^2)}`), the winning-frontier barrier, and explicit tree size `2*n! - 1`. These are appropriate reasons why explicit enumeration/frontier listing is not a succinct certificate class. The scope limitation is important and correctly stated: it does not rule out selective, symbolic, or otherwise compressed coNP witnesses.

*Dependency note:* the cited `2^{(1/4-o(1)) n (log n)^2}` winning-frontier barrier and its extension to exact `k=S(n)` via Sergeev’s sublinear surplus are inherited from `docs/research-winning-frontier-barrier.md` / cited literature; this audit does not re-prove them. The use here is conditional on those results.

**B2 (finite adversary-memory certificates).** Appropriately qualified. The note states a strong structural/practical obstruction — no known `poly(N)` memory bound, natural memory is state/poset-like, and compression must preserve universal totality — while explicitly refusing to call it a separation proof. This is sound. The Brightwell–Winkler reference is correctly labeled as a barrier to the greedy/counting route, not a direct memory lower bound.

**B3 (alternation / universal strategy verification).** Sound. Using raw alternation as the certificate does not produce a one-sided existential witness with deterministic polynomial verification. The citation to Chandra–Kozen–Stockmeyer and the connection to the PSPACE upper bound are appropriate. The scope statement avoids overclaiming.

**B4 (encoding-related classes).** Sound and aligned with `AGENTS.md`/`problem.md`. Sparsity/Mahaney is correctly used only as a barrier to many-one NP-hardness/certain hardness routes, not as evidence for or against coNP membership. The distinction between unary and binary encodings is preserved.

### 5. No unconditional lower-bound/separation claims — pass

The note does not claim `SORT-BOUND-U ∉ coNP`, `SORT-BOUND-U ∉ NP`, `SORT-BOUND-U ∉ P`, `P != NP`, `NP != PSPACE`, or any unconditional super-polynomial lower bound. It repeatedly marks membership as open and limits obstacles to stated certificate classes or to absence of known succinct representations. The conclusion says “not a separation proof” for adversary-memory obstacles and confines decisive obstructions to class-specific forms. This satisfies the requested constraint.

### 6. Minor editorial/technical notes

- The phrase “semantic completeness” in A2 would be clearer if it explicitly said “semantic existence of an adversary strategy implies a strategy object; it does not imply a polynomial-size explicit encoding.” 
- In B1, the argument is strongest for *full* frontier/enumeration and for witnesses that must inspect that full frontier; compressed certificates that certify only a sufficient invariant are outside scope, as the note states.
- The note’s references to project-local research docs are useful but should not be read as independent primary proofs except where primary literature is cited.

## Conclusion

The audited note is substantially sound for its stated purpose: it gives a plausible coNP/refuter-certificate *format* at the semantic/strategy level, correctly ties NO instances to adversary winning strategies for `S(n)>k`, and identifies class-specific obstructions without making unconditional complexity separations. The only material correction needed is to tighten A2’s completeness language so it cannot be read as asserting a succinct explicit refuter graph whenever `S(n)>k`. All other findings are clarifications or dependency notes.
