## 1. Construction basis

- **Source spec:** `docs/research-framed-certificate-frontier.md` §2 "All-n polynomial DAG for adaptive merge sort" (paper construction; independent all-n implementation audit pending).
- **Model/checker:** `scripts/check_framed_strategy.py` (acyclic topologically numbered DAG, root 0; edges carry `lt`/`gt` outcomes and full-slot `perm` mappings old-slot→new-slot; relations are propagated/intersected as strict partial orders; leaves must be total orders; depth ≤ budget). See also `docs/problem.md` for S(n)/model context (distinct labelled keys, adaptive comparisons).
- **Merge invariant (implemented):** for a merge of contiguous sorted queues of lengths `p,q` at offset `l`, a comparison state is `(a,b)` with `1 ≤ a ≤ p, 1 ≤ b ≤ q` remaining elements. Slot layout at prefix length `m = p+q-a-b`:
  - prefix `[l, l+m-1]` sorted/output,
  - left remainder `[l+m, l+m+a-1]` sorted (size `a`),
  - right remainder `[l+m+a, l+m+a+b-1]` sorted (size `b`).
  Invariant relations (maintained/strengthened along any feasible path): total orders within prefix/left/right and `prefix < left`, `prefix < right` (no left-right order except through comparisons). Paths with the same `(a,b)` at the same merge stage share the same node/layout, so incoming relation sets are intersected by the checker at that join.
- **Comparison/frames:** compare heads `hL = l+m`, `hR = l+m+a`.
  - `lt` (`hL < hR`): take left head; layout already matches `(a-1,b)` or merge-complete, so `perm = identity`.
  - `gt` (`hR < hL`): move right head to `hL` by rotating `[hL..hR]` (explicit permutation `perm[hR]=hL`, `perm[k]=k+1` for `k∈[hL,hR)`), yielding layout for `(a,b-1)` or merge-complete.
- **Termination/joins:** when a queue empties (`a==1` on `lt`, or `b==1` on `gt`), the edge targets the merge-complete continuation (next merge/phase entry or final leaf). This joins all interleavings of the merge into a single completed state whose guaranteed order is total on the merged range.
- **Global composition:** standard top-down balanced merge sort over slots `[0,n)`; recursive sequencing `sort(left) → sort(right) → merge → continuation`, so each subproblem's completion continuation is the entry of the next stage. Full-slot identity permutations are used except on `gt` rotations.
