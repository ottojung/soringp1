## 5. Issues / recommendations (non-blocking)

1. **Reproducibility:** The audit cannot rerun the verifier/experiments. If this work is promoted beyond an internal note, include the script, exact command line, commit hash, and environment so the small-instance ACCEPTs and bounded abort are reproducible.
2. **Canonical failure detail:** The artifact could be slightly sharper by naming the representative-move mismatch mode (e.g., whether moves were canonicalized against the original state or the representative state, and how child states were keyed). This would help future attempts avoid the same error.
3. **`G(6,9)` max `|Inc(P)|`:** Not reported; the root antichain has 15 incomparable pairs. Reporting it would make the table uniformly checkable.
4. **Rough-byte accounting:** `approx bytes (rough)` is useful as order-of-magnitude evidence but not a formal size bound; the artifact already labels it rough.
5. **Lean/model correspondence:** None claimed — appropriate. The verifier checks a finite combinatorial DAG over explicit posets; it is not a kernel proof that this object corresponds to `S(n)` except through the standard game definition.

## 6. Bottom line

The artifact satisfies the requested audit criteria:

- **C4 verifier/format claims** are clearly stated and plausible for an explicit labelled C4 refuter DAG: total coverage of `Inc(P)`, TC-recomputed children, budget decrement, terminal non-total at zero budget, and soundness only for accepted objects under the checked rules.
- **Measured small-instance results** are reported only for reduced subgames (`G(3,2)`, `G(4,4)`, `G(5,6)` accepted; `G(6,9)` bounded abort). They are plausible and appropriately caveated but were not independently rerun here.
- **`(12,29)` compression-obstruction claims** are reasonable and evidence-based for the direct explicit C4 route: 66 root moves, rapid DAG/verifier blowup on bounded fragments, naive `12!` full canonicalization infeasible, and dominance not verifier-sound without proof rules.
- **No `S(12)>29` short compressed witness is claimed**, and **no complexity separation is claimed**.
