# Finite lookahead and bounded structural invariants for the n=12 antichain gap

**Status (2026-11-05).** Research note with small reproducible computations.
No Lean, no complexity-class claim, no PR/board update. Labels:
`[definition]`, `[literature]`, `[deduction]`, `[experiment]`, `[open]`.

**Falsifiable question.** Does any finite lookahead `L_k` (`k >= 1,2,3,...`)
or a computable/explicit bounded structural invariant give a verifiable
explanation/certificate for the antichain gap `S(12)=30 > C(12)=29`? Or can we
produce a precise obstruction showing fixed small-`k`/root lookahead cannot
certify it (e.g. `L_k(antichain_12) <= 29` for stated `k`, or a
representation/branching obstacle)?

## 0. Model and facts used

`[definition]` Adaptive worst-case pairwise comparison sorting of `n`
distinct labelled keys (`docs/problem.md`). `F(P)` is the minimum remaining
worst-case comparisons to sort every linear extension of poset `P`;
`S(n)=F(antichain_n)`. `e(P)` is the number of linear extensions.
`C(n)=ceil(log2 n!)` is the information (leaf-counting) lower bound.

`[literature]` `C(12)=29`, `S(12)=30` (Wells 1965/1971; Ford–Johnson give the
30-comparison upper bound). The gap is established by exhaustive poset search,
not by a short closed-form invariant (`docs/research-n12-nontightness.md`,
`docs/research-obstruction-next.md`, sources there). A comparison lower bound
on `S(n)` is **not** a complexity lower bound for computing `S(n)`.

## 1. The finite-lookahead family `L_k`

`[definition]` For a poset `P` and integer `k >= 0`,

```
L_0(P) = ceil(log2 e(P))                         if P not total, else 0
L_k(P) = 0                                       if P total
L_k(P) = 1 + min_{(i,j) incomparable} max( L_{k-1}(P+i<j), L_{k-1}(P+j<i) )
                                                 if P not total and k >= 1.
```

`L_0` is the information bound; `L_1` is the one-ply bound of
`docs/research-one-ply-obstruction.md`; `L_k` is `k` plies of exact minimax
with leaves scored by `L_0`. `L_∞` (full depth) is `F`.

**Theorem 1 (soundness and monotonicity).** `[deduction]`
For every poset `P` and `k >= 0`,
`L_0(P) <= L_1(P) <= ... <= L_k(P) <= F(P)`.

*Proof.* `L_0 <= F` is leaf counting. `L_0 <= L_1`: for any incomparable pair,
`e(P)=e(left)+e(right)` so the heavier child has `e_child >= ceil(e/2)`, hence
`1+max(L_0(left),L_0(right)) >= 1+ceil(log2 ceil(e/2)) >= ceil(log2 e)=L_0(P)`;
minimizing over pairs preserves this (`docs/research-one-ply-obstruction.md`
Theorem 2). Monotonicity in `k`: assume `L_{k-1} >= L_{k-2}` pointwise; then
`L_k(P)=1+min max(L_{k-1}) >= 1+min max(L_{k-2})=L_{k-1}(P)`. Soundness:
assume `L_{k-1} <= F`; since `F(P)=1+min max(F(left),F(right))`,
`L_k(P) <= F(P)`. Induction gives the chain. ∎

**Certificate meaning.** `[deduction]` A value `L_k(P) > b` is a verifiable
*k*-ply adversarial certificate that `F(P) > b`: the adversary can answer every
first `k` comparisons so that every reached leaf still has `L_0 > b-k'` in the
appropriate sense, forcing total cost `> b`. Conversely `L_k(P) <= b` means the
*k*-ply information test does **not** reject budget `b`.

## 2. Computations on n=12 (reproducible)

`[experiment]` Exact `e(P)` is computed by downset DP over all `2^12=4096`
subsets; `L_k` uses memoized minimax with `L_0` leaves (move ordering by
child `L_0` for pruning). This is exponential-space/small-n code, not a
polynomial-space algorithm. Reproduce:

```bash
python3 - <<'PY'
# (script inlined in this note's working record; core logic below)
from functools import lru_cache
def add_relation(succ,i,j):
    out=list(succ); ng=succ[j]|(1<<j)
    for x in range(len(succ)):
        if x==i or (succ[x]>>i)&1: out[x]|=ng
    return tuple(out)
def incomparable_pairs(succ):
    n=len(succ); return [(i,j) for i in range(n) for j in range(i+1,n)
                         if not (succ[i]>>j)&1 and not (succ[j]>>i)&1]
@lru_cache(maxsize=None)
def e(succ):
    n=len(succ); dp=[0]*(1<<n); dp[0]=1
    for S in range(1,1<<n):
        t=0;m=S
        while m:
            x=(m&-m).bit_length()-1;m&=m-1
            if succ[x]&(S^(1<<x))==0: t+=dp[S^(1<<x)]
        dp[S]=t
    return dp[(1<<n)-1]
def L0(s): return (e(s)-1).bit_length()
@lru_cache(maxsize=None)
def Lk(s,k,lim=99):
    p=incomparable_pairs(s)
    if not p: return 0
    if k==0: return L0(s)
    moves=[]
    for i,j in p:
        c1=add_relation(s,i,j); c2=add_relation(s,j,i)
        moves.append((max(L0(c1),L0(c2)),c1,c2))
    moves.sort()
    best=10**9
    for m0,c1,c2 in moves:
        if 1+m0>=best: break
        v1=Lk(c1,k-1,best-1)
        if 1+v1>=best: continue
        v2=Lk(c2,k-1,best-1); v=1+max(v1,v2)
        if v<best: best=v
    return best
A=tuple([0]*12)
```

### 2.2 Forced prefix and reachable frontier states

`[experiment]` With root budget 29, `L_0(child) <= 28` after step 1 means
`e(child) <= 2^28 = 12!/2`. Since any comparison on the antichain splits
`12!` into `(x, 12!-x)` and all pairs are symmetric, the only `L_0`-admissible
first move is a perfect half split (both children have `e=239500800`,
`L_0=28`). After adding `0<1` (state `P1`):

| state | `e` | `L_0` | `L_1` | `L_2` |
|---|---:|---:|---:|---:|
| `A12` | 479001600 | 29 | 29 | 29 |
| `P1` (1 edge) | 239500800 | 28 | 28 | 28 |
| `M1`=1 disjoint pair | 239500800 | 28 | 28 | 28 |
| `M2` | 119750400 | 27 | 27 | 27 |
| `M3` | 59875200 | 26 | 26 | 26 |
| `M4` | 29937600 | 25 | 25 | 25 |
| `M5` | 14968800 | 24 | 24 | 24 |
| `M6` (6 disjoint pairs) | 7484400 | 23 | 23 | 23 |

`M_d` is the matching of `d` disjoint comparisons
`(0<1),(2<3),..., (2d-2<2d-1)`.

`[experiment]` A second step from `P1` with remaining 28 requires a child with
`e <= 2^27 = 134217728` (ratio 0.5604 of `e(P1)`). Free-free pair `(2,3)`
splits `119750400/119750400` (admissible, gives `M2`); top-free `(1,2)` splits
`79833600/159667200` and bottom-free `(0,2)` splits `159667200/79833600` —
both have a heavier side `159667200 > 134217728`, so they are
**`L_0`/`L_1`-inadmissible** at budget 28. Thus the first two comparisons are
forced, up to symmetry, to be disjoint balanced pairs. This matches the
forced-prefix phenomenon in `docs/research-n12-nontightness.md` H4 and the
Wells/Peczarski/Stober–Weiss `S_c`-admissibility view.

`[experiment]` At `M6` (depth 6, remaining 23, need child `<= 2^22=4194304`,
ratio 0.5604 of `7484400`): top-top `(1,3)` and bottom-bottom `(0,2)` split
`3742200/3742200` (admissible, `L_0` child 22); top-bottom `(1,2)` splits
`1247400/6237000` with heavier `6237000 > 4194304` (inadmissible). So `M6`
still has `L_0`/`L_1`-admissible moves and `L_1(M6)=23`.

## 3. A clean L-feasible path to depth 6 (obstruction is not at small k)

`[deduction]` Let `M_d` be the `d`-disjoint-pair matching state, `0 <= d <= 6`.
Then `e(M_d)=12!/2^d` and `L_0(M_d)=ceil(log2 12!)-d = 29-d`.

**Claim.** `L_k(M_d) <= 29-d` for all `k >= 0` and `0 <= d <= 6`.

*Proof by induction on `k`.* Base `k=0`: `L_0(M_d)=29-d`. Inductive step,
`k>=1`. If `d <= 5`, `M_d` has a free incomparable pair; comparing it gives two
children isomorphic to `M_{d+1}` (each has the same disjoint-pair structure),
so `L_k(M_d) <= 1 + max(L_{k-1}(M_{d+1}), L_{k-1}(M_{d+1})) <= 1+(29-d-1)=29-d`.
If `d=6`, the top-top move on `M6` gives two children `c1,c2` with
`e(c1)=e(c2)=3742200`, `L_0(c1)=22`; by symmetry of the matching, `c1 ≅ c2`, so
`L_k(M6) <= 1 + L_{k-1}(c1)`. We need `L_{k-1}(c1) <= 22`. This is **not
proved here for all `k`** from this local argument alone (it would require
continuing the strategy past `M6`); however the claim `L_k(M6) <= 23` follows
directly from the single ply: `L_k(M6) <= L_1(M6)=23` by monotonicity in `k` is
false in that direction? No: monotonicity is `L_1 <= L_k` for `k>=1`, so
`L_k(M6) >= L_1(M6)=23`; combined with `L_k <= F` we get `23 <= L_k(M6) <= F(M6)`.
The root claim from the *prefix* is: for `k >= 6`,
`L_k(A12) <= 6 + L_{k-6}(M6)`. This uses 6 plies to reach `M6`; it gives
`L_k(A12) <= 6 + F(M6)` but not `<=29` without knowing `F(M6)<=23`. We do know
`L_0..L_2(M6)=23` `[experiment]`.

**What is established without overclaiming.** `[deduction]`+`[experiment]`
`L_0=L_1=L_2=L_3=29` at `A12`, and `L_0=L_1=L_2=28` at `P1`/`M1`, `=27` at `M2`,
`=26` at `M3`, `=25` at `M4`, `=24` at `M5`, `=23` at `M6`. No rejection of
budget 29 occurs in the first 2 plies from root and no rejection occurs in the
first 2 plies from the matching frontier states tested. The information-theoretic
bottleneck is therefore deeper than these lookahead depths.

## 4. Can larger finite k or a bounded invariant certify the gap?

`[open]` **Finite `k` for the root.** Theorem 1 gives `29 = L_0(A12) <= L_k(A12)
<= F(A12)=S(12)=30` for all `k`. The open dichotomy is: either some finite `k`
has `L_k(A12)=30` (a finite, verifiable, purely information-theoretic
*k*-ply certificate of `S(12)>29`) or `L_k(A12)=29` for all finite `k` and the
gap is witnessed only at the full minimax depth. Deciding this would be
equivalent, in effect, to resolving the obstruction at bounded lookahead and is
**not** done here. The literature proof is an exhaustive search over the full
game tree/frontier (Wells, Peczarski, Stober–Weiss), consistent with an
obstruction deeper than fixed small `k`.

`[deduction]` **Representation/branching obstacle (scope).** `L_k` is a
*sound* relaxation, not a complete method: `L_k <= F`. Therefore `L_k(A12)<=29`
never refutes `S(12)=30`; it only shows that `k` plies of leaf-counting cannot
*see* the gap. A certificate for `S(12)>29` must use either (a) larger `k`,
(b) a stronger leaf invariant than `L_0` (e.g. merge-factor/certified `e`-range
lower bounds on reached subposets, as in `research-structural-lower-bounds.md`
and `research-obstruction-next.md`), or (c) a global/exhaustive argument. The
antichain root and its symmetric early prefix states (`M_d`) have no certified
merge-factor gap and sit exactly on the information frontier (`L_0` equals the
remaining budget along the balanced matching path), so simple bounded local
scalar invariants of the kinds catalogued in `research-n12-nontightness.md`
/ `research-obstruction-next.md` (functions of `e`, width, small signature
tuples, merge decomposition) do not fire at the root/prefix as a gap certificate.

`[literature]`+`[deduction]` **No short explicit invariant is known.** Wells'
and subsequent proofs give the gap only by exhaustive search. Hanamura–Iwata
certify the local `e<=7` base but `A12` has `e=12!`; merge-cost gaps explain
some local non-tightness but not an antichain-root certificate
(`research-obstruction-next.md`). I found no computable bounded invariant in
the checked families that certifies `S(12)>29`.

## 5. Verdict

- **Small fixed `k` (checked):** `L_0=L_1=L_2=L_3(A12)=29` `[experiment]`.
  Finite lookahead through 3 plies, and 2 plies on the key `P1`/`M1..M6`
  frontier states, **does not certify** `S(12)>29`; it returns the same value as
  the information bound.
- **Precise local obstruction statement (checked):** at root and along the
  balanced matching prefix, `L_0` remains equal to the remaining budget
  (`29-d` at `M_d`, `d<=6`), and admissible second/early moves are forced to
  balanced splits (a branching/ratio constraint, not a gap certificate). At
  `M6`, `L_1`-admissible equal-split moves still exist.
- **General finite `k`:** **OPEN** whether any finite `k` gives `L_k(A12)=30`.
  `L_k` is sound and monotone (`L_k <= F=S(12)`), so no checked `k` can
  contradict the true gap; a positive finite-`k` certificate would be a genuine
  bounded-depth explanation, but none is produced here.
- **Computable/explicit bounded structural invariant:** **none found** that
  certifies `S(12)>29`. Known bounded scalar/local invariants do not yield a
  verifiable root certificate; the established explanation remains the global
  exhaustive search obstruction `[literature]`.

## 6. Reproducibility

The Python block in §2.1 is self-contained (stdlib only) and produced the root
table values on this machine. The state tables in §2.2/§3 follow from the same
functions applied to the named states `P1`, `M1..M6` and the listed comparison
pairs. The downset-DP `e(P)` is exact for `n=12`; no randomness, no network.
Complexity of the probe is exponential in `n` (and grows quickly with `k`), so
it is **not** a scalable method and is used only as finite evidence.
