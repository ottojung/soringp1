## 0. Baseline (literature / repository)

- `[literature/definition]` `S(n)` is the minimax height of adaptive comparison sorting of `n` distinct labelled keys; `SORT-BOUND-U = {1^n#1^k : S(n) <= k}` has input length `N=n+k+1` (`docs/problem.md`).
- `[literature/deduction, docs/research-budgeted-dfs.md]` Budgeted DFS decides `CanSort(P,d)` correctly by the minimax recurrence in `2^{O(d log n)}` time. For function evaluation with `d <= U(n)=O(n log n)`, time is `2^{O(n log^2 n)}` and a transcript-only implementation uses `O((d+n)log(n+2)) = O(n log^2 n)` bits: stack/transcript `O(d log n)` (one pair + cursor, `O(log n)` bits per frame, depth `<=d+1`), plus one reachability workspace `O(n log n)` bits (visited bit-vector and queue/stack of labels), plus `O(log n)` counters. For decision, `d=k` gives `O((k+n)log(n+2)) <= O(N log(N+2))` bits when `k < U(n)` (§5.3).
- `[literature]` Information bound: `S(n) >= ceil(log2(n!)) = n log2 n - n/log(2) + O(log n) = Theta(n log n)` for all sufficiently large `n`.

## 1. Space decomposition (bit complexity, numeric n)

For exhaustive minimax DFS from a state reached in `t` comparisons with remaining budget `d-t`:

| Component | Typical size | Notes |
|---|---:|---|
| Comparison path / call stack | `Theta(t log n)` bits | each of `t` frames: compared pair in `[n]^2` and/or cursor over `B=binom(n,2)` candidates, `Theta(log n)` bits; depth `t <= d`. |
| Poset/state | `0` (implicit) to `Theta(n^2)` bits/frame | transcript-only: implicit via path, no matrix stored; closure-matrix-per-frame: `n^2` bits/frame, total `Theta(d n^2)` worst-case path if retained. |
| Reachability / comparability workspace | `Theta(n)` to `Theta(n log n)` bits | BFS/DFS over `n` vertices and current edges: visited `n` bits, queue/stack `O(n log n)` bits; can be reused (one workspace). |
| Counters / budget / indices | `O(log n)` to `O(log(d+n))` bits | dominated. |

Total (transcript-only, reused reachability workspace): `Theta(t log n + n log n)` at depth `t`; peak over a successful evaluation is `Theta(S(n) log n + n log n)`.

## 2. (b) Barrier for transcript/path-storing exhaustive DFS [deduction]

**Class C_path (deterministic transcript-storing budgeted DFS).** Uniform deterministic algorithms that decide `S(n) <= k` / evaluate `S(n)` by exhaustive depth-first exploration of the comparison game and, at every reached node of transcript depth `t`, store an explicit representation sufficient to (i) identify the ordered sequence of the `t` comparison outcomes on the current root-to-node path and (ii) resume the deterministic enumeration of the sorter's candidate moves at every ancestor after backtracking. The algorithm may recompute comparability/reachability from the stored path in auxiliary workspace (not counted as storing additional path/state copies except that workspace) and must run in sub-`2^{O(n^2)}` time in numeric `n`.

**Theorem (path-storage barrier).** Every algorithm in C_path uses `Omega(S(n) log n) = Omega(n log^2 n)` bits of work space on infinitely many `n`, in particular for all sufficiently large `n`. Hence `o(n log^2 n)` bits is obstructed for C_path.

**Argument.** Let `B_n = binom(n,2) >= n(n-1)/2`. For `n >= 4`, `log2 B_n >= log2(n^2/4) = 2 log2 n - 2 >= log2 n` (and in fact `Theta(log n)`). Consider any successful evaluation/decision run establishing `S(n)=k` (or `S(n)<=k` with `k>=S(n)`): there is at least one root-to-leaf execution path of depth `S(n)` on which every step is a non-redundant comparison (a comparison between currently comparable keys cannot be part of a shortest winning strategy in that state except impossible here; more generally the minimax-optimal/winning transcript has length `S(n)` and each step selects a pair from the current incomparable set). 

The algorithm's configuration at depth `t=S(n)` must encode the ordered outcomes on that path well enough to distinguish it as the current DFS position in the implicit game tree: otherwise, after returning along backtracks, it could not in general resume the correct ancestor cursor/outcome branch (a DFS must be able to revisit the parent state logically). An explicit ordered transcript of `t` comparisons, each being an ordered pair/outcome from an alphabet of effective size >= 2 (at least the binary adversary answer, and to identify the move/resume point one needs the chosen pair index or equivalent `Theta(log B_n)` information per sorter move in the standard candidate-scan model) requires at least `sum_{i<=t} Omega(log n) = Omega(t log n)` bits. 

Taking `t=S(n)` and using `S(n) >= log2(n!) = Omega(n log n)` yields `Omega(n log n * log n) = Omega(n log^2 n)` bits for all sufficiently large `n`. The time constraint sub-`2^{O(n^2)}` is satisfied by known transcript-only DFS and is orthogonal to this space lower bound. ∎

*Scope note:* this is a barrier for the **path-storing** paradigm, not for all possible exact evaluators of `S(n)`. It rules out `O(n log n)`, `O(n)`, and polylog(`n`) space for C_path in the stated regime because the depth factor `S(n)=Theta(n log n)` is unavoidable on successful runs.

## 3. Other classes (partial analysis) [deduction / open]

**State-representing (closure-matrix-per-frame) DFS.** Storing an `n x n` transitive-closure bitmatrix per active frame costs `n^2` bits/frame and `Theta(d n^2)` bits on a path of depth `d`, i.e. `Theta(n^3 log n)` for `d=Theta(n log n)`, strictly worse than transcript-only. Not a route to `o(n log^2 n)`.

**Transcript-only with recomputed reachability (the known algorithm).** Recomputing comparability by graph reachability removes stored closure/state but still stores the transcript/path: `O(d log n)` stack + `O(n log n)` workspace = `O(n log^2 n)` for evaluation. The reachability workspace alone is `O(n log n)` (BFS) and cannot be reduced below `Omega(n)` bits by trivial means while solving reachability on `n` vertices; but the dominant term is the path when `d=Theta(n log n)`.

**Checkpoint/replay or path recomputation (Savitch-style / tree-evaluation tradeoffs).** One may imagine not storing the full path but recomputing ancestors or replaying from the root. However, to backtrack in exhaustive DFS one must know, for each ancestor, which candidate pair/cursor and which adversary branch have been explored — information equivalent to the transcript/cursor path unless regenerated. Deterministic replay/checkpointing schemes (e.g. Bennett-style reversible/replay or generic tree-evaluation time-space tradeoffs) can reduce peak path storage only by increasing recomputation/time; known methods do not suggest a way to obtain `o(n log^2 n)` bits while preserving the `2^{O(n log^2 n)}` (or any stated sub-`2^{O(n^2)}`) time bound for this game tree, and I did not find a concrete algorithm achieving both. **[open]**: a rigorous lower bound for all checkpoint/replay exhaustive evaluators under the stated time constraint would require a formal time-space tradeoff model for this specific minimax tree; not established here.

**Non-path-storing / non-DFS exhaustive paradigms.** The question scopes “budgeted-DFS/exhaustive-game-search paradigm”. Algorithms that avoid storing/exploring transcripts (e.g. algebraic/compressed state counts, if they existed) would fall outside C_path but no such uniform exact method beating the path barrier while keeping sub-`2^{O(n^2)}` time is known here. **[open]**.

## 4. Consequences for SORT-BOUND-U / PSPACE [deduction, careful]

- SORT-BOUND-U is in PSPACE (and in DSPACE(O(N log N)) for input length `N` by the budgeted-DFS accounting, per `docs/research-budgeted-dfs.md`). The barrier in §2 is a **method barrier** for C_path, not a separation and not a lower bound against all PSPACE algorithms.
- A uniform exact evaluator in `o(n log^2 n)` bits by a genuinely different exhaustive paradigm would be a space upper-bound improvement for this problem/method family but would not by itself imply complexity-class separations. No such algorithm is exhibited.

## 5. Answer to the posed question

- **(a) Space-improved algorithm:** not found. The known transcript-only budgeted DFS already achieves `O(n log^2 n)` bits for numeric-`n` evaluation and is the baseline; no concrete `o(n log^2 n)`-bit uniform deterministic algorithm with stated sub-`2^{O(n^2)}` time and correctness/cost argument was obtained.
- **(b) Barrier (falsifiable):** for the clearly stated class C_path of transcript/path-storing exhaustive budgeted DFS, `Omega(S(n) log n)=Omega(n log^2 n)` bits are necessary for all sufficiently large `n` (on successful runs reaching depth `S(n)`), because `Theta(log n)` bits per comparison level are needed over `S(n)=Theta(n log n)` levels to represent/resume the current path. Thus `o(n log^2 n)` bits is obstructed for C_path. For checkpoint/replay and broader exhaustive paradigms, only a conditional/open discussion is given (no theorem proved here).
