1. **Pairing (3 comparisons).** Compare 3 disjoint pairs `(e0,e1),(e2,e3),(e4,e5)`; `e6` is odd/straggler. For each pair record winner `a_i` and loser `b_i` with `b_i < a_i`.
2. **Sort winners (3 comparisons).** Recursively sort the 3 winners `a1,a2,a3` into a chain `a_{p1}<a_{p2}<a_{p3}` (optimal for 3 elements: 3 comparisons). Carry associated losers with their winners (frame/slot permutation requirement).
3. **Insert pendings in Jacobsthal order (7 comparisons).** With `m=3` winners and one odd element, pending set in FJ/Jacobsthal order is `b_{p1}, b_{p3}, b_{p2}, e6` (cf. `fj_order(4)=[1,3,2,4]`, logic consistent with `scripts/upper_witness.py:fj_order/fj_sort`):
   - `b_{p1}`: known `b_{p1}<a_{p1}`, insert before `a_{p1}` into empty prefix → **0** comparisons.
   - `b_{p3}`: known `b_{p3}<a_{p3}`, insert into chain prefix below `a_{p3}` of size 3 (`b_{p1},a_{p1},a_{p2}` region) → `ceil(log2(4))=2` comparisons.
   - `b_{p2}`: known `b_{p2}<a_{p2}`, insert into chain below `a_{p2}`; size ≤4 after prior insertion → `ceil(log2(5))` worst-case 3 but FJ bound counts 2 here (`3+3+0+2+2+3=13` total) given rank/window; exact certified step bound is `ceil(log2(i+t))` per §3 / Jacobsthal schedule.
   - `e6` (odd, no paired-winner upper bound except end): insert into full chain of 6 elements → `ceil(log2(7))=3` comparisons.

Total `3+3+0+2+2+3 = 13 = F_FJ(7)=S(7)`.

## 4. Mismatch/obstruction or confirmation

**No checker-verified FJ framed DAG for n=7 constructed.** Precise obstruction points (evidence-based):

1. **Recursive frame / carrying associated losers during winner sort (phases 1→2).** After 3 pairing comparisons, each outcome can be normalized by explicit perms so that slots encode `(loser_i,winner_i)` pairs (identity vs swap per pair). Sorting the 3 winner slots into ascending order requires comparisons on winner slots but **every transposition/reordering of winners must apply the same permutation to their associated loser slots** to preserve `b_i < a_i` in-slot (pair-coupled frame). A full tree unfolding over pairing outcomes is structurally uniform in slots but implementing the 3-element sorting network/DAG on slots `(1,3,5)` with coupled moves on `(0,2,4)` and correct topological emission for all branches is nontrivial; partial scaffold in `artifacts/build_fj7_tree.py` shows the required `pair_swap_perm` coupling but incomplete/aborted composition (no verifiable witness).
2. **Rank-envelope joins with locally checkable relaxed windows (phase 3, §3 core).** For a pending insertion (e.g. `b_{p3}` into a 3-element prefix, 4 possible ranks; later `b_{p2}`, `e6`), the §3 method requires: expand search as a tree with O(n) query nodes and permute slots to place the inserted element, then **join leaves** so other pending elements satisfy the next stage’s relaxed window `current[ℓ_j] < x_j < current[u_j+t]` regardless of chosen rank. In this checker, a join is `relations[child] = intersection(incoming_relations)` at a common child node reached via explicit `perm`s. Encoding a sound join therefore requires a **fixed post-insertion slot layout and permutation scheme per path** such that, after placing the inserted element at different ranks, the intersected slotwise guaranteed relation is exactly the intended weak envelope (and still strong enough for subsequent comparisons/bounds) without conflating distinct element identities in ways that break totality at leaves. Designing and proving this slot/perm scheme for FJ’s concrete pending set — including boundary sentinels and dynamic main-chain indices — was not completed; naive layouts leave rank-dependent relations that intersect to an invariant too weak or misaligned for later certified bounds.
3. **Odd element and recursive/boundary handling.** n=7 includes an odd straggler `e6` (full-range insertion, 3 comparisons) and the winner sort is a recursive instance (n=3 base) whose internal frame must be embedded into the n=7 slot frame; §3 notes “complete recursive frame construction and odd case” as subject to checking. A general generator must correctly lift base-case permutations, maintain paired-winner anchors `a_i` under prior insertions, and handle sentinel/index boundaries at chain ends — all in explicit perms accepted by the forward-DAG/topological checker. This lifting was not implemented/specified to a checkable artifact here.
4. **Evidence of gap (not a checker limitation claim).** Baseline `--bubble 4` is accepted and unit tests pass, confirming the verifier enforces the stated local semantics; the obstruction is in producing a **correct, specific FJ n=7 witness** satisfying §3’s join/relaxation intent, not in running the checker.
