## Definition: PGF, “annotation”, and what is checker-acceptable `[definition]`

A **PGF certificate** (as implemented by `check_framed_strategy.py`) is a forward acyclic DAG with:
- `root = 0`, `R(0)=∅` (guaranteed strict partial order over n slots).
- Each internal node does a single comparison `compare=[a,b]` with two edges `lt`, `gt`. For a feasible outcome: add `smaller<larger`, take transitive closure via `_closure()`, apply the edge **permutation `perm`** via `_rename()` (mapping old slot indices to new slot indices). Impossible outcomes (contradicting current `R(v)`) are skipped.
- **Join:** `R(u)=⋂ R_in` over feasible incoming renamed guarantees (bitwise intersection of per-slot bitmasks after renaming each branch).
- **Leaf:** accepted only if `R(leaf)` is a total order on all pairs; `max depth <= budget`.

**“Annotation” relative to the checker `[definition]`:** 
- The checker’s only per-edge “frame/annotation” is the list `perm` (a permutation of `n` slots) attached to each outgoing edge (`lt`/`gt`). 
- There is **no disjunctive/multi-state join field** in the current format; joins are only single-poset intersection. 
- A **“stronger join annotation beyond meet”** (e.g. carrying a disjunction, a set of possible posets, or auxiliary join metadata) is **not checker-acceptable** under the existing `check_framed_strategy.py` without extending the format and providing new soundness/checking proofs. Frame **normalization (F-norm)** means choosing `perm` on incoming edges so that renamed posets become compatible (their meet preserves required facts). This is checker-acceptable as long as it uses only `perm` per edge.

### Non-isomorphic residual (blocks frame normalization)
Let incoming guaranteed posets before join be (slots named before edge `perm`):
- `R1 = {0<1, 0<5}`
- `R2 = {1<0, 0<5}` (non-isomorphic to `R1` under naive alignment)

Both facts `(0,1)` and `(0,5)` are required for any total order completion in this fragment. Try F-norm repairs:

### Finite constraint (proof sketch) `[deduction]`
Let `p1,p2` be edge permutations. Want `J = rename(R1,p1) ∩ rename(R2,p2)` to contain `0<1` and `0<5`. Set `p1=id`: need `rename(R2,p2)` to have `0<1` => from `1<0` in `R2`, require `p2(1)=0, p2(0)=1`. Need `0<5` => from `0<5` in `R2`, require `p2(0)=0, p2(5)=5`. Contradiction (`p2(0)` would need to be both 1 and 0). By symmetry no pair `(p1,p2)` preserves both facts. If the required residual below the join demands both `(0,1)` and `(0,5)` in the meet for total completion, checker-acceptable single-poset F-norm fails.

## Repairability at (12,30): precise answer

- **(a) Repairable by explicit checker-acceptable frame/annotation?** Conditionally **yes** if the join is placed where all required downstream facts are join-stable/isomorphic under some explicit edge permutations `perm` (F-norm). The checker accepts such cases (F2).
- **(b) Violates any existing-checker-acceptable single-poset-meet completion?** For the **C_id-loss/non-isomorphic residual class** above (F1, F3), **yes**: no pair of edge permutations produces a single-poset meet preserving all facts required for a total-order completion in that fragment, so any PGF completion of that fragment using only single-poset intersection + per-edge permutations is checker-rejected. The concrete instances are `A_idloss_n12k30` and `6_nonisomorphic_block_n12k30_{swap,id}`.

**Caveat:** No complete, accepted exact-height-30 total-sorting PGF for all 12 elements was constructed here. This is a class-sensitive constraint on a bounded fragment, not a global proof that `(12,30)` is unrepairable in general. Stronger join annotations beyond meet are not checker-acceptable in the existing format.
