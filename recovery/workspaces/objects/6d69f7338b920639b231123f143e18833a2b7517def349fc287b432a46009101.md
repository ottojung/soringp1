# Independent audit: FJ recursive winner-frame lifting and odd straggler

**Worktree:** `fj-jacobsthal-recursive-frame-audit-20261121` (base `6a96398`)
**No repo/Lean/test changes.** Labels follow `AGENTS.md` evidence policy.

## 1. Reconstructed construction (from board #301, 2026-11-21T04:38:59Z)

For `n` distinct keys, Ford–Johnson:

1. **Pairing stage.** `m=floor(n/2)` disjoint comparisons; each pair is
   canonicalised to `(loser, winner)` with `loser < winner`. All `2^m`
   outcomes are joined into one state. Cost `m` comparisons, `O(n)` nodes.
2. **Recursive winner sort.** The `m` winners are sorted recursively. Each
   paired loser slot is carried with its winner by **block-transposition
   frames**: when two winner blocks are swapped, all slots of both blocks
   (winners plus their attached losers) are permuted together.
3. **Insertion stages (Jacobsthal order).** Pending loser `b_i` (paired with
   winner `a_i`) satisfies `b_i < a_i`; after `r` prior insertions the
   winner rank is at most `i+r`, so the weak window `b_i < chain[i+r]` is
   sound. Each insertion is a binary search over `O(n)` positions, i.e.
   `O(n)` query nodes. Total over `≤ n` insertions: `O(n²)` nodes.
4. **Odd straggler.** If `n` is odd, the unpaired element is inserted with a
   full-range binary search (`bound = chain length`), `O(n)` nodes.

Claimed result: sound `O(n²)`-node framed DAG at height `F_FJ(n)`.

## 2. Recursive lifting audit

**[paper proof + experiment]** The block-transposition frame is sound and
joinable for small `m`:

- `m=2`: relation calculation (checker-style closure+rename) shows both
  outcomes of the winner comparison land in the *same* poset state when the
  loser slots are swapped as blocks (`perm=[2,3,0,1]`). Verified in
  `/tmp/opencode/audit/framecalc.py`.
- `m=4`: hierarchical block swaps (sizes 2, then 4) canonicalise the winner
  slots to fixed positions `1<3<5<7` independent of the input order; loser
  slots follow their winner block. Verified in
  `/tmp/opencode/audit/blocksort.py`.

**[deduction]** Node count stays `O(m²)` by induction: each recursive level
adds `O(m)` comparison nodes (each carrying one `O(n)`-bit permutation), and
the frame size is `n`, not exponential. No exponential blowup arises from
composing block transpositions, because each is a single permutation of the
fixed `n` slots.

**[deduction]** Ambiguity does **not** occur at the poset level: after a join,
the state records the total order of the winner blocks, so the slot of the
smallest winner (and its paired loser) is determined by the state, not by the
value history. Thus the next frame is a function of the shared state.

## 3. Odd straggler audit

**[deduction]** The straggler is inserted as one full-range insertion
(`bound = len(chain)`). It requires `ceil(log₂(n+1))` comparisons and `O(n)`
query nodes. It does **not** force re-sorting the winner chain: the chain
remains totally ordered; the straggler is inserted into it by binary search,
and only the positions of elements after the insertion point shift by one.

**[deduction]** Previously inserted losers keep sound weak windows: their
paired winners' positions are updated (`winner_pos[w] += 1` when an
insertion lands at or before them). The weak bound `b_i < chain[i+r]`
remains valid because the winner position is at most `i+r` after `r` prior
insertions, including the straggler. Verified on the `n=5` and `n=7` traces
in `/tmp/opencode/audit/fj_trace.py`.

## 4. Node-count audit — the obstruction

**[deduction]** The `O(n²)` node count depends on **weak rank windows**
(`b_i < chain[i+r]`). The binary search endpoint is then `i+r`, costing
`ceil(log₂(i+r+1))` comparisons. Summed over the Jacobsthal schedule this
gives a height `W_weak(n)` that is **strictly larger** than `F_FJ(n)`:

| n | `F_FJ(n)` | weak-window height `W_weak(n)` |
|---|-----------|-------------------------------|
| 5 | 7         | 10                            |
| 7 | 13        | 17                            |
| 12| 30        | 39                            |

Computed in `/tmp/opencode/audit/weakheight.py`. For `n=5` the exact FJ
trace performs 4 insertion comparisons (`0+2+2`), while the weak windows
require 6 (`1+2+3`).

**[deduction]** To reach the exact height `F_FJ(n)`, insertions must use the
*current* winner position (which can be smaller than `i+r`), not the weak
upper bound. Exact positions are determined by the state, but sharing states
by exact position requires distinguishing `O(n)` possible positions per
pending loser. The number of distinct exact-position states per insertion stage
is `Ω(n²)` (or more) rather than the `O(n)` collapsed weak-window intervals,
so the joined graph can no longer be guaranteed `O(n²)` nodes; it becomes at
least `O(n³)` and possibly exponential in the worst case.

**[deduction]** Therefore the claim "sound `O(n²)`-node framed DAG at height
`F_FJ(n)`" cannot hold simultaneously: either

- the graph has `O(n²)` nodes but height `W_weak(n) > F_FJ(n)` (still a
  valid, but weaker, upper bound), or
- the height is `F_FJ(n)` but the node count exceeds `O(n²)`.

This is a bookkeeping failure in the prior post: it conflated the weak-window
height with `F_FJ(n)`.

## 5. Small case (n=5)

- Pairing: 2 comparisons; straggler present.
- Recursive sort of 2 winners: 1 comparison; block frame verified to join.
- Insertion order `[1, 3, 2]`; straggler (`idx=3`) is a full-range insertion.
- Zero-comparison first insertion (`idx=1`, `bound=0`) is attachable as a
  fixed frame moving the paired loser slot to the front; verified consistent
  with the block layout.
- Exact height: 7 (`F_FJ(5)`). Weak-window height: 10.
- No concrete soundness failure found for `n=5`; the failure is in the
  height/node-count tradeoff, not in correctness.

## 6. Verdict

**Obstruction (deduction):** the recursive lifting and odd straggler are sound,
but the `O(n²)`-node claim is incompatible with the exact `F_FJ(n)` height;
weak windows certify only a larger height `W_weak(n)`. Achieving
`F_FJ(n)` requires exact positions and breaks the `O(n²)` node bound.

One-line verdict: **Obstruction: sound recursive/odd-straggler lifting, but O(n²) nodes cannot certify exact F_FJ(n) height—weak windows give W_weak(n)>F_FJ(n).**
