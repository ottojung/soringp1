**Audited against (this repo/workspace):** `AGENTS.md`, `docs/problem.md`, `docs/research-framed-certificate-frontier.md`, `docs/research-n12-nontightness.md`, `scripts/check_framed_strategy.py`.

## 1. Model and checker baseline

- `docs/problem.md` `[definition]/[literature]`: `S(12)=30` is known in the sorting-number literature (Wells); `C(12)=ceil(log2 12!)=29`, so `S(12)>C(12)`. The active target is unary `SORT-BOUND-U`; NP membership is not established by exhibiting a sorting decision tree/large object.
- `docs/research-framed-certificate-frontier.md` `[paper theorem; implemented checker]`: PGF certificates are sound and checkable in time polynomial in explicit graph length and `n`. **No all-`n` polynomial-size completeness theorem at exact height `S(n)` is known.** An accepted joined/normalized graph does not imply NP membership; improving sharing does not repair merge-architecture comparison deficits.
- `scripts/check_framed_strategy.py` `[definition/experiment]` implements local checks: topological forward propagation, feasibility filter `relations[v][larger] & (1<<smaller)` skips impossible branches, closure+rename, intersection at joins, leaf total-order check, budget/depth check. This matches the soundness story in the frontier note.

## 2. O1 claims at `(n,k)=(12,30)`

**Claim (note §PGF/obstruction, §2, §4):** O1 (meet-induced incompleteness) means a join/intersection can discard disjunctive facts needed downstream; this is a representation/naive-encoding/local obstruction, not a proof that no PGF exists. A concrete fragment at `(12,30)` is rejected because the meet loses the `0v1` fact.

**Audit:**
- `[deduction]` Correct from the checker semantics: `relations[child] = [x & y for ...]` is meet/intersection of feasible incoming renamed guarantees. If one branch guarantees `0<1` and another `1<0` (with incompatible frames), neither fact survives the meet for that pair; a leaf requiring `0,1` ordered must be rejected.
- `[experiment]` Reproduced with the note's script:
  - `accepted_join_n3`: `ACCEPT depth=3 nodes=6 PASS`.
  - `o1_reject_n3`: `REJECT leaf 3 does not sort 0,1 PASS`.
  - `o1_reject_n12_budget30` (`n=12,k=30`): `REJECT leaf 3 does not sort 0,1 PASS`.
- The constructed `n=12` fragment is **budget-feasible as a path/depth object** (depth 2 before leaf) and uses valid forward edges/frames; rejection is due to missing `0,1` order at leaf 3, not budget. This supports “O1 is active at the hard-case parameters as a concrete local constraint.”
- **Scope check:** The note explicitly states this does *not* prove no other exact-height-30 PGF exists for `n=12` and does *not* prove a size lower bound. This is the right limit: a positive alternative would require frame normalization or a different join structure preserving required facts.

**Assessment:** **Supported, no overclaim.**

## 3. Frame-normalized accepted join

**Claim:** `accepted_join_n3` shows joins/disjunctive control flow are representable when frames make the meet preserve sufficient guarantees.

**Audit:** `[experiment]/[deduction]` Reproduced accept. Root `gt` applies swap `(1,0,2)`, so the `1<0` raw outcome is renamed to `slot0<slot1` before joining with the `lt` identity branch; both incoming states certify `slot0<slot1`, so intersection preserves it. The note correctly qualifies this as a positive local existence for frame-normalized joins, **not** a certificate for `S(n)`. Consistent with `research-framed-certificate-frontier.md` (“sound and checkable… No such all-n polynomial-size completeness theorem is known”).

**Assessment:** **Supported.**

## 4. Bounded `C_id-loss` class

**Claim:** The named class `C_id-loss` (identity-frame/no-normalizing join losing a required pair `(p,q)` that later must be certified) is ruled out as a local completion mechanism by the checker; `o1_reject_n12_budget30` is an instance. Not a bound on all framed joins because frame normalization can sometimes make meets strong enough.

**Audit:**
- `[deduction]` For the stated class, `R_join[p][q]=R_join[q][p]=0` after intersection, so any completing leaf in that joined region that still needs `(p,q)` ordered cannot satisfy the checker’s leaf total-order test for that pair. This is a direct consequence of checker semantics, not a probabilistic/search claim.
- The class is **named and bounded in scope**; the note does not quantify it as “all PGFs”, “all joins”, or “all strategies at `(12,30)`”.
- A natural caveat (already implied, worth making explicit): `C_id-loss` is defined by a *semantic* loss at join plus downstream need; checking membership for an arbitrary proposed certificate is local/explicit, but the note’s argument is not an exhaustive enumeration of all certificates, only a class constraint. The note states this correctly.

**Assessment:** **Supported as a bounded class constraint.**

## 5. O2 claims

**Claim:** O2 is a single deterministic policy-tree fact (distinct nodes in a reduced policy cannot share identical labelled poset states), ruling out trivial identical-state hash-consing for one policy; PGF is stronger because frames can normalize. Global labelled-poset reachability collisions illustrate the distinction, not an `n=12` exact-height result.

**Audit:**
- `[deduction]` The distinction is important and stated: global reachability collisions across *all* comparisons/outcomes do not contradict “one reduced deterministic policy has no identical labelled-state sharing”. The script prints this caveat with the table.
- `[experiment]` Reproduced: `n=2: 3,0`; `n=3: 19,24`; `n=4: 219,826`. These are tiny sanity values only.
- **No overclaim found:** the note does not turn O2 into an exact-height PGF size lower bound at `n=12`, and says O2 was not turned into such a bound. This aligns with the request to avoid a global/lower-bound overclaim.

**Assessment:** **Supported; scope appropriately limited.**

## 6. Exhaustive search / global nonexistence / NP

**Claimed limits:** No exhaustive global framed-join search at `(12,30)`; `12!` leaves/tree size and larger PGF search space make it infeasible here. No exact-height-30 PGF constructed; no global proof all PGF classes fail at `(12,30)`; no lower bound on exact-height PGF size for `n=12`; no NP/coNP claim.

**Audit:**
- `[deduction]` The feasibility argument is reasonable as a statement of what was *not* done: exact decision trees at `n=12` are enormous (`12!=479,001,600` leaves), and arbitrary PGF graphs with joins/frames are a larger design space. The note does not present this as a mathematical impossibility of search, only as a reason no exhaustive global claim is made.
- Consistent with `AGENTS.md`/`docs/problem.md` model fidelity: no NP membership claim from a certificate object unless an all-`n` polynomial-size completeness theorem is established; no separation/lower-bound claim.
- `docs/research-n12-nontightness.md` context is also respected: `S(12)>C(12)` is structural/exhaustive in the literature and does not by itself give a short PGF obstruction.

**Assessment:** **No prohibited overclaim detected.**

## 7. Minor issues (non-blocking)

1. **Tiny minimax sanity printout is misleading.** `[experiment]` In `check_framed_n12_falsify.py`, `can_sort_poset_game` takes `(n,budget)` but never uses `budget` (it returns minimax height from the antichain). The script prints `height 3=3; height 2=3` for `n=3` and `height 5=5; height 4=5` for `n=4`, which reads as if budget-2/budget-4 succeed; in fact `S(3)=3>2` and `S(4)=5>4`. This does **not** affect the O1/checker claims, which were independently reproduced. The note’s prose states “S(3)=3, can sort at 3, cannot at 2…” — that prose is correct, but the reproduced script output should be interpreted carefully.
2. **Global-collision numbers are script-reported, not otherwise cross-checked.** They are plausible as an illustration of global reachability collisions and are not used to support a main claim.
3. **External artifact dependency.** The note cites `/home/lubko/soring-fronts/exact-s12-height-dag-obstruction-20261105/docs/exact-s12-height-dag-obstruction.md`; this audit checked the note’s *internalized* O1/O2/O3 summary and the reproduced checker behavior, not that external file itself.
