## Model and definitions (labelled)

- **Definition (problem.md, upper-bound.md, SoringP1/Minimax.lean context).** `F(P)=adv L(P)` is the exact minimax remaining comparisons for a poset state `P` reachable from the antichain; `S(n)=F(∅_n)`. Reachable states along comparison histories are exactly posets whose `L(P)` is the consistent linear extensions (research-compression-next.md Lemma 1 + reachability); hence every poset is root-reachable and poset-realizable. `R_h(P)=max(d+F(P), max_i(i+F(Q_i)))` is the root-prefix viability.
- **Definition (ordinal sum).** `A ⊕ B`: all of `A` below all of `B`; `F(A ⊕ B)=F(A)+F(B)` (series-decomposition.md Thm. 1, deterministic direct sum, Jain–Klauck–Sántha IPL 110 (2010) Thm. 1).
- **Definition (disjoint union / parallel).** `A ⊔ B`: no cross relations; `L(A ⊔ B)=L(A)×L(B)` as sets, but cross-block comparisons are informative, so `F` is *not* additive.
- **Definition (candidate interface summary).** For a block `B`, a polynomial-state summary `σ(B)` used to compose `F(A ⊔ B)` without the full poset. Two candidates tested:
  - *weak* `σ_w(B)=(e(B), F(B))`;
  - *strong* `σ_s(B)=(e(B), F(B), MVM(B))`, where `MVM(B)` is the sorted multiset of `max(F(B+x<y), F(B+y<x))` over incomparable pairs `{x,y}` — the full local game profile (move values). Both `σ_w, σ_s` are **self-dual** invariants: `n, e, F, MVM` are invariant under `P ↦ P^op`.
- **Definition (chain interface).** A block that is a single chain of length `a` has summary `a` (and `F=0, e=1`); the composite `chain_a ⊔ chain_b ⊔ …` is the classical multiway-merge problem.

## Results (evidence-labelled)

### A. Ordinal-sum interface — exact but root-inapplicable (deduction + literature)

`F(A ⊕ B)=F(A)+F(B)` is exact and root-preserving in the sense of the adversary: the consistent set stays a product `W_A×W_B`, and the potential argument gives the lower bound branch-wise, so both sibling branches of every comparison are preserved (series-decomposition.md §2). **But the antichain root `A_n` is series-prime** (its incomparability graph is connected), so this interface never applies at the root itself; it yields no state-space gain and no recurrence reaching `S(n)` from smaller blocks (series-decomposition.md §7). Established baseline, not new. No obstruction to report here; the interface simply does not reach the root.

### B. Parallel (disjoint-union) interface — the one that *could* reach the root

Since `A_n = 1 ⊔ 1 ⊔ … ⊔ 1`, a sound summary-based composition at this interface would compute `S(n)` bottom-up from block summaries — a genuine compositional recurrence. I tested whether `F(A ⊔ B)` is determined by `σ(A), σ(B)`.

**B1. Block-level `σ`-collisions exist (experiment, n ≤ 5).** Even the *strong* summary does not determine a block's orientation type:

| n | iso classes | strong-σ collision groups | block pairs |
|---|-------------|---------------------------|-------------|
| 3 | 5 | 1 | 1 |
| 4 | 16 | 4 | 6 |
| 5 | 63 | 21 | 46 |

Representative collision (n=3): the V-type poset `(0,0,3)` and its dual Λ-type `(4,4,0)` both have `e=2, F=1, MVM=(0,)` — identical strong summaries — yet are non-isomorphic (duals). Counted over all collision groups: 53 block pairs. This alone shows interface summaries are not injective on blocks.

**B2. Composite values are σ-invariant in the tested range (experiment, n ≤ 6).** I enumerated, for every pair of same-σ block classes (weak and strong, including cross-`n` pairs) and every partner size with total size ≤ 6, both `F(X ⊔ Y)` and `F(X' ⊔ Y')`, allowing *both* blocks to vary. **Zero composite-value differences were found** (0/ all tested combinations, one-block and two-block variants). Concretely: `F(X ⊔ Y)=F(X' ⊔ Y')` whenever `σ_s(X)=σ_s(X')` and `σ_s(Y)=σ_s(Y')`, for all composites up to 6 elements. Thus the strong summary may (conjecturally) suffice for disjoint-union composition at small sizes; **no "same summary, different root optimum" collision was found at composite level up to n=6.** This is an honest negative for the "root optimum differs" version of the falsifier in the tested range.

**B3. Explicit sibling-incompatibility obstruction (experiment + deduction).** The branch-level data shows why a self-dual summary cannot *preserve both sibling branches*, even when composite values agree. Take the V/Λ pair composed with a singleton (4-element composites `X ⊔ 1` and `X^op ⊔ 1`, both `F=3`):

```
X   = V-type : branch (block elem < singleton) F=2, branch (singleton < block elem) F=3, max=3
X^op= Λ-type : branch (block elem < singleton) F=3, branch (singleton < block elem) F=2, max=3
```

The two sibling branches have **mirrored** values `(2,3)` vs `(3,2)`. Because every natural candidate summary (`n, e, F, MVM`, and any function of these) is self-dual, `σ(X)=σ(X^op)`; a recurrence built on such a summary is **orientation-blind**: it cannot tell which branch carries which value. It still computes `max(2,3)=3` correctly at the composite level (explaining B2), but it does not, and cannot, "preserve both sibling branches" as distinct objects — the branch identity is lost in the summary. This is an explicit **sibling-incompatibility obstruction** for any self-dual polynomial interface summary on the parallel interface: the recurrence would conflate the two orientations of a cross-block comparison, which is precisely the information the adversarial root needs in order to evaluate `max(F(P+x<y), F(P+y<x))` branch-wise.

### C. Chain interface — optimal multiway merge is not pairwise composable (experiment)

`F(chain_a ⊔ chain_b ⊔ … ⊔ chain_c)` is the worst-case optimal number of comparisons to merge `c` sorted lists of sizes `a,b,…` (the classical merge problem). A compositional recurrence over chain interfaces would compute this from pairwise merge values `M(a,b)=F(chain_a ⊔ chain_b)`. It does not:

| chains (a,b,c) | F (exact, = info bound) | best pairwise-first merge | gap |
|---|---|---|---|
| (1,2,2) | 5 (=⌈log₂30⌉) | 6 | 1 |
| (2,1,2) | 5 | 6 | 1 |
| (2,2,1) | 5 | 6 | 1 |
| (2,2,2) | 7 (=⌈log₂90⌉) | 8 | 1 |
| (2,2,3) | 8 | 9 | 1 |
| (2,3,2) | 8 | 9 | 1 |
| (3,2,2) | 8 | 9 | 1 |
| (3,3,2) | 10 | 11 | 1 |
| (2,3,3) | 10 | 11 | 1 |

(Values computed by exact memoised minimax DP; `S(1..6)=0,1,3,5,7,10` and poset counts `1,3,19,219,4231,130023` match the established baseline, validating the DP.) The pairwise-first value is `min` over choices of first merged pair of `M(pair)+M(merged, third)`; the exact optimum is strictly smaller. The optimal first comparisons are **cross-chain** (e.g. for (1,2,2) they pair the singleton with an element of a 2-chain) and never commit to completing a merge of two chains before touching the third; the remaining comparison budget is shared across all chains. Hence the two/three sibling branches of the root comparison cannot be isolated into separate sub-recurrences — an explicit **sibling-incompatibility obstruction** for the chain interface. Extensible family: balanced triples with at least two chains of size ≥ 2; the gap persists (and grows for larger balanced inputs, consistent with the classical non-decomposability of optimal multiway merging).

*Note on `M(a,b)`.* `F(chain_a ⊔ chain_b)` is the optimal merge decision-tree value, not the naive `a+b−1` (e.g. `M(1,3)=2=⌈log₂4⌉`, while naive merging gives 3). The obstruction above is against *optimal* pairwise composition, not merely naive merging.

## Interpretation and consequence for the central question

1. **No compositional exact recurrence through the tested interfaces preserves the adversarial root and both sibling branches.** The ordinal-sum interface is exact but never applies at the series-prime antichain root. The parallel (disjoint-union) interface — the only one that could reach the root — admits self-dual interface summaries that are orientation-blind: they conflate the two orientations of a cross-block comparison, losing the branch identity the root needs (B3), even though composite *values* agree (B2). The chain interface's optimal multiway merge is not a function of optimal pairwise merges (C).
2. **The obstruction is sibling-level, not value-level.** This is the sharper form asked for: the values can agree (`F(X⊔1)=F(X^op⊔1)=3`) while the sibling branches differ (`(2,3)` vs `(3,2)`). A recurrence that only tracks composite values would pass the value test but fail to "preserve both sibling branches"; the obstruction names the missing datum (orientation/branch identity of the cross comparison).
3. **A candidate positive direction (unproven).** The strong summary `σ_s=(e,F,MVM)` survived all composite tests up to 6 elements (0 collisions, B2). It is polynomial in size (`e` has `O(n log n)` bits; `F` and each MVM entry `O(log n)` bits, `O(n²)` entries). Whether `F(A ⊔ B)` is in fact a function of `σ_s(A), σ_s(B)` for all sizes is **open**; the branch-level blindness (B3) shows that even if composite values factor through `σ_s`, the recurrence cannot be branch-preserving without additional orientation data. No complexity improvement follows.
4. **No complexity-class claim.** These are structural obstructions on interface families; they do not establish `P`, `NP`, or any bound for `SORT-BOUND-U`. No Lean file, test, or PR was added; only this report.

## Limitations

- Composites tested only up to 6 elements (memoised DP cost). The "same summary, different root optimum" (value-level) version of the falsifier was **not** found at tested sizes; the obstruction supplied is the sibling-incompatibility (branch-level) form, which is the stronger, more structural one and matches the task's "or show an explicit sibling-incompatibility obstruction" alternative.
- The chain family witnesses are exact and info-bound-tight but small; extensibility is argued from the classical non-decomposability of optimal multiway merging, not from a computed infinite family.
- `σ_s`-sufficiency for composite values remains a conjecture, not a theorem.
