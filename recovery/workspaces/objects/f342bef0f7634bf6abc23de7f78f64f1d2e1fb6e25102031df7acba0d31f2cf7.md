# Framed DAG with prefix-determined frames: zero-comparison elimination experiment

Date: 2026-11-21. Worktree base 6a96398. No repository code changed.

## What was built

A checker-accepted framed DAG for n=5 with frames determined solely by the
outcome prefix:

- `/tmp/opencode/opt5.json`: n=5, budget 7 (= S(5)), depth 7,
  nodes = 239.
- Checker: `ACCEPT: n=5, depth=7, nodes=239`.

Construction: an optimal 7-comparison sorting decision tree on fixed slots
(`scripts/generate_optimal_tree.py`, n=5, depth 7) encoded as a framed DAG.
Every edge carries the identity permutation; comparisons are fixed slot pairs,
so no slot move depends on value state. At each node the outgoing comparison
and both frames are fixed by the node's position in the tree, i.e. by the
outcome prefix. This satisfies the prefix-determined frame requirement.

## FJ insertion structure: obstruction

The Ford-Johnson joined rank-envelope insertion stage cannot be encoded as a
polynomial-size framed DAG with prefix-determined frames without removing its
zero-comparison insertions, and those zeros are inherent:

1. Zero-comparison insertions occur for the loser paired with the smallest
   winner (idx=1) whenever that winner remains at the front of the chain.
   This happens in a value-dependent subset of inputs (e.g. 72/120
   permutations for n=5).
2. The original generator handles such a zero by composing a prepend move
   onto the frame of the preceding comparison edge. Whether a given
   comparison edge is the "preceding" (last) comparison of the previous
   insertion, and whether the prepend applies, depends on whether that
   insertion's binary search terminated at that node. That termination
   depends on value state, not only on the outcome prefix. Hence the same
   node (e.g. compare slots (4,2)) needs perm_lt = [0,1,3,4,2] in one
   value context and [1,2,4,0,3] in another; no single frame sorts both.
3. Exact bookkeeping reason: the frame on a shared edge would have to encode
   both "insert the current loser at its binary-search position" and,
   conditionally, "prepend the next loser whose paired winner is still at
   the front". The second move's source slot is the next loser's slot,
   which is fixed, but whether the move applies is a function of earlier
   insertion outcomes that is not determined by the single comparison's own
   outcome. A fixed permutation on that edge cannot be both the plain
   insertion frame and the insertion-plus-prepend frame.

Restructurings tried:

- Reordering insertions (idx=1 first): makes idx=1 always zero and foldable
  into compaction, but shifts subsequent winners and raises their comparison
  counts; not verified to stay within S(n) for all n.
- Absorbing zeros into compaction with a uniform frame: only valid when the
  zero condition holds for all inputs, which it does not.
- Splitting shared nodes on frame conflict: resolves correctness but forces
  duplication of every ancestor, i.e. exponential blowup (n! paths); not
  polynomial.

## Claims (labels)

- n=5 prefix-determined framed DAG, depth 7, 239 nodes: experiment
  (checker-accepted).
- FJ zero-comparison insertions force value-dependent frames on shared edges:
  experiment (checker-rejected original) + deduction (bookkeeping above).
- Polynomial-size generalization via FJ insertion is obstructed by inherent
  zeros: conjecture (supported by n=5 obstruction).
- Fixed-slot optimal tree construction generalizes to any n for which an
  optimal comparison tree is available: deduction (frames identity, prefix-
  determined by construction).
