# Framed DAG witness for n=7 (S(7)=13) — execution report

## 1. Problem statement and S(7) baseline

**Task/front.** `framed-dag-witness-n7-exact` (falsifiable, independent): does there exist an explicit, checkable permutation-framed strategy DAG certificate of exact height `S(7)=13` for `n=7`, and what is its concrete size/depth/profile compared to polynomial envelopes (e.g. `O(n^2)` nodes, `O(n log n)` path length)?

**Model (per checker/docs).** A certificate is an acyclic directed graph with root 0 and topologically forward edges. Each internal node gives a comparison `[a,b]` on *current slot indices* and two outgoing arcs `lt` (`a<b`) / `gt` (`b<a`), each with `next` and a permutation `perm` mapping old slot indices to new slot indices. The verifier propagates guaranteed strict partial orders, takes transitive closure, applies edge permutations, and at joins intersects incoming guaranteed relations (soundness only where branches agree). Leaves must guarantee a total order. Longest reachable path depth must be ≤ `budget`. See `scripts/check_framed_strategy.py` and `docs/research-framed-certificate-frontier.md`.

**`S(7)` baseline.** `docs/problem.md` and `docs/research-framed-certificate-frontier.md` context record the literature value `S(7)=13` (known in the sorting-number literature, e.g. Stober & Weiß ALENEX 2023 cited in repo docs). This report does **not** claim a new proof of `S(7)=13`; it treats 13 as the target exact height/budget for a witness.

## 3. Concrete results / witness or obstruction

### 3.1 Verified framed witness (n=6, exact height)

- **File:** `framed_n6_witness_tree.json` (explicit framed certificate, tree/DAG form, identity slot permutations).
- **Checker result:** `ACCEPT: n=6, depth=10, nodes=1439` (matches `S(6)=10`).
- **Structural measurements:** `n=6`, `budget/depth=10`, `nodes=1439` (total nodes = internal comparison nodes + leaves), no merge/join nodes (tree). Depth equals known exact optimum for n=6.
- **Comparison to envelopes:** for this explicit tree certificate, node count is far below the worst-case `2^(h+1)-1` bound but far above `O(n^2)`; path length is 10 (≈ `n log2 n` scale). This is a *tree* witness, not a shared/joined framed DAG, so it does not address polynomial-size sharing.

### 3.2 n=7 attempt (target height 13)

- **Target:** explicit, checkable framed strategy DAG certificate at exact height `S(7)=13`.
- **Outcome:** **not produced/verified in this run.** Labelled poset minimax DP + full optimal-policy tree materialization (`/tmp/gen_n7_framed.py 7`) did not complete within 120s wall-clock in this environment; no witness JSON was emitted. Details recorded in `framed_n7_attempt.log`.
- **Evidence/obstruction (computational, concrete):**
  - Full labelled exact minimax state space for n=7 is large (repo/docs note ~6,129,859 labelled poset states for n=7 in related DP contexts; e.g. `docs/research-compression-next.md`, `docs/research-state-compression.md` mention 6.1M states / 2045 isomorphism classes). Policy extraction that materializes an explicit height-13 decision tree requires exploring optimal branches over reachable states and emitting the whole certificate.
  - Growth from verified tree witnesses: n=5→239 nodes, n=6→1439 nodes at exact heights (7,10). A height-13 binary decision tree for n=7 is plausibly on the order of ~10^4 nodes (well within file/checker size in principle) but generating it via naive labelled DP/memoization in pure Python exceeded the attempted budget here.
  - This is an **engineering/computational obstruction for this construction route**, not a mathematical proof that no framed DAG witness of height 13 exists. Existence of *some* optimal comparison strategy of height 13 is consistent with the literature value `S(7)=13`; encoding it as a framed certificate remains to be done.

### 3.3 Baseline non-optimal framed certificate

- `check_framed_strategy.py --bubble 7` → `ACCEPT: n=7, depth=21, nodes=22` (identity/simple swap frames; demonstrates format and soundness, not optimality).
