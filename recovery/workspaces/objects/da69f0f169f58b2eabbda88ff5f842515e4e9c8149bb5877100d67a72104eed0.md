# Exec report: non-path-storing exact evaluator space (SoringP1 #301, billy-dev)

**Front:** non-path-storing exact evaluator space.  
**Question (all `n`, falsifiable):** Can exact evaluation of `S(n)` / decision of `SORT-BOUND-U` be done by any uniform deterministic algorithm in `o(n log^2 n)` bits of work space on unary/binary input, possibly at higher but sub-`2^{O(n^2)}` time, without storing an explicit comparison path/DFS transcript?  
**Outcome:** **not claimed.** No `o(n log^2 n)`-space non-path-storing uniform deterministic exact evaluator is constructed. A concrete obstruction is given for a well-defined *path-transcript backtracking* class (the natural generalization of budgeted DFS beyond storing the explicit comparison transcript); broader classes remain open.

## 1. Model, workspace, and scope

- **Problem/model.** `S(n)` is the minimax height of a deterministic adaptive comparison decision tree sorting `n` distinct labelled keys. `SORT-BOUND-U = {1^n # 1^k : S(n) <= k}` has unary input length `N = n+k+1`; `SORT-BOUND-B = {bin(n)#bin(k): S(n)<=k}` has binary input length `Θ(log n + log k)` on informative instances (`k <= U(n)=O(n log n)`). `CanSort(P,d)` / `G(n,d)` is the exact sorter/adversary game: `S(n)<=k` iff sorter wins from the empty poset with budget `k` (docs/problem.md, docs/research-certificates-barriers.md §0, docs/research-budgeted-dfs.md §1,3). [definition]
- **Workspace counted.** Standard deterministic Turing-machine work space: bits on read/write work tapes, excluding the read-only input tape and write-only output. The `O((d+n)log(n+2))` accounting of docs/research-budgeted-dfs.md §5.2 counts the transcript/stack, counters/cursor, and one reachability workspace (visited bits + queue/stack of labels) but not the input. For decision with the supplied budget, `d=k`; for computing `S_unary(1^n)` by `O(log n)` threshold calls, `d = Θ(U(n)) = Θ(n log n)` on the hardest calls, so `O((d+n)log n)=O(n log^2 n)`. [definition/deduction from cited note]
- **“Explicit comparison path/DFS transcript”.** Any stored representation from which the current branch history is recoverable as a sequence of chosen comparison pairs and/or adversary outcomes along the root-to-current path (e.g. the transcript `σ=((a_1,b_1),..., (a_t,b_t))` in §5.2, a call stack storing one comparison+cursor per frame, or an equivalent replay log). An algorithm is *non-path-storing* here if it does not keep such an explicit path/transcript; it may still keep the current induced poset/state, counters, or other summaries if explicitly accounted. [definition, for this front]
- **Target.** Uniform deterministic, exact for all `n` (and all relevant `k`), work space `o(n log^2 n)` bits, time sub-`2^{O(n^2)}` in numeric `n` (allowed to exceed `2^{O(n log^2 n)}`), no explicit comparison path/DFS transcript. [definition]

## 3. Non-path-storing construction attempts (and why none closes here)

### 3.1 Recompute poset from root without a transcript
- **Idea.** Avoid storing `σ`; regenerate the current `P(σ)` by replaying comparisons from the empty order.
- **Analysis.** [deduction] Deterministic replay requires the very sequence being replayed (the transcript/path) or an equivalent index into it; discarding it loses the information needed to reconstruct which of the up to `(2B)^d` branches is current. Canonical re-exploration of the AND-OR game still needs control state identifying the current node/return points. Therefore “recompute instead of store transcript” is not by itself a space-saving algorithm; it is circular unless combined with a smaller control representation (see §3.3, §4).
- **Falsifier condition.** Exhibit a uniform exact evaluator that, on every branch, reconstructs the current induced game state and all pending backtrack decisions using only `o(d log n)` bits of branch/control information while preserving correctness for all `n,k`.

### 3.2 Store current state explicitly (matrix/DAG), not path
- **Idea.** Keep `P` as an `n×n` transitive-closure bitmatrix (or another explicit current-state representation) and backtrack by mutation/undo.
- **Analysis.** [deduction] A labelled strict partial order is an arbitrary transitive acyclic digraph up to the model constraints; representing a general current state explicitly needs `Ω(n^2)` bits in the worst case without a proved compression scheme (matrix is `Θ(n^2)`; edge/list forms are no better in worst case). Undo/backtracking additionally needs history unless state is copied, so this is `Ω(n^2)` space, far above `o(n log^2 n)`. The winning-frontier barrier gives `2^{(1/4-o(1))n log^2 n}` nonisomorphic winning states at some depth (including at budget `S(n)` asymptotically), ruling out full-frontier enumeration but also indicating no known small explicit canonical state set (docs/research-winning-frontier-barrier.md). [deduction/literature-in-repo]
- **Falsifier condition.** A provably correct representation of every reachable/winning-relevant state in `o(n log^2 n)` bits total, with update/backtrack in that space and sub-`2^{O(n^2)}` time.

### 3.3 Checkpointing / tree-pebbling / recomputation time-space tradeoffs
- **Idea.** Do not keep the full depth-`d` transcript; keep checkpoints and recompute segments (generic tree/pebbling tradeoff intuition).
- **Analysis.** [deduction, partial] This is the most plausible generic route, but it does **not** yield the requested bound from known ingredients:
  - The evaluated object is an *implicit* minimax AND-OR game, not a static explicitly given tree: children/branching depend on the chosen incomparable pair policy and on poset state. Standard pebbling lower/upper bounds for fixed trees do not transfer without a model-specific reduction.
  - A checkpoint that allows resuming without the path must encode enough information to identify the node: either (a) the transcript prefix itself (size `Θ(t log n)`), (b) the induced poset/state (`Ω(n^2)` worst-case unless compressed), or (c) some other canonical index. Balancing checkpoint size against recomputation can trade time for space, but no schedule was found that makes *all* of control+state `o(n log^2 n)` while keeping time sub-`2^{O(n^2)}` for all `n`.
  - Any such scheme must still solve the AND-OR evaluation: for a sorter-chosen pair it must verify both adversary outcomes unless short-circuited, so recomputation can multiply work; remaining sub-`2^{O(n^2)}` is plausible only with a careful bound but unproved here.
- **Falsifier condition.** Give an explicit checkpoint/recomputation (or pebbling) schedule for `CanSort` with proved invariants: (i) exactness for all `n,k`, (ii) peak work space `o(n log^2 n)` bits including all checkpoints/control/state, (iii) deterministic time `2^{o(n^2)}` (or at least `< 2^{c n^2}` for every fixed `c>0` eventually, as required) and a concrete accounting.

### 3.4 Implicit state enumeration / algebraic or counting ideas / catalytic-style space
- **Idea.** Enumerate or count states/winning positions implicitly (order-theoretic recurrences, algebraic combinators, catalytic restoration) without storing the explored path.
- **Analysis.** [deduction/open] No bridge found from known algebraic/counting objects to exact minimax `S(n)`. `e(P)` (linear extensions) is #P-complete in general and does not determine `F(P)=S(P)` (docs/research-hardness-boundaries.md §5, docs/research-plan.md barrier table), so counting extensions cannot replace path/state evaluation. Catalytic or reversible simulation techniques can reduce clean space in some models but require a reversibly accessible catalytic memory/state encoding and a correctness-preserving reversible simulation of the comparison game; no such encoding with total clean work space `o(n log^2 n)` is known for this problem. These remain speculative without a concrete all-`n` construction.
- **Falsifier condition.** A uniform exact algorithm using one of these paradigms with a full space/time proof and an explicit statement of what auxiliary/catalytic memory (if any) is counted as workspace.

## 4. Obstruction for a well-defined class (beyond path-storing DFS, but limited)

**Class `C_path` (path-addressed backtracking evaluators).** Uniform deterministic algorithms that decide `CanSort(∅,k)`/compute `S(n)` by exact backtracking evaluation of the game tree and that, at every point where control may return to a previously visited internal game node, can recover that node’s pending alternatives only from stored branch-control information proportional to a root-to-node address in the move/adversary-outcome tree (a comparison path/transcript, frame stack, trail, or equivalent index string), rather than from a recomputed global canonical name of the game state.

- **Claim (obstruction within `C_path`).** [deduction, information-theoretic/control-state lower bound for this class] On instances with required search depth `d` and at least two legal continuations per relevant step (the regime of budgeted DFS analysis, with up to `B=Θ(n^2)` pair choices and 2 adversary outcomes), distinguishing the current backtrack context among `2^{Ω(d log n)}` possible prefixes requires `Ω(d log n)` bits of branch-control information on some execution. For exact evaluation at budgets `d >= S(n)=Ω(n log n)` (by the information lower bound on sorting), this is `Ω(n log^2 n)` bits, so **no algorithm in `C_path` achieves `o(n log^2 n)` work space** on all `n`.
- **Scope note.** This is **not** a general space lower bound for all exact evaluators of `S(n)`: it excludes only algorithms whose resumption capability is fundamentally path-addressed. It does not rule out a non-`C_path` method that represents/resumes states by a smaller canonical invariant, by implicit enumeration, or by a yet-unknown succinct game-state compression—*if* such a representation exists and supports exact backtracking in the stated time/space.
- **Falsifier condition (for this obstruction’s practical relevance).** Produce an exact uniform deterministic evaluator outside `C_path` with proved `o(n log^2 n)` workspace and sub-`2^{O(n^2)}` time, or show that every exact evaluator is equivalent (up to constant-factor space) to a `C_path` evaluator for this game.

## 5. Falsifiable consequences and checks

- A positive result would need, at minimum: (a) a precise definition of what replaces the path/transcript, (b) a proof that current state and all pending minimax obligations are recoverable, (c) peak-space accounting in bits including reachability/control, and (d) a time bound `< 2^{c n^2}` for large `n` (sub-`2^{O(n^2)}` in the usual asymptotic sense). [deduction]
- A general negative result (beyond `C_path`) would need to rule out all canonical-state, checkpoint, catalytic, or algebraic representations for exact `S(n)` evaluation under the stated workspace model—much stronger than available evidence. [not claimed]

## 6. Open obstacles

1. **Succinct resumable game state:** Is there a canonical encoding of a reachable `CanSort` node (poset + remaining obligation/choice context) in `o(n log^2 n)` bits supporting exact adversarial backtracking? State count alone (winning-frontier barrier) does not answer this. [open]
2. **Checkpoint/pebbling for implicit AND-OR comparison games:** Formalize and optimize time-space tradeoffs for `CanSort`; determine whether any schedule beats `Θ(n log^2 n)` space under sub-`2^{O(n^2)}` time. [open]
3. **Certificate/implicit-evaluation bridge:** Can a succinct proof/certificate object (cf. framed-certificate frontier, NP/coNP questions) be turned into a low-space uniform evaluator, or vice versa, without reintroducing a path transcript? [open/conjectural direction, not established]
4. **Stronger lower bounds:** Prove (or refute) an unconditional `Ω(n log^2 n)` workspace lower bound for all uniform deterministic exact evaluators in a standard TM model, or identify a weaker but nontrivial barrier class strictly larger than `C_path`. [open]
