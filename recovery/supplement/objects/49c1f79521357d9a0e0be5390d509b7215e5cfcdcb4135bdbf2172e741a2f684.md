# Correction and Conditional Analysis: Reductions to Unary SORT-BOUND-U

**Status:** research note (correction + conditional analysis). Not Lean-checked.
Every item labelled `[literature]`, `[deduction]`, `[experiment]`, `[conjecture]` or `[open]`.

This note **retracts** the false unconditional no-go claim in the prior report
("pigeonhole counting proves NO polynomial-time many-one reduction to unary
SORT-BOUND-U") and replaces it with the correct conditional analysis.

---

## 0. Retraction of the false claim

`[deduction]` **Retracted claim.** The prior report argued: "The number of
distinct posets on m elements is 2^{Θ(m²)}, while S(n) for n ≤ poly(m) takes
only poly(m) values; hence by pigeonhole no polynomial-time many-one reduction
from POSORT to SORT-BOUND-U can exist."

This is **false**. Many-to-one reductions need not be injective. The pigeonhole
principle does not apply to reduction *functions* (which may map many inputs
to the same output), only to reduction *images* under additional structure.

`[deduction]` **Trivial reduction (corrected).** Let `L` be any language in `P`
and `S` any nontrivial sparse language (e.g. `SORT-BOUND-U`). A polynomial-time
many-one reduction `f: L → S` exists: on input `x`, decide `x ∈ L` in
polynomial time, output fixed `yES ∈ S` if yes, fixed `NO ∉ S` if no. This is
a valid poly-time many-one reduction. Hence reductions to sparse languages
exist unconditionally for languages in `P`.

`[literature]` **Correct statement (Mahaney 1982).** If a sparse set is NP-hard
under polynomial-time many-one reductions, then `P = NP`. Equivalently: if
`P ≠ NP`, then no sparse set is NP-hard under poly-time many-one reductions.
This is a **conditional** barrier keyed on NP-hardness of the source, not an
unconditional impossibility.

## 1. Precise definition: generalized poset sorting threshold (unary)

`[definition]` **POSORT-U.** Input is a poset `P` on `n` elements encoded as a
list of comparable pairs `(i,j)` with `i < j`, where each `i, j` is written in
unary, together with `k` in unary. Question: is `S(P) ≤ k`?

- Input length: `L = Θ(n² + k)` in unary (dense posets have `Θ(n²)` pairs).
- `S(P)` = minimum height of a comparison tree sorting all linear extensions
  of `P`.
- For the antichain `A_n`, `S(A_n) = S(n)` (the sorting number).

`[definition]` **SORT-BOUND-U.** `{ 1^n # 1^k : S(n) ≤ k }`, both parameters
unary. Input length `m = n + k + 1`.

---

## 2. Conditional consequences of a poly-time uniform reduction POSORT-U ≤ SORT-BOUND-U

`[deduction]` **Theorem 2.1 (necessary condition: P/poly).** If
`POSORT-U ≤_m^p SORT-BOUND-U` via a polynomial-time uniform reduction, then
`POSORT-U ∈ P/poly`.

*Proof.* `SORT-BOUND-U ∈ P/poly` (Lemma 3.2, `research-encoding-consequences.md`:
every sparse language is in `P/poly`). `P/poly` is closed under polynomial-time
many-one reductions: compose the reduction with the advice for `SORT-BOUND-U`.
∎

`[deduction]` **Theorem 2.2 (conditional collapse).** If `POSORT-U ≤_m^p
SORT-BOUND-U` and `POSORT-U` is NP-hard, then `P = NP`.

*Proof.* By Theorem 2.1, `SORT-BOUND-U` is NP-hard. By Mahaney (1982), a sparse
NP-hard set implies `P = NP`. ∎

`[deduction]` **Theorem 2.3 (PH collapse under Turing reduction).** If
`POSORT-U ≤_T^p SORT-BOUND-U` (polynomial-time Turing reduction) and
`POSORT-U` is NP-hard, then `PH = Σ₂P`.

*Proof.* By Karp–Lipton (1980), if `SAT` is polynomial-time Turing reducible to
a sparse set, then `PH = Σ₂P`. ∎

`[deduction]` **Corollary 2.4 (what the reduction does NOT imply).** The
reduction does **not** imply:
- `SORT-BOUND-U ∈ NP` or `∉ NP`;
- `SORT-BOUND-U ∈ P` or `∉ P`;
- any unconditional separation.

It gives only the conditional consequences above.

## 3. Restricted-encoding reductions that survive Mahaney

`[deduction]` **Theorem 3.1 (survival criterion).** A polynomial-time
reduction from a restricted poset sorting problem `POSORT-R` to `SORT-BOUND-U`
**survives Mahaney's barrier** iff `POSORT-R` is **not NP-hard** under
polynomial-time many-one reductions.

*Proof.* (⇒) If `POSORT-R` is NP-hard and reduces to sparse `SORT-BOUND-U`,
then `SORT-BOUND-U` is NP-hard, so `P = NP` by Mahaney. Hence if `P ≠ NP`,
no such reduction exists. (⇐) If `POSORT-R` is not NP-hard, Mahaney's theorem
is vacuous: it says nothing about reductions from non-NP-hard sources. ∎

`[deduction]` **Corollary 3.2 (trivial survival).** If `POSORT-R ∈ P`, a
reduction exists unconditionally (compute the answer, output fixed YES/NO
strings). This reduction is correct but **uninformative**: it does not relate
the complexity of `POSORT-R` to `SORT-BOUND-U`.

`[deduction]` **Theorem 3.3 (non-trivial survival).** A **non-trivial**
reduction from `POSORT-R` to `SORT-BOUND-U` (one that does not simply decide
`POSORT-R` first) survives Mahaney iff `POSORT-R` is not NP-hard.

*Proof.* If `POSORT-R` is NP-hard, Mahaney blocks the reduction unless
`P = NP`. If `POSORT-R` is not NP-hard, Mahaney does not apply. The reduction
may still be blocked by other considerations (e.g. `POSORT-R ∉ P/poly`), but
not by Mahaney. ∎

`[open]` **Question.** Is there a **non-trivial** restricted poset class `R`
such that `POSORT-R` is provably not NP-hard but a reduction to `SORT-BOUND-U`
exists and is not of the trivial "decide-then-map" form?

## 4. Exact conditions and falsification

### 4.1 Exact conditions for a reduction to exist

`[deduction]` **Theorem 4.1 (necessary and sufficient).** A polynomial-time
uniform many-one reduction `POSORT-U → SORT-BOUND-U` exists **iff**
`POSORT-U ∈ P/poly`.

*Proof.* (⇒) Theorem 2.1. (⇐) If `POSORT-U ∈ P/poly`, then since
`SORT-BOUND-U ∈ P/poly` and `P/poly` is closed under composition with
polynomial-time reductions... wait, this direction requires a reduction FROM
`POSORT-U` TO `SORT-BOUND-U`, not the converse. The correct statement is:

**Theorem 4.1 (corrected).** A polynomial-time uniform many-one reduction
`POSORT-U → SORT-BOUND-U` exists only if `POSORT-U ∈ P/poly`. The converse
does **not** hold: `POSORT-U ∈ P/poly` does not imply a reduction to
`SORT-BOUND-U` (membership in `P/poly` is not sufficient for reducibility to a
specific sparse language).

*Proof of forward direction.* Theorem 2.1. ∎

`[deduction]` **Remark 4.2.** The exact condition `POSORT-U ∈ P/poly` is
**necessary but not sufficient**. The reduction must map each poset instance
`⟨P⟩#1^k` to a specific pair `(n', k')` such that `S(P) ≤ k ⟺ S(n') ≤ k'`.
This is a **semantic** requirement, not just a complexity requirement.

### 4.2 Falsification criteria

`[deduction]` **Falsification 4.3.** A reduction `POSORT-U → SORT-BOUND-U` does
not exist if any of the following holds:
1. `POSORT-U ∉ P/poly` (necessary condition fails);
2. `POSORT-U` is NP-hard and `P ≠ NP` (Mahaney barrier);
3. There exist posets `P₁, P₂` with `S(P₁) ≠ S(P₂)` but any valid reduction
   must map them to the same `(n', k')` with `S(n') ≤ k'` giving the same
   answer for both — i.e. no semantic encoding of poset structure into
   `(n', k')` preserves the predicate.

`[experiment]` **Falsification 4.4 (witness for condition 3).** Two 5-element
posets with `e(P₁) = e(P₂) = 8` but `S(P₁) = 3 ≠ 4 = S(P₂)`:
- `P₁`: relations `0<3, 1<2, 1<3, 2<3, 4<2, 4<3`
- `P₂`: relations `0<1, 0<3, 0<4, 2<1, 2<3, 4<3`

Hence `S(P)` is not determined by `e(P)`. Any reduction computing `e(P)` and
applying a function of it **fails**. (This falsifies the `#P`-counting route,
not all reductions.)

## 6. Binary encoding (out of scope)

`[deduction]` `SORT-BOUND-B = {bin(n) # bin(k) : S(n) ≤ k}` is **not sparse**
(Theorem 4.6, `research-encoding-consequences.md`), so Mahaney's barrier does
**not** apply. This note does not analyze the binary encoding.

## 7. Next question

The corrected analysis shows the reduction question is **conditional on the
complexity of POSORT-U**, which is open. The most informative next step is to
determine whether `POSORT-U` is in `P`, in `NP`, or harder. This is itself
open. A concrete experiment: for small `n`, compute `S(P)` for all posets `P`
on `n` elements and check whether the values `S(P)` are determined by
`e(P)` (falsified at `n=5`), by `|P|` alone (falsified: chain vs antichain),
or by any simple invariant. If no simple invariant determines `S(P)`, this
is evidence that `POSORT-U` is genuinely harder than counting linear
extensions.
