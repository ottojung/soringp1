# Disproof of the naive "small gap implies P" argument for SORT-BOUND-U

**Status:** research note (paper analysis). **Not Lean-checked.**
Every item is labelled `[definition]`, `[literature]`, `[deduction]`,
`[conjecture]` or `[open]`. Unary encoding only.

---

## 0. The naive argument and its precise statement `[definition]`

The naive reasoning to be disproved:

> **Naive Claim.** The gap between the best computable upper and lower bounds
> for `S(n)` is `U(n) − I(n) = Θ(n)`. Therefore binary search over the `O(n)`
> candidate values needs only `O(log n)` threshold queries of the form
> "is `S(n) ≤ k`?". Each such query is a single decision problem solvable in
> polynomial time. Hence `SORT-BOUND-U ∈ P`.

The argument has three implicit premises:
1. **P1 (small gap):** `U(n) − I(n) = O(n)`, so there are `O(n)` candidate values.
2. **P2 (few queries):** Binary search over `O(n)` values needs `O(log n)` queries.
3. **P3 (cheap queries):** Each threshold query "is `S(n) ≤ k`?" is solvable in
   polynomial time.

The conclusion is: `O(log n)` queries × poly-time each = poly-time total, so
`SORT-BOUND-U ∈ P`.

---

## 1. The central disproof: P3 is the original problem `[deduction]`

**Theorem 1.1 (P3 is false as stated).** The threshold query "is `S(n) ≤ k`?"
is not known to be in `P`. It is *exactly* the decision problem
`SORT-BOUND-U = {1^n # 1^k : S(n) ≤ k}`, whose membership in `P` is the open
question. The naive argument assumes P3 as a premise, but P3 is the conclusion.

*Proof.* By definition, `SORT-BOUND-U` is the language of all pairs `(n, k)`
such that `S(n) ≤ k`. A polynomial-time algorithm for the threshold query is
precisely a polynomial-time algorithm for `SORT-BOUND-U`. The naive argument
therefore assumes `SORT-BOUND-U ∈ P` in order to prove `SORT-BOUND-U ∈ P`. ∎

**Theorem 1.2 (circularity).** The naive argument is logically circular: it
assumes the conclusion as premise P3.

*Proof.* Let `A` be the statement "`SORT-BOUND-U ∈ P`". The naive argument has
the form: "P1 ∧ P2 ∧ P3 ⟹ A", where P3 is itself `A`. The argument is therefore
"A ⟹ A", which is vacuous. ∎

**Theorem 1.3 (what binary search actually shows).** Binary search establishes
a *Turing reduction* from the function problem `S_unary` to the decision problem
`SORT-BOUND-U`:

```
S_unary ≤_T^p SORT-BOUND-U
```

via `O(log n)` adaptive queries. This is a *reduction*, not a complexity upper
bound. It shows that if `SORT-BOUND-U ∈ P` then `S_unary ∈ FP`, but it does not
show either membership.

*Proof.* Given an oracle for `SORT-BOUND-U`, compute `S(n)` by binary search
over `k ∈ [I(n), U(n)]` (width `Θ(n)`, so `O(log n)` queries). Each query is
one oracle call. The reduction is adaptive (each query depends on previous
answers) and polynomial-time (the search itself is `O(log n)` steps). ∎

**Remark 1.4 (equivalence, not membership).** The converse reduction also holds:
given `S(n)`, answer `S(n) ≤ k` in `O(1)` time. Hence:

```
SORT-BOUND-U ∈ P  ⟺  S_unary ∈ FP
```

This is an *equivalence* between two open problems. It does not place either in
`P` or `FP`. The binary search argument establishes the forward direction of
this equivalence; it does not establish membership.

## 2. What would make the argument work `[deduction]`

**Theorem 2.1 (sufficient condition).** The naive argument would be valid if
there existed a polynomial-time algorithm for the threshold query "is `S(n) ≤ k`?"
for *any* `k`. But this is precisely `SORT-BOUND-U ∈ P`, the original problem.

*Proof.* A polynomial-time algorithm for "is `S(n) ≤ k`?" for any `k` is a
polynomial-time decider for `SORT-BOUND-U`. ∎

**Theorem 2.2 (no shortcut via gap size).** The small gap `U(n) − I(n) = Θ(n)`
does not provide a polynomial-time algorithm for the threshold query. The gap
bounds the *number* of candidate values, not the *cost* of deciding each one.

*Proof.* The gap `U(n) − I(n) = Θ(n)` follows from `log₂ n! = n log₂ n − Θ(n)`
and `U(n) = n⌈log₂ n⌉`. This is a statement about the *range* of `S(n)`, not
about the complexity of deciding `S(n) ≤ k`. The decision problem requires
determining whether a comparison tree of height `k` exists, which is a
minimax game over posets — a problem whose complexity is independent of the
width of the search window. ∎

**Remark 2.3 (the gap is not even known to be small).** The gap `U(n) − I(n)`
is the gap between *computable bounds*, not the gap between `S(n)` and `I(n)`.
The actual gap `S(n) − I(n)` is `0` for `n ≤ 11` and `1` at `n = 12`, and is
unknown for `n ≥ 23`. Even if `S(n) − I(n) = O(1)` were proven, the binary
search would still need `O(log n)` queries over the window `[I(n), U(n)]`
unless the upper bound were also improved.

## 3. Does the small gap give *any* advantage? `[deduction]`

**Theorem 3.1 (query count reduction only).** The small gap reduces the
*number* of threshold queries from `O(n log n)` (linear scan) to `O(log n)`
(binary search), but does not reduce the *cost* of each query.

*Proof.* Linear scan over `[0, U(n)]` makes `O(U(n)) = O(n log n)` queries.
Binary search makes `O(log(U(n) − I(n))) = O(log n)` queries. The per-query
cost is unchanged: each is a full `SORT-BOUND-U` decision. ∎

**Theorem 3.2 (no asymptotic advantage).** If each threshold query requires
time `T(n)`, then binary search requires total time `O(log n) · T(n)`. The
logarithmic factor does not change the asymptotic class:
- If `T(n) = poly(n)`, total is `poly(n)` — but this requires P3, which is open.
- If `T(n) = 2^{O(n)}`, total is `2^{O(n)}` — the log factor is absorbed.
- If `T(n) = 2^{O(n log² n)}` (the best known bound), total is `2^{O(n log² n)}`.

*Proof.* `O(log n) · 2^{O(n)} = 2^{O(n) + O(log n)} = 2^{O(n)}`. More generally,
for any `T(n) = 2^{Ω(n)}`, the factor `O(log n)` is absorbed. ∎

**Remark 3.3 (the gap does not help with the hard part).** The hard part of
computing `S(n)` is not the *number* of candidate values but the *decision*
for each candidate. The small gap means there are fewer candidates, but each
candidate is still as hard as the original problem. This is analogous to
reducing a search problem with `O(n)` solutions to one with `O(log n)` solutions
via binary search — the reduction is useful only if each solution can be
*verified* efficiently, which is exactly what is not known here.

## 4. Exponential per-query cost dominates `[deduction]`

**Theorem 4.1 (exponential queries defeat binary search).** Suppose each
threshold query "is `S(n) ≤ k`?" requires time `2^{Ω(n)}` (which is consistent
with the best known upper bound `2^{O(n log² n)}`). Then `O(log n)` queries
require total time `2^{Ω(n)}`, which is exponential.

*Proof.* Let `T(n) = 2^{cn}` for some `c > 0`. Then `O(log n) · T(n) =
O(log n) · 2^{cn} = 2^{cn + O(log n)} = 2^{Ω(n)}`. ∎

**Theorem 4.2 (formal statement).** For any algorithm `A` that decides
`SORT-BOUND-U` in time `T(n, k)`, the binary-search algorithm for `S_unary`
runs in time `O(log n) · max_{k} T(n, k)`. If `T(n, k) = 2^{Ω(n)}` for some
`k` in the search window, the total is `2^{Ω(n)}`.

*Proof.* Direct from Theorem 3.2. ∎

**Remark 4.3 (the best known per-query bound).** The budgeted DFS of
`docs/research-budgeted-dfs.md` decides `S(n) ≤ k` in time `2^{O(n log² n)}`
and space `O(n log² n)` bits. The memoized DP of `docs/upper-bound.md` runs
in time `2^{O(n²)}`. Both are exponential in `n`. The binary search over
`O(log n)` values therefore yields total time `2^{O(n log² n)}` or `2^{O(n²)}`
respectively — both exponential, neither polynomial.

## 5. Does the small gap help with approximation? `[deduction]`

**Theorem 5.1 (approximation narrows the window, not the query cost).**
Suppose there exists a polynomial-time algorithm `Approx` that computes a
value `Ŝ(n)` with `|Ŝ(n) − S(n)| ≤ g(n)` for some gap function `g(n)`. Then
binary search over the window `[Ŝ(n) − g(n), Ŝ(n) + g(n)]` needs
`O(log(2g(n) + 1))` exact threshold queries. The total time is
`O(log g(n)) · T_exact(n)`, where `T_exact(n)` is the cost of one exact query.

*Proof.* The approximation narrows the search window to `2g(n) + 1` values.
Binary search over this window needs `O(log(2g(n) + 1))` queries. ∎

**Corollary 5.2 (PTAS does not suffice).** Even if `g(n) = O(1)` (a
polynomial-time approximation scheme with additive error `O(1)`), the binary
search needs `O(1)` exact queries, each of which is the full `SORT-BOUND-U`
problem. The total is `O(1) · T_exact(n) = T_exact(n)`, which is exponential
if `T_exact(n)` is exponential.

*Proof.* Direct from Theorem 5.1 with `g(n) = O(1)`. ∎

**Corollary 5.3 (approximation + exact query = exact algorithm).** If there
exists both (a) a poly-time approximation with additive error `g(n)` and
(b) a poly-time exact threshold query, then `S_unary ∈ FP`. But (b) is
`SORT-BOUND-U ∈ P`, the original problem.

*Proof.* Binary search over the `O(g(n))`-wide window needs `O(log g(n))`
exact queries, each poly-time, so total is poly-time. ∎

**Remark 5.4 (the gap does not substitute for exact decision).** The small
gap `U(n) − I(n) = Θ(n)` is a statement about *computable bounds*, not about
*approximability*. It does not imply the existence of a poly-time approximation
algorithm. Even if such an approximation existed, it would not reduce the cost
of the exact threshold queries needed to pinpoint `S(n)`.

**Remark 5.5 (approximation of S(n) is itself hard).** Approximating `S(n)`
within any constant factor requires distinguishing `S(n) = k` from
`S(n) > k`, which is the exact decision problem. The information lower bound
`⌈log₂ n!⌉` is computable in poly-time (it is a closed-form expression), but
it is not tight (`S(12) = 30 > 29 = ⌈log₂ 12!⌉`), so it does not approximate
`S(n)` within `o(n)`.

## 6. Unary encoding analysis `[deduction]`

**Theorem 6.1 (unary input length).** For `SORT-BOUND-U`, the input is
`1^n # 1^k` with length `N = n + k + 1`. For informative instances
(`k = Θ(n log n)`), `N = Θ(n log n)`.

*Proof.* Direct from the definition. ∎

**Theorem 6.2 (gap in terms of N).** The gap `U(n) − I(n) = Θ(n) = O(N)`,
since `n ≤ N`. Binary search over the gap needs `O(log N) = O(log n)` queries.

*Proof.* `U(n) − I(n) = Θ(n)` and `n ≤ N`, so `U(n) − I(n) = O(N)`. Binary
search over `O(N)` values needs `O(log N)` queries. ∎

**Theorem 6.3 (per-query cost in unary).** Each threshold query "is `S(n) ≤ k`?"
takes time `2^{O(n log² n)}` (budgeted DFS) or `2^{O(n²)}` (memoized DP),
which is `2^{O(N log² N)}` or `2^{O(N²)}` in terms of the unary input length
`N`. Both are exponential in `N`.

*Proof.* For informative instances, `n = Θ(N / log N)` (since `N = Θ(n log n)`).
Then `n log² n = Θ(N log N)` and `n² = Θ(N² / log² N)`. Both are `O(N²)`,
so the per-query cost is `2^{O(N²)}` in the worst case. ∎

**Theorem 6.4 (total cost in unary).** The binary-search algorithm for
`S_unary` on input `1^n` runs in time `O(log n) · 2^{O(n log² n)} =
2^{O(n log² n)}`, which is `2^{O(N log² N)}` in terms of the unary input
length `N = n`. This is exponential in `N`.

*Proof.* Direct from Theorems 3.2 and 6.3. ∎

**Remark 6.5 (the unary encoding does not make the problem easier).** The
unary encoding makes the input *longer* (`N = n` for `S_unary`, vs
`N = log n` for `S_binary`), so the same numeric-`n` algorithm is *less*
expensive relative to the input length. But the problem is still exponential
in `N`: the best known bound is `2^{O(N log² N)}` for `S_unary`, which is
exponential in the unary input length. The small gap does not change this.

## 7. Summary of the disproof `[deduction]`

| Naive premise | Status | Why it fails |
|---|---|---|
| P1: gap is `O(n)` | **True** | `U(n) − I(n) = Θ(n)` is correct |
| P2: `O(log n)` queries | **True** | Binary search is correct |
| P3: each query is poly-time | **False (open)** | This is `SORT-BOUND-U ∈ P`, the original problem |
| Conclusion: `SORT-BOUND-U ∈ P` | **Invalid** | Circular: assumes P3 which is the conclusion |

**The disproof in one sentence:** The naive argument confuses a *Turing
reduction* (which shows `S_unary ≤_T^p SORT-BOUND-U`) with a *complexity upper
bound* (which would require `SORT-BOUND-U ∈ P`); the reduction is valid but
establishes only that the two problems are of equivalent difficulty, not that
either is in `P`.

---

## 8. What the small gap *does* give `[deduction]`

The small gap `U(n) − I(n) = Θ(n)` is not useless — it gives:

1. **Query complexity upper bound:** `O(log n)` threshold queries suffice
   (vs `O(n log n)` for linear search). This is a genuine reduction in the
   number of queries.

2. **Nonuniform advice compression:** The `P/log` bound of
   `docs/research-encoding-consequences.md` (Theorem 3.7) uses monotonicity of
   `f(n) = n + S(n)` to compress advice to `O(log L)` bits. This uses the
   structure of `S(n)`, not just the gap.

3. **Forced regions:** For `k < I(n)` the answer is always "no", and for
   `k ≥ U(n)` it is always "yes". These regions are decided in `O(1)` time
   without any threshold query. Only the `Θ(n)`-wide window `[I(n), U(n))`
   requires real queries.

4. **Equivalence of function and decision:** The binary search establishes
   `SORT-BOUND-U ∈ P ⟺ S_unary ∈ FP`, which is a useful structural fact even
   though it does not resolve either membership.

What the gap does **not** give:
- A polynomial-time algorithm for any threshold query.
- Any reduction in the per-query cost.
- Any evidence for `SORT-BOUND-U ∈ P` or `S_unary ∈ FP`.

## 10. Conclusion `[deduction]`

The naive argument "small gap `O(n)` ⟹ binary search `O(log n)` queries ⟹
`SORT-BOUND-U ∈ P`" is **disproved**. The argument's only non-trivial premise
(P3: each threshold query is poly-time) is the original problem. The binary
search is a valid Turing reduction showing `S_unary ≤_T^p SORT-BOUND-U`, but a
reduction is not a complexity upper bound. The small gap reduces the number of
queries but not their cost; if each query requires exponential time (as the
best known algorithms do), the total remains exponential. No sense in which
the small gap helps — approximation, advice compression, or forced regions —
yields a polynomial-time algorithm for the exact threshold query, which is the
open problem.

---

## 11. Next obstacle `[open]`

The central obstruction remains: **no polynomial-time algorithm is known for
the threshold query `S(n) ≤ k`**, and the small gap does not provide one. The
decisive question is whether the per-query cost can be reduced from
`2^{O(n log² n)}` to `poly(n)` — equivalently, whether `SORT-BOUND-U ∈ P`.
The small gap is a statement about the *range* of `S(n)`, not about the
*complexity* of deciding membership in that range.
