# Unary surplus FPT and the incompleteness of info-only pruning

**Status:** research note (2026-10-20). Paper-level theorems, a literature
quantification, and bounded experiments. **Not Lean-checked. No PR.** Every
item is labelled `[definition]`, `[deduction]`, `[literature]`, `[experiment]`,
`[conjecture]` or `[open]`. Unary encoding only; no binary work. Companion
scratch programs live in `/tmp/opencode` and are **not** committed.

This note answers the packet: *is there a nontrivial exact FPT algorithm
`f(s)·poly(n+k)` (or XP time) for `CanSort(antichain_n,k)` with surplus
`s = k − L(n)`, or a rigorously defined poset family falsifying a proposed FPT
compression of near-tight winning states?* The answer is **negative for the
proposed compression**, with a new clean admissibility lemma, a restatement of
the winning-frontier counting theorem in the surplus parameter, a tightness
observation, and a full cost quantification of the Stober–Weiß bidirectional
exact search and of symbolic state quotients.

## 0. Scope, model, and the two questions

`[definition]` From `docs/problem.md`. `S(n)` is the minimum height of a
deterministic **adaptive** binary comparison decision tree that sorts every
permutation of `n` distinct labelled keys. A state is the transitively closed
strict partial order `P` on the keys induced by the comparisons made so far;
`e(P)` is its number of linear extensions; `F(P)` is the minimum further
worst-case comparison count, so `S(n) = F(antichain_n)`. Write

```
L(n) = ceil(log2 n!)                       (information lower bound)
s    = k − L(n)                            (surplus; the packet's parameter)
CanSort(antichain_n, k)  ⇔  S(n) ≤ k.
```

`[deduction]` If `s < 0` then `CanSort` is **trivially NO** (`n! > 2^k` forces a
leaf-count contradiction). The informative regime is `s ≥ 0`, where
`CanSort` is YES iff `s ≥ g(n) := S(n) − L(n)`. Since `S(n) ≤ n·ceil(log2 n)`
(merge sort), the surplus in the informative window is `0 ≤ s ≤ O(n log n)`.

**The parameterized question.** `[definition]` Is there a computable `f` and a
polynomial `p` such that `CanSort(antichain_n, k)` is decided in time
`f(s)·p(n+k)` (**FPT** in `s`), or in time `(n+k)^{f(s)}` (**XP** in `s`)?
The unary word length is `N = n+k+1`, so `poly(n+k) = poly(N)`.

**The proposed compression.** `[definition]` Let `W(n,k)` be the set of
isomorphism classes `[P]` such that `P` is reachable from `antichain_n` in at
most `k` comparisons and `F(P) ≤ k − c(P)` (`c(P)` = depth). Proposal P(s):
`|W(n,k)| ≤ f(s)·poly(n+k)`, so enumerating `W(n,k)` decides the problem in
FPT time. Section 3 falsifies P(s) at `s = 0`.

## 1. Depth versus complexity (the packet's requested distinction)

`[deduction]` `S(n)` is a **number** — the depth of an optimal tree — and is
`O(n log n)`. Deciding `CanSort(antichain_n, k)` is a **search problem** whose
cost is the size of the adaptive-tree search, not the depth of the answer. The
two are unrelated: a depth-`O(n log n)` answer can require `2^{Θ(n log^2 n)}`
search to *find*. The parameter `s` measures the surplus above the information
bound, not the depth. Small `s` does **not** imply small search: `n = 12` has
`s = 0` (`k = 29 = L(12)`) and needs an exhaustive search, because
`S(12) = 30 > 29` (Wells; see `docs/literature.md`). This is the canonical
witness that the information bound is not a sufficient statistic and that the
near-tight regime is not compressed by it.

## 2. Lemma: info-only pruning cannot reject the early prefix

`[definition]` In the forward search with budget `k`, the **info-only pruning**
rule prunes a state `P` at depth `c` when `e(P) > 2^{k−c}` (equivalently
`F(P) > k − c` by leaf counting). This is a sound necessary condition.

`[deduction]` **Lemma 1 (matching prefix).** Let `n ≥ 2`, `k ≥ L(n)`, and for
`j = 0, …, ⌊n/2⌋` let `P_j` be the state after comparing the disjoint pairs
`(1,2), (3,4), …, (2j−1, 2j)`. Then `P_j` is a disjoint union of `j` 2-chains
and `n − 2j` singletons, so

```
e(P_j) = n! / 2^j   and   e(P_j) ≤ 2^{k−j}.
```

*Proof.* A disjoint union of lists of lengths `ℓ_1, …, ℓ_a` has
`n!/(∏ ℓ_i!)` linear extensions; here the lists are `j` chains of length 2 and
`n−2j` singletons, giving `n!/(2^j·1^{n−2j}) = n!/2^j`. The bound
`n!/2^j ≤ 2^{k−j}` is equivalent to `n! ≤ 2^k`, which holds because
`k ≥ L(n) = ceil(log2 n!)`. ∎

`[deduction]` **Corollary 1.1 (no early rejection).** The info-only pruning
never fires at any state of the matching prefix, whose length is `⌊n/2⌋`. Hence
a NO-certificate that uses only this rule must have depth `> ⌊n/2⌋`; the rule
cannot reject the early prefix while `s ≥ 0`. At `n = 12, k = 29` (`s = 0`) the
answer is NO, so the rule is **incomplete**: it must be supplemented by an
exhaustive search.

`[experiment]` Direct extension counting (`/tmp/opencode/explore_surplus.py`,
independent of `scripts/evaluate.py`) reproduces `e(P_j) = n!/2^j` and
`e(P_j) ≤ 2^{k−j}` for all `j ≤ n/2` and `n ≤ 8`.

`[deduction]` The matching prefix is admissible but **not forced** beyond depth
3: at `n = 12` the fourth comparison may be imbalanced (the forced-prefix
analysis of the 2026-10-19 board comments). Lemma 1 is about admissibility, a
strictly weaker and cleaner statement, and it holds for every `n`, `s ≥ 0`.

## 3. Theorem: a large winning frontier at every surplus `s ≥ 0`

`[deduction]` **Theorem 2 (winning-frontier counting).** There are constants
`c > 0`, `r_0` such that for every `r ≥ r_0`, with `s = 2^r`, `n = s^2` and
every `k ≥ L(n)` (i.e. every `s ≥ 0`), there are at least
`2^{c·n·(log2 n)^2}` pairwise **nonisomorphic** posets `P` on `n` elements with

1. `P` reachable from `antichain_n` in `≤ k` comparisons;
2. `F(P) ≤ k − c(P)` (winning);
3. `e(P) ≤ 2^{k−c(P)}` (so the info-only pruning does not prune `P`).

*Construction (de Bruijn levels).* Partition the labels into `s` levels
`L_0, …, L_{s−1}`, `L_i = {(i,x) : x ∈ ℤ/sℤ}`. Fix the skeleton relations

```
(i,x) < (i+1, 2x mod s),      (i,x) < (i+1, (2x+1) mod s)
```

for `0 ≤ i ≤ s−2` (exactly `2s(s−1)` edges). Let `M` be the set of pairs
`((i,x),(i+1,y))` **not** in the skeleton; `|M| = (s−1)·s·(s−2) = Θ(n^{3/2})`.
Choose any `A ⊆ M` with `|A| = m = ⌊rn/2⌋` and let `P_A` be the transitive
closure of skeleton `∪ A`.

*Reachability.* Every skeleton edge and every chosen edge joins adjacent levels
and is not implied by any other path (a path from level `i` to `i+1` is a single
edge), so each is a legal comparison; `P_A` is reached in exactly
`t = 2s(s−1) + m` comparisons. Distinct `A` give distinct labelled posets,
because adjacency between levels is exactly the chosen edge set.

*Winning.* From `(i,x)`, after `r = log2 s` levels the reachable residues are
`(2^r x + b) mod s`, `b = 0, …, 2^r − 1`, i.e. **all** of level `i+r` (since
`s = 2^r`). Hence every vertex of level `i` precedes every vertex of level
`i+r`, so an antichain spans at most `r` levels and `width(P_A) ≤ rs`. By
Dilworth, `P_A` splits into `≤ rs` chains; a tournament merge sorts it in at
most `(w−1) + (n−1)·ceil(log2 w) ≤ rs + n(r + ceil(log2 r))` comparisons, so

```
F(P_A) ≤ rs + n(r + ceil(log2 r)).
```

Meanwhile `k ≥ ceil(log2 n!) ≥ n(2r − log2 e)` and
`k − t ≥ n(3r/2 − 2 − log2 e) + 2√n`. For `r ≥ r_0` the right side exceeds
`F(P_A)`, so `P_A` is winning; and `F(P_A) ≤ k − t` implies
`e(P_A) ≤ 2^{k−t}` by leaf counting.

*Counting.* There are `binom(|M|, m)` labelled states, and each isomorphism
class has at most `n!` labellings, so

```
log2 #classes ≥ m·log2(|M|/m) − log2 n!
             ≥ (rn/2)·(r − 1 − log2 r) − 2rn
             = rn·( (r − 1 − log2 r)/2 − 2 ) = Ω(n r^2) = Ω(n (log2 n)^2).
```

∎

`[experiment]` `/tmp/opencode/verify_construction.py` reproduces the
`r`-level reachability, the width bound `rs`, the winning inequality for
`r = 16, 20, 24`, and the class-count lower bound
`≈ 0.070 n(log2 n)^2, 0.079, 0.085` at `r = 16, 20, 24`. For `r ≤ 12` the
inequality is not yet positive, as expected for an asymptotic construction.

`[deduction]` **Corollary 2.1 (falsification of P(s)).** At `s = 0` the
proposal P(s) would require `|W(n, L(n))| ≤ f(0)·poly(n)`, but Theorem 2 gives
`|W(n, L(n))| ≥ 2^{Ω(n(log2 n)^2)}`. No such `f` exists. **The near-tight
winning frontier is exponentially large at `s = 0`.**

`[deduction]` **Corollary 2.2 (no FPT/XP enumeration).** Any algorithm that
enumerates admissible winning states — even after merging by the full
`S_n × ℤ_2` symbolic quotient — must output `2^{Ω(n(log2 n)^2)}` classes at
`s = 0`, which is not `f(0)·poly(n)` and not `(n+k)^{f(0)}`. The quotient
removes only `2^{Θ(n log n)}` (Section 5) and does not change the exponent.

## 4. Tightness of the counting bound

`[deduction]` **Proposition 3.** The number of states reachable from the
antichain in `≤ k` comparisons is at most `2^{O(n(log2 n)^2)}` for
`k = L(n)`. Hence the exponent `Θ(n(log2 n)^2)` in Theorem 2 is tight up to the
leading constant.

*Proof.* A comparison adds at most one Hasse edge (Stober–Weiß, Observation
2.1), so a state reached in `≤ k` comparisons has a Hasse diagram with `≤ k`
edges. The number of DAGs on `n` vertices with `≤ k` edges is
`Σ_{c≤k} binom(n(n−1)/2, c)`. For `k = L(n) ≤ n log2 n`,

```
log2 binom(n^2/2, k) = O(k·log2(n^2/k)) = O(n log n · log(n/log n))
                     = O(n (log2 n)^2).
```
∎

`[deduction]` The construction attains `≈ (1/8)·n(log2 n)^2` in the exponent,
so the winning-state count is `2^{Θ(n(log2 n)^2)}` in log scale. This is a
genuine "constant fraction" lower bound, not merely a superpolynomial one.

## 5. Stober–Weiß bidirectional exact search: full cost

`[literature]` F. Stober, A. Weiß, *Lower Bounds for Sorting 16, 17, and 18
Elements*, ALENEX 2023, arXiv:2206.05597v2. All rows below are at
`k = C(n) = L(n)`, i.e. **surplus `s = 0`**. "Stored" is the number of posets
stored during both searches (the paper notes it is less than the number
explored). Runtimes on 2× Xeon E5-2650v4 (24 threads), 768 GB RAM.

| n | `C(n)` | efficiency `E_tot` | bandwidth | stored posets | forward | backward | total |
|---|---|---|---|---|---|---|---|
| 12 | 29 | 0.89 | 0.05 | 6,190 ‡ | 15 ms | 137 ms | 152 ms |
| 13 | 33 | 0.72 | 0.08 | 254,574 | 1.0 s | 1.4 s | 2.4 s |
| 16 | 45 | 0.59 | 0.20 | 3.99·10⁹ | 3 h | 8 h | 11 h |
| 17 | 49 | 0.63 | 0.24 | 13.2·10⁹ | 66 h | 49 h | 115 h |
| 18 | 53 | 0.71 | 0.19 | 10.0·10⁹ | 56 h | 33 h | 89 h |

‡ For `n = 12` the bidirectional search *increased* the space; most posets come
from the backward search. `[literature]` Pure forward search at `n = 13`
explores `2,032,125` posets; the backward search traverses `6.82·10⁸`; the
bidirectional search stores `254,574` (87% smaller). `[literature]` The state is
a Hasse diagram (upper-triangular adjacency matrix, `n(n−1)/2 + 5` bits),
quotiented by **congruence** = isomorphism or dual isomorphism (the
`S_n × ℤ_2` quotient); colour refinement gives a canonical form, with a
`boost::vf2` graph-isomorphism fallback for `1.4%` of tests at `n = 17`.

`[deduction]` **Cost scaling.** The stored count grows from `2.5·10^5`
(`n = 13`) to `1.3·10^{10}` (`n = 17`), i.e. by `~2^{15}` over four values of
`n`; the runtimes grow from seconds to days. The per-layer forward peaks are
`1.2·10^9` (`n = 16`, layer 31), `5.0·10^9` (`n = 17`, layer 34),
`2.8·10^9` (`n = 18`, layer 39). This is `2^{Θ(n(log n)^2)}`-consistent and
**far** from any `f(0)·poly(n)`; the state of the art at `s = 0` is
`10^9`–`10^{10}` posets. The efficiency bandwidth is a *user-chosen* parameter
(`E_thr − E_tot`), not a measured window; Stober–Weiß's Lemma 4.2 gives only a
partial coverage guarantee, so absence below the threshold is a sound NO while
absence above it proves nothing.

`[deduction]` **Symbolic quotients do not help.** The `S_n` quotient removes a
factor `≈ n! = 2^{Θ(n log n)}`; adding order-duality (`ℤ_2`) doubles it. Since
the winning frontier is `2^{Θ(n(log n)^2)}` and `n(log n)^2 ≫ n log n`, the
quotient leaves the exponent unchanged. The construction of Theorem 2 is
already stated up to isomorphism, so it is unaffected by the quotient.

## 7. What is and is not established

`[deduction]` **Established (this note).**
1. The info-only pruning does not fire on the first `⌊n/2⌋` levels of the
   matching prefix, for every `n` and `s ≥ 0` (Lemma 1).
2. At `s = 0` there are `2^{Ω(n(log2 n)^2)}` nonisomorphic reachable winning
   states, all admissible for the info-only pruning (Theorem 2); this is tight
   up to the leading constant (Proposition 3).
3. Therefore the proposed compression P(s) is false, and no FPT/XP algorithm
   that enumerates winning states exists (Corollaries 2.1–2.2).
4. The state of the art (Stober–Weiß) at `s = 0` is `10^9`–`10^{10}` stored
   posets and days of runtime; the `S_n × ℤ_2` symbolic quotient does not
   change the exponent.

`[deduction]` **Not established.**
* No **unconditional time lower bound** for computing `S(n)` or deciding
  `CanSort`; Theorem 2 bounds the *output size of one enumeration*, not the
  runtime of every algorithm (a selective/symbolic algorithm could avoid the
  frontier).
* No **NP/W[1]-hardness** and no parameterized reduction is claimed. The unary
  language is sparse, so ordinary many-one NP-hardness would imply `P = NP`
  (Mahaney); the note imports no generic poset/decision-tree hardness.
* No claim that `SORT-BOUND-U ∈ P`, `∉ P`, `∈ NP`, or `∉ NP`. The FPT/XP
  question in `s` remains **open**; this note only closes the specific
  "enumerate near-tight winning states" route.
* The counting theorem is asymptotic; the construction needs `r ≥ 16`
  (`n = 2^{32}`), so it is vacuous at small `n` (as the 2026-10-19 peer review
  of `510a18001221` correctly observed).

## 8. Next obstacle

`[open]` The decisive question is now **not** "are there many winning states?"
(they are) but "can any sound algorithm avoid materializing them?" Two
concrete targets:

1. **A compression not of the enumeration form.** The `n = 5` same-`e` witness
   and the `n = 7` child-`e` witness rule out scalar and one-ply state
   invariants; a sound merging coarser than isomorphism classes, or a
   decomposition (disjoint-union / series-parallel) recurrence, is the natural
   remaining route. None is currently sound for the minimax value.
2. **A lower bound against a restricted algorithm class.** Theorem 2 plus
   Proposition 3 show that *enumeration* is `2^{Θ(n(log n)^2)}`. Proving that
   any algorithm using only info-only pruning (plus isomorphism) needs
   `2^{Ω(n(log n)^2)}` time would be a genuine step; it is not proved here.
