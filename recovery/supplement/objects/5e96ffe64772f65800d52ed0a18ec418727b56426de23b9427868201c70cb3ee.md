# Recomputation-based DSPACE(O(N)) for SORT-BOUND-U: analysis

**Status:** research note (paper analysis). Not Lean-checked.
Labels: `[definition]`, `[deduction]`, `[open]`.

---

## 1. Question

`SORT-BOUND-U = {1^n # 1^k : S(n) <= k}`, input length `N = n+k+1`.
The certified budgeted DFS (`research-budgeted-dfs.md` §5.3) decides it in
`DSPACE(O(N log(N+2)))` work-tape bits. Can recomputation remove the
`log N` factor and achieve `DSPACE(O(N))`?

## 2. Space decomposition of the DFS `[deduction]`

`CanSort(P,d)` evaluates the minimax recurrence by backtracking search with
no memoization. Peak workspace decomposes into three terms:

1. **Stack / transcript.** Depth `<= k+1` frames. Each frame stores a
   comparison `(a_s,b_s)` (or equivalently a cursor `c_s` in
   `[0, binom(n,2))`) plus loop state: `O(log n)` bits. Total
   `O(k log n)` bits.
2. **Reachability workspace.** Comparability queries (`x ~ y` in `P(sigma)`)
   are graph reachability searches. A BFS/DFS uses a visited bit-vector
   (`n` bits) plus a queue of `<= n` labels (`O(n log n)` bits). One shared
   workspace suffices (allocated/released inside the helper). Total
   `O(n log n)` bits.
3. **Counters / indices.** `O(log n)` bits each, dominated by the above.

Naive total: `O(k log n + n log n) = O((k+n) log n) = O(N log n)` bits.
This matches the existing `O(N log(N+2))` bound.

## 3. Removing the reachability log factor `[deduction]`

By Savitch's theorem, `STCONN in DSPACE(log^2 n)`. Reachability in the
digraph `([n], sigma)` therefore costs `O(log^2 n)` work bits, not
`O(n log n)`. The visited-vector workspace collapses to a recursion stack
of `O(log n)` levels each storing two vertex indices (`O(log n)` bits).
This is a single shared workspace (reused per query), so it adds only
`O(log^2 n)` bits, not a per-frame multiplier.

**Refined bound.** `O(k log n + log^2 n)` bits. The dominant term is the
per-frame stack cost `O(k log n)`.

## 4. The per-frame log n barrier `[deduction]`

**Why `O(log n)` per frame is necessary.** Backtracking search must, on
returning from a child, resume the parent's pair enumeration. The resume
point is the cursor `c_s`, an integer in `[0, binom(n,2))`. Storing it
explicitly costs `ceil(log2 binom(n,2)) = 2 log n - O(1)` bits. Any
explicit representation of "which pair to try next" requires
`Omega(log n)` bits because there are `binom(n,2) = Theta(n^2)` distinct
pairs.

**Can the cursor be recomputed?** No, not cheaply. The cursor is not a
function of the poset alone; it encodes the search history (which pairs
were tried and failed at this node). Recomputing it from the root
requires replaying the entire failed subtree, which costs exponential
time per level and defeats the purpose. The cursor is genuine
`Omega(log n)`-bit state per frame.

**Cumulative checkpointing does not help.** Storing full poset snapshots
every `m` frames costs `Omega(k^2 log n / m)` bits because transcripts are
cumulative (frame `s` embeds all `s` prior relations). The optimum
`m = k` recovers the plain `O(k log n)` bound. Matrix snapshots cost
`Omega(k n^2 / m)` bits, requiring `m = Omega(n^2)` to reach `O(N)`,
impossible since `m <= k = O(n log n)`.

**Poset representation lower bound.** A reachable poset with `s` relations
has entropy `Theta(s log n)` bits (at most `n^{2s}` such posets). When
`s = k = Theta(n log n)`, this is `Theta(n log^2 n)` bits, strictly
larger than `O(n)`. No representation of the poset fits in `O(N) = O(n)`
bits; the transcript (also `Theta(k log n)`) is already near-optimal.

## 5. Why O(N) fails at the hard instances `[deduction]`

The hard instances have `k = Theta(n log n)` (between the information
bound and the mergesort bound). Then `N = Theta(n log n)` and

```
k log n = Theta(n log^2 n) = Theta(N log N) = omega(N).
```

The per-frame cost alone exceeds `O(N)` by a `log N` factor. No
recomputation scheme that stores an explicit cursor or comparison
per frame can close this gap.

## 6. What O(N) would require `[open]`

Achieving `O(N) = O(n+k)` bits means `O(1)` bits per frame on average,
which requires eliminating the per-frame cursor. This is possible only
if the pair selection becomes a **canonical function of the poset**
(no enumeration state). A canonical/greedy pair choice that is provably
preserves the minimax optimum would be a major result (it would give a
polynomial-time algorithm for sorting). No such choice is known.

Alternative routes to `O(N)`:
- a non-search characterization of `S(n) <= k` (algebraic, invariant);
- a structural theorem collapsing the state space to `poly(N)` states;
- a fundamentally different algorithm (none known).

None is available, and there is no proof that `O(N)` is impossible.

## 7. Time-space tradeoff summary `[deduction]`

| Approach | Space (bits) | Time |
|---|---|---|
| Memoized DP | `2^{Theta(n^2)}` | `2^{O(n^2)}` |
| Transcript DFS (BFS reach) | `O(N log N)` | `2^{O(N log N)}` |
| Transcript DFS (Savitch reach) | `O(k log n + log^2 n)` | `2^{O(k log n)} * quasi-poly` |
| `O(N)` target | `O(N)` | requires non-backtracking; not known |

The DFS trades exponential time for polynomial space. The `log N`
factor in space is the price of backtracking state; removing it requires
a structurally different algorithm, not a recomputation trick.

## 8. Conclusion `[deduction]`

`DSPACE(O(N))` is **not achievable** by the recomputation-based DFS.
The per-frame cursor costs `Omega(log n)` bits and cannot be recomputed
or compressed, giving `Omega(k log n) = omega(N)` at the hard instances
`k = Theta(n log n)`. The current `O(N log N)` bound is inherent to
backtracking search over pairs. Achieving `O(N)` would require a
non-search-based method (canonical pair selection, invariant
characterization), which is not known and would itself be a significant
theorem. No impossibility proof exists; the question whether
`SORT-BOUND-U in DSPACE(O(N))` remains open.
