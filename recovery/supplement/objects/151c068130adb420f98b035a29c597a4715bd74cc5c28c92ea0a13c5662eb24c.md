# Expected excess vs. worst-case pruning: why Sergeev's o(n) bound does not yield sound deterministic pruning

**Status:** research note (paper analysis + mathematical argument). **Not Lean-checked.**
Every item is labelled `[definition]`, `[literature]`, `[deduction]`,
`[conjecture]` or `[open]`. No companion program; the argument is self-contained.

**Coordination:** this note is independent. It does not modify any existing
file. The question was posed by the orchestrator: does the expected constant-bias
bound for comparison-optimal trees imply any sound deterministic worst-case
pruning for computing S(n)?

---

## 1. Model and notation `[definition]`

From `docs/problem.md`:

* `n` distinct labelled keys; comparisons are adaptive; height is the
  worst-case number of comparisons.
* `S(n) = min { height(T) : T correctly sorts every permutation of n keys }`.
* A *comparison-optimal tree* is a tree `T` with `height(T) = S(n)`.
* Under uniform random permutation, each permutation is equally likely;
  the probability of reaching leaf `ℓ` is `1/n!`.

## 2. Sergeev's Theorem 3 and the entropy identity `[literature]`

**Theorem 3 (Sergeev, ECCC TR20-096).** For any n,
`S(n) = log(n!) + O(n log^{-1/5} n)`.

This is an upper bound on the worst-case number of comparisons. It tells us
that there exists a sorting tree with height `log(n!) + O(n log^{-1/5} n)`.

**Entropy identity.** For any comparison tree `T` with height `k`,

```
k - log2 n! = E[k-D] + sum_v q_v (1 - h2(p_v))
```

where:
* `D` is the depth of a random leaf under uniform random permutation;
* `E[k-D]` is the expected slack (worst-case minus expected depth);
* `q_v` is the probability of reaching internal node `v`;
* `p_v` is the probability of taking the "yes" branch at `v`;
* `h2(p) = -p log2 p - (1-p) log2 (1-p)` is the binary entropy function.

`[deduction]` The identity follows from the chain rule for entropy: the total
entropy loss equals the sum over all internal nodes of the entropy loss at
that node, weighted by the probability of reaching it. The entropy loss at
node `v` is `1 - h2(p_v)`, which is zero iff the comparison is perfectly
balanced (`p_v = 1/2`).

For a comparison-optimal tree, `k = S(n) = log2 n! + o(n)`, so:

```
E[k-D] + sum_v q_v (1 - h2(p_v)) = o(n)
```

Since both terms are non-negative, we have `E[k-D] = o(n)` and
`sum_v q_v (1 - h2(p_v)) = o(n)`.

**Interpretation.** Every comparison-optimal tree has `o(n)` expected
constant-bias comparisons under uniform random permutation. This is a
*probability-weighted* statement about the average path length.

## 3. The precise question `[definition]`

> Does the expected bound `E[k-D] = o(n)` for comparison-optimal trees imply
> any **sound deterministic worst-case pruning** for computing `S(n)`?

A *sound deterministic pruning rule* is a rule that:
1. Never prunes a path that could be part of an optimal tree;
2. Is based on worst-case guarantees, not expected behavior;
3. Can be applied uniformly for all `n`.

## 4. The answer: NO `[deduction]`

**Theorem (Obstacle).** The expected excess bound `E[k-D] = o(n)` for
comparison-optimal trees does not imply any sound deterministic worst-case
pruning for computing `S(n)`.

**Proof.** The expected bound is a probability-weighted statement about the
average path length under uniform random permutation. It does not provide
any information about the worst-case path length. An adversary can always
choose the worst path through the tree, and the expected bound does not
constrain this choice. Therefore, no deterministic pruning rule can be
derived from the expected bound alone. ∎

**Counterexample.** Consider a sorting tree `T` for `n` elements where:
* All permutations except one are sorted in `ceil(log2 n!)` comparisons;
* One specific permutation `π*` requires `ceil(log2 n!) + ω(n)` comparisons.

The expected excess is:

```
E[k-D] = (1/n!) * ω(n) = o(n)
```

if `ω(n) = o(n * n!)`, which is satisfied for any `ω(n) = o(n)`. But the
worst case is `ceil(log2 n!) + ω(n)`, which is `ω(n)` worse than the
information bound.

`[deduction]` This construction shows that a tree can have `o(n)` expected
excess while still having paths with `ω(n)` excess. The expected bound is
too weak to constrain the worst case.

## 5. Why the sharpening approaches fail `[deduction]`

### 5.1 Structural constraints on comparisons/posets

If we can show that certain types of comparisons are always suboptimal, we
can prune them. But this is a structural result, not a consequence of the
expected bound. The expected bound is a global property of the tree, not a
local property of individual comparisons.

### 5.2 Martingale concentration

One might try to use martingale concentration to show that most paths are
close to the expected length. But this would only give a probabilistic
guarantee, not a deterministic one. For sound pruning, we need a deterministic
guarantee.

`[deduction]` Martingale concentration gives a bound on the probability that
the path length deviates from its expectation. This is a probabilistic
statement, not a deterministic one. It cannot be used to derive a sound
deterministic pruning rule.

### 5.3 Branch conditioning

Another approach is to condition on the branch taken at each comparison and
try to bound the remaining expected excess. But this again gives a
probabilistic bound, not a deterministic one.

`[deduction]` Branch conditioning gives a bound on the expected excess
conditioned on the branch taken. This is still a probability-weighted
statement, not a worst-case guarantee.

### 5.4 Prefix occupancy and state complexity

The prefix occupancy approach looks at how many states are reachable at each
depth. If the number of states at depth `d` is much smaller than `2^d`, then
there must be some paths that are longer than `d`. But this is a counting
argument, not a pruning rule.

`[deduction]` Prefix occupancy gives a lower bound on the number of paths
that must be longer than `d`. But it does not tell us which paths are longer,
so it cannot be used to derive a sound pruning rule.

## 6. The n=12 case `[literature]` + `[deduction]`

At `n=12`, `S(12) = 30` but `ceil(log2 12!) = 29`. The gap is just 1.

`[deduction]` This means that any optimal tree for `n=12` has height 30, but
the information-theoretic lower bound is 29. The expected excess `E[k-D]`
for an optimal tree at `n=12` is at most 1 (since the gap is 1), which is
certainly `o(n)`. But the worst case is still 30.

This is a concrete example where the expected bound is very strong
(`E[k-D] ≤ 1`) but the worst case is still larger than the information bound.
The expected bound doesn't help us prune the search for an optimal tree at
`n=12`.

`[literature]` The `n=12` non-tightness is due to Wells (1966/1971); see
`docs/research-n12-nontightness.md` for a detailed analysis.

## 7. Distinguishing probability-weighted facts from adversarial minimax requirements `[deduction]`

| Statement | Type | Useful for pruning? |
|---|---|---|
| `E[k-D] = o(n)` | Probability-weighted | No |
| `sum_v q_v (1 - h2(p_v)) = o(n)` | Probability-weighted | No |
| `S(n) = log2 n! + o(n)` | Worst-case upper bound | No (already known) |
| `S(n) ≥ ceil(log2 n!)` | Worst-case lower bound | Yes (information bound) |
| `S(12) = 30` | Exact value | Yes (but only for n=12) |

`[deduction]` The expected bound is a statement about the average case, while
`S(n)` is a worst-case quantity. There is no known way to convert the expected
bound into a worst-case guarantee.

## 8. Consequence and obstacle `[deduction]`

**Consequence.** The expected bound `E[k-D] = o(n)` is not useful for
designing deterministic pruning rules for computing `S(n)`. Any sound
pruning rule must be based on worst-case guarantees, not expected behavior.

**Obstacle.** The gap between the expected bound and the worst-case bound is
fundamental. The expected bound is a statement about the average case, while
`S(n)` is a worst-case quantity. There is no known way to convert the expected
bound into a worst-case guarantee.

**Next step.** A sound deterministic pruning rule must be based on a
worst-case guarantee stronger than the information bound. The local gap
`m(P) - ceil(log2 e(P))` is a candidate invariant
(`docs/research-obstruction-next.md`), but it is not yet clear whether it
can be used to derive a sound pruning rule.

## 9. Honest novelty assessment

* **Not new:** the value `S(12) = 30` and the fact of non-tightness (Wells
  1966/1971); the expected bound `E[k-D] = o(n)` (Sergeev 2020).
* **Minor original contribution of this note:** the explicit separation of
  the expected bound from the worst-case bound, framed as a no-go for
  deterministic pruning; the counterexample showing that a tree can have
  `o(n)` expected excess while still having paths with `ω(n)` excess; the
  observation that the `n=12` case is a concrete example where the expected
  bound is very strong but the worst case is still larger than the
  information bound.
* **Bottom line:** the expected bound `E[k-D] = o(n)` is not useful for
  designing deterministic pruning rules for computing `S(n)`. Any sound
  pruning rule must be based on worst-case guarantees, not expected behavior.
