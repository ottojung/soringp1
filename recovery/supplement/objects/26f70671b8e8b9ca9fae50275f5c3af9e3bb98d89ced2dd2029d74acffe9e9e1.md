# Linear-workspace question for SORT-BOUND-U: state-entropy obstacle

**Status:** research note (deduction + experiment). Not Lean-checked. Every item
is labelled `[definition]`, `[deduction]`, `[experiment]`, `[conjecture]` or
`[open]`. This note answers the O(N)-workspace question for the unary
threshold language with a rigorously identified obstacle, **not** a machine
lower bound. It refines the open remark of `docs/research-budgeted-dfs.md` §5.3
("does not imply … deterministic linear space O(N)").

## 1. Question `[definition]`

`SORT-BOUND-U = { 1^n # 1^k : S(n) ≤ k }`, input length `N = n+k+1`, workspace
counted in work-tape bits (read-only input). The budgeted DFS of
`docs/research-budgeted-dfs.md` decides it in `DSPACE(O(N log(N+2)))`. Question:
does it admit **deterministic O(N) workspace**? Examined routes: recomputation,
game-tree divide and conquer, compact valid transcripts.

## 2. Regimes `[deduction]`

With `L(n) = ⌈log₂(n!)⌉` (computable in `O(log n)` space via exact BigInt
arithmetic) and `U(n) = n⌈log₂ n⌉` (merge sort):

- `k ≥ U(n)`: accept, `O(log n)` space.
- `k < L(n)`: reject, `O(log n)` space.
- `L(n) ≤ k < U(n)`: the **informative window**, width `U(n)−L(n) = Θ(n)`,
  where `k = Θ(n log n)` and `N = Θ(n log n)`.

A comparison transcript of length `t` needs `Θ(t log n)` bits. It fits in
`O(N) = O(n+k)` iff `t log n = O(n+k)`, i.e. `t = O(n/log n)`. But every
informative instance has `t ≥ L(n) = Θ(n log n) ≫ n/log n`. **The transcript
never fits in O(N) on any informative instance.** The question is exactly the
informative window.

## 3. State entropy `[deduction]`+`[experiment]`

**Proposition.** The number of posets on `[n]` generated by `s = Θ(n log n)`
comparisons is `2^{Θ(n log² n)}`.

*Proof.* Upper bound: `≤ (n(n−1))^s` generating sequences. Lower bound: height-2
posets (bipartite bottoms/tops) with `≤ s` edges are distinct posets and number
`Σ_{i≤s} C((n/2)², i) = 2^{Ω(s log n)}`. ∎

Measured: at `n=1000`, `s=10⁴` comparisons give `log₂(#states) ≈ 6.1·10⁴`
bits vs `O(N) ≈ 10⁴`; the ratio is `≈ log₂ n`. **So any representation of an
arbitrary reachable state needs `ω(N)` bits.** This is a counting statement
about states; it is NOT a machine lower bound (a machine may recompute).

## 4. The obstacle `[deduction]`

**Blocker.** Any algorithm that decides the game by materialising the current
poset (or transcript) and computing closures / pair enumeration from it needs
`Ω(n log² n) = ω(N)` bits on informative instances: the future computation
(totality, incomparable pairs, closures) is a function of the full poset, and
the poset's worst-case description length is `Θ(n log² n)` bits.

**Recomputation does not help.** The state `P(σ)` is a function of the adaptive
(pair, answer) history `σ`, not of the adversary answers alone: at a node the
sorter may try many pairs, so the same answer prefix leads to different states.
Recomputing `P` from the root requires replaying `σ`, which requires retaining
`σ` — the same `Ω(n log² n)` bits. A canonical pair-selection rule (pair =
function of `P` only) is unsound: it computes a specific tree, not the game
optimum (balanced-greedy returns `S(9)=20 > 19`, `docs/research-state-compression.md`;
the optimal first comparison is not a fixed function of `P`).

**Divide and conquer / meet-in-the-middle** needs a frontier of states; the
frontier is a set of up to `2^{Θ(n log² n)}` posets — exponential space.

## 5. Falsified concrete proposals `[deduction]`

| Proposal | Verdict |
|---|---|
| Canonical-strategy DFS (fixed pair rule) | unsound — restricted tree class ≠ optimum (`n=9`) |
| Restart-DFS with answer-sequence encoding | ill-posed — state not a function of answers |
| Non-adaptive comparison schedule | wrong model — networks ≠ adaptive trees |
| Meet-in-the-middle frontier | exponential space |

## 6. What O(N) would require `[open]`

A positive result needs a **state-free** method for the game value: computing
`CanSort(P,d)` without ever representing `P`. No such method is known; the value
depends on finer structure than the linear-extension count (`n=5` witness) and
than the comparability graph (`n=7` witness). An unconditional `ω(N)` lower
bound is beyond current techniques (no explicit language is known outside
`DSPACE(n)`). The descriptive-complexity heuristic agrees: the game value needs
alternation (∃ strategy ∀ answers), captured by LFP/PFP, not by deterministic
transitive closure; a linear-space algorithm would be surprising but is not
ruled out by any known theorem.

## 7. Verdict

`SORT-BOUND-U ∈ DSPACE(O(N))` is **open**. The rigorous obstacle is state
entropy: on every informative instance the reachable game state has
`Θ(n log² n) = ω(N)` bits, and all known exact methods materialise it.
Recomputation, divide-and-conquer, and compact transcripts are each blocked by
the adaptivity of the comparison choices. A linear-space algorithm would be a
major structural result; a superlinear lower bound is out of reach.

**Reproduce:** the regime and state-entropy tables are exact integer/BigInt
computations (`L(n)`, `U(n)`, window widths, `log₂ C((n/2)², s)`); no
heuristic estimates are used.
