# Local lookahead cannot close the information bound: the k-ply hierarchy and unary consequences

**Status:** research note (2026-10-19). Every item is labelled `[definition]`,
`[deduction]`, `[literature]`, `[experiment]`, `[conjecture]` or `[open]`. It is
**not** Lean-checked, makes **no** complexity-class separation, and uses the
**unary** encoding only (no binary encoding appears anywhere in this note).
Companion program: `scripts/unary_ply_obstruction.py`; regression test:
`tests/test_unary_ply_obstruction.py`.

This note attacks the lower-bound side of the `n = 12` obstruction with a
*different* question from `docs/research-n12-nontightness.md` (which audits the
global `n = 12` search) and `docs/research-one-ply-obstruction.md` (which
introduces the one-ply bound `L1` and its smallest strict witness). Here we ask:

> How much **local lookahead** is needed before a strengthening of the
> information bound can exceed it at the *root* (the antichain)? The answer is
> `Omega(n)` plies, so the excess `S(n) - C(n)` is invisible to every bounded-ply
> potential. This is a new obstruction to closing the information gap.

---

## 0. Model and encodings (fixed once, used throughout)

`[definition]` From `docs/problem.md`. `S(n)` is the minimum height
(worst-case number of pairwise comparisons) of a **deterministic adaptive**
comparison decision tree that sorts every permutation of `n` distinct labelled
keys. A state is the transitively closed strict partial order `P` on
`{0,...,n-1}`; `e(P)` is its number of linear extensions; `F(P)` is the minimum
remaining worst-case number of comparisons that sorts every linear extension of
`P`. `F(antichain_n) = S(n)` (A24, `S_eq_adv_univ`). The **information bound**
is `L0(P) = ceil(log2 e(P))`; `F(P) >= L0(P)` pointwise, and
`S(n) >= C(n) := ceil(log2 n!)` is the root case.

`[definition]` **Unary threshold language** `SORT-BOUND-U = { 1^n # 1^k :
S(n) <= k }`; input length `L = n + k + 1`. The only `k` that matter lie in the
window `[C(n), U(n))` with `U(n) = n ceil(log2 n)`; outside it the answer is
forced (`k < C(n)` is no, `k >= U(n)` is yes).

`[definition]` **Free elements.** An element is *free* in `P` if it is
incomparable with every other element. A poset is a *chain-and-free* poset if it
is a disjoint union of chains and `f` free elements.

## 1. Precise question

The classical strengthening attempts (`docs/research-structural-lower-bounds.md`
merge factor; `docs/research-one-ply-obstruction.md` one-ply `L1`;
`docs/research-obstruction-next.md` `e <= 7` base) all share one feature: they
look at the *current* poset and its immediate extension counts. The one-ply bound
`L1` is exactly the one-step version of this idea. It is a lower bound
(`L1 <= F`) and is *strict* on an infinite family (smallest witness `n = 5`,
`e = 8`, `L0 = 3`, `L1 = F = 4`).

But `L1` is **not** strict at the root: the antichain `P0` has
`L1(P0) = L0(P0) = C(n)`, because every root comparison splits `n!` exactly in
half. So the one-ply bound cannot improve `S(n)` at all. The natural question is
whether iterating the one-ply idea helps:

> Does the `k`-ply hierarchy `L_k` exceed `C(n)` at the root for small `k`, and
> if so, how fast? Could a bounded-ply (hence plausibly compact) potential certify
> the hard no-instances `C(n) <= k < S(n)` of `SORT-BOUND-U`?

---

## 2. The k-ply hierarchy

`[definition]` For `k >= 0` define `L_k` on posets by

```
L_0(P) = ceil(log2 e(P)),
L_k(P) = 0 if P is total, else
         1 + min over incomparable {i,j} of max(L_{k-1}(P+i<j), L_{k-1}(P+j<i)).
```

`L_k` is the value of the `k`-round game in which the sorter minimises, the
adversary maximises, and the leaf payoff at depth `k` is the information bound
`L0`. By induction, `L_0 <= L_1 <= ... <= L_k <= ... <= F` pointwise, and
`L_k -> F` as `k -> infinity`. `L1` is the bound of
`docs/research-one-ply-obstruction.md`; the family `{L_k}` is new here.

`[deduction]` **Soundness of `L_k` (induction).** `L_0 <= F` is the information
bound. If `L_{k-1} <= F` then for every pair
`max(L_{k-1}(left), L_{k-1}(right)) <= max(F(left), F(right))`, so
`L_k <= F`. Monotonicity `L_k >= L_{k-1}` is the same argument with `L_0` in
place of `F` on the children (the prior work proves `L_0 <= L_1`; the induction
step is identical).

---

## 3. Theorem 1 (root balancing: `Omega(n)` plies are needed)

`[deduction]` **Theorem 1.** Let `P` be a chain-and-free poset with `f` free
elements. Then

```
L_k(P) = L_0(P)   for every k <= floor(f/2).
```

In particular, for the antichain `P0` on `n` elements (`f = n`),

```
L_k(P0) = C(n)   for every k <= floor(n/2).
```

`[deduction]` **Proof.** We first note `L_k >= L_0` for all `k` (Section 2). For
the reverse inequality we use the elementary fact that a comparison of two free
elements halves the extension count: if `a,b` are free in `P`, then
`e(P+a<b) = e(P+b<a) = e(P)/2`, so `L_0(P+ab) = L_0(P) - 1`.

Induction on `k`. The case `k = 0` is trivial. Let `1 <= k <= floor(f/2)`, so
`f >= 2k >= 2`; choose free elements `a, b`. The children `P+ab`, `P+ba` are
chain-and-free with `f-2` free elements, and
`k-1 <= floor(f/2) - 1 = floor((f-2)/2)`, so the induction hypothesis gives
`L_{k-1}(P+ab) = L_0(P+ab) = L_0(P) - 1` (and the same for `P+ba`). Hence

```
L_k(P) = 1 + min_{i,j} max(L_{k-1}(P+ij), L_{k-1}(P+ji))
       <= 1 + max(L_{k-1}(P+ab), L_{k-1}(P+ba))
       = 1 + (L_0(P) - 1) = L_0(P).
```

Combining with `L_k >= L_0` gives `L_k(P) = L_0(P)`. ∎

`[deduction]` **Corollary 2 (ply-depth obstruction).** The `k`-ply hierarchy
cannot exceed the information bound at the root until
`k > floor(n/2) = Omega(n)` plies. Equivalently, any lower-bound potential that
is a bounded-ply lookahead (or, a fortiori, any potential that is a function of
the current extension count alone) has value exactly `C(n)` at the root.

---

## 4. Why the sorter can balance: the mechanism

`[deduction]` The antichain's `n` free elements give the sorter a large supply
of *perfectly balancing* moves: comparing two free elements always halves the
extension set. Each such comparison consumes two free elements, so the sorter
can keep the extension split exactly balanced for `floor(n/2)` consecutive
comparisons, and the local lookahead has nothing to work with. The information
bound is therefore **locally tight** at the root: it is exactly the value of the
relaxation in which the sorter is allowed to balance every split independently.

`[deduction]` The excess `S(n) - C(n)` must therefore be **global**: it comes
from the fact that a single tree cannot balance all `n!` permutations
simultaneously, not from any single comparison. This is the same "local vs
global" picture as `docs/research-n12-nontightness.md` §8, but now expressed as
a *quantitative* obstruction: the local relaxation is exact for `Omega(n)` plies.

## 5. Computational verification

`[experiment]` `scripts/unary_ply_obstruction.py` memoizes `L(succ, k)` on
`(succ, k)` and reports `L_k(P0)` for `k = 0..kmax`. Results:

| n | `C(n)` | `floor(n/2)` | `L_k(P0) = C(n)` for `k <= floor(n/2)` | memoized states (`kmax = floor(n/2)`) |
|---|---|---|---|---|
| 2 | 1  | 1 | yes | 10 |
| 3 | 3  | 1 | yes | 46 |
| 4 | 5  | 2 | yes | 288 |
| 5 | 7  | 2 | yes | 1304 |
| 6 | 10 | 3 | yes | 4414 |
| 7 | 13 | 3 | yes | 12170 |

(The run `--max-n 7 --kmax 3` completes in a few seconds; `n = 8,9` at
`kmax = floor(n/2)` exceed the small-host budget.) For `n <= 11` the exact values
satisfy `S(n) = C(n)`, so `L_k(P0) = C(n)` for *all* `k` there; the
non-vacuous case is `n = 12`, where `S(12) = 30 > 29 = C(12)` (`[literature]`,
Wells; Peczarski; Stober–Weiß). The theorem predicts
`L_k(P0) = 29` for `k <= 6` and the first strict increase only after that.
The computation verifies the *mechanism* (the recursion really returns `C(n)`,
not a hand-asserted value) up to `n = 7`; the theorem proves it for all `n`.

`[experiment]` Contrast with a non-root poset: for the `n = 5` witness
`W = (26,0,10,0,8)` (`e = 8`), `L_0(W) = 3` but `L_1(W) = 4 = F(W)`
(`docs/research-one-ply-obstruction.md`). So the hierarchy *is* strict at `W`
with one ply; it is the *root* that is immune. This is the precise sense in
which the obstruction is about the antichain.

## 6. Consequences for the unary threshold language

`[deduction]` **Theorem 3 (hard core of `SORT-BOUND-U`).** For each `n`, the
only uncertain `k` are in `[C(n), U(n))`, of width `Theta(n)`. Within it:

* the **no-instances** `k < S(n)` include the *hard* range
  `[C(n), S(n))`, which the information bound does not certify;
* the **yes-instances** `k >= S(n)` include the *hard* range
  `[S(n), U(n))`, which no known compact witness certifies
  (`docs/research-encoding-consequences.md` §5.2).

`[deduction]` **Corollary 4 (no bounded-ply lower-bound certificate).** By
Corollary 2, every bounded-ply potential `phi` (in particular every potential
whose value is determined by the current extension count) satisfies
`phi(P0) = C(n)`. Hence no such potential can certify a hard no-instance
`C(n) <= k < S(n)`: it returns the *wrong* answer `phi(P0) = C(n) <= k`. Any
succinct lower-bound certificate for `SORT-BOUND-U` must therefore be
**non-local**: it must encode the global interaction that the `k`-ply hierarchy
loses, or it must be an entirely different kind of object.

`[deduction]` **Remark 5.** This is a *barrier to a technique*, not a
complexity-class lower bound. It does not show `SORT-BOUND-U not in coNP`; it
shows that the natural family of local potentials (the canonical
strengthening of the information bound) is insufficient. Combined with the
explicit-tree barrier of `docs/research-encoding-consequences.md` §5.2, the two
natural certificate routes (a compact potential for the no-side, a compact
strategy for the yes-side) are both obstructed.

## 7. Certificates

`[deduction]` **Table.** Status of certificate formats for `SORT-BOUND-U`
(unary input length `L = n+k+1`).

| Candidate | Size | Status |
|---|---|---|
| explicit adaptive tree | `>= 2n! - 1 = 2^{Theta(L)}` | super-polynomial; `docs/research-encoding-consequences.md` Thm 5.2 |
| strategy DAG (all optimal moves) | unknown; `65551` nodes at `n=6` | `[open]`; `docs/research-strategy-certificates.md` |
| `k`-ply potential (`k <= floor(n/2)`) | compact *description* | **value `C(n)` at the root**; cannot certify the hard no-core (Cor. 4) |
| information bound `L0` | compact (`ceil(log2 e)`) | certifies only `k < C(n)`; not tight at `n = 12` |
| nonuniform advice | `O(log L)` | `P/log` (`docs/research-encoding-consequences.md` Thm 3.7); nonuniform |

`[open]` The central open problem is unchanged: **is there any polynomial-size
certificate for `S(n) <= k` or `S(n) > k`?** Theorem 1 closes one natural route
(a bounded-ply potential) and sharpens the reason the known potential
`log2 e(P)` is the best local one.

## 8. Falsification attempts

`[experiment]` **F1 (does some small `k` beat `C(n)` at the root?).** Searched
`n = 2..7`, `k <= floor(n/2)`: `L_k(P0) = C(n)` in every case. The proof rules
this out for all `n`, so this route is closed, not merely unobserved.

`[deduction]` **F2 (merge-bound route).** A tempting lower bound on `S(n)` is
the exact merge cost `M(a,b)` of `Merge(a,b)`, since `S(n) >= F(Merge(a,b)) =
M(a,b)` by extension monotonicity. This is a dead end asymptotically:
`M(a,b) = O(a+b) = O(n)` (tape merge; `M(m,m) = 2m-1`,
`[literature]` Stockmeyer–Yao 1980), while `C(n) = Theta(n log n)`. So the
merge bound is *weaker* than the information bound for large `n` and cannot
close the gap. (For small `n` it can be stronger — e.g. `M(2,4) = 5 > C(6) =
4` — but `M(2,4) = 5 <= S(6) = 10` leaves a large gap.) The merge mechanism of
`docs/research-structural-lower-bounds.md` is a lower bound for a *specific*
sub-poset, not for the antichain root.

`[experiment]` **F3 (width-based potential).** The potential
`phi(P) = ceil(log2 e(P)) + width(P) - 1` would beat `C(n)` at the root
(`phi(P0) = C(n) + n - 1`). **Falsified at `n = 3`**: for
`P = {0<1, 2 free}`, `e = 3`, `width = 2`, so `phi = 2 + 1 = 3`, but
`F(P) = 2` (compare `2` with `0`; if `0<2` then compare `1,2`). So `phi` is not
a valid lower bound. No low-dimensional scalar correction of the information
bound is available.

`[deduction]` **F4 (does the hierarchy ever become strict at the root?).** For
`n <= 11` it does not (`S(n) = C(n)`). For `n = 12` it must (since `S(12) = 30 >
29`), but Corollary 2 says only that the first strict increase is at
`k > floor(n/2) = 6`, i.e. at depth `7` or later. The exact depth is not
computable here (it requires the posets reachable in `Omega(n)` plies from the
antichain, which for `n = 12` is infeasible in pure Python on the target host).

## 9. What was learned, and the next obstacle

**Learned.**
1. The `k`-ply hierarchy `{L_k}` is the canonical local strengthening of the
   information bound; `L_0 <= L_1 <= ... <= F`.
2. **Theorem 1**: at a chain-and-free poset with `f` free elements,
   `L_k = L_0` for `k <= floor(f/2)`. At the root this means
   `L_k(P0) = C(n)` for `k <= floor(n/2)`: the information bound is locally
   exact for `Omega(n)` plies.
3. The `n = 12` excess is therefore invisible to every bounded-ply potential;
   any lower-bound certificate for the hard no-core of `SORT-BOUND-U` must be
   non-local.
4. The merge-bound route to `S(n)` is asymptotically weaker than the
   information bound and cannot close the gap (F2).

**Next obstacle.**
`[open]` The decisive question is whether **any** compact potential can beat
`C(n)` at the root. The `k`-ply hierarchy is the maximal *bounded-ply* potential
and it cannot (Theorem 1). A non-local potential would have to capture the
global routing of all `n!` permutations; no such object is known. Two concrete
next steps:

1. **Certificate size.** Measure the number of distinct poset states on *some*
   optimal play for `n = 7, 8` (the open experiment of
   `docs/research-encoding-consequences.md` §11). If it is polynomially bounded,
   a succinct yes-certificate route survives; if it matches the full poset count,
   that route is obstructed too.
2. **A non-local potential.** Find a compactly describable potential `phi` with
   `phi(P0) > C(n)` for some `n`, or prove that none exists (a no-go theorem
   excluding the local-potential route entirely). Either outcome is a material
   change to what is known about the uniform complexity of `S(n)`.
