# Bidirectional Minimax Recurrence for SORT-BOUND-U: Worst-Case Analysis

**Status:** research note (paper analysis + deduction). Not Lean-checked.
Every item is labelled `[literature]`, `[deduction]`, `[conjecture]` or `[open]`.
Primary source: Stober & Weiß, *Lower Bounds for Sorting 16, 17, and 18
Elements*, ALENEX 2023, arXiv:2206.05597v2.

---

## 1. Setup and notation `[definition]`

**Language.** `SORT-BOUND-U = {1^n # 1^k : S(n) ≤ k}`, input length
`N = n + k + 1`. We decide the threshold, not the function.

**Game state.** A transitively closed strict partial order `P` on `n` labelled
elements. `e(P)` = number of linear extensions. `m(P)` = minimum worst-case
comparisons to sort every extension of `P` (`m(P) = 0` iff `P` total). Start:
antichain `P₀` (`m(P₀) = S(n)`).

**Key predicates.**
- *Information bound* (Stober–Weiß Obs. 2.2): `e(P) > 2^r` ⇒ `m(P) > r`.
  Contrapositive: `m(P) ≤ r` ⇒ `e(P) ≤ 2^r`.
- *Efficiency* (Stober–Weiß §2): for `P` obtained after `c` comparisons,
  `E(P) = n! / (2^c · e(P))`. `E_tot = n! · 2^{-k}` (efficiency of a total
  order after `k` comparisons).
- *Monotonicity* (Stober–Weiß Obs. 2.3): some child `P'` of `P` satisfies
  `E(P') ≤ E(P)`.

**Decision regime.** Trivial YES if `k ≥ U(n) = O(n log n)` (merge sort);
trivial NO if `k < C(n) = ⌈log₂ n!⌉` (info bound). Nontrivial instances:
`C(n) ≤ k < U(n)`, so `k = Θ(n log n)` and `N = Θ(n log n)`, whence
`n = Θ(N/log N)` and `k = Θ(N)`.

## 2. The bidirectional recurrence `[literature]` + `[deduction]`

### 2.1 Forward search (Stober–Weiß §3) `[literature]`

Minimax recurrence:

```
S_c(P) = ∨_{(u,v) incomparable} ( S_{c+1}(P+uv) ∧ S_{c+1}(P+vu) )
S_c(P) = True  if P total
S_c(P) = False if c = k and P not total
```

`S₀(P₀)` decides `S(n) ≤ k`. Pure forward DFS: at most `(2B)^k` nodes where
`B = binom(n,2)` ⇒ `2^{O(k log n)} = 2^{O(N log N)}`.

### 2.2 Backward search (Stober–Weiß §4.1) `[literature]`

BFS from the total order (level `k`) downward. Level `c` = posets sortable in
`≤ k-c` comparisons. Predecessors of `P` (§5.7): remove a Hasse-diagram edge
`(u,v)`, choose which transitive edges to add back → poset `P'` with
`P = P' + uv`. `P'` is an actual predecessor iff `P' + vu` is sortable in
`≤ k-c` (the "reverse edge poset" must be on level `≥ c`).

**Lemma 4.1** (completeness with Hasse optimization): storing only posets with
`≤ c` Hasse edges at level `c` preserves completeness — a forward-reachable
sortable `P` at level `c` is still found.

### 2.3 Partial backward search with efficiency threshold (§4.2) `[literature]`

Fix `0 ≤ C_f ≤ k` and `E_tot ≤ E_thr < 2·E_tot`.

- **Full layers** (`c ≥ C_f`): store *all* posets sortable in `≤ k-c`.
- **Partial layers** (`c < C_f`): store only posets with `E(P) ≤ E_thr`,
  i.e., `e(P) ≥ n!/(2^c · E_thr) ≈ 2^{k-c}` (using `E_thr ≈ E_tot`).

**Lemma 4.2** (coverage): if `P` is forward-reachable in `c` comparisons and
`m(P) ≤ k-c`, then:
1. If `c ≥ C_f`: `P ∈ ∪_{d≥c} B'_d` (full layers cover it).
2. If `E(P) ≤ E_thr`: `P ∈ B'_c` (partial table covers it).

**Contrapositive (sound NO):** if `E(P) ≤ E_thr` and `P ∉ B'_c`, then
`m(P) > k-c`.

### 2.4 Forward search with advice `[deduction]`

At level `c`, for each active poset `P`:

```
if E(P) ≤ E_thr:
    if P ∉ B'_c:          → NO (prune, Lemma 4.2)
    elif P ∈ B'_c, known:  → YES (prune)
    else:                  → expand (unknown)
else:                      → expand
```

The forward search expands only posets with `E(P) > E_thr`, i.e.,
`e(P) < n!/(2^c · E_thr) ≈ 2^{k-c}` (using `E_thr ≈ E_tot`).

## 3. State-count recurrence `[deduction]`

Let `F_c` = number of posets *expanded* by forward search at level `c`.
Let `M_c` = number of posets in the backward table at level `c`.

**Forward recurrence:**

```
F_0 = 1
F_{c+1} ≤ 2B · F_c  (each expanded poset has ≤ 2B children)
```

But expanded posets satisfy `e(P) < 2^{k-c}` (§2.4). A poset from `c`
comparisons has `≤ c` Hasse edges (Obs. 2.1), so the number of such posets is
at most `binom(n(n-1)/2, c) · 2^{O(c)} = 2^{O(c log n)}`. Hence:

```
F_c ≤ min( (2B)^c, 2^{O(c log n)} ) = 2^{O(c log n)}
```

**Total forward:** `Σ_{c=0}^{k} F_c = 2^{O(k log n)}`.

**Backward recurrence:**

At full layers (`c ≥ C_f`): `M_c ≤` number of posets sortable in `≤ k-c`
`≤ 2^{O((k-c) log n)}` (posets with `≤ k-c` Hasse edges).

At partial layers (`c < C_f`): `M_c ≤` number of posets with `e(P) ≥ 2^{k-c}`
sortable in `≤ k-c`. By info bound, sortable ⇒ `e(P) ≤ 2^{k-c}`, so the band
is `[2^{k-c}, 2^{k-c}]` — a factor-2 window. The number of posets in this
window with `≤ c` Hasse edges is `≤ 2^{O(c log n)}`.

**Total backward:**
```
Σ_{c=C_f}^{k} 2^{O((k-c) log n)} + Σ_{c=0}^{C_f} 2^{O(c log n)}
= 2^{O(k log n)} + 2^{O(C_f log n)} = 2^{O(k log n)}   (since C_f ≤ k)
```

**Theorem (worst-case time).** `[deduction]`
The bidirectional search decides `S(n) ≤ k` in time `2^{O(k log n)}`.
In terms of `N = n+k+1`: since `k ≤ N` and `n ≤ N`, this is `2^{O(N log N)}`.

This matches the forward-only bound of `docs/research-budgeted-dfs.md` §5.3.
The efficiency threshold improves the *constant factor* (by pruning posets
with `E ≤ E_thr`) but **not the asymptotic exponent**.

## 4. Why the exponent does not improve `[deduction]`

The forward search at level `c` must expand every poset with
`e(P) < 2^{k-c}` (outside the efficiency band). The number of such posets is
bounded by `2^{O(c log n)}` — the number of posets with `≤ c` Hasse edges.
This bound is tight in the worst case: there exist `2^{Θ(c log n)}` distinct
labelled posets with exactly `c` Hasse edges (e.g., choose `c` independent
edges from `binom(n,2)` possible), and a positive fraction of them can have
`e(P) < 2^{k-c}` for appropriate `k`.

The efficiency threshold prunes posets with `e(P) ≥ 2^{k-c}` (inside the
band). But the *expanded* posets — those with `e(P) < 2^{k-c}` — are the
majority at low levels (small `c`), because `2^{k-c}` is large and most
posets with few constraints have `e(P)` close to `n!`, which exceeds `2^{k-c}`
when `k-c < C(n)`. Wait — this needs care. At level `c`, posets have `≤ c`
Hasse edges. The antichain (`c=0`) has `e = n!`. Each comparison can at most
halve `e`. So `e(P) ≥ n!/2^c` for any `P` at level `c`. The condition
`e(P) < 2^{k-c}` requires `n!/2^c < 2^{k-c}`, i.e., `c > log₂(n!) - k =
C(n) - k`. For `k ≥ C(n)` (nontrivial regime), this is `c > C(n) - k ≤ 0`,
so **all** levels `c ≥ 0` can have posets with `e(P) < 2^{k-c}`.

Concretely: at `c = 0`, the antichain has `e = n!`. If `n! < 2^k` (i.e.,
`k > C(n)`), the antichain is pruned by the info bound. But if `k = C(n)`
(the tight regime), `n! > 2^k` and the antichain must be expanded. More
generally, at level `c`, posets with `e(P) ∈ [n!/2^c, 2^{k-c})` must be
expanded. The width of this interval (in log scale) is `(k-c) - (C(n)-c) =
k - C(n)`, independent of `c`. So the "expansion window" has constant
log-width at every level, and the number of posets in it is `2^{O(c log n)}`
at level `c`.

**Conclusion:** the exponent `O(k log n) = O(N log N)` is determined by the
width of the expansion window (`k - C(n)`), not by the efficiency bandwidth.
A smaller bandwidth shrinks the backward table but does not shrink the
forward expansion.

## 5. Space bound `[deduction]`

**Forward-only (existing bound):** `O(N log N)` bits (transcript-only DFS,
`docs/research-budgeted-dfs.md` §5.2).

**Bidirectional:** the backward table must be stored for lookup. Its size is
`M = Σ_c M_c = 2^{O(k log n)} = 2^{O(N log N)}` in the worst case. Even with
disk-based storage (Stober–Weiß §5.1: SSDs, partial hashes in memory), the
*total* storage is exponential. The in-memory portion can be reduced to
`O(N log N)` bits (hash buckets + active layer), but the disk I/O cost
dominates.

**Streaming alternative:** compute the backward table level-by-level,
use it to prune the forward search at that level, then discard. This reduces
memory to `O(N log n)` bits but recomputes the backward table `k` times,
giving time `2^{O(k² log n)}` — worse.

**Nonuniform advice:** if the backward table is precomputed and supplied as
advice (read-only tape), the forward search uses `O(N log N)` work space.
But this is a nonuniform model — the advice depends on `n` and `k` and is
not computable by the same uniform algorithm.

**Proposition.** `[deduction]` The bidirectional search with on-the-fly
backward table computation uses `2^{O(N log N)}` space in the worst case.
Achieving `O(N log N)` space requires either (a) a nonuniform advice model,
or (b) a streaming approach with `2^{O(k² log n)}` time, or (c) a
compression of the backward table to polynomial size (open).

## 6. What would change the bound `[open]`

1. **Poset-counting theorem.** If one proves that the number of posets with
   `≤ c` Hasse edges and `e(P) < 2^{k-c}` is `2^{o(c log n)}` (e.g.,
   `2^{O(c · α(n))}` with `α(n) = o(log n)`), the exponent drops. This
   requires a structural result about the joint distribution of `(#Hasse
   edges, e(P))` — no such theorem is known.

2. **Polynomial certificate for `S(n) ≤ k`.** If a polynomial-size witness
   (e.g., a compressed decision tree or a succinct proof of sortability)
   exists and is verifiable in poly-time, `SORT-BOUND-U ∈ NP`. Not
   established; the best sorting trees may be exponentially large.

3. **Exact poset-counting recurrence.** If the number of posets sortable in
   `≤ r` comparisons is `2^{O(r · β(n))}` with `β(n) = o(log n)` for
   `r = O(n log n)`, both forward and backward bounds improve. The current
   bound `2^{O(r log n)}` comes from `binom(n(n-1)/2, r)`; a tighter count
   would require ruling out most edge-sets as non-posets or non-sortable.

4. **Efficiency-threshold tightness.** If `E_thr` could be set to
   `E_tot · (1 + o(1))` (bandwidth → 0), the backward table shrinks but the
   forward expansion window (§4) is unchanged. The exponent is insensitive
   to the bandwidth.

## 8. Obstacle summary `[deduction]`

The bidirectional search with efficiency threshold (Stober–Weiß §4.2) has
worst-case time `2^{O(N log N)}` — the same exponent as forward-only.
The obstacle to a better bound is:

> **The expansion window has log-width `k - C(n)` at every level `c`.**
> Posets with `e(P) ∈ [n!/2^c, 2^{k-c})` must be expanded, and their number
> is `2^{Θ(c log n)}` in the worst case. The efficiency threshold prunes
> the complementary band but does not shrink the expansion window.

A breakthrough requires either (a) a theorem that the expansion window
contains `2^{o(c log n)}` posets (structural, not algorithmic), or (b) a
polynomial-size certificate for `S(n) ≤ k` (would imply NP membership), or
(c) a sub-exponential bound on the number of posets with `≤ c` edges and
`e(P) < 2^{k-c}` (open combinatorial question).

The space bound `O(N log N)` of the forward-only DFS cannot be matched by
a uniform bidirectional search without exponential disk storage or
nonuniform advice, because the backward table is `2^{Θ(N log N)}` in the
worst case.
