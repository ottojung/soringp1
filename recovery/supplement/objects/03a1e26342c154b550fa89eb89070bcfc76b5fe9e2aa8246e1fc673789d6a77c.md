# Reducing per-decision cost in unary threshold search for S(n)

**Status:** research note (paper analysis). **Not Lean-checked.** Every item is
labelled `[definition]`, `[literature]`, `[deduction]`, `[conjecture]` or `[open]`.
No new Lean files, no commits.

**Scope:** unary encoding exclusively. `SORT-BOUND-U = {1^n # 1^k : S(n) <= k}`,
input length `N = n + k + 1 = Theta(n log n)`.

---

## 1. Precise question

The gap `U(n) - L(n) = Theta(n)` is small relative to `n log n` (the magnitude
of `S(n)` itself). Binary search needs `O(log n)` threshold queries. The question:

> Can the small gap be exploited to make each threshold query **cheaper** than
> the current `2^{O(n^2)}` minimax DP, ideally sub-exponential in `N`?

Six sub-questions:
1. Preprocessing / data structures for cheaper subsequent queries?
2. Poly-time reduction to a problem with smaller parameter?
3. Ford-Johnson structure guiding a cheaper decision procedure?
4. Properties of the gap interval `[L(n), U(n)]` allowing pruning?
5. Incremental computation reusing work across different `k`?
6. A "threshold certificate" verifiable in poly time?

---

## 2. Key insight: the small gap is a red herring

**The hardness of computing `S(n)` comes from the combinatorial structure of
optimal sorting, not from the size of the range.** Even with a gap of size 1,
we would still need to compute `S(n)` exactly.

The gap being `Theta(n)` means there are `Theta(n)` possible values of `k` in
`[L(n), U(n)]`. But the decision problem `S(n) <= k` requires distinguishing
between these values, which requires computing `S(n)` exactly. The gap only
tells us **where to look**, not **what the value is**.

**Deduction.** Suppose we know `S(n) in {100, 101}`. To decide `S(n) <= 100`, we
must determine whether `S(n) = 100` or `S(n) = 101`. This is the full problem of
computing `S(n)` exactly. The gap size is irrelevant to the per-query cost.

---

## 3. Analysis of the six sub-questions

### 3.1 Preprocessing / data structures

**Answer: No known preprocessing helps.**

The minimax DP computes `F(P)` for all reachable posets `P`. This is the
expensive part (`2^{Theta(n^2)}` states). Any preprocessing that makes
subsequent queries cheaper would need to compute `F(P)` for all `P`, which is
the hard problem itself.

**Deduction.** The minimax function `F` is defined on the set of all posets,
which has `2^{Theta(n^2)}` elements. There is no known compact representation
of `F` that allows faster evaluation. The `S_n` symmetry quotient reduces the
state count by a factor `2^{Theta(n log n)}` but does not change the
`2^{Theta(n^2)}` asymptotics.

### 3.2 Poly-time reduction to smaller parameter

**Answer: No such reduction is known.**

`S(n)` does not obviously decompose into smaller subproblems. The only known
decomposition is for disjoint unions of posets, but the minimax value of a
disjoint union is **not additive** (comparisons across components may be
interleaved).

**Deduction.** For a disjoint union `P = P1 + P2`, we have `F(P) < F(P1) + F(P2)`
in general, because cross-component comparisons can be interleaved. This makes
it impossible to compute `F(P)` from `F(P1)` and `F(P2)` alone.

### 3.3 Ford-Johnson structure

**Answer: FJ structure does not guide a cheaper decision procedure.**

The Ford-Johnson algorithm is optimal only for `n <= 11`. For larger `n`, the
optimal algorithm is not known. The structure of optimal algorithms is not well
understood.

**Deduction.** Without a characterization of optimal algorithms, we cannot use
FJ structure to guide a cheaper decision procedure. The FJ algorithm gives an
upper bound `U(n)`, but this bound is not tight for `n >= 12`.

### 3.4 Gap interval properties

**Answer: The gap does not allow pruning.**

The gap `[L(n), U(n)]` has width `Theta(n)`. This is still wide enough that we
need to distinguish between `Theta(n)` different values, which requires
`log(Theta(n)) = O(log n)` bits of information. But each bit of information
requires a comparison, and the number of comparisons needed to sort `n` elements
is `S(n) = Theta(n log n)`.

**Deduction.** The gap does not reduce the number of comparisons needed. The
information-theoretic lower bound `ceil(log2 n!)` is the best known lower bound,
and it is not tight for `n >= 12`. No stronger lower bound is known that would
allow pruning.

### 3.5 Incremental computation

**Answer: The minimax DP already computes all values at once.**

The minimax DP computes `F(P)` for all reachable posets `P`, not for specific
`k` values. So the computation is already "incremental" in the sense that it
computes all values at once.

**Deduction.** The question is whether we can compute `F(P)` more efficiently
by exploiting the structure of the problem. No such method is known. The
minimax recurrence is already the most efficient known method.

### 3.6 Threshold certificate

**Answer: No polynomial-size certificate is known.**

A certificate for `S(n) <= k` would be a sorting tree of height `k`. But such a
tree has `2n! - 1` nodes, which is exponential in `N`. A certificate for
`S(n) > k` would require proving no such tree exists, which is even harder.

**Deduction.** The explicit tree witness has `2n! - 1` nodes. For unary
encoding, `n! = 2^{Theta(n log n)} = 2^{Theta(N)}`, so the witness size is
exponential in `N`. No polynomial-size certificate is known.

---

## 4. Can we make each query sub-exponential?

**Answer: Unlikely.**

The current best deterministic algorithm runs in time `2^{O(n^2)}`. In terms of
`N = Theta(n log n)`, this is `2^{O(N^2 / log^2 N)}`, which is super-polynomial
in `N` but **not** sub-exponential (which would be `2^{o(N)}`).

**Conjecture.** The problem is PSPACE-complete. The game `G(n,k)` is a two-player
game with perfect information, and determining the winner of such games is
typically PSPACE-complete. If `SORT-BOUND-U` is PSPACE-complete, then there is
no sub-exponential algorithm (unless `PSPACE subseteq SUBEXP`, which is unlikely).

**Deduction.** The game `G(n,k)` has:
- `k = Theta(n log n) = Theta(N)` rounds
- `O(n^2) = O(N^2 / log^2 N)` choices per round
- Game tree depth `Theta(N)`, branching factor `O(N^2 / log^2 N)`

The PSPACE algorithm uses alternation to guess the optimal strategy. The key
is that the game has polynomial alternating time, which puts it in PSPACE.
The question is whether the game is PSPACE-complete.

## 5. What was learned

1. **The small gap is a red herring.** The hardness of computing `S(n)` comes
   from the combinatorial structure of optimal sorting, not from the size of
   the range. Even with a gap of size 1, we would still need to compute `S(n)`
   exactly.

2. **No preprocessing helps.** The preprocessing itself is the hard problem.

3. **No poly-time reduction to smaller parameter.** `S(n)` does not decompose.

4. **Ford-Johnson structure doesn't help.** FJ is not always optimal.

5. **Gap interval properties don't allow pruning.** The gap is still `Theta(n)`
   wide.

6. **Incremental computation is already optimal.** The minimax DP computes all
   values at once.

7. **No threshold certificate.** The explicit tree has `2n! - 1` nodes.

8. **The PSPACE bound is likely tight.** The game structure suggests
   PSPACE-completeness.

---

## 6. Next unresolved obstacle

The central obstruction is **the absence of any succinct certificate in either
direction**, and its likely cause is the **absence of a compact canonical object**
describing optimal comparison play.

**Upper bound.** We need a polynomial-size object from which the existence of
a height-`k` tree follows, checkable in polynomial time. The standard known
witness is a reduced comparison tree of size `2n! - 1`. A plausible route is a
canonical branching program / DAG whose states are reachable posets; its
worst-case size is the number of labelled posets (`2^{Theta(n^2)}`), and it is
**open** whether optimal play confines the DAG to polynomially many states.

**Lower bound.** For `k >= ceil(log2 n!)` (e.g. `n=12, k=29`) no succinct
witness for `S(n) > k` is known; the published proofs are exhaustive searches
over posets (Wells, Peczarski, Stober-Weiss). A polynomial certificate would
likely require a new potential function stronger than `log2 e(P)`, which does
not exist yet.

**Classification.** The PSPACE upper bounds leave a large gap to the only known
lower bounds (trivial decidability and the sparse-set barrier). The specific
obstacle to closing it is that `S(n)` is a **single-parameter family**: no known
reduction exploits the symmetric, fixed-test-set structure, and the unary
sparse-set barrier rules out the most direct many-one route to NP-hardness.

---

## 7. Strongest defensible complexity claim

> **Theorem (informal, deduction).** `SORT-BOUND-U in PSPACE`. The unary
> language is sparse and cannot be NP-hard under polynomial-time many-one
> reductions unless `P = NP`. No polynomial-size certificate is known. The
> small gap `U(n) - L(n) = Theta(n)` does not reduce the per-decision cost.
