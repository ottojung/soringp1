# PACKET 02 — W[1]-hardness reduction attempt: symmetry/information obstruction

**Status:** research note (paper argument + obstruction proof). Not Lean-checked.
Every item is labelled `[definition]`, `[literature]`, `[deduction]`,
`[conjecture]`, `[experiment]` or `[open]`. Intended for Antonina issue #301.

---

## 1. Precise question

`[definition]` Can a parameterized fpt-reduction map an instance `(G, k)` of
k-Clique (or k-Independent-Set) to an instance `(n', s')` of
`CanSort(antichain, ·)` with `s' = O(k)` and `|(n', s')| = poly(|(G, k)|)`, such
that `G` has a k-clique **iff** `S(n') ≤ L(n') + s'`? Equivalently: is the
parameterized problem `{(n, s) : S(n) ≤ L(n) + s}` W[1]-hard?

**Answer: No.** The obstruction is fundamental and provable. No such reduction
exists. The antichain's total lack of per-instance structure makes it impossible
to encode arbitrary graph instances.

---

## 2. Strongest primary source

`[literature]` Downey & Fellows, *Fundamentals of Parameterized Complexity*
(Springer 2013), Chapter 13 — W-hierarchy and fpt-reductions. The key definition:
an fpt-reduction from `(Q, κ)` to `(Q', κ')` is a map `f` computable in
`g(κ(x)) · poly(|x|)` time with `κ'(f(x)) ≤ h(κ(x))`, preserving membership.

`[literature]` Mahaney (1982), *Sparse complete sets for NP* — already recorded in
`docs/research-hardness-boundaries.md` Theorem 4.2. `SORT-BOUND-U` is sparse and
in `P/log` (Theorem 4.3). These constrain but do not directly decide W[1]-hardness;
the obstruction below is independent.

## 3. What I attempted

### Attempt 1: Encode G into n

Map `(G, k) → (n', s')` where `n' = f(G)` for some graph encoding `f`, and
`s' = O(k)`. Then `G` has k-clique iff `S(f(G)) ≤ L(f(G)) + s'`.

**Failure.** The predicate `S(n') ≤ L(n') + s'` depends only on the integer
`n' = f(G)` and `s'`, NOT on the graph structure of `G`. Two different graphs
`G1, G2` with `f(G1) = f(G2)` produce the same `(n', s')` and hence the same
answer. The reduction must be injective on the clique/no-clique distinction,
but `f` maps `2^{Θ(m^2)}` graphs to at most `2^{poly(m)}` outputs. For any
polynomial `f`, collisions are unavoidable among graphs with different clique
status. `[deduction]`

### Attempt 2: Use comparison outcomes as edges

Build a gadget where the sorter's comparisons "discover" graph edges: comparing
elements `u, v` corresponds to querying whether `(u,v)` is an edge in `G`.

**Failure.** The adversary (worst-case analysis) controls comparison outcomes,
not the algorithm. The sorter cannot force a specific outcome to "encode" an
edge. Moreover, the sorter's goal is to determine a total order, not to learn
a graph — the adversary can answer in a way that maximizes comparisons while
revealing no graph structure. The game `G(n, k)` has no mechanism to represent
an external graph. `[deduction]`

### Attempt 3: Adaptive structure building

Use the sorter's adaptive choices to build a graph structure over comparisons,
where the "shape" of the decision tree encodes `G`.

**Failure.** The decision tree's shape is chosen by the sorter to minimize
worst-case comparisons, not to encode an external object. The sorter has no
knowledge of `G`. Any adaptive strategy is a function from comparison histories
to next comparisons; it cannot "plant" a graph into the sorting process because
the sorting process is entirely determined by `n` and the adversary's answers. `[deduction]`

### Attempt 4: Turing reduction (multiple oracle queries)

Make poly(|G|) adaptive queries `(n_1, s_1), …, (n_t, s_t)` to the CanSort
oracle and use the answers to decide k-Clique.

**Failure.** Each oracle answer is a fixed predicate of `(n_i, s_i)`. The
algorithm can learn `S(n)` for poly(|G|) values of `n` by binary search, but
`S(n)` is a single integer sequence with no connection to graph theory. There
is no way to extract clique information from the sequence `S(1), S(2), …`. `[deduction]`

## 4. The obstruction: three independent proofs

### Obstruction A: The fixed-function (circularity) argument `[deduction]`

`S(n)` is a **fixed** function of `n` alone — it does not take a graph as input.
The predicate `P(n, s) := [S(n) ≤ L(n) + s]` is a fixed binary relation on
pairs of integers. An fpt-reduction `f: (G, k) → (n', s')` must satisfy:

```
G has k-clique  ⇔  P(f(G, k)) = true
```

Since `P` is fixed, the reduction must **choose** `(n', s')` such that `P` happens
to be true exactly when `G` has a k-clique. But to know whether `G` has a
k-clique, the reduction must solve k-Clique — which is W[1]-hard. The reduction
cannot compute `f(G, k)` without already knowing the answer. This is circular
and impossible for any reduction that does not solve k-Clique internally. ∎

**Key distinction:** In a typical W[1]-hardness reduction (e.g., k-Clique to
k-Vertex-Cover), the reduction *constructs* a new instance whose structure
encodes the original. Here, the target instance `(n', s')` has no structure
beyond two integers, and the predicate `P` is fixed. There is nothing to
"construct" — only a fixed truth table to look up, and the reduction cannot
look up the right entry without solving the problem first.

### Obstruction B: The symmetry argument `[deduction]`

The antichain on `n` elements has full `S_n` symmetry: all `n!` orderings are
equally valid initial states, and the comparison game treats them identically.
Any comparison-based algorithm is `S_n`-equivariant — it cannot distinguish
inputs based on graph structure because there IS no graph structure in the input.

Formally: the game `G(n, k)` is defined purely in terms of `n` and `k`. The
state space is the lattice of posets on `n` elements, which is `S_n`-symmetric
at the root. No external graph enters the definition. A reduction from k-Clique
would need to inject graph information into this symmetric structure, but there
is no channel: the game's rules are fixed by `n` alone. ∎

### Obstruction C: The information/cardinality argument `[deduction]`

An fpt-reduction runs in time `g(k) · poly(|G|) = g(k) · poly(m + log k)`. The
output `(n', s')` has size `O(g(k) · poly(m))` bits. The number of distinct
outputs is at most `2^{g(k) · poly(m)}`.

The number of graphs on `m` vertices is `2^{m(m-1)/2}`. For the reduction to be
correct, no two graphs with different k-clique status may map to the same
output. This requires at least `2^{m(m-1)/2}` distinct outputs (one per graph,
up to the distinction). But `2^{g(k) · poly(m)}` is bounded by `2^{poly(m)}`
(for any computable `g`), which is eventually smaller than `2^{m^2/2}`.
Collisions are unavoidable. ∎

**Note:** Obstruction C is the weakest of the three (it depends on the growth
rate of `g`); Obstructions A and B are unconditional.

## 5. The P/log barrier (supporting evidence)

`[deduction]` From `docs/research-hardness-boundaries.md` Theorem 4.3:
`SORT-BOUND-U ∈ P/log`. With `O(log L)` advice bits (the cutoff `t_L`), the
problem is decidable in deterministic polynomial time. A W[1]-hard problem
under fpt-reductions would be highly unusual in `P/log` — parameterized
hardness typically requires the problem to have enough structure to encode
graph problems, which sparse truth-table problems do not.

This is **not** a proof that the problem is not W[1]-hard (P/log membership
does not rule out W[1]-hardness unconditionally), but it is strong structural
evidence consistent with Obstructions A–C. `[deduction]`

---

## 6. Why the antichain is different from general posets

`[deduction]` The generalized problem `CanSort(P, k)` for an explicit poset `P`
DOES have per-instance structure: the poset `P` can encode a graph (e.g., via
comparability graphs or poset dimension). This is why `GEN-SORT` might be
harder — it has a channel for graph information. The antichain `A_n` is the
**poset with zero structure**, and this is precisely what blocks the reduction.

Any W[1]-hardness result for `CanSort` must go through the generalized
`GEN-SORT`, not the antichain. But the transfer lemma
(`docs/research-hardness-boundaries.md` Lemma 1.1) only transfers hardness
**upward** (antichain-hard ⇒ GEN-SORT-hard), not downward. So even if
`GEN-SORT` were W[1]-hard, this would not imply W[1]-hardness for the antichain. `[deduction]`

---

## 7. Decisive result

**Theorem (symmetry/information obstruction).** There is no fpt-reduction from
k-Clique (or k-Independent-Set) to `CanSort(antichain_n, ·)` with surplus
parameter `s = O(k)`. The parameterized problem `{(n, s) : S(n) ≤ L(n) + s}`
is **not W[1-hard** via any reduction that encodes graph structure into the
antichain sorting instance.

*Proof.* By Obstruction A (circularity): any such reduction would need to
choose `(n', s')` based on the clique status of `G`, which requires solving
k-Clique. By Obstruction B (symmetry): the antichain has no structure to encode
a graph. Both are unconditional. ∎ `[deduction]`

**Caveat.** This does not rule out W[1]-hardness via some other route — e.g.,
a reduction that does not attempt to encode graph structure but instead uses
the problem as a "clock" or "counter." Such a reduction would require `S(n)` to
have specific number-theoretic structure that can simulate parameterized
computation, for which there is no evidence. `[open]`

---

## 8. Next step

The obstruction shows that **parameterized hardness of `CanSort` is not the
right tool** for this problem. The question "is `CanSort` FPT in `s`?" should be
approached via:

1. **Algorithmic upper bounds** (can we beat `2^{O(n log^2 n)}` in `s`?) —
   the budgeted DFS of `docs/research-budgeted-dfs.md`.
2. **Structural properties of `e(n) = S(n) - L(n)`** — the excess sequence is
   the key object; its structure determines FPT membership.
3. **Non-parameterized complexity** — is `SORT-BOUND-U` in P? This is equivalent
   to `S_unary ∈ FP`, the original research question.

The W[1]-hardness route is closed. The problem's difficulty (if any) lies in
the arithmetic of `S(n)`, not in combinatorial structure. `[deduction]`
