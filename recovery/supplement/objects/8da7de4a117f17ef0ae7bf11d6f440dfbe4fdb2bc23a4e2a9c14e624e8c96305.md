# Two naive complexity inferences fail: state-space size and value-gap size

**Status:** research note (literature audit + deductions + one small
experiment). **Not Lean-checked.** Every item is labelled `[literature]`,
`[deduction]`, `[experiment]`, `[conjecture]` or `[open]`. No NP-hardness, no
separation, and no new complexity-class membership is claimed. Companion
program: `scripts/state_gap_audit.py`.

This note audits two inferences that could mislead the classification of
`SORT-BOUND-U = {1^n # 1^k : S(n) <= k}`:

- **Inference 1 (state-space-to-hardness):** "the minimax state space has
  `2^{Theta(n^2)}` states, therefore computing `S(n)` is hard."
- **Inference 2 (narrow-gap-to-P):** "`S(n)` is within `O(n)` of the
  information lower bound, so the gap is small, therefore computing `S(n)`
  should be easy."

**Verdict.** Both inferences are **false as stated**. Inference 1 fails for
three independent reasons (§1–§3): a large state space is an algorithmic
artifact, not a problem invariant; even if it were a lower bound it forces only
logarithmic time, which is polynomial here; and sparsity gives no hardness
conclusion. Inference 2 fails because a small gap is an *approximation*
statement, and there are NP-hard problems with arbitrarily good approximations
(§5–§7). The note also states, in each case, the additional assumption that
would make the inference valid and why it is not available (§4, §8).

The scope is the unary encoding `N = n + k + 1`; the numeric `n` is used only
when discussing the `2^{Theta(n^2)}` DP state space. The binary language is not
an active target (`docs/problem.md`).

---

## 1. Inference 1 is refuted: a large state space is not a problem invariant

### 1.1 The premise is about one algorithm, not about the problem

`[deduction]` The number `2^{Theta(n^2)}` counts the states visited by the
**memoized partial-order dynamic program** of `docs/upper-bound.md`. It is a
property of that algorithm. The complexity of `S(n)` is a property of the
problem, i.e. a minimum over **all** algorithms. A lower bound on one
algorithm's state count is not a lower bound on the problem, unless one proves
that every correct algorithm must distinguish that many states (§2.1).

`[literature]`/`[deduction]` **Counterexample (Nim).** In Nim with heaps
`h_1, ..., h_k`, the position space has `prod_i (h_i + 1)` elements, which is
exponential in `k` and in the bit-length of the heaps. Yet Bouton's theorem
(1901/02) decides the winner in `O(k log H)` time via the nim-sum
`h_1 xor ... xor h_k != 0`, and Sprague–Grundy theory (Sprague 1935; Grundy
1939) extends this to all impartial games. A game with an exponentially large
state space is therefore in P. The repository script reproduces the agreement
on small instances:

```
  piles          | states (prod(p+1)) | brute-force | nim-sum | agree
          (2, 3) |                 12 |        True |    True | True
       (3, 4, 5) |                120 |        True |    True | True
    (1, 1, 1, 1) |                 16 |       False |   False | True
    (3, 4, 5, 6) |                840 |        True |    True | True
    (5, 6, 7, 8) |               3024 |        True |    True | True
```

`[deduction]` Other standard examples: minimum spanning tree (exponentially
many spanning trees, greedy in polynomial time, Kruskal 1956; Prim 1957);
shortest path (exponentially many paths, Dijkstra 1959); bipartite matching
(exponentially many matchings, Hopcroft–Karp 1973). In each case the natural
search space is exponential and the problem is in P.

### 1.2 Even a state-space lower bound would only force logarithmic time

`[deduction]` **Lemma 1.1 (configuration counting).** A deterministic Turing
machine that halts within `T(N)` steps on inputs of length `N` has at most
`|Q| · (N + T) · 2^{O(T)} = 2^{O(T)}` distinct configurations. Hence it can
distinguish at most `2^{O(T)}` inputs. Consequently, if a problem requires
distinguishing `M` distinct input classes, every correct deterministic
algorithm runs in time `Omega(log M)`.

`[deduction]` **Corollary 1.2.** The poset DP state space is `M = 2^{n^2}`.
Even under the **strongest possible** reading — that every correct algorithm
must distinguish all `2^{n^2}` states — Lemma 1.1 yields only
`Omega(log M) = Omega(n^2)`. In the unary encoding `N = n`, this is
`Omega(N^2)`, which is **polynomial**. To force exponential time
`2^{Omega(N)}` one would need `M = 2^{2^{Omega(N)}}`, a doubly exponential
deficit. The script makes the gap vivid:

```
  n | poset states 2^{n^2} | forced time lower bound | states needed for 2^{Omega(n)} time
   8 | 2^64                 | Omega(64)                | 2^(2^8) = 2^256
  12 | 2^144                | Omega(144)               | 2^(2^12) = 2^4096
  16 | 2^256                | Omega(256)               | 2^(2^16) = 2^65536
  32 | 2^1024               | Omega(1024)              | 2^(2^32) = 2^4294967296
```

`[deduction]` The inference therefore overstates the state-space premise by an
exponential: it treats "exponential in `n^2`" as if it implied "exponential in
`n`". The configuration-counting relation between state count and time is
**logarithmic**, not linear.

`[deduction]` **Remark 1.2a (the counting bound is tight).** Lemma 1.1 is not a
barrier that large state spaces *cannot* be easy; it is a best-case guarantee
that they *can* be easy. For every `M` there is a decision problem solvable in
`Theta(log M)` time that distinguishes `M` input classes: membership in a
sorted dictionary of `M` keys by binary search. So a state space of size `M`
admits an algorithm matching the `Omega(log M)` floor exactly. A large state
space is therefore *compatible with* an easy matching algorithm; the counting
bound alone never rules out `P`.

`[deduction]` **Corollary 1.3 (the "large" state space is small).** A
deterministic algorithm running in time `N^c` has at most `2^{O(N^c)}`
configurations. For `c > 2`, `2^{O(N^c)} >> 2^{N^2}`. Hence the poset state
space `2^{n^2} = 2^{N^2}` is **within** the configuration space of a
polynomial-time machine. A state count that a cubic-time algorithm can already
afford cannot by itself be an obstruction to `P`.

### 1.3 Sparsity does not rescue the inference

`[deduction]` `SORT-BOUND-U` is sparse (`O(L^2)` strings of length `<= L`), and
every sparse set is in `P/poly` (`docs/research-encoding-consequences.md`
Lemma 3.2). `[literature]` `P/poly` is exactly the class of languages
polynomial-time Turing reducible to a sparse set (Meyer, cited in
Berman–Hartmanis 1977). Hence sparse sets can encode arbitrary complexity: the
unary encoding of any undecidable set is sparse and undecidable. Sparsity is
therefore **compatible with undecidability** and yields no uniform lower
bound.

`[literature]` **Mahaney's theorem** (1982): a sparse set that is NP-hard
under polynomial-time many-one reductions implies `P = NP`. `[deduction]` This
is a **conditional barrier** on one specific hardness proof, not a membership
statement and not a lower bound. It says nothing about `P`, `PSPACE`, or
decidability.

`[deduction]` **Conclusion.** "Sparse + large state space" implies nothing
precise about the complexity of `SORT-BOUND-U`. The two premises are
compatible with every level from `P` (indeed `SORT-BOUND-U in P/log`,
`docs/research-encoding-consequences.md` Theorem 3.7) to arbitrary nonuniform
complexity. The only hardness statement available is conditional (Mahaney),
and it is a barrier, not a result.

### 1.4 The DP state count is not even a decision-tree lower bound

`[deduction]` A correct comparison tree for `n` keys has at least `n!` reachable
leaves (one per permutation). The memoized poset DP visits `A001035(n)` states,
and `A001035(n) > n!` for every `n >= 2`:

```
  n | labelled posets (DP states) | n! (reduced tree leaves) | DP > leaves
   2 |                          3 |                        2 | True
   3 |                         19 |                        6 | True
   4 |                        219 |                       24 | True
   5 |                       4231 |                      120 | True
   6 |                     130023 |                      720 | True
   7 |                    6129859 |                     5040 | True
```

The DP explores **more** states than there are permutations, so its state count
is not a lower bound on the information-theoretic complexity either. The
`2^{Theta(n^2)}` figure is an artifact of enumerating labelled posets, not a
measure of the problem's intrinsic difficulty.

## 2. What assumption would make Inference 1 valid

`[deduction]` To conclude hardness from a state-space count, one would need:

1. a proof that **every** correct algorithm must distinguish at least `M`
   states (a state-distinguishability, adversary, or communication-complexity
   theorem), and
2. `M` large enough that `log M` is superpolynomial.

`[deduction]` Here `M = 2^{n^2}`, so `log M = n^2` is polynomial. Even if (1)
were proved, the conclusion would be `Omega(n^2)` time, which is consistent
with `P`. To obtain exponential time one would need `M = 2^{2^{Omega(n)}}`,
i.e. a doubly exponential state space. The actual state space is doubly
exponentially too small. **No strengthening of the existing premise suffices**;
a hardness result would require an entirely different lower-bound mechanism.

## 3. Inference 2 is refuted: a small gap is an approximation, not an exact algorithm

### 3.1 The premise conflates "close to a lower bound" with "easy to compute"

`[deduction]` If a computable lower bound `L(n)` satisfies
`S(n) - L(n) <= g(n)`, then `L` is a `g(n)`-additive approximation to `S`. A
good approximation is **not** an exact algorithm. There is no theorem that
converts a small gap into an exact polynomial-time algorithm.

`[literature]` **Counterexamples (NP-hard problems with arbitrarily good
approximation).**

- **Euclidean TSP.** Arora's PTAS (1998) computes a `(1+eps)`-approximation
  for any fixed `eps > 0` in polynomial time, i.e. the gap to `OPT` is made
  arbitrarily small. Yet exact Euclidean TSP is NP-hard (Papadimitriou 1977).
- **0-1 knapsack.** The FPTAS of Ibarra–Kim (1975) and Lawler (1977) computes
  a `(1-eps)`-approximation for any fixed `eps > 0`; exact knapsack is NP-hard
  (weakly). The gap tends to zero, the exact problem stays hard.
- **Metric TSP.** Christofides' algorithm (1976) gives a `1.5`-approximation;
  exact metric TSP is NP-hard.
- **Vertex cover.** The LP relaxation gives a `2`-approximation; exact vertex
  cover is NP-hard.

`[deduction]` In each case the optimum is close to a known bound, yet exact
computation is NP-hard. A small gap therefore says nothing about exact
complexity. (The standard theory of approximation algorithms and
inapproximability, e.g. Garey–Johnson 1979, is consistent with this: a PTAS or
FPTAS coexists with NP-hardness.)

### 3.2 The gap structure of `S(n)` does not help

`[experiment]` The known gap `S(n) - ceil(log2 n!)` is:

```
  n | S(n) | I(n) | gap | note
   0 |    0 |    0 |   0 |
   ...
  11 |   26 |   26 |   0 | last gap-0 before n=12
  12 |   30 |   29 |   1 | first obstruction (Wells)
  20 |   62 |   62 |   0 | gap 0 again (literature)
  21 |   66 |   66 |   0 | gap 0 again (literature)
```

`[deduction]` The gap is `0` for `n <= 11` and `n = 20, 21`, but `1` at
`n = 12`. This is **not** a monotone or simply structured sequence: the
information bound is tight at most small `n`, fails at `n = 12`, and is tight
again at `n = 20, 21`. Knowing that the gap is `O(n)` does not tell you *where*
it is `0`, and the exceptions are exactly where the obstruction lives.

`[deduction]` A small gap means the information bound is a good
**approximation**. It does not make the exact value easy: the exact value of
`S(n)` is open for `n >= 23` even though the gap is `O(n)` (indeed `S(n) <= n
log2 n` and `ceil(log2 n!) = n log2 n - Theta(n)`). The small gap is
precisely the phenomenon that makes the problem *look* easy while remaining
open.

### 3.3 A large gap can be easier than a small gap

`[deduction]` Gap size and complexity are independent:

- **Large gap, easy:** shortest path (trivial lower bound `0`, gap = shortest
  distance, which can be huge; Dijkstra is polynomial). Minimum spanning tree
  (trivial lower bound = heaviest edge, gap can be large; Kruskal/Prim are
  polynomial).
- **Small gap, hard:** Euclidean TSP (gap `-> 0` via PTAS; exact NP-hard);
  vertex cover (LP gap `2`; exact NP-hard).

So "large gap" is not a hardness indicator and "small gap" is not an easiness
indicator. The inference's direction is not monotone.

## 4. What assumption would make Inference 2 valid

`[deduction]` If the lower bound were **attained** (`gap = 0`) for all `n`,
then `S(n) = ceil(log2 n!)` would be computable in polynomial time: `n!` is
computable in polynomial time in the unary input length `n` (it has
`Theta(n log n)` bits), and `ceil(log2 n!)` follows. So **tightness**, not
smallness, is what would help — and tightness is a proof obligation, not a
numerical observation.

`[deduction]` More generally, the inference would be valid only under an
assumption of the form: "there is a polynomial-time exact decision procedure
for `S(n) <= k`" (which is the original problem), or a self-reducibility
theorem that converts a `g(n)`-additive approximation into an exact algorithm.
No such theorem is available for `S(n)`, and the existence of NP-hard problems
with PTAS/FPTAS (§3.1) shows it cannot be a general principle.

`[deduction]` **Remark 4.1a (any gap-to-exact theorem must be problem-specific).**
Suppose a general theorem converted "a `g(n)`-additive approximation to `OPT`
computable in polynomial time" into "exact `OPT` computable in polynomial
time" for every optimisation problem. Apply it to Euclidean TSP: Arora's PTAS
computes a `(1+eps)`-approximation in polynomial time for every fixed `eps`,
so the gap tends to `0` as `eps -> 0`, and exact Euclidean TSP would lie in `P`.
This contradicts Papadimitriou's NP-hardness of exact Euclidean TSP (1977)
unless `P = NP`. Hence no such general theorem exists; a gap-to-exact conversion
for `S(n)` would have to exploit *specific* structure of comparison sorting
that is not present in the general approximation landscape. This is a no-go for
the *principle*, not for the specific problem.

## 8. Next unresolved obstacle

The two inferences are dead ends, and their failure does not advance the
classification. The decisive question remains: is there a **compact canonical
object** (a recurrence, certificate, or logical formula) that determines
optimal comparison play without enumerating the `2^{Theta(n^2)}` poset states?
Both refutations point the same way: the state-space size is an algorithmic
artifact and the information-bound gap is an approximation, so progress must
come from a structural theorem, not from counting states or gaps.
