# Kernel-checked results

Inventory of the machine-checked (Lean 4 + Mathlib) results for the sorting
number `S(n)`, the exact statement each proves, and the open fronts. Every
theorem below is kernel-checked with no `sorry`/`admit`/`axiom`/`native_decide`;
all modules build with `lake build --wfail` and replay under `leanchecker`.

Model (`SoringP1/Model.lean`): a deterministic adaptive comparison algorithm is
`ComparisonTree n` (`leaf (Equiv.Perm (Fin n)) | compare i j yes no`); `height`
is the worst-case comparison count; `run ranking tree` returns the leaf reached;
`Correct tree` means `∀ ranking, run ranking tree = ranking.symm`;
`HasBudget n k` means some correct tree has height `≤ k`; and
`S n := sInf {k | HasBudget n k}`.

## Achieved

### A0 — existence (`SoringP1/Existence.lean`)
- `exists_hasBudget (n) : ∃ k, HasBudget n k` — a correct sorting tree exists
  for every `n`, via an explicit fuel-driven insertion-sort tree `sortTree`.
  This makes `S n` a genuine (nonempty) infimum.
- `sortTree_correct`, `sortTree_height : height (sortTree n) ≤ n*(n+2)+(n+1)+1`.

### A1 — attainment and minimality (`SoringP1/Attainment.lean`)
- `hasBudget_S (n) : HasBudget n (S n)` — the infimum is attained.
- `S_le_iff {n k} : S n ≤ k ↔ HasBudget n k` — `S n` is exactly the minimum
  feasible budget.
- `S_is_minimal`, `S_le_explicit (n) : S n ≤ n*(n+2)+(n+1)+1`,
  `exists_tree_S (n) : ∃ tree, Correct tree ∧ height tree ≤ S n`.

### A2 — information lower bound (`SoringP1/LowerBound.lean`)
- `factorial_le_two_pow_height {n} (tree) (h : Correct tree) :
    n.factorial ≤ 2 ^ height tree`
- `factorial_le_two_pow_S (n) : n.factorial ≤ 2 ^ S n`
  (the classic `S(n) ≥ log₂ n!` bound, kernel-checked against the model).
- Supporting: `numLeaves_le_two_pow_height`, `leafSet_card_le_numLeaves`,
  `run_mem_leafSet`, `factorial_le_numLeaves`.

### A4 / A5 — exact small values (`SoringP1/SmallValues.lean`)
- `S_zero : S 0 = 0`, `S_one : S 1 = 0`, `S_two : S 2 = 1`, `S_three : S 3 = 3`.
- Explicit optimal trees `treeTwo` (1 comparison) and `treeThree`
  (3 comparisons), each proven `Correct`; lower bounds from A2.

### A7 — exact values `S 4 = 5`, `S 5 = 7`, `S 6 = 10`
  (`SoringP1/SmallValues4.lean`, `SmallValues5.lean`, `SmallValues6.lean`)
- Optimal trees `treeFour`/`treeFive`/`treeSix` of heights 5/7/10, **generated by
  a minimax search over partial orders** (`scripts/generate_optimal_tree.py`) and
  emitted mechanically with computable swap-composition leaves, so `Correct` is
  closed by `fin_cases … <;> decide`.
- `S_four : S 4 = 5`, `S_five : S 5 = 7`, `S_six : S 6 = 10`, via the helper
  `S_eq_of {n v} (hup : HasBudget n v) (hlo : 2^(v-1) < n!) : S n = v` and the
  lower bounds from A2.
- Hence **`S(0..6) = 0, 0, 1, 3, 5, 7, 10` are all exact and kernel-checked**,
  matching `scripts/evaluate.py`. Each value equals `⌈log₂ n!⌉` for `n ≤ 6`.
- `SoringP1/SmallValues7.lean`: `thirteen_le_S_seven : 13 ≤ S 7`,
  `S_seven_le : S 7 ≤ 21` (and `S_seven_bracket`) — `S 7` is beyond the
  evaluator/generator range but is bracketed by the general bounds.
- `SoringP1/TightSmall.lean`: `S_eq_clog_of_le_six (n) (h : n ≤ 6) :
  S n = Nat.clog 2 n.factorial` — the information bound is tight for `n ≤ 6`.

### A8 — monotonicity (`SoringP1/Monotone.lean`)
- `S_mono (n) : S n ≤ S (n + 1)` — the optimal comparison count is
  nondecreasing in `n`.
- Built by pruning an `(n+1)`-tree to an `n`-tree (`ext`, `stripMax`, `prune`,
  `stripMax_symm_ext`, `height_prune`, `run_prune`): comparisons against the
  largest element are fixed and the element is stripped from leaves, so the
  pruned tree is correct with no greater height.

### A9 — elementary general bounds (`SoringP1/Bounds.lean`)
- `n_sub_one_le_S (n) : n - 1 ≤ S n` — at least `n - 1` comparisons are needed,
  via `two_pow_pred_le_factorial : 2 ^ (n - 1) ≤ n!` and the information bound.
- `log2_factorial_le_S (n) : Nat.log2 n.factorial ≤ S n` — the information
  bound in logarithmic form.
- `le_S_of_pow_lt (n k) (h : 2 ^ (k-1) < n!) : k ≤ S n` — a usable lower-bound
  form; instances `thirteen_le_S_seven : 13 ≤ S 7`, `sixteen_le_S_eight : 16 ≤ S 8`.
- `clog_factorial_le_S (n) : Nat.clog 2 n.factorial ≤ S n` — the information
  bound in ceiling-logarithm form (`S n ≥ ⌈log₂ n!⌉`).

### A10 — tight upper bound (`SoringP1/TightBound.lean`)
- `S_le_tight (n) : S n ≤ n * (n - 1) / 2` — the insertion tree's true
  comparison count (insert position `i` costs ≤ `i`), via the comparison-exact
  height invariant `height_go_tight` (`Hinto`, `Haux`; a length-only invariant so
  both children of a comparison node satisfy it). Supersedes the loose
  `n(n+2)+(n+1)+1`.

### Evaluator (`SoringP1/Minimax.lean`)
- `splitPairs (S) : Finset (Fin n × Fin n)` — comparison pairs that split a
  ranking set into two nonempty parts; `splitPairs_nonempty : 2 ≤ S.card →
  (splitPairs S).Nonempty` (the combinatorial core).
- `adv (S) : ℕ` — the partial-order minimax value (least worst-case comparison
  count for sorting every ranking in `S`), **computable** by recursion on
  `S.card`; `filter_card_lt` gives the termination measure.
- `Sorts S T` — `T` sorts every ranking in `S`.
- `adv_le_height : Sorts S T → adv S ≤ height T` — the adversary lower bound.
- `adv_le_height_correct : Correct T → adv univ ≤ height T`.
- `adv_univ_le_S (n) : adv univ ≤ S n` — the adversary bound in infimum form.
- `adv_eq_zero_iff (S) : adv S = 0 ↔ S.card ≤ 1`.
- `bestPair S` — an optimal comparison pair (argmin of the minimax cost), and
  `bestPair_le`; `minimaxTree S` — the minimax sorting tree (compare the optimal
  pair, recurse); `minimaxTree_sorts : Sorts S (minimaxTree S)`.
- **A24 complete**: `minimaxTree_height (S) : height (minimaxTree S) ≤ adv S`;
  `minimaxTree_spec` combines height and correctness;
  `hasBudget_adv_univ`, `S_le_adv_univ` yield the upper half.
- **`S_eq_adv_univ (n) : S n = adv univ`** — the exact minimax characterization,
  kernel-checked and CI-verified (A24, commit `379c4a14`). This is a
  mathematical equivalence, **not** a Turing-machine time bound.

## Open fronts

Routine Lean formalization is paused in favor of literature-led,
paper-and-computation research. This inventory records proofs, not a
queue of next theorems. See `AGENTS.md` and `docs/research-plan.md`.

1. **Machine-time complexity bridge:** the `2^{O(n²)}` partial-order dynamic
   programming argument is an **informal algorithm sketch**, not a
   kernel-checked uniform Turing-machine cost bound. Unary and binary
   representations must be distinguished. A proof of termination of `adv`
   is not a machine-time theorem.
2. **Structural understanding:** search for better exact algorithms and
   explain obstructions such as `S(12)=30 > ceil(log₂(12!))=29`.
   Known values like `S(7)=13` and `S(8)=16` belong in the literature
   baseline, **not** a default Lean milestone queue.
3. **Complexity-class classification:** no P, NP or unconditional separation
   theorem is established. Certificates, uniform computation and reduction
   barriers require independent investigation.

The tighter insertion upper bound (A10) and small `S 4`–`S 6` certificates
are **already completed**; old references treating them as open were stale.

A theorem about a surrogate problem is not a theorem about S; each result
above states its exact object.
